# 07 - 用户认证系统与权限管理

本步骤的目标：**实现默认免登录的数据管理与清除功能、可选用户认证，以及按需申请的权限管理。当前所有项目模板和示例统一选择「不需要登录」。**

## 当前默认与可选功能

- **当前默认**：`{{项目名}}AuthEnabled = false`，闪屏初始化完成后直接进入主页面；不显示登录、注册、退出登录或删除账号入口，也不以登录状态限制浏览、编辑资料、收藏或发布等功能。
- **必备功能**：设置页面提供 **Clear Data（清除本地数据）** 按钮；个人资料和行为数据在应用重启后恢复，清除后恢复初始状态。
- **可选认证**：只有需求明确改为「需要登录」后，才启用认证选项并实现登录、退出登录、删除账号等完整流程。此选项是项目配置，不需要在产品设置页暴露技术开关。
- **权限管理**：仅为实际使用的相机、相册、麦克风功能配置权限，并在使用前请求。

## 二、目标产物

### 1. 免登录流程（当前必备）

- 闪屏显示应用 Logo、名称和 loading，初始化缓存与数据服务后直接进入主页面（详见 04 步骤）。
- 不创建登录页、认证拦截或虚假的已登录状态；如业务数据需要关联本地资料，可建立本地资料标识，但不将其当成账号登录。
- 个人资料编辑及行为记录通过独立的数据服务读写，不依赖 AuthController 或登录方法。所有修改即时更新页面并持久化，重启应用后恢复。
- 用户协议和隐私政策入口保留在设置页，通过 `{{项目名}}_agreement_config.dart` 统一获取路径；不依赖登录页提供协议入口。

### 2. 设置页面与清除本地数据（当前必备）

- 提供英文按钮 **Clear Data**；当前不显示 **Login / Logout / Delete Account**。
- 点击后先显示英文二次确认，明确会清除个人资料、内容与操作记录、偏好设置等本应用保存的数据，用户取消时不修改任何数据。
- 用户确认后，清除本应用持久化的个人资料、发布内容、评论、浏览历史、点赞、收藏、分享、举报、拉黑、不感兴趣记录、偏好设置及缓存文件（按实际功能覆盖）；保留随包资源、预置 Mock 数据和项目配置。
- 清除时禁用重复操作，协调正在执行的数据读写，避免旧异步结果把已清除的数据写回。同步重置内存模型、GetX Controller、EventBus 关联统计与页面状态。
- 清除成功后显示英文完成提示，通过重置导航栈返回主页面并恢复初始数据；再次启动也不能恢复已删除的资料和操作记录，且始终无需登录。
- 清除失败时显示英文错误提示，允许重试，不得误报成功。
- 底部显示应用名称和 **Version 1.0.0**，与 `pubspec.yaml` 一致。

### 3. 用户认证（可选，当前不启用）

只有明确启用 `{{项目名}}AuthEnabled = true` 后，才需要实现本节并验收：

- **登录界面**：Logo、应用名、可选标语、带 loading 的快速登录按钮、可点击的协议链接和协议勾选；未勾选不能登录。
- **用户标识**：首次创建用户时使用 `userid_UUID`，用户名使用 `appname_随机5位`，其余资料按产品设计初始化；登录状态和完整用户资料持久化。
- **启动路由**：已登录进入主页面，未登录进入登录页。
- **退出登录（Logout）**：只清除登录状态，保留完整资料和行为数据；返回登录页，再次登录恢复同一用户及编辑后的资料。
- **删除账号（Delete Account）**：二次确认后清除所有用户相关数据与状态，返回登录页，再次登录创建新用户。
- **Clear Data**：仍保留独立入口；若清除范围包含认证数据，成功后重置导航栈到登录页，避免残留已登录状态。当前免登录配置下始终返回主页面。
- 在 `docs/当前项目信息.md` 记录认证已启用，并同步更新路由、提审材料与测试清单；不能只增加按钮而缺少实际行为。

### 4. 权限管理与代码规范

- 相机、相册、麦克风均在对应功能使用前请求，拒绝或受限时给出可理解的提示。
- 在 `ios/Runner/Info.plist` 添加实际需要的英文权限说明，并在 `permission_handler` 的 iOS 编译配置中开启相应权限宏。
- 所有项目代码放在 `lib/{{项目名}}/` 下，文件名、类名和方法名以项目名为前缀；私有函数以 `_{{项目名}}` 为前缀。
- UI 文案使用英文，代码注释使用中文，import 使用 `package:项目名/...` 绝对路径。

## 六、注意事项

- **免登录是当前唯一默认选择**：不能因参考项目或产品类型有账号体系，就自动启用认证。复用模板时移除默认登录重定向和账号操作入口。
- **清除与重启行为区分**：普通重启恢复数据，只有用户确认清除才重置；可选认证启用后的账号删除按对应流程处理。
- **权限请求要在使用前进行**：不在启动时一次申请所有权限；权限说明应准确解释功能用途，例如 "We need access to your camera to take photos"。

### iOS 端权限宏与 ATS 配置建议

- **1）在 iOS 工程中为 `permission_handler` 开启所需权限宏**  
  - 推荐在 `ios/Podfile` 或 Xcode 的 `GCC_PREPROCESSOR_DEFINITIONS` 中添加如下定义（按你的实际需要裁剪）：  
    - `'PERMISSION_CAMERA=1'`  
    - `'PERMISSION_MICROPHONE=1'`  （例如用于音视频 SDK，如 Agora）  
    - `'PERMISSION_PHOTOS=1'`  
    - `'PERMISSION_PHOTOS_ADD_ONLY=1'`  
    - `'PERMISSION_APP_TRACKING_TRANSPARENCY=1'`  
  - 这些开关可以避免在未使用某些权限时产生多余的系统弹窗和审核风险，同时保证已用到的相机 / 相册 / 麦克风 / 跟踪权限都被正常声明。

- **2）配置 App Transport Security（ATS）以便加载外部资源**  
  - 如果应用中需要加载非 HTTPS 的外链资源（例如某些图片或 Mock 接口），可以在 `ios/Runner/Info.plist` 中加入：

```xml
<key>NSAppTransportSecurity</key>
<dict>
    <key>NSAllowsArbitraryLoads</key>
    <true/>
</dict>
```

  - 实际项目中可根据需要改为**只对特定域名放行**以降低审核风险；本流程作为马甲骨架，可以先开放，后续按上线版本再收紧。
