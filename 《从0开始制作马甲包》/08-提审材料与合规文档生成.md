# 08 - 提审材料与合规文档生成

本步骤的目标：**生成 App Store 提审所需的材料（应用介绍、关键字、类别、副标题）和合规文档（隐私政策、用户协议），并创建协议管理类用于集中管理协议文件路径。**

---

  - 项目名称
  - 应用名称
  - 产品类型
  - 功能模块列表
- 05 步骤中已经实现的：
  - 完整功能模块

## 二、目标产物

本步骤结束后，你应该得到：

1. **提审材料**（`/audit/Intro.md`）：
   - 应用介绍（基于产品功能，符合 AppStoreConnect 规范）
   - 关键字（相关且符合规范）
   - 类别（选择合适的 App Store 类别）
   - 副标题（两个单词，例如：Video & Chat）

2. **合规文档**（英文 HTML 文件，存放在 `/audit/agreement/` 目录下）：
   - `Terms&Conditions.html`（用户协议，基于产品功能）
   - `PrivacyPolicy.html`（隐私政策，支持邮箱：support@[AppName].com）
   - `index.html`（关于我们，可选）
   - `Support.html`（支持页面，可选）
   - `logo.png`（应用 Logo 图片）

3. **协议管理类**（存放在 `lib/{{项目名}}/config/` 目录下）：
   - 创建一个协议管理类（例如：`{{项目名}}_agreement_config.dart`）
   - 用于集中管理用户协议和隐私协议的路径
   - 方便后续修改和替换协议文件

4. **文件结构**：

```text
audit/
  Intro.md
  agreement/
    Terms&Conditions.html    # 用户协议
    PrivacyPolicy.html        # 隐私政策
    index.html               # 关于我们（可选）
    Support.html             # 支持页面（可选）
    logo.png                 # 应用 Logo 图片

lib/{{项目名}}/config/
  {{项目名}}_agreement_config.dart  # 协议管理类
```

## 五、执行步骤建议

1. **生成提审材料**
   - 使用「给 AI 的提示词模板：生成提审材料」，让 AI 生成 `/audit/Intro.md`。
   - 审阅内容是否符合 App Store 规范。
   - 如有需要，可以要求 AI 调整。

2. **生成合规文档和协议管理类**
   - 使用「给 AI 的提示词模板：生成合规文档」，让 AI 生成 HTML 文件和协议管理类。
   - 在 `/audit/` 目录下创建 `agreement/` 文件夹。
   - 将生成的 HTML 文件保存到 `/audit/agreement/` 目录：
     - `Terms&Conditions.html`（用户协议，必须）
     - `PrivacyPolicy.html`（隐私政策，必须）
     - `index.html`（关于我们，可选）
     - `Support.html`（支持页面，可选）
     - `logo.png`（应用 Logo 图片，从 `assets/{{项目名}}_logo.png` 复制）
   - 检查邮箱地址是否正确（support@[AppName].com）。
   - 在 `lib/{{项目名}}/config/` 目录下创建协议管理类（`{{项目名}}_agreement_config.dart`）。

3. **在应用中链接合规文档**
   - 在设置页面或登录页面添加"Terms & Conditions"和"Privacy Policy"链接。
   - **使用协议管理类**：通过 `{{项目名}}_agreement_config.dart` 获取协议文件路径，不要直接硬编码路径。
   - 链接指向本地 HTML 文件或在线版本。
   - 确保协议管理类提供清晰的 API，方便在多个页面中使用。

4. **更新步骤文档**
   - 完成本步骤后，更新 `docs/步骤.md` 文档，标记本步骤为"已完成"
   - 记录完成的工作和遇到的问题，便于后续继续完善功能

## 七、注意事项

- **应用介绍要真实**
  - 不要夸大功能，要基于实际实现的功能来写。
  - 符合 App Store 审核要求，不要使用违规词汇。

- **关键字要相关**
  - 关键字要与产品功能相关，不要使用无关的关键字。
  - 不要使用竞品名称作为关键字。

- **合规文档要完整**
  - 隐私政策要说明所有数据收集和使用情况。
  - 用户协议要包含所有必要的法律条款。
  - 邮箱地址要正确，确保用户可以联系到你。

- **文档格式要专业**
  - HTML 文档要有基本的样式，看起来专业。
  - 可以使用内联 CSS 或外部样式表。

- **协议管理类要便于维护**
  - 协议管理类（`{{项目名}}_agreement_config.dart`）应该集中管理所有协议文件的路径。
  - 后续如果需要修改或替换协议文件，只需要修改这个配置类即可，不需要修改业务代码。
  - 确保协议管理类提供清晰的 API，方便在登录页面、设置页面等地方使用。

#### 禁用词（强制）
- **禁用词列表**：`mock`、`local`、`offline`、`device storage`、`local data`、`mock data`、`local storage`、`offline only`
- **禁用原因**：App Store 审核要求应用不能暴露"本地模拟数据"的技术实现细节，必须呈现为"真实应用"
- **适用范围**：所有用户可见的 UI 文案（按钮文字、提示信息、页面标题、空态文案），以及 `/audit/Intro.md` 中的应用介绍、关键字、副标题等
- **不适用范围**：代码注释、变量名、开发文档、法律合规条款本身（如在隐私政策中客观描述数据存储方式）
