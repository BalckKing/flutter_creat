# 02 - 项目脚手架创建与基础配置

本步骤的目标：**在明确了"当前项目信息"之后，创建一个参考 Zorion 结构的 Flutter 工程脚手架，配置 GetX，建立以项目名为前缀的统一命名规范，并初步确定依赖、目录与入口结构。**

---

## 一、前置输入

在开始前，建议你准备好：

- **1. 来自 01 步骤的《当前项目信息.md》**  
  - 文档位置：`docs/当前项目信息.md` 或项目根目录下的 `当前项目信息.md`
  - 项目名称（用于 `flutter create` 的 `--project-name` 与显示名称参考，也作为命名前缀）。
  - **目标平台：仅 iOS**（不需要支持 Android 或其他平台）。

- **2. 包名 / 应用 ID 命名规则**
  - 例如：`com.company.{{项目名}}` 或 `com.{{项目名}}.app`。

- **3. 目录与依赖约定**
  - 代码目录：在 `lib/` 下新增一个以项目名命名的文件夹（如 `lib/huddle/`），**所有项目代码都放在该目录下**；
  - 依赖：必须包含 `get`、`flutter_screenutil`、`pull_to_refresh`、`image_picker`、`permission_handler`、`cached_network_image`、`shared_preferences` 等（参考 Zorion 的 `pubspec.yaml`）。
- **4. 模块架构命名方案（必选）**
  - **每次从 0 创建新项目时，须为本项目选定一套「模块层命名方案」**，且与以往项目不同（见 00 文档中的「模块架构命名变化规则」）。
  - 可选示例：方案 A（page/component/controller/service/widget）、方案 B（presentation/widget/controller/service）、方案 C（screen/component/controller/widget/service）等。
  - 选定后须在 **本步骤** 写入 `当前项目信息.md` 的「模块架构命名方案」一节，后续 04、05 等步骤统一按该方案命名目录与文件。

## 二、目标产物

本步骤结束后，你应该得到：

1. 一个可运行的 Flutter 工程（**仅支持 iOS 平台**，不需要支持 Android 或其他平台）。
2. 一份初版的 `pubspec.yaml` 依赖配置，至少包含：  
   - `get`（状态管理 + 路由）
   - `flutter_screenutil`、`pull_to_refresh`  
   - `image_picker`、`permission_handler`  
   - `cached_network_image`、`shared_preferences`  
   - `freezed_annotation`、`json_annotation`（用于数据模型）
   - `build_runner`（用于代码生成）
   - 以及网络与工具依赖（如 `dio`、`uuid` 等，可参考 Zorion）。
3. 一个为后续步骤准备好的基础目录结构，**所有命名以项目名为前缀**，例如（以项目名 `huddle` 为例）：

```text
lib/
  huddle/
    core/
      theme/
      routing/
      env/
    shared/
      widgets/          # 通用组件和子组件（如卡片组件、按钮组件等）
      utils/
    modules/
      huddle_home/
      huddle_login/
      huddle_profile/
      ...
    data/
      models/
      repositories/
    config/                    # 配置管理（包括协议配置等）
main.dart

assets/
  {{项目名}}_img/            # A面资源目录
    icons/
    # 注意：A面资源绝对不能放在 assets/images 目录，该目录是B面专用的
```

## 四、执行步骤建议

### 预备步骤：Git 仓库与开发分支（**仅在你有远端 git 仓库链接时执行**）

1. 如果你提供了远端 git 仓库地址（推荐），先在本地 clone 仓库：  
   ```bash
   git clone {{你的git仓库地址}}
   cd {{仓库目录名}}
   ```  
2. 从主分支拉取最新代码：  
   ```bash
   git checkout main  # 或 master
   git pull
   ```  
3. 创建并切换到开发分支：  
   ```bash
   git checkout -b feat/v1.0.0
   ```  
4. 后续所有从 0 创建 Flutter 项目和功能开发，都在 `feat/v1.0.0` 分支上完成；如果你没有远端 git 仓库，可以跳过本小节，在本地先用 `flutter create` 创建工程，后续再按需要 `git init` / 添加远端。

### 步骤1：用命令行创建 Flutter 工程（**建议在开始 01–09 任意步骤前，最先完成这一命令**）

1. 决定工程目录与工程名（**直接使用项目名称**，不需要添加 `_app` 后缀）。
2. 在终端中执行（示例，假设项目名为 `huddle`）：

```bash
flutter create \
  --project-name huddle \
  --org com.huddle \
  --platforms=ios \
  huddle
```

> **注意**：
> - 使用 `--platforms=ios` 参数，**仅创建 iOS 平台支持**，不创建 Android 平台。
> - `--project-name` 和最后的目录名都**直接使用项目名称**（如 `huddle`），不需要添加 `_app` 等后缀。

3. 在 IDE 中打开该工程，运行一次确保能在 iOS 模拟器或真机上启动。
4. **记录完成的工作**：例如"已完成 Flutter 工程创建，项目名：huddle，包名：com.huddle"。

### 步骤2：配置代码规范文件

1**验证代码规范生效**：
   - 在 IDE 中打开项目，代码规范应该自动生效。
   - **注意**：不需要执行 `flutter analyze` 命令，IDE 会自动检查。
   - 
### 步骤3：根据 AI 建议调整 `pubspec.yaml`

1. 将 AI 输出的 `dependencies` 片段复制到 `pubspec.yaml` 对应位置。
2. 运行：

```bash

```

3. 如果出现依赖冲突或版本问题，可以再次将错误信息贴给 AI，请它协助调整版本。
4. **记录完成的工作**：例如"已完成依赖配置，包含 get、flutter_screenutil、pull_to_refresh 等核心库"。

### 步骤4：搭建基础目录结构（严格遵循命名规范）

**重要**：
- 确保创建 `lib/{{项目名}}/config/` 目录，用于存放配置管理类（如协议配置等）。
- **所有文件名、文件夹名、模块名都必须以项目名为前缀**。
- **模块层命名**须使用本项目在「模块架构命名方案」中选定的一套名称（如 page/component/controller 或 presentation/widget/service）；选定后须写入 `当前项目信息.md` 的「模块架构命名方案」一节，供 04、05 等步骤一致引用。

1. 按 AI 给出的目录结构建议，在 `lib/` 下创建目录，例如（假设项目名为 `huddle`）：


2. 在每个关键目录内创建一个占位文件（避免空目录不被提交），例如：

## 七、注意事项

### 代码规范必须遵守
- 所有代码必须遵守该规范（**不需要执行 `flutter analyze` 命令**）。

### 导包必须使用绝对路径
- **所有 import 语句必须使用绝对路径**（`package:项目名/...`），不能使用相对路径（`../`、`../../` 等）。
- 示例：
  - ✅ 正确：`import 'package:huddle/shared/widgets/huddle_button.dart';`
  - ❌ 错误：`import '../shared/widgets/huddle_button.dart';`

### 命名规范要严格执行
- **命名规范是硬性要求**：从这一步开始，所有后续步骤都必须严格遵循以项目名为前缀的命名规范。
- **文件内的函数（私有函数或工具函数）必须以 `_{{项目名}}` 为前缀**（如 `_huddleCalculateTotal()`），避免多个文件之间的函数名冲突问题。
- 如果发现命名不符合规范，需要立即修正。
- `--org` 建议使用稳定的公司/团队域名；
- 项目名直接使用，不需要添加 `_app` 等后缀。

### GetX 的使用策略
- 多个页面的状态管理：使用 GetX Controller
- 简单页面：使用 Flutter 原生状态管理（`setState`）

### 依赖不要一次性加太多
- 优先保证项目能跑起来，GetX 配置好。
- 复杂功能/三方 SDK 可在 05、07 等步骤再逐步补充。

### 目录结构从一开始就为"配置驱动"留位置
- 比如 `config/` 目录将承载：马甲配置、文案配置、资源配置等；
- `core/theme/`、`core/routing/` 等目录会在 03、04 步骤中进一步完善。
- 代码目录：在 `lib/` 下新增一个以项目名命名的文件夹（如 `lib/huddle/`），**所有项目代码都放在该目录下**。
