# 04 - 路由与基础页面框架搭建

本步骤的目标：**根据 01 步骤的功能模块，设计路由结构和基础页面骨架，为后续模块实现提供“挂载点”。**

---

## 一、前置输入

- 01 步骤整理好的《当前项目信息》，特别是：
  - 功能模块列表；
  - 预期的主流程（例如：首页 → 列表 → 详情 → 个人中心）。
- 02 步骤中确定的：
  - 路由库选择（例如：`go_router` / `auto_route` / 自定义）。
  - 目录结构（例如有无 `core/routing/` 目录）。
- 对底部导航 / 抽屉 / 顶部 Tab 等框架形态的大致偏好：
  - 是否需要底部 Tab？（**如果使用底部 Tab，尽量设计 3、4 个，如果中间是发布按钮，则可能是 5 个，根据产品类型和功能需求，发挥创造力和想象力自主决定 Tab 数量**）
  - 大概率会有哪些主入口页面（如：首页、收藏、个人中心等）。

---

## 二、目标产物

本步骤结束后，建议你得到：

1. 一套 GetX 路由配置（例如在 `lib/core/routing/{{项目名}}_app_routes.dart` 中）：  
   - 定义所有核心页面的路由路径；  
   - 所有文件名、类名都以项目名为前缀。  
2. 若干基础页面文件（位于 `modules` 下），例如：

```text
lib/modules/{{项目名}}_home/presentation/{{项目名}}_home_page.dart
lib/modules/{{项目名}}_detail/presentation/{{项目名}}_detail_page.dart
lib/modules/{{项目名}}_profile/presentation/{{项目名}}_profile_page.dart
```

3. 一个主框架页面（如带底部导航的页面）：
   - **底部 Tab 尽量设计 3、4 个**，根据产品类型和功能需求，发挥创造力和想象力自主决定
   - **如果中间是发布按钮**，则可能是 5 个 Tab（例如：首页、发现、发布、消息、我的）
   - 把常用页面（首页、收藏、我的等）挂在底部 Tab 中；  
   - 为后续模块开发提供稳定入口。

---

## 三、给 AI 的提示词模板一：设计路由结构与文件分布

> 使用方式：  
> 1. 把「当前项目信息」中的功能模块列表贴在提示词后。  
> 2. 告诉 AI 你使用的路由库（如 `go_router`）。  

```text
你现在是一个熟悉 Flutter 路由生态的架构师。

我有一个 Flutter 项目，准备使用 {{你选择的路由库，例如 go_router}} 来管理路由。
下面是这个 App 的功能模块和主流程描述，请你基于这些信息设计路由结构。

请你完成：
1）给出一个推荐的路由表（路由 path + name），涵盖核心页面，例如：首页、列表、详情、个人中心、设置等；
2）设计一份路由常量或枚举定义，保证命名规范；
3）给出目录与文件分布建议（例如：路由配置放在 lib/core/routing/，页面放在对应 modules 目录下）。

输出格式：
- 用 Markdown 列表先描述路由结构（树状关系）；
- 再给出一份伪代码/接口草图，说明路由配置大致长什么样。

下面是 App 的功能模块与主流程描述：
===
{{粘贴 01 步骤中“功能模块”相关内容}}
===
```

## 四、给 AI 的提示词模板二：生成具体路由代码与页面骨架

> 使用方式：  
> 1. 确定好路由库（如 `go_router`）；  
> 2. 用下面的提示词，让 AI 生成实际可用的 Dart 代码。  

```text
继续基于你刚才设计的路由结构，我们使用 GetX 来管理路由。

项目名称：{{项目名称}}
命名规范：所有文件名、类名、方法名都必须以项目名为前缀

请你帮我：

1）在 `lib/core/routing/` 下，设计并实现一个路由配置文件（`{{项目名}}_app_routes.dart`）：
   - 使用 GetX 的 `GetPage` 配置所有核心页面；
   - 定义路由常量类（例如：`{{项目名首字母大写}}Routes`），所有路由 path 以项目名为前缀（例如：`/{{项目名}}/home`）；
   - 支持一个主框架页面（如带底部导航的根页面）；
   - 尽量保持代码清晰，方便后续扩展。

2）**实现闪屏页面（Splash Screen）**：
   - 创建闪屏页面文件：`lib/modules/{{项目名}}_splash/presentation/{{项目名}}_splash_page.dart`
   - 实现功能：
     - **展示应用 Logo**：从 `assets/{{项目名}}_logo.png` 或 `/audit/agreement/logo.png` 加载
     - **展示应用名称**：在闪屏上显示应用名称，与品牌一致
     - **可增加更多 UI 元素和动画效果**：如渐变、淡入、缩放等，使闪屏更生动
     - **转圈圈的 loading 效果**：使用 `CircularProgressIndicator` 或自定义转圈动画，表示正在加载
     - 在闪屏页面进行初始化检查：
       - 检查登录状态（从本地缓存读取）
       - 初始化数据服务
       - 加载必要的配置
     - 闪屏页面完成后跳转逻辑：
       - 如果已登录，跳转到主页面
       - 如果未登录，跳转到登录页面
   - 如果有参考项目，可以参考其闪屏页面的实现方式
   - 闪屏页面应该作为应用的初始路由

3）为主要页面生成基础骨架代码（只需简单 UI，占位即可），例如：
   - `lib/modules/{{项目名}}_home/presentation/{{项目名}}_home_page.dart`
   - `lib/modules/{{项目名}}_detail/presentation/{{项目名}}_detail_page.dart`
   - `lib/modules/{{项目名}}_profile/presentation/{{项目名}}_profile_page.dart`
   等等。

要求：
- 所有文件名、类名、方法名都以项目名为前缀（例如：`HuddleSplashPage`、`HuddleHomePage`、`huddleBuildBody()`）；
- **文件内的函数（私有函数或工具函数）以 `_{{项目名}}` 为前缀**（如 `_huddleCalculateTotal()`），避免多个文件之间的函数名冲突问题；
- 每个页面包含一个 `StatelessWidget` 或 `StatefulWidget`，带简单的 `Scaffold` 和标题；
- UI 文案使用英文，代码注释使用中文；
- 代码能直接编译运行；
- 注释中简要说明后续会在何处接入真实业务逻辑。

请直接输出完整的 Dart 代码文件，使用 Markdown ```dart 代码块分隔。
```

## 五、执行步骤建议

1. **先抽象路由结构（不写代码）**
   - 使用「提示词模板一」，让 AI 帮你先画路由树；  
   - 根据结果检查是否覆盖了所有核心功能模块；  
   - 调整路由 path，确保所有命名以项目名为前缀。
   - **记录完成的工作**：例如"已完成路由结构设计，包含登录、首页、个人中心等页面路由"。

2. **再生成路由代码与页面骨架**
   - 使用「提示词模板二」，让 AI 输出 `{{项目名}}_app_routes.dart` 和若干页面文件；  
   - 将代码粘贴到相应目录（`lib/{{项目名}}/core/routing/` 和 `lib/{{项目名}}/modules/`），**确保所有文件名、类名、方法名都以项目名为前缀**；  
   - 运行应用，确认路由跳转和主框架（如底部导航）正常工作。
   - **记录完成的工作**：例如"已完成路由配置和页面骨架，包含路由文件和所有基础页面"。

3. **在 `main.dart` 中接入路由**
   - 使用 GetX 的 `GetMaterialApp`，配置 `getPages`；  
   - **设置初始路由为闪屏页面**（`{{项目名}}_splash_page`）
   - 把 03 步骤中实现的主题与路由集成到一起。
   - **记录完成的工作**：例如"已完成 main.dart 路由配置，已集成主题和路由，初始路由设置为闪屏页面"。

4. **更新步骤文档**
   - 完成本步骤后，更新 `docs/步骤.md` 文档，标记本步骤为"已完成"
   - 记录完成的工作和遇到的问题，便于后续继续完善功能

## 六、注意事项

- **严格遵循命名规范**
  - 路由文件：`{{项目名}}_app_routes.dart`
  - 路由常量类：`{{项目名首字母大写}}Routes`
  - 路由 path：`/{{项目名}}/home`、`/{{项目名}}/detail` 等
  - 页面文件：`{{项目名}}_home_page.dart`
  - 页面类：`{{项目名首字母大写}}HomePage`
  - 方法名：`{{项目名}}BuildBody()`

- **页面划分尽量模块化**
  - 与 `modules` 下的业务模块对齐，如：`modules/{{项目名}}_home`、`modules/{{项目名}}_detail` 等；  
  - 避免所有页面都堆在一个 `pages/` 目录中。

- **控制复杂度**
  - 首版只需保证主流程跑通，复杂权限控制、多深度嵌套路由可以后置；  
  - 越简单越利于在后续通过 AI 自动生成/修改。

- **UI 文案使用英文，代码注释使用中文**
  - 这是硬性要求，确保一致性。
