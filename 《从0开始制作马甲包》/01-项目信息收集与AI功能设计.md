# 01 - 项目信息收集与AI功能设计

本步骤的目标：**收集项目基础信息（项目名称、产品类型、配色），然后让 AI 自主设计完整的功能体系、用户流程和界面结构。**

---

## 一、前置输入（极简输入，推荐方式）

你只需要提供以下信息：

- **项目名称**：例如 `huddle`、`zenith`、`vortex` 等（将作为所有命名前缀）。
- **产品类型/方向**：例如：
  - "健康追踪应用"
  - "食谱管理应用"
  - "旅行日记应用"
  - "社交聊天应用"
  - "健身打卡应用"
  - 等等
- **配色方案**：主色、辅色等（可以只给颜色方向，如"蓝色系"、"绿色系"、"紫色系"）。
- **Git 仓库链接（可选）**：如果你有现成的项目或模板，可以提供 git 链接，AI 会先分析仓库结构，用作架构参考。
- **项目模板（可选）**：如果你有一个参考项目的架构或关键文件，可以提供作为模板。
- **用户认证（可选）**：当前统一选择 **不需要登录**（`{{项目名}}AuthEnabled = false`）；默认直接进入主页面，设置页必须有 **Clear Data（清除本地数据）** 按钮。只有后续明确要求时才改为需要登录，AI 不得自行启用。
- **固定技术基线**：版本 `1.0.0`、Dart `^3.10.9`、Flutter `>=3.44.0`、iOS 最低版本 `15.6`（含 `ios/Flutter/AppFrameworkInfo.plist`，配置与锁文件检查见 02），三种 AppIcon 配置见 03。

> **⚠️ 重要提示**：如果你提供了参考项目（Git 链接或项目模板），AI 应该：
> - 分析参考项目的架构和设计思路，作为**参考和启发**；
> - **不能全盘照抄**参考项目的代码、功能或设计；
> - 基于参考项目的架构思路，**发挥自己的想象力和创造力**，设计出符合当前产品类型的独特功能和界面。

**示例输入**：

```markdown
项目名称：huddle
产品类型：社交聊天应用
配色方案：蓝色系，主色偏深蓝
项目模板：无
用户认证：不需要登录
设置功能：清除本地数据（Clear Data）
```

## 二、前置输入（详细规划，可选方式）

如果你希望对项目有更详细的规划和控制，可以先想清楚以下内容，然后交给 AI 整理：

- **1. 产品定位**
  - 这个 App 要解决什么问题？
  - 它更偏向：工具 / 内容浏览 / 社交 / 电商 / 教育 / 其他？

- **2. 目标用户**
  - 主要用户是谁？（年龄、地区、使用设备、使用场景）
  - 他们在什么场景下会打开这个 App？

- **3. 核心功能清单**
  - 你期望的 3–5 个核心功能模块（例：浏览内容、搜索、收藏、个人主页、设置等）；当前无需登录注册。

- **4. 品牌与风格偏好（为 03 主题配置做准备）**
  - 应用暂定名称（可以先用工作名）。
  - 品牌调性关键词（如：清爽、科技感、年轻、商务、卡通等）。
  - 颜色偏好（主色、大致颜色方向即可：蓝色、绿色、暗色等）。
  - 是否有 logo / 图标风格参考链接。

- **5. 上架与合规要求**
  - 目标平台：**仅 iOS**（App Store）
  - 需要特别注意的政策（隐私、账号体系、内容审查等）。

- **6. 技术与非功能性要求**
  - 是否需要多语言？
  - 是否需要离线能力？
  - 对性能、包体积、启动速度有没有特别要求？

**示例输入（详细规划方式）**：

```markdown
产品定位：
- 一个帮助用户浏览精选资讯的轻量级内容浏览 App

目标用户：
- 18–35 岁，主要在手机上刷内容的年轻用户

核心功能：
- 首页推荐流
- 内容详情页
- 收藏与历史记录
- 个人中心（基础信息配置）
- 设置页清除本地数据；不需要登录

品牌与风格：
- 调性：清爽、轻快、年轻
- 主色：偏蓝绿色
- 有一个现成 logo，主色是 #27B3A6

上架与合规：
- 目标：App Store（仅 iOS）
- 需要隐私政策页面与基础埋点说明

技术与非功能性要求：
- 多语言：暂时英文为主
- 性能：启动时间尽量少于 2 秒（冷启动）
```

## 三、目标产物

本步骤结束时，AI 会生成以下文档到项目中：

### 1. `当前项目信息.md` 结构化文档

**存放位置**：`docs/当前项目信息.md` 或项目根目录下的 `当前项目信息.md`

**文档内容**：
- **项目基础信息**：名称、简介、目标平台（**仅 iOS**）
- **AI 自主设计的功能体系**：
  - 完整的功能模块列表（AI 根据产品类型自主设计）
  - 详细的用户流程（从启动到完成主要任务的完整链路）
  - 界面结构设计（每个功能模块对应的页面和交互）
- **品牌与视觉风格**：基于你提供的配色方案
- **技术栈要求**：GetX、命名规范等
- **用户认证选项**：不需要登录，`{{项目名}}AuthEnabled = false`；包含 Clear Data 按钮、清除范围与清除后返回主页面的流程
- **版本与平台限制**：`version: 1.0.0`、`environment.sdk: ^3.10.9`、Flutter `>=3.44.0`、iOS `15.6`，以及 02、03 步骤的锁文件与 AppIcon 要求
- **模块架构命名方案**：本项目的模块层命名采用的整套名称（如 page/component/controller 或 presentation/widget/service 等）。**在 02 步骤确定并写入**，后续 04、05 等步骤须一致引用该方案。

> **重要**：这份文档是后续所有步骤的输入来源，后续步骤会不断引用这份文档中的功能列表、用户流程、界面结构等。

### 2. `步骤.md` 简单步骤文档

**存放位置**：`docs/步骤.md` 或项目根目录下的 `步骤.md`

**文档内容**：
- 简要列出整个项目的制作步骤（00-10）
- 每个步骤的简要说明和当前状态（待开始/进行中/已完成）
- 记录当前执行进度，以便于后续继续完善功能
- 用于快速了解项目进度和下一步要做什么

> **用途**：
> - 方便快速查看项目制作进度，了解当前处于哪个步骤，下一步应该做什么
> - **记录执行进度**：每次完成一个步骤后，更新文档中的状态标记，便于后续继续完善功能
> - 如果项目制作中断，可以通过这个文档快速了解已完成的工作和下一步要做什么

## 六、执行步骤建议

### 方式一：极简输入（推荐）

1. **准备基础信息**
   - 确定项目名称（建议简短、易记，将作为所有命名前缀）。
   - 明确产品类型（可以是宽泛的方向，AI 会帮你细化）。
   - 确定配色方案（可以只给大致方向）。

2. **使用提示词模板一让 AI 设计功能体系**
   - 复制「给AI的提示词模板一」，填入你的项目信息。
   - 把提示词发给 AI，等待它输出完整的项目信息文档。

3. **审阅并调整 AI 的设计**
   - 检查功能模块是否完整、合理。
   - 确认用户流程是否符合你的预期。
   - 如有需要，可以要求 AI 补充或调整某些部分。

4. **保存文档到项目中**
   - **创建 `docs/` 目录**（如果项目还没有创建，可以在项目创建后保存）：
     ```bash
     mkdir -p docs
     ```
   - **保存 `当前项目信息.md`**：
     - 路径：`docs/当前项目信息.md` 或项目根目录下的 `当前项目信息.md`
     - 这份文档是后续所有步骤的输入来源
   - **保存 `步骤.md`**：
     - 路径：`docs/步骤.md` 或项目根目录下的 `步骤.md`
     - 用于快速查看项目制作进度

### 方式二：详细规划（可选）

1. **先写再问**  
   - 不要直接把需求都丢给 AI，让它「自己想」。  
   - 建议先用 10–20 分钟，把你对这个 A 面的真实想法写下来（参考「前置输入（详细规划）」部分）。

2. **用提示词模板二整理一次**  
   - 把你写的内容按「给AI的提示词模板二」发给 AI。  
   - 检查 AI 输出的结构化文档，手动做一些增删改。

3. **确认这份"当前项目信息"是后续唯一来源**  
   - 后面 02–08 步骤遇到任何「名字、颜色、功能解释」，都优先从这份文档中读取。  
   - 如果中途需求变了，尽量先在这份文档里调整，再继续后面的步骤。

## 七、注意事项

### 信任 AI 的设计能力
- 你不需要提供详细的功能列表，AI 会根据产品类型自主设计。
- 如果 AI 的设计有偏差，可以在审阅时要求调整。

### 项目名称一旦确定，后续所有命名都要遵循
- 文件名：`{{项目名}}_home_page.dart`
- 模块名：`{{项目名}}_home`
- 方法名：`{{项目名}}BuildBody()`
- **文件内的函数（私有函数或工具函数）**：`_{{项目名}}CalculateTotal()`、`_{{项目名}}FormatDate()`（避免多个文件之间的函数名冲突）
- 资源目录：`assets/{{项目名}}_img/`

### 这一步的产物是后续所有步骤的输入
   - 后面 02–08 步骤会不断引用这份文档中的功能列表、用户流程、界面结构等。
- 如果中途需要调整，建议先更新这份文档，再继续后续步骤。

### 不要在这一步就纠结所有细节
- 比如："到底要不要加 IM 功能？"，可以先标记为「待确认」，后面再决定。

### 尽量保持命名的一致性
- 模块名、页面名、功能名，最好从现在开始就固定一个说法，方便后面 AI 生成代码时引用。

### 这一步的产物非常关键
- 它相当于整个「从0开始制作马甲包」流程的「总蓝图」。  
- 建议你在后续每次大改需求前，都回到这里更新一次。
