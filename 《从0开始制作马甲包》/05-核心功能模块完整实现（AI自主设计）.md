# 05 - 核心功能模块完整实现（AI自主设计）

本步骤的目标：**AI 自主设计并实现所有功能模块的完整代码，包括 UI 界面、交互逻辑、数据模型，使用 Mock 方案提供假数据（通过模拟请求数据，假数据放在 `lib/{{项目名}}/data/` 文件夹里），让应用看起来像成品。在实现完整功能之前，建议先为每个核心功能模块设计清晰的边界与接口，并用"假数据占位实现"跑通主流程。**

## ⚠️ 重要提示

1. **发挥 AI 的想象力和创造力**：
   - 鼓励 AI 基于产品类型自主设计完整的功能体系，实现功能性和完整性，而不仅仅是按模板填空。
   - **重要**：如果你提供了参考项目（Git 链接或项目模板），AI 应该：
     - 分析参考项目的架构和代码组织方式，作为**参考和启发**；
     - **不能全盘照抄**参考项目的代码、UI 设计或功能实现；
     - 基于参考项目的架构思路，**发挥自己的想象力和创造力**，设计出符合当前产品类型的独特功能、界面和交互逻辑；
     - 参考项目只是帮助你理解代码组织模式，但具体的功能实现、UI 设计、交互逻辑等都应该根据当前产品类型**自主创新**。

2. **分模块生成，避免上下文过多**：**可以一个个模块生成**，避免一次性生成所有模块导致上下文过多而中断问题。例如：
   - 先完成首页模块
   - 再完成个人中心模块
   - 再完成设置与清除本地数据模块；当前不需要登录模块
   - 以此类推

3. **记录完成的工作**：**完成每一步时，可以简单列出完成的工作**，好接入上下文，避免断层问题。建议在每次与 AI 对话时，先简要说明已完成的内容，再提出新的需求。

4. **保证功能完整性和设计统一性**：
   - 确保每个功能模块都有完整的 UI 界面和交互逻辑
   - 所有页面和组件遵循统一的设计风格和交互模式
   - 避免太复杂的设计和功能，优先实现核心功能，保持简洁实用

5. **主界面设计规范（严格执行）**：
   - **底部 Tab 数量**：
     - **尽量设计 3、4 个 Tab**，根据产品类型和功能需求，发挥创造力和想象力自主决定
     - **如果中间是发布按钮**，则可能是 5 个 Tab（例如：首页、发现、发布、消息、我的）
     - 根据产品类型和功能需求，发挥创造力和想象力自主决定 Tab 数量
   - **第一个 Tab（通常是首页）**：主要以**大图展示**为主，发挥想象力设计布局（如：轮播大图、瀑布流、卡片式大图、全屏大图等），布局要有创意、有视觉冲击力
   - **第二个 Tab**：主要以**九宫格**或类似网格布局为主，发挥想象力设计布局（如：3x3 网格、2x4 网格、不规则网格、动态网格等），布局要有创意、有视觉冲击力
   - **其他 Tab**：根据产品类型和功能需求，AI 自主设计布局和交互方式，充分发挥创造力和想象力
   - 不能只是简单的列表或单一布局，要充分发挥设计想象力

## 十一、列表刷新和加载功能实现示例

### 1. Controller 实现示例

```dart
class CharzHomeController extends GetxController {
  final RefreshController refreshController = RefreshController(initialRefresh: false);
  
  final List<CharzImage> _images = [];
  List<CharzImage> get images => _images;
  
  @override
  void onInit() {
    super.onInit();
    _loadInitialData();
  }
  
  // 加载初始数据
  void _loadInitialData() {
    _images.clear();
    _images.addAll(CharzImageRepository.getImages().take(10));
    update();
  }
  
  // 下拉刷新
  void onRefresh() async {
    try {
      // 模拟网络延迟
      await Future.delayed(Duration(seconds: 1));
      
      // 从已有数据中随机获取数据
      final allImages = CharzImageRepository.getImages();
      allImages.shuffle();
      
      _images.clear();
      _images.addAll(allImages.take(10));
      
      refreshController.refreshCompleted();
      update();
    } catch (e) {
      refreshController.refreshFailed();
    }
  }
  
  // 上拉加载
  void onLoading() async {
    try {
      // 模拟网络延迟
      await Future.delayed(Duration(seconds: 1));
      
      // 从已有数据中随机获取数据
      final allImages = CharzImageRepository.getImages();
      allImages.shuffle();
      
      final newImages = allImages.take(10).toList();
      _images.addAll(newImages);
      
      refreshController.loadComplete();
      update();
    } catch (e) {
      refreshController.loadFailed();
    }
  }
  
  @override
  void onClose() {
    refreshController.dispose();
    super.onClose();
  }
}
```

### hashCode 实现问题（GetX 响应式更新，重要）
- **必须注意 hashCode 问题**：GetX 需要能够检测到对象的变化，但当前的 hashCode 实现只基于 id，这意味着相同 ID 的帖子即使内容不同也会有相同的 hashCode
- **问题影响**：如果 hashCode 只基于 id，当对象内容发生变化（如点赞数增加）但 id 不变时，GetX 无法检测到变化，导致响应式更新失效
- **解决方案**：
  - 在定义数据模型时，必须确保 `hashCode` 和 `==` 方法基于所有相关字段（不仅仅是 id）
  - 如果帖子模型包含 id、title、content、likes、comments 等字段，hashCode 应该基于所有这些字段计算
  - 可以在模型类中显式重写 `hashCode` 和 `==` 方法，确保包含所有需要检测变化的字段
- **验证方法**：修改对象内容后，检查 GetX 的响应式更新是否正常工作
