# Flutter 工程：复制、安装、执行

这是可移植的 Codex 执行技能资料包。整个文件夹可以放在另一台 Mac 的任意位置，不要求用户名是 `admin`，也不要求放在桌面。

## 第一次使用

1. 把整个 `Flutter工程` 文件夹复制到新机器，保留下面列出的文件和目录。
2. 双击 `start.command`。它会安装执行技能、复制完整规范，并从远程仓库的 `feature/1.2.1-A1` 分支同步完整 `ios-app-listing` checkout，然后打开 Codex 并将启动语句复制到剪贴板。只安装而不打开 Codex 时，可双击 `install.command`。
3. 首次安装或更新后重新打开 Codex，选择你要存放工程的项目/工作目录，再进入新对话。
4. 在技能列表搜索 `Flutter 工程执行` 或 `flutter-engine-runner` 并选择；也可以直接粘贴并发送：

```text
使用 $flutter-engine-runner，请开始执行。
```

5. 缺少输入时，Codex 会先询问创意主题和项目名称。提供后，查看完整思维导图，回复“确认，按此执行”。之后继续自主开发；质量复核后只使用安装器同步的远程 `ios-app-listing` checkout 生成 AppListing 和对应 About 页面，校对配色并改名/整理为 `aduit`。紧接着，用项目实际功能和主题色完全替换 `aduit/site/index.html`，将单文件引导页接入每次启动进入的 Welcome 本地 WebView；所有显示图片均以内嵌 Base64 data URI 提供，不能依赖工程内图片资源或远程图片地址，含图片编码的 HTML 总大小严格小于 262,144 字节。核验图片解码、格式/尺寸/可读性与离线显示，并检查英文介绍卡片、轮播、分页点、Continue bridge 与回退，以及四个指定视口。该 Welcome 页和 HTML 引导页不显示协议通用文案或 Terms/Privacy 页脚。通过后、生成英文审核备注前，才从 `aduit/intro.md` 的 `All URL` 原样复制四个地址；协议通用文案只加入 Clear Data 确认清理成功后出现的 Initialization 页底部，Terms of Use 与 Privacy Policy 分别可点击：

```text
By continuing, you agree to our
Terms of Use and Privacy Policy
```

随后接入 Settings 中仅有的 Privacy Policy、Terms of Use、Support 三个 WebView 入口；地址失效不会阻断 App 流程。无需提供域名，也不公开部署。

`@Flutter工程` 是文件夹引用，不等于安装或调用技能。`@` 是否列出技能取决于客户端版本与技能加载状态；看到资料文件不代表执行技能已注册。优先使用技能选择器或 `$flutter-engine-runner`。如果仍未出现，复制安装器打印的“读取并使用……/SKILL.md，开始执行工作流”语句，直接让 Codex 使用已安装技能。

启动器完成的是安装与启动语句准备；它不会自动发送聊天消息。请将语句发送给 Codex 才会执行工作流。

## 一次提供输入，直接进入思维导图

在 Codex 中发送，例如：

```text
使用 $flutter-engine-runner。
创意主题：帮助用户记录旅行见闻，整理照片与语音。
项目名称：Journey Notes
完整工程目录：/你指定的位置/Journey Notes
请先展示完整思维导图，确认后全权执行。
```

需要智能体生成创意时：

```text
使用 $flutter-engine-runner，请自行生成一个创意主题。
项目名称：Journey Notes
完整工程目录：/你指定的位置/Journey Notes
```

示例中的名称与路径请换成自己的；它们不是默认主题、默认项目或真实执行目录。项目名称由你提供，不能由智能体取名；仅 Flutter 内部标识会按工具要求规范化，App 显示名称保留你给定的名称。

## 工程创建在哪里

你当前新建或明确指定的工程文件夹本身就是工程根目录：`pubspec.yaml`、`lib/`、`assets/`、`ios/`、`aduit/` 等直接创建在其中。不要在该目录下再创建“项目名称”子文件夹。项目名称只用作 App 显示名称及合法化后的 Flutter 内部标识，不改变文件夹层级。

未提供位置时，使用 Codex 当前选定项目/工作目录本身作为目标；优先复用本任务的匹配工程，否则直接在该文件夹中创建新工程，不再创建同名子目录。资料包目录和技能安装目录只用于读取流程，不是默认输出位置；若当前工作目录恰好在资料包或技能内，回退到当前用户的 `Documents/FlutterProjects/` 下一个直接目标文件夹，并在思维导图方案中说明，该目标文件夹本身就是工程根目录。

不会再询问项目位置，也不会因为目标文件夹尚不存在而改到资料包里。不要只在 Finder 中选中一个目录就认为 Codex 已获得输出位置；请选定 Codex 工作目录或在启动消息里写明。

## 跨机器与更新

复制时至少包含：

```text
Flutter工程/
├── 工作流文档/              # 整个目录：总入口、十份正文与 manifest.txt
├── flutter-engine-runner/
│   ├── SKILL.md
│   └── agents/openai.yaml
├── start.sh
├── start.command
├── install.command
└── README.md
```

无需复制个人机器上的 `.codex` 文件夹，也不要只复制 Markdown 或启动器。安装器默认使用当前用户的 `CODEX_HOME/skills`，未设置 `CODEX_HOME` 时使用 `~/.codex/skills`；另在 `~/.agents/skills` 建立指向同一安装的兼容链接。会复用旧版的 `flutter工程执行` 安装目录，避免留下同名的旧规则。实际安装路径以启动器输出为准。

安装后的工作流文档来自资料包，AppListing 则每次由安装器从远程仓库 `feature/1.2.1-A1` 分支重新同步为 Git checkout；不会把资料包中的同名目录、旧安装或手写页面作为运行时来源。修改 `工作流文档/` 中的正文或执行技能后，重新双击 `start.command` 同步更新，再重新加载 Codex。安装器会在更新前逐项检查文档清单，缺少任何列出的正文或远程 AppListing 必要文件时不覆盖现有技能。远程同步失败时保留旧安装但将 AppListing 阶段视为受阻，修复网络/权限后重新运行安装器；不得回退到本地副本。旧安装保存在技能目录同级的 `skill-backups/flutter-engine-runner/`，可恢复；不会覆盖其他技能。

Mac 若不允许双击启动器，可在终端输入 `/bin/zsh `，拖入 `start.sh` 并回车。终端入口也支持 `--project-dir` 指定完整工程目录；该路径会加入待发送的启动语句，不会直接创建工程。`--install-only` 只安装，`--help` 查看选项。

Logo 仍通过 `http://stargate.local:3100/image` 生成。该地址是生成界面，不是图片下载接口；不能直接 `curl` 后把网页、JSON 或错误响应保存为 `assets/logo.png`。必须从真实任务结果取得二进制图片，并再次检查 MIME、文件签名、尺寸、可解码性和 Alpha。另一台机器需要能访问该服务；路径可移植不代表服务或 Flutter/Xcode 会自动安装。服务失败时记录正式 Logo 与取色为 `Blocked`，优先复用有效 AppIcon 或明确标记的 `unverified` 开发资源继续本地页面和材料生成，不把回退资源宣称为正式品牌。

Logo 下载或导出后先命名为 `用户提供的项目名称.png`，验收后以该名称放入目标工程 `assets/`，再改为 `logo.png`：`项目名称.png → assets/项目名称.png → assets/logo.png`。取色、App 引用和 Listing 统一使用最终文件，下载路径与改名链路写入品牌记录；项目名称只用于文件名，Logo 画面仍不含文字。

Logo 提示词先根据主题元素，在模拟现实画风、手绘画风、油画画风和艺术画风中合理选择一种主画风，并记录依据，不固定使用同一画风。模拟现实强调可信结构、材质和光影；手绘强调细腻线条与层次；油画强调精细笔触、颜料层次和清晰主体；艺术画风强调明确的表现手法、构图与色彩语言。四种画风都需精致好看、小尺寸可辨。Logo 需至少三种鲜明色彩和协调的多色渐变，不能呈现冷峻、灰暗或近乎单色的整体色调；同时避免几何色块堆叠、简陋图案，禁止 3D 与明显 AI 生成感，并检查原尺寸与图标尺寸的实际视觉效果。颜色链路需有证据：Logo 原始 HEX → Flutter 主题令牌 → 至少三个实际 App 页面/组件 → iPhone 截图。其余生成规格和文件命名条件不变，详细话术见 `工作流文档/02-创意与思维导图.md` 第 2.5 节。

Logo 还需检查主题造型、比例、材质和光线是否自然协调，修复明显畸变、断裂边缘、重复纹理、随机碎片、伪文字或廉价塑料/强光效等生成瑕疵；“自然可信”不要求 Logo 做成照片，也不改变其鲜艳配色与渐变。每个主要内容列表至少包含两种有意义的明显尺寸；`featured` / `standard` / `compact` 三档按内容在主要浏览体验跨页面覆盖，不要求每页都有三档。多个列表型 Tab 至少使用两种有意区分的主编排，例如分组列表、双列网格、精选大卡加横向滚动、瀑布流/不规则卡片或分段式复合布局；单个 Tab 也可以复合使用多种形式。卡片可以长短不齐、大小不一、图片比例不同，但必须由内容重要性、任务优先级、信息密度、媒体比例或排序依据决定，并记录响应式降级与无障碍顺序；不允许随机错落、只为装饰改变尺寸、固定高度截断文字或拉伸图片。设置、协议、权限等便于扫描的功能列表保持整齐。完整实现及验收标准见工作流文档第 6.9 节。

Logo 实际生成失败时，会先在 Stargate 的生成参数里切换其他已配置、可用且支持相同规格的图像模型，再尝试生成；不是只修改提示词。保持高质量、1 张、`1024x1024` 与最终无 Alpha 要求，所有模型共用最多 3 次提交和原 10 分钟预算，不再询问用户。没有可用替代模型或尝试仍失败时，保留真实记录并继续本地 Listing、`aduit/` 和 Remarks。

Logo 下载后还必须实际替换 iPhone 桌面 App 图标、iOS 原生启动品牌图、Welcome/Initialization 页面及现有 App/About 品牌位置，重新构建并检查最终显示，不能仅保存图片。详见 `工作流文档/06-素材与真实照片.md` 第 10.4 节；内容照片封面仍使用贴题的第三方素材，`aduit/site/img/` 仍只保留 `logo.png`。

最后检查还会扫描项目解析出的本地依赖、构建目录和 App bundle，清除其中的 `aduit/` 副本并确认依赖中不得残留；项目根目录的 `aduit/` 交付物必须保留。App 品牌引用 `assets/logo.png`；Entry/Settings 协议链接直接使用 `aduit/intro.md` 中 `All URL` 的原始网址，通过无网络 stub 核对映射，不访问或探测真实 URL，也不把本地协议 HTML 打包进依赖。详细边界见第 10.7 节。

页面边界固定：iOS 原生启动页、欢迎页和初始化页三者彼此独立。欢迎页不显示协议文本；协议文本只在初始化页底部显示。

浅色模式（含 System 当前为浅色）下，所有自有页面及生成的 HTML 使用包含最终 Logo 暖色配色的渐变底色，禁止纯白整页背景，也不能只在白底上加少量暖色点缀；正文与控件保持稳定、高对比。深色模式及 System 深色沿用现有规则。颜色来源、实际页面效果与主题切换纳入第 6.5、11.3 节验收，不通过重复铺贴 Logo 实现背景。

启动体验恰好包含三页：iOS 原生冷启动页、每次启动进入且含 `Continue` 的 Flutter Welcome 页、以及只有用户确认 `Clear Data` 且真实清理成功后才显示并含 `Entry` 的 Flutter Initialization 页。这三页彼此独立；启动准备、百分比、进度和错误恢复均为 Welcome 内部状态，不创建 Flutter Loading 页面。协议文本只在 Initialization 页底部显示：`By continuing, you agree to our` 换行 `Terms of Use and Privacy Policy`；Welcome、其 `aduit/site/index.html` 引导页和原生启动页都没有这段文案。三页各自背景均须避免纯白或近白空白，使用 Logo 衍生渐变、鲜明色彩点缀和主题装饰，Light 模式也使用浅彩品牌背景。原生页以完整静态构图衬托更大 Logo、独立 `PRYRIN` 字标、项目名、定位文案与装饰线，不包含动画、进度或交互；Welcome 保留丰富的主题引导卡片与 `Continue`，并在页面内部显示真实准备状态；Initialization 提供清理成功后的说明、`Entry` 和唯一协议页脚。整个项目多使用与 Logo 主题色对应的渐变，并按页面任务差异化实际呈现，不得只配置令牌或重复铺同一背景；文字与控件始终保持可读。对少量有明确反馈价值的点击操作，可用 `AnimationController` + `CustomPainter` 绘制主题粒子效果，在 `onTapUp` 坐标生成具有位置、速度、重力、颜色和拖尾的烟花/喷泉/拖尾粒子；需限制数量和时长、及时释放控制器、穿透触摸、不遮挡内容，并尊重系统减少动态设置。任何 AI 生成图都不得采用简约线条、细轮廓、扁平几何或纯色块堆叠风格，且不能代替规定的真实内容照片。先呈现 Welcome 首帧，再异步准备；进度只由真实必需里程碑驱动，准备就绪后启用 `Continue`，不为展示动画人为停留，系统减少动态设置即时生效。Welcome 错误态保留 `Try again` 与复用现有确认流程的 `Clear Data`，并验证成功后进入 Initialization。需实际验证小屏/大屏 iPhone、大字号、原生冷启动、Welcome 首帧/受控慢准备、Initialization、清除后返回及错误态并留证；只改文档或热重载不代表 UI 验收通过。详情见第 6.5、7.1–7.2、10.4、11.3 节。

Listing 生成器优先使用有效的 `assets/logo.png`，不再优先选旧 AppIcon。没有正式 Logo 时可用已有有效图标或 `.codex-work/development-brand.png` 继续本地生成，并保留品牌未验证状态；完全无有效图片时仍输出介绍与四页 HTML，缺图和目录契约检查如实失败，后续 `aduit/` 整理及 Remarks 继续执行。

所有页面还须按第 6.10 节落实与任务相关的图文表达，不只美化首页：内容/详情结合主题摄影或图解与有信息价值的模块，搜索使用缩略图/分类图标和元信息，Settings 有品牌区与分组图标，媒体页呈现真实预览与反馈，空/错误态有对应图形和下一步。确认框保持风险清楚、操作简洁，协议保留完整易读正文与品牌层次。每页及适用状态都纳入规划和当前构建验收；纯文字堆叠、反复贴 Logo、同文换容器、假统计或无关装饰不算丰富，必要实景照片仍从已列第三方网站取得并核许可。

内部 UI 减少重复使用 Logo：保留必要品牌入口，同屏原则上只展示一处，Welcome 的 Flutter 外层与 HTML 不重复叠加，介绍卡片、分类封面和状态图不再反复贴 Logo。可自主绘制符合主题的插画、步骤/关系图与状态图，导出到 `assets/illustrations/<feature_or_page_id>/`，按用途命名并实际接入页面；不以 Logo 换色/裁剪冒充新图。沿用鲜明品牌色、渐变、圆角和真实照片要求，并在最终检查核对重复及加载结果，详见第 6.12 节。

所有自有界面的图片统一使用圆角，覆盖 Logo、列表/详情图片、缩略图、视频封面、媒体预览及 HTML 内嵌图；图片本身须实际裁剪，加载、错误、放大与转场中也不能露出尖角。按主题适当增加 Logo 配色的细边框，同类图片圆角与边框保持一致。原始 Logo 仍为无 Alpha 图片，AppIcon 使用系统蒙版。最终逐页检查实际显示，详见第 6.3、11.3、10.7 节。

协议网址会按生成器的四个 `All URL` 原封不动接入，即使暂不可访问也不修改。完整地址、路径和文件名严格保留大小写，例如 `PrivacyPolicy.html` 不得变为 `privacypolicy.html`。本地 `Intro.md` 改名不影响 URL；生成原文、最终介绍、App 配置及点击传入 WebView 的值须精确一致。你日后要求换正式域名时，仅改域名，其余部分保持原样。详见第 12.1、11.3 节。

原长文档已拆分到同一资料包下的 `工作流文档/`。唯一维护源是总入口 `工作流文档/00-总入口.md` 和按清单列出的十份正文；旧版长文档兼容入口不是必需文件。

```text
工作流文档/
├── 00-总入口.md
├── 01-执行约定.md

├── 03-产品定义与导航.md

├── 06-素材与真实照片.md
├── 07-测试与质量验收.md

```

运行语句、执行顺序和原第 0–16 节编号不变。技能会读取总入口并按顺序完整读取十份正文，不是只看目录或按标题猜测内容。规范资源根仍是文档集的父目录；AppListing 运行时目录由安装器从远程仓库同步，工程输出位置不受拆分影响。跨机器复制时必须带上整个文档集、执行技能和启动器，不能只复制启动器或兼容入口；资料包不需要也不应携带本地 AppListing 副本。安装器在旧版长文档不存在时，会用总入口生成安装副本中的旧路径兼容文件。

本次拆分未改写正文；修改需求时编辑对应正文，并同步有实际关联的摘要或引用。拆分前原长文档备份在本机的 `skill-backups/flutter-engine-runner/source-documents/`，不参与执行。

## 页面拆分与品牌视觉

每个独立 App 页面都使用自己的 Dart 文件，并按稳定 `page_id` 分类；`main.dart` 只启动并装配根 App，不集中编写所有页面。每页使用 Stargate 生成专属主题装饰，按 `assets/backgrounds/<page_id>/<page_id>_background.png` 保存、登记并由对应页面实际引用，装饰不得代替真实照片。

全项目主要页面按任务差异化使用从 Logo 主题色派生的协调渐变，并保留高对比阅读区域；减少动态或性能受限时回退为同配色静态渐变。少量有明确反馈价值的点击可采用 `AnimationController` + `CustomPainter`，在 `onTapUp` 坐标绘制主题粒子；控制位置、速度、重力、颜色和拖尾，限制粒子数量与时长，不阻塞触摸、不遮挡内容，并遵循系统减少动态设置。

## 真实照片素材要求

如果返回 403、429、超时、登录墙、验证码或许可证无法核验，将对应照片项记为 `Blocked`/`Not verified`；继续生成本地 AppListing、About、`aduit/` 和 `aduit/review/remarks.md`，不能再以素材失败停止整个交付流程。

执行流程必须实际搜索 Pexels、Pixabay、Unsplash、Wikimedia Commons 等第三方网站，核对主题与许可，下载真实实物/实景摄影到目标工程的 `assets/media/` 并接入 App 页面。`http://stargate.local:3100/image` 用于生成 Logo 以及逐页主题化背景装饰，不得用于生成或替代内容照片、实景封面、视频帧或其他真实摄影。每页装饰须按 `assets/backgrounds/<page_id>/<page_id>_background.png` 单独保存并由对应页面实际引用。原生图标、代码矢量符号、其他装饰插画与渐变等非摄影 UI 素材不需要从照片网站取得，也不计作真实照片。没有 API Key 或资源下载技能时仍尝试可用公开网页与合法下载方式；来源失败则切换其他来源，按规范有限尝试，不无限等待。

Emoji、渐变、矢量插画、AI 拟真图或仅写素材清单不能代替真实照片。验收要有来源与许可、实际页面截图及离线展示证据；不能只下载不使用，也不能用一张图填满所有分类。所有可用途径确实失败时可继续独立开发，但照片缺口必须明确报告，不能把该项资源质量标为通过。搜索记录与接触表在目标工程 `.codex-work/`，内容照片不进入 `aduit/`。

### iPhone 与权限配置

本流程只创建、构建和验证 iOS iPhone App，最低 iOS 部署版本为 15.6；实际依赖要求更高时保留更高版本，并按正文核对 Podfile、所有构建 target 的解析设置及可用产物。运行与截图必须明确指定 iPhone 机型及 UDID；没有可用 iPhone 时继续可执行检查，不回退到其他设备或平台。按实际权限插件检查 `ios/Podfile` 并尽力设置最小权限宏；使用 PhotoKit 整库读取 API 时，必须设置并从 Pods 解析后的编译设置证实 `PERMISSION_PHOTOS=1`；只用系统照片选择器时不启用整库权限宏。宏配置失败需记录，但不得因此中止 Pods 安装或 iOS 打包尝试。默认无追踪；确认无 Apple 定义的追踪后，对 ATT 进行清理移除，包括请求、用途说明、框架链接、IDFA 访问及不必要追踪依赖，并核验最终产物。宏配置、构建结果与权限运行验证分开报告，失败的权限路径不能标为通过。详情见工作流文档第 0.7、11.7 节。
