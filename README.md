# Flutter 工程：复制、安装、执行

这是可移植的 Codex 执行技能资料包。整个文件夹可以放在另一台 Mac 的任意位置，不要求用户名是 `admin`，也不要求放在桌面。

历次修改的有效规则统一收录在 [执行约定第 0.12 节：历史要求对照](工作流文档/01-执行约定.md#012-最新用户硬性覆盖与历史要求对照)，同一主题以最新指令为准。仅获授权的主题和已确认范围内的页面/功能组合可随机，其余适用要求全部作为硬门槛，按对应正文检查真实结果。

运行入口需要安装 `$flutter-engine-runner`；没有统一必装的额外 Codex 插件。生成 App 仍需要可用的 Flutter、Xcode/iPhone SDK、适用的 CocoaPods，以及 Stargate 服务与浏览/下载能力，安装器不会自动安装这些工具。可选插件缺失时使用可用 CLI/工具；实际能力缺失则记录受影响项并继续独立任务。

## 第一次使用

1. 把整个 `Flutter工程` 文件夹复制到新机器，保留下面列出的文件和目录。
2. 双击 `start.command`。它会安装执行技能、复制完整规范，并从远程仓库的 `feature/1.2.1-A1` 分支同步完整 `ios-app-listing` checkout，然后打开 Codex 并将启动语句复制到剪贴板。只安装而不打开 Codex 时，可双击 `install.command`。
3. 首次安装或更新后重新打开 Codex，选择你要存放工程的项目/工作目录，再进入新对话。
4. 在技能列表搜索 `Flutter 工程执行` 或 `flutter-engine-runner` 并选择；也可以直接粘贴并发送：

```text
使用 $flutter-engine-runner，请开始执行。
```

5. 缺少输入时，Codex 会先询问创意主题和项目名称。提供后，查看完整思维导图，回复“确认，按此执行”。之后继续自主开发；质量复核后按远程 `ios-app-listing` checkout → `/Applications/config/ios-app-listing` → 随包输出契约的顺序生成 AppListing 和对应 About 页面，任一来源失败都记录状态并继续后续材料步骤。`aduit/intro.md` 的 `Description` 必须充分说明已实现的用途、主模块、典型任务、实际媒体能力（如有）、成果回访和数据边界，遵守生成器选定结构与 4,000 字符上限；生成后复核并精修该正文，删除重复 URL 栏目和多余网址，只在 `All URL` 保留首页、隐私政策、用户协议、Support 四个完整原始地址，四值原文不变；Intro/Remarks 中的教育类展示标签统一为英文 `Popular Science`（科普），其他类别与事实不变。随后校对配色并改名/整理为 `aduit`。紧接着，将生成的 `aduit/site/index.html` 保留为站点四页之一，并将当前引导页写入工程根目录 `welcome.html`，只将根文件接入每次启动的 Welcome 本地 WebView；引导页操作不替换或移动 `aduit/site/` 四页，必要的配色、Logo 优化与成品文案修正照常执行；`aduit/` 不保存 Welcome 副本；所有显示图片均以内嵌 Base64 data URI 提供，不能依赖工程内图片资源或远程图片地址，含图片编码的 HTML 总大小严格小于 262,144 字节。核验图片解码、格式/尺寸/可读性与离线显示，并检查英文介绍卡片、轮播、分页点、Continue bridge 与回退，以及四个指定视口。该 Welcome 页和 HTML 引导页不显示协议通用文案或 Terms/Privacy 页脚。完成检查并记录结果后、生成英文审核备注前，从 `aduit/intro.md` 的 `All URL` 原样复制四个地址；外部验证受阻不取消后续材料生成，也不算验收通过；协议通用文案只加入 Clear Data 确认清理成功后出现的 Initialization 页底部，Terms of Use 与 Privacy Policy 分别可点击：

```text
By continuing, you agree to our
Terms of Use and Privacy Policy
```

随后接入 Settings 中仅有的 Privacy Policy、Terms of Use、Support 三个 WebView 入口；地址失效不会阻断 App 流程。无需提供域名，也不公开部署。

安装器会先运行 `tests/test_workflow_integrity.sh`，核对 `manifest.txt` 的完整文档集、实施步骤 1–20、跨文档硬性门槛以及第 17–20 步的最终顺序；检查失败时不会覆盖现有技能安装。手动复核可运行：

```bash
zsh tests/test_workflow_integrity.sh
```

需要一次性回归全部本地契约时，运行 `tests/run_all.sh`。它按完整性、引导页、视觉实现、Review Remarks、公开文案、远程 AppListing 安装器、About 文案顺序执行；任一项失败都会返回非零状态，不会把后续结果误报为通过。Review Remarks 检查器固定要求第 1 项为 `iPhone 17 Pro Max, iOS 26.5`、第 2 项仅允许有据的 iPhone 记录、第 6 项为 `All regions are the same.`，并拒绝待确认占位语、非 iPhone 设备、网页容器术语、中文、`**` 和超过 4,000 字符的公开备注。设备记录的真实性须另对照当前 App 的证据。公开文案检查器提供 Dart 直接 UI 字符串、根目录 `welcome.html`、About 静态 HTML 与无障碍属性的补充扫描；间接字符串、脚本动态内容、图片嵌字及运行画面仍需按第 11.4 节复核。它不扫描内部记录，也不替代 Remarks 中真实外部服务的披露。

```bash
./tests/run_all.sh
```

`@Flutter工程` 是文件夹引用，不等于安装或调用技能。`@` 是否列出技能取决于客户端版本与技能加载状态；看到资料文件不代表执行技能已注册。优先使用技能选择器或 `$flutter-engine-runner`。如果仍未出现，复制安装器打印的“读取并使用……/SKILL.md，开始执行工作流”语句，直接让 Codex 使用已安装技能。

启动器完成的是安装与启动语句准备；它不会自动发送聊天消息。请将语句发送给 Codex 才会执行工作流。

## 一次提供输入，直接进入思维导图

在 Codex 中发送，例如：

```text
使用 $flutter-engine-runner。
创意主题：帮助用户记录旅行见闻，整理照片与语音。
项目名称：Journey Notes
完整工程目录：/你指定的位置/Journey Notes
请先展示完整思维导图，确认后全权执行。
```

需要智能体生成创意时：

```text
使用 $flutter-engine-runner，请自行生成一个创意主题。
项目名称：Journey Notes
完整工程目录：/你指定的位置/Journey Notes
```

示例中的名称与路径请换成自己的；它们不是默认主题、默认项目或真实执行目录。项目名称由你提供，不能由智能体取名；仅 Flutter 内部标识会按工具要求规范化，App 显示名称保留你给定的名称。

## 工程创建在哪里

你当前新建或明确指定的工程文件夹本身就是工程根目录：`pubspec.yaml`、`lib/`、`assets/`、`ios/`、`aduit/` 等直接创建在其中。不要在该目录下再创建“项目名称”子文件夹。项目名称只用作 App 显示名称及合法化后的 Flutter 内部标识，不改变文件夹层级。

未提供位置时，使用 Codex 当前选定项目/工作目录本身作为目标；优先复用本任务的匹配工程，否则直接在该文件夹中创建新工程，不再创建同名子目录。资料包目录和技能安装目录只用于读取流程，不是默认输出位置；若当前工作目录恰好在资料包或技能内，回退到当前用户的 `Documents/FlutterProjects/` 下一个直接目标文件夹，并在思维导图方案中说明，该目标文件夹本身就是工程根目录。

不会再询问项目位置，也不会因为目标文件夹尚不存在而改到资料包里。不要只在 Finder 中选中一个目录就认为 Codex 已获得输出位置；请选定 Codex 工作目录或在启动消息里写明。

## 跨机器与更新

复制时至少包含：

```text
Flutter工程/
├── 工作流文档/              # 整个目录：总入口、十份正文与 manifest.txt
├── flutter-engine-runner/
│   ├── SKILL.md
│   ├── scripts/             # About、视觉、Remarks 与公开文案检查器
│   └── agents/openai.yaml
├── start.sh
├── start.command
├── install.command
├── tests/
│   ├── run_all.sh
│   ├── test_workflow_integrity.sh
│   ├── test_onboarding_guide_workflow.sh
│   ├── test_start_remote_listing.sh
│   ├── test_validate_visual_implementation.py
│   ├── test_validate_review_remarks.py
│   ├── test_validate_public_copy.py
│   └── test_validate_about_copy.py
└── README.md
```

无需复制个人机器上的 `.codex` 文件夹，也不要只复制 Markdown 或启动器。安装器默认使用当前用户的 `CODEX_HOME/skills`，未设置 `CODEX_HOME` 时使用 `~/.codex/skills`；另在 `~/.agents/skills` 建立指向同一安装的兼容链接。会复用旧版的 `flutter工程执行` 安装目录，避免留下同名的旧规则。实际安装路径以启动器输出为准。

安装后的工作流文档来自资料包，AppListing 则每次由安装器优先从远程仓库 `feature/1.2.1-A1` 分支重新同步为 Git checkout；不会把资料包中的同名目录、旧安装或手写页面作为运行时来源。修改 `工作流文档/` 中的正文或执行技能后，重新双击 `start.command` 同步更新，再重新加载 Codex。安装器会在更新前逐项检查文档清单，缺少任何列出的正文或远程 AppListing 必要文件时不覆盖现有技能。远程同步失败或 checkout 不完整时，自动尝试 `/Applications/config/ios-app-listing`；两者均不可用时仍安装核心流程并按随包契约继续生成全部材料，单独记录受阻校验，不中断后续任务。旧安装保存在技能目录同级的 `skill-backups/flutter-engine-runner/`，可恢复；不会覆盖其他技能。

Mac 若不允许双击启动器，可在终端输入 `/bin/zsh `，拖入 `start.sh` 并回车。终端入口也支持 `--project-dir` 指定完整工程目录；该路径会加入待发送的启动语句，不会直接创建工程。`--install-only` 只安装，`--help` 查看选项。

Logo 仍通过 `http://stargate.local:3100/image` 生成。该地址是生成界面，不是图片下载接口；不能直接 `curl` 后把网页、JSON 或错误响应保存为 `assets/logo.png`。必须从真实任务结果取得二进制图片，并再次检查 MIME、文件签名、尺寸、可解码性和 Alpha。另一台机器需要能访问该服务；路径可移植不代表服务或 Flutter/Xcode 会自动安装。服务失败时记录正式 Logo 与取色为 `Blocked`，优先复用有效 AppIcon 或明确标记的 `unverified` 开发资源继续本地页面和材料生成，不把回退资源宣称为正式品牌。

全局配色契约：从最终 `assets/logo.png` 的真实像素提取 raw HEX，并写入 `common_module/theme/app_theme.dart`，由 AppPalette/AppTheme 统一供所有页面、组件和 About 使用；不得在局部页面另定义品牌色。若色板冷色主导，必须重新生成或重选 Logo；最终颜色要温暖、鲜明、含协调渐变且不过度鲜艳，并用实际 iPhone 页面截图证明主题令牌已生效。

Logo 下载或导出后先命名为 `用户提供的项目名称.png`，验收后以该名称放入目标工程 `assets/`，再改为 `logo.png`：`项目名称.png → assets/项目名称.png → assets/logo.png`。取色、App 引用和 Listing 统一使用最终文件，下载路径与改名链路写入品牌记录；项目名称只用于文件名，Logo 画面仍不含文字。

Logo 按主题元素生成 12 张独立候选：模拟现实、手绘、油画、艺术表现四种画风各 3 张。每张用独立提示词和独立任务，实际查看并比较生成痕迹、主题准确度与图标辨识，从全部候选中优先选生成痕迹最少且合格的一张；不能只生成一种画风或在首张成功后停止。候选先放在本项目专属暂存目录 `~/Downloads/<sanitized-project-name>/logo-candidates/c01/` 至 `c12/`（本机默认为 `/Users/admin/Downloads/<sanitized-project-name>/`），仅选中图按原命名链路进入 `assets/logo.png`；比较记录和哈希放在 `.codex-work/`。模拟现实强调可信结构、材质和光影；手绘强调细腻线条与层次；油画强调精细笔触、颜料层次和清晰主体；艺术表现强调明确的表现手法、构图与色彩语言。四种画风都需精致好看、小尺寸可辨。Logo 需至少三种鲜明色彩和协调的多色渐变，不能呈现冷峻、灰暗或近乎单色的整体色调；同时避免几何色块堆叠、简陋图案，禁止 3D 与明显 AI 生成感，并检查原尺寸与图标尺寸的实际视觉效果。颜色链路需有证据：Logo 原始 HEX → Flutter 主题令牌 → 至少三个实际 App 页面/组件 → iPhone 截图。其余生成规格和文件命名条件不变，详细话术见 `工作流文档/02-创意与思维导图.md` 第 2.5 节。

Logo 还需检查主题造型、比例、材质和光线是否自然协调，修复明显畸变、断裂边缘、重复纹理、随机碎片、伪文字或廉价塑料/强光效等生成瑕疵；“自然可信”不要求 Logo 做成照片，也不改变其鲜艳配色与渐变。每个主要内容列表至少包含两种有意义的明显尺寸；`featured` / `standard` / `compact` 三档按内容在主要浏览体验跨页面覆盖，不要求每页都有三档。多个列表型主要页面至少使用两种有意区分的主编排，例如分组列表、双列网格、精选大卡加横向滚动、瀑布流/不规则卡片或分段式复合布局；单个页面也可以复合使用多种形式。卡片可以长短不齐、大小不一、图片比例不同，但必须由内容重要性、任务优先级、信息密度、媒体比例或排序依据决定，并记录响应式降级与无障碍顺序；不允许随机错落、只为装饰改变尺寸、固定高度截断文字或拉伸图片。设置、协议、权限等便于扫描的功能列表保持整齐。完整实现及验收标准见工作流文档第 6.9 节。

Logo 实际生成失败时，会先在 Stargate 的生成参数里切换其他已配置、可用且支持相同规格的图像模型，再尝试生成；不是只修改提示词。保持高质量、每任务 1 张、总计 12 张独立候选、`1024x1024` 与最终无 Alpha 要求；12 次初始提交加最多 12 次补图，所有模型/候选共用最多 24 次提交与整组 30 分钟预算，不再询问用户。没有可用替代模型或尝试仍失败时，保留真实记录并继续本地 Listing、`aduit/` 和 Remarks。

Logo 下载后还必须实际替换 iPhone 桌面 App 图标、iOS 原生启动品牌图、Welcome/Initialization 页面及现有 App/About 品牌位置，重新构建并检查最终显示，不能仅保存图片。详见 `工作流文档/06-素材与真实照片.md` 第 10.4 节；内容照片封面仍使用贴题的第三方素材，`aduit/site/img/` 仍只保留 `logo.png`。

最后检查还会扫描项目解析出的本地依赖、构建目录和 App bundle，清除其中的 `aduit/` 副本并确认依赖中不得残留；项目根目录的 `aduit/` 交付物必须保留。App 品牌引用 `assets/logo.png`；Entry/Settings 协议链接直接使用 `aduit/intro.md` 中 `All URL` 的原始网址，通过无网络 stub 核对映射，不访问或探测真实 URL，也不把本地协议 HTML 打包进依赖。详细边界见第 10.7 节。

运行时边界：Welcome 只读取工程根目录的 `welcome.html`（可在 `pubspec.yaml` 以根级 asset 声明），`lib/`、`pubspec.yaml`、`.dart_tool`、iOS 工程、Pods、构建目录和 App bundle 中不得出现任何 `aduit/` 路径或目录；`aduit/` 不保存 Welcome 副本，也不得被运行时代码引用。

页面边界固定：iOS 原生启动页、欢迎页和初始化页三者彼此独立。欢迎页不显示协议文本；协议文本只在初始化页底部显示。

浅色模式（含 System 当前为浅色）下，所有自有页面及生成的 HTML 使用包含最终 Logo 暖色配色的渐变底色，禁止纯白整页背景，也不能只在白底上加少量暖色点缀；正文与控件保持稳定、高对比。深色模式及 System 深色沿用现有规则。颜色来源、实际页面效果与主题切换纳入第 6.5、11.3 节验收，不通过重复铺贴 Logo 实现背景。

所有项目自有资源、文件夹与文件能简写就统一简写，不展开可替代的完整词组或专名；改名必须同步代码/配置/数据/原生工程及测试中的全部引用，并检查受影响构建和断网加载。固定契约路径、用户项目名和四个原始 URL 保持原样，详见第 9.3.1 节。`assets/` 内项目自有资源使用简短的英文主题/用途名称，例如 `assets/media/city/cbd_cover.jpg`；去掉下载附带的网站名、日期/时间戳、供应商编号和随机串，专有名词统一使用可辨认的缩写。完整名称、缩写及旧新路径映射保留在 `.codex-work/asset-names.md`，来源与许可记录继续保留；固定 `assets/logo.png` 和逐页背景路径不变。既有资源改名后同步声明、代码与数据引用，并重建确认实际加载，详见第 10.1.2、11.1 节。

如果返回 403、429、超时、登录墙、验证码或许可证无法核验，将对应照片项记为 `Blocked`/`Not verified`；继续生成本地 AppListing、About、`aduit/` 和 `aduit/review/remarks.md`，不能再以素材失败停止整个交付流程。

执行流程必须实际搜索 Pexels、Pixabay、Unsplash、Wikimedia Commons 等第三方网站，核对主题与许可，下载真实实物/实景摄影到目标工程的 `assets/media/` 并接入 App 页面。`http://stargate.local:3100/image` 用于生成 Logo 以及逐页主题化背景装饰，不得用于生成或替代内容照片、实景封面、视频帧或其他真实摄影。每页装饰须按 `assets/backgrounds/<page_id>/<page_id>_background.png` 单独保存并由对应页面实际引用。原生图标、代码矢量符号、其他装饰插画与渐变等非摄影 UI 素材不需要从照片网站取得，也不计作真实照片。没有 API Key 或资源下载技能时仍尝试可用公开网页与合法下载方式；来源失败则切换其他来源，按规范有限尝试，不无限等待。

Emoji、渐变、矢量插画、AI 拟真图或仅写素材清单不能代替真实照片。验收要有来源与许可、实际页面截图及离线展示证据；不能只下载不使用，也不能用一张图填满所有分类。所有可用途径确实失败时可继续独立开发，但照片缺口必须明确报告，不能把该项资源质量标为通过。搜索记录与接触表在目标工程 `.codex-work/`，内容照片不进入 `aduit/`。

### iPhone 与权限配置

本流程只创建、构建和验证 iOS iPhone App，最低 iOS 部署版本为 15.6；实际依赖要求更高时保留更高版本，并按正文核对 Podfile、所有构建 target 的解析设置及可用产物。运行与截图必须明确指定 iPhone 机型及 UDID；没有可用 iPhone 时继续可执行检查，不回退到其他设备或平台。按实际权限插件检查 `ios/Podfile` 并尽力设置最小权限宏；使用 PhotoKit 整库读取 API 时，必须设置并从 Pods 解析后的编译设置证实 `PERMISSION_PHOTOS=1`；只用系统照片选择器时不启用整库权限宏。宏配置失败需记录，但不得因此中止 Pods 安装或 iOS 打包尝试。不集成追踪功能；ATT 权限申请、弹窗、四状态、触发条件与启动任务全部移除，同时清除请求 API、用途键、框架链接、启用宏、IDFA 访问和追踪依赖。发现仍会追踪的组件时禁用、移除或替换，不恢复该授权流程；核验实际数据流与最终产物，并据实披露。宏配置、构建结果与权限运行验证分开报告，失败的权限路径不能标为通过。摄像机、相册和录音可自由或随机组合，也可全部不包含；未选项不添加页面、插件或权限。全部实现、发布材料、图片及依赖检查结束后，最后执行第 11.6 节 iOS 权限双向校验：实际 API 必需的用途键/宏/能力配置必须完整有效，无真实用途的配置、请求和依赖全部移除；无受保护能力时验证零无关权限。若修正后重建，刷新受影响的最终显示证据并再次核对产物权限。详情见工作流文档第 0.7、11.6–11.7 节，证据记录于项目 `.codex-work/ios-permissions.md`。

最终 `aduit/intro.md` 的 `## Description` 会依据项目实际功能充分展开，覆盖定位与受众、各主模块、典型使用过程、实际媒体能力（如有）、可回访成果、进入与清除流程和数据边界；遵守生成器选定的文案结构及最多 4,000 字符限制。生成后重新读取并核对覆盖，避免只留下几句短文或功能清单；仅在 `All URL` 保留首页、隐私政策、用户协议、Support 四个完整 URL；移除重复的独立 URL 栏目及其他多余网址，这四个地址（含大小写、路径、参数）保持原样，其他事实字段仅允许按第 12.1 节统一科普展示标签，不因暂不可访问而删改。详细写作与验收见第 12.1、11.1 节，审核备注仍单独按其格式生成。

## 4.3/5.6 工程审核风险门槛

工作流会在工程阶段建立 `.codex-work/differentiation-brief.md`，明确目标用户问题、现有替代做法、主题领域模型、专属核心动作、任务顺序、首个有用结果和可回访成果。每个项目必须在真实数据、路由、交互规则和结果状态中体现这些差异；只换名称、Logo、配色、渐变、图片、字体、文案、卡片样式或底部导航外壳不能证明差异化，也不能批量生成地区/品牌/主题克隆。

发布前会使用唯一 Bundle ID 核对产品身份，并扫描隐藏审核模式、远程换功能、虚假账号/计费/服务/权限、伪造测试记录、评价诱导、评分奖励、搜索/榜单/引荐/安装量操纵，以及崩溃、白屏、占位图、死链接、错误权限、数据丢失和核心流程失败。App Store 元数据、截图、About、Intro、Support 和 Remarks 只能写已确认事实，且必须互相一致。专项结果写入 `.codex-work/app-review-risk.md`；关键项失败会记录为 `Release readiness: Blocked`，不会因为其他材料已生成而报告为可上架。外部网络或素材失败仍按现有回退继续独立任务。

免责与版权说明合并在现有法律页；样式与脚本内联，使用系统字体。最终 `aduit/site/` 保留生成器提供的四个 HTML 页面，不被引导页替换；将当前引导页写入工程根目录 `welcome.html`，仅改写根目录文件为自包含引导页；Welcome 只加载根目录 `welcome.html`。引导页所显示图片以 Base64 data URI 内嵌，HTML 总大小（含全部编码图片）严格小于 262,144 字节，不引用项目图片路径、`file://` 或远程图片 URL。`aduit/` 顶层仅允许 `intro.md`、`imgs/`、`site/`、`review/`；`site/` 只允许四个 HTML 页面与 `img/logo.png`，`review/` 只允许 `remarks.md`。执行记录、质量报告、截图、备份及额外文件放在目标工程的 `.codex-work/`，不进入交付目录。审核备注全英文、不超过 4,000 字符，基于已确认事实；基本信息逐项列出，七章正文分点描述、设置流程按操作顺序编号；全文不出现 WebView、WebKit 或网页容器等实现描述，外部服务仍据实说明；全文仅保留 iPhone 机型、对应 iOS 版本及有据测试记录，生成或更新时清除其他设备及其测试、兼容性说明，不改名套用其测试结果；生成后检查七项内容与白名单，并清理目标工程的 `AppListing/` 和旧 `aduit/html/`。
