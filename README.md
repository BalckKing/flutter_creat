# Flutter 工程：复制、安装、执行

这是可移植的 Codex 执行技能资料包。整个文件夹可以放在另一台 Mac 的任意位置，不要求用户名是 `admin`，也不要求放在桌面。

## 第一次使用

1. 把整个 `Flutter工程` 文件夹复制到新机器，保留下面列出的文件和目录。
2. 双击 `start.command`。它会安装执行技能、复制完整规范，并从远程仓库的 `feature/1.2.1-A1` 分支同步完整 `ios-app-listing` checkout，然后打开 Codex 并将启动语句复制到剪贴板。只安装而不打开 Codex 时，可双击 `install.command`。
3. 首次安装或更新后重新打开 Codex，选择你要存放工程的项目/工作目录，再进入新对话。
4. 在技能列表搜索 `Flutter 工程执行` 或 `flutter-engine-runner` 并选择；也可以直接粘贴并发送：

```text
使用 $flutter-engine-runner，请开始执行。
```

5. 缺少输入时，Codex 会先询问创意主题和项目名称。提供后，查看完整思维导图，回复“确认，按此执行”。之后继续自主开发；质量复核后只使用安装器同步的远程 `ios-app-listing` checkout 生成 AppListing 和对应 About 页面，校对配色并改名/整理为 `aduit`。紧接着，用项目实际功能和主题色完全替换 `aduit/site/index.html`，将单文件引导页接入 Entry 本地 WebView；核验英文介绍卡片、轮播、分页点、Continue bridge 与回退，以及四个指定视口。通过后、生成英文审核备注前，才从 `aduit/intro.md` 的 `All URL` 原样复制四个地址，并将引导页底部改为以下两行（Terms of Use 与 Privacy Policy 分别可点击）：

```text
By continuing, you agree to our
Terms of Use and Privacy Policy
```

随后接入 Settings 的 WebView 协议入口；地址失效不会阻断 App 流程。无需提供域名，也不公开部署。

`@Flutter工程` 是文件夹引用，不等于安装或调用技能。`@` 是否列出技能取决于客户端版本与技能加载状态；看到资料文件不代表执行技能已注册。优先使用技能选择器或 `$flutter-engine-runner`。如果仍未出现，复制安装器打印的“读取并使用……/SKILL.md，开始执行工作流”语句，直接让 Codex 使用已安装技能。

启动器完成的是安装与启动语句准备；它不会自动发送聊天消息。请将语句发送给 Codex 才会执行工作流。

## 一次提供输入，直接进入思维导图

在 Codex 中发送，例如：

```text
使用 $flutter-engine-runner。
创意主题：帮助用户记录旅行见闻，整理照片与语音。
项目名称：Journey Notes
完整工程目录：/你指定的位置/Journey Notes
请先展示完整思维导图，确认后全权执行。
```

需要智能体生成创意时：

```text
使用 $flutter-engine-runner，请自行生成一个创意主题。
项目名称：Journey Notes
完整工程目录：/你指定的位置/Journey Notes
```

示例中的名称与路径请换成自己的；它们不是默认主题、默认项目或真实执行目录。项目名称由你提供，不能由智能体取名；仅 Flutter 内部标识会按工具要求规范化，App 显示名称保留你给定的名称。

## 工程创建在哪里

你在当前请求或同一任务中明确指定的工程目录优先。指定完整工程目录时直接在该位置创建；明确指定父目录时，才在其中创建以用户项目名称命名的子目录。

未提供位置时，使用 Codex 当前选定项目/工作目录，优先复用本任务的匹配工程，否则创建同名子目录。资料包目录和技能安装目录只用于读取流程，不是默认输出位置；若当前工作目录恰好在资料包或技能内，回退到当前用户的 `Documents/FlutterProjects/` 下，并在思维导图方案中说明。

不会再询问项目位置，也不会因为目标文件夹尚不存在而改到资料包里。不要只在 Finder 中选中一个目录就认为 Codex 已获得输出位置；请选定 Codex 工作目录或在启动消息里写明。

## 跨机器与更新

复制时至少包含：

```text
Flutter工程/
├── 工作流文档/              # 整个目录：总入口、十份正文与 manifest.txt
├── flutter-engine-runner/
│   ├── SKILL.md
│   └── agents/openai.yaml
├── start.sh
├── start.command
├── install.command
└── README.md
```

无需复制个人机器上的 `.codex` 文件夹，也不要只复制 Markdown 或启动器。安装器默认使用当前用户的 `CODEX_HOME/skills`，未设置 `CODEX_HOME` 时使用 `~/.codex/skills`；另在 `~/.agents/skills` 建立指向同一安装的兼容链接。会复用旧版的 `flutter工程执行` 安装目录，避免留下同名的旧规则。实际安装路径以启动器输出为准。

安装后的工作流文档来自资料包，AppListing 则每次由安装器从远程仓库 `feature/1.2.1-A1` 分支重新同步为 Git checkout；不会把资料包中的同名目录、旧安装或手写页面作为运行时来源。修改 `工作流文档/` 中的正文或执行技能后，重新双击 `start.command` 同步更新，再重新加载 Codex。安装器会在更新前逐项检查文档清单，缺少任何列出的正文或远程 AppListing 必要文件时不覆盖现有技能。远程同步失败时保留旧安装但将 AppListing 阶段视为受阻，修复网络/权限后重新运行安装器；不得回退到本地副本。旧安装保存在技能目录同级的 `skill-backups/flutter-engine-runner/`，可恢复；不会覆盖其他技能。

Mac 若不允许双击启动器，可在终端输入 `/bin/zsh `，拖入 `start.sh` 并回车。终端入口也支持 `--project-dir` 指定完整工程目录；该路径会加入待发送的启动语句，不会直接创建工程。`--install-only` 只安装，`--help` 查看选项。

Logo 仍通过 `http://stargate.local:3100/image` 生成。该地址是生成界面，不是图片下载接口；不能直接 `curl` 后把网页、JSON 或错误响应保存为 `assets/logo.png`。必须从真实任务结果取得二进制图片，并再次检查 MIME、文件签名、尺寸、可解码性和 Alpha。另一台机器需要能访问该服务；路径可移植不代表服务或 Flutter/Xcode 会自动安装。服务失败时记录正式 Logo 与取色为 `Blocked`，优先复用有效 AppIcon 或明确标记的 `unverified` 开发资源继续本地页面和材料生成，不把回退资源宣称为正式品牌。

Logo 提示词先按项目主题在精致手绘插画或非 3D 写实风格中选择一种，不固定使用同一画风：手绘须细腻有层次而非粗糙简笔；写实须结构、比例、材质和光影可信。Logo 需至少三种鲜明色彩和协调的多色渐变，不能呈现冷峻、灰暗或近乎单色的整体色调；同时避免几何色块堆叠、简陋图案，禁止 3D 与明显 AI 生成感，并检查原尺寸与图标尺寸的实际视觉效果。颜色链路需有证据：Logo 原始 HEX → Flutter 主题令牌 → 至少三个实际 App 页面/组件 → iPhone 截图。详细话术见 `工作流文档/02-创意与思维导图.md` 第 2.5 节。

Logo 还需检查主题造型、比例、材质和光线是否自然协调，修复明显畸变、断裂边缘、重复纹理、随机碎片、伪文字或廉价塑料/强光效等生成瑕疵；“自然可信”不要求 Logo 做成照片，也不改变其鲜艳配色与渐变。每个主要内容列表至少包含两种有意义的明显尺寸；`featured` / `standard` / `compact` 三档按内容在主要浏览体验跨页面覆盖，不要求每页都有三档。大小服务于内容主次，不随机错落；设置、协议、权限等便于扫描的功能列表保持整齐。完整实现及验收标准见工作流文档第 6.9 节。

Logo 实际生成失败时，会先在 Stargate 的生成参数里切换其他已配置、可用且支持相同规格的图像模型，再尝试生成；不是只修改提示词。保持高质量、1 张、`1024x1024` 与最终无 Alpha 要求，所有模型共用最多 3 次提交和原 10 分钟预算，不再询问用户。没有可用替代模型或尝试仍失败时，保留真实记录并继续本地 Listing、`aduit/` 和 Remarks。

Logo 下载后还必须实际替换 iPhone 桌面 App 图标、启动品牌图、Loading/Entry 欢迎封面及现有 App/About 品牌位置，重新构建并检查最终显示，不能仅保存图片。详见 `工作流文档/06-素材与真实照片.md` 第 10.4 节；内容照片封面仍使用贴题的第三方素材，`aduit/site/img/` 仍只保留 `logo.png`。

最后检查还会扫描项目解析出的本地依赖、构建目录和 App bundle，清除其中的 `aduit/` 副本并确认依赖中不得残留；项目根目录的 `aduit/` 交付物必须保留。App 品牌引用 `assets/logo.png`；Entry/Settings 协议链接直接使用 `aduit/intro.md` 中 `All URL` 的原始网址，通过无网络 stub 核对映射，不访问或探测真实 URL，也不把本地协议 HTML 打包进依赖。详细边界见第 10.7 节。

启动视觉分为两层：iOS 原生冷启动页静态呈现更大的 Logo、独立 `PRYRIN` 字标、品牌定位文案和装饰线；随后 Flutter Loading 使用深色品牌渐变、光晕/呼吸效果及真实步骤、百分比和进度条。进度必须由已完成的真实启动里程碑驱动；系统开启减少动态时立即停用循环和过渡动画。初始化错误页保留 `Try again` 与复用原二次确认流程的 `Clear Data`。详情见第 7.1 节及第 10.4 节。

Listing 生成器优先使用有效的 `assets/logo.png`，不再优先选旧 AppIcon。没有正式 Logo 时可用已有有效图标或 `.codex-work/development-brand.png` 继续本地生成，并保留品牌未验证状态；完全无有效图片时仍输出介绍与四页 HTML，缺图和目录契约检查如实失败，后续 `aduit/` 整理及 Remarks 继续执行。

## 文档集与原入口

原长文档已拆分到同一资料包下的 `工作流文档/`。唯一维护源是总入口 `工作流文档/00-总入口.md` 和按清单列出的十份正文；旧版长文档兼容入口不是必需文件。

```text
工作流文档/
├── 00-总入口.md
├── 01-执行约定.md
├── 02-创意与思维导图.md
├── 03-产品定义与导航.md
├── 04-视觉与页面功能.md
├── 05-数据与工程架构.md
├── 06-素材与真实照片.md
├── 07-测试与质量验收.md
├── 08-发布与About材料.md
├── 09-实施顺序与交付报告.md
├── 10-第三方资源来源.md
└── manifest.txt
```

运行语句、执行顺序和原第 0–16 节编号不变。技能会读取总入口并按顺序完整读取十份正文，不是只看目录或按标题猜测内容。规范资源根仍是文档集的父目录；AppListing 运行时目录由安装器从远程仓库同步，工程输出位置不受拆分影响。跨机器复制时必须带上整个文档集、执行技能和启动器，不能只复制启动器或兼容入口；资料包不需要也不应携带本地 AppListing 副本。安装器在旧版长文档不存在时，会用总入口生成安装副本中的旧路径兼容文件。

本次拆分未改写正文；修改需求时编辑对应正文，并同步有实际关联的摘要或引用。拆分前原长文档备份在本机的 `skill-backups/flutter-engine-runner/source-documents/`，不参与执行。

## 真实照片素材要求

如果返回 403、429、超时、登录墙、验证码或许可证无法核验，将对应照片项记为 `Blocked`/`Not verified`；继续生成本地 AppListing、About、`aduit/` 和 `aduit/review/remarks.md`，不能再以素材失败停止整个交付流程。

执行流程必须实际搜索 Pexels、Pixabay、Unsplash、Wikimedia Commons 等第三方网站，核对主题与许可，下载真实实物/实景摄影到目标工程的 `assets/media/` 并接入 App 页面。`http://stargate.local:3100/image` 只用于生成 Logo，不能用于生成内容照片或其他主题摄影。原生图标、代码矢量符号、装饰插画与渐变等非摄影 UI 素材不需要从照片网站取得，也不计作真实照片。没有 API Key 或资源下载技能时仍尝试可用公开网页与合法下载方式；来源失败则切换其他来源，按规范有限尝试，不无限等待。

Emoji、渐变、矢量插画、AI 拟真图或仅写素材清单不能代替真实照片。验收要有来源与许可、实际页面截图及离线展示证据；不能只下载不使用，也不能用一张图填满所有分类。所有可用途径确实失败时可继续独立开发，但照片缺口必须明确报告，不能把该项资源质量标为通过。搜索记录与接触表在目标工程 `.codex-work/`，内容照片不进入 `aduit/`。

### iPhone 与权限配置

本流程只创建、构建和验证 iOS iPhone App，最低 iOS 部署版本为 15.6；实际依赖要求更高时保留更高版本，并按正文核对 Podfile、所有构建 target 的解析设置及可用产物。运行与截图必须明确指定 iPhone 机型及 UDID；没有可用 iPhone 时继续可执行检查，不回退到其他设备或平台。按实际权限插件检查 `ios/Podfile` 并尽力设置最小权限宏；宏配置失败需记录，但不得因此中止 Pods 安装或 iOS 打包尝试。宏配置、构建结果与权限运行验证分开报告，失败的权限路径不能标为通过。

## 最终交付目录

目标工程中的 `aduit/` 必须严格保持（由最终生成的 `AppListing/` 改名/整理而来，不执行公开部署）：

```text
aduit/
├── intro.md
├── site/
│   ├── index.html
│   ├── PrivacyPolicy.html
│   ├── Terms&Conditions.html
│   ├── Support.html
│   └── img/
│       └── logo.png
└── review/
    └── remarks.md
```

免责与版权说明合并在现有法律页；样式与脚本内联，使用系统字体。最终 `aduit/site/index.html` 是替换生成 About Home 后的自包含引导页，App 与工作流共用此唯一文件；它仍占原四页名额，不新增文件。`aduit/` 顶层仅允许 `intro.md`、`site/`、`review/remarks.md`；`site/` 只允许四个 HTML 页面与 `img/logo.png`，`review/` 只允许 `remarks.md`。执行记录、质量报告、截图、备份及额外文件放在目标工程的 `.codex-work/`，不进入交付目录。审核备注全英文、不超过 4,000 字符，基于已确认事实；生成后检查七项内容与白名单，并清理目标工程的 `AppListing/` 和旧 `aduit/html/`。
