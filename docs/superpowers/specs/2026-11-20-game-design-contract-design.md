# 游戏设计契约失效修复设计

## 问题

现有游戏资料包要求 2.5D/3D、场景层次、材质、动态反馈和可玩垂直切片，但这些要求分散在多个文档与 `game-engine.json` 字段中，没有一个可执行的唯一设计来源。领域数据、渲染代码、资产分层、页面路由、运行证据和发布状态也没有一条强制一致性链，因此实现可以退化成静态背景、矩形道路、纯色几何和重复截图，同时仍被文档描述为完整。

## 设计决策

新增项目级 `.codex-work/game-design-contract.json`，作为游戏视觉与领域设计的唯一权威来源。其优先级为：

`game-design-contract.json` → 页面契约 → 领域/渲染/资源实现 → 运行证据 → 发布状态。

已有 `.codex-work/game-engine.json` 继续负责引擎必要性和游戏大厅/垂直切片路线；它不能覆盖或替代新的设计契约。`validate_game_design_contract.py` 负责静态可执行检查，`validate_game_project.py` 在游戏或混合项目中调用它；缺少契约或契约失败时游戏预检失败。

契约必须包含：

- `source_of_truth`：唯一来源标识、版本、优先级、禁止的非权威来源和冲突处理。
- `visual_system`：渲染技术、投影/坐标、相机、设计令牌、前中后景层、材质/光照/阴影、可测量阈值和否决条件。
- `modes[]`：每个模式独立环境、道路/空间、车辆/角色、行人/实体、规则、结果和模式专属资产；每个领域字段绑定 `render_consumers`。
- `asset_pipeline`：离线资源、层级、透明度、遮挡顺序、统一坐标、加载入口、占位/纯色/矩形几何禁止项。
- `pages[]`：每页真实路由、独立布局签名、构图、资源、状态、交互、错误恢复和证据清单。
- `evidence`：每个验收项唯一证据，绑定项目版本、Bundle ID、设备/UDID、状态、文件哈希和证据类型。
- `status`：分离 `plan_status`、`implementation_status`、`verification_status`、`release_status`，并禁止不一致状态组合。
- `rejection_rules`：缺少独立场景、领域字段不被渲染消费、模式只改文案、没有碰撞因果、占位资产、纯色拼接、重复截图、静态图冒充动效、未实现路由或缺少当前设备证据时直接拒绝。

## 检查边界

检查器只做源工程静态和证据台账检查，不声称替代 iPhone 运行。它会验证路径、字段类型、数量下限、领域消费链、页面路由/文件/状态、证据绑定、哈希、状态一致性和否决规则。真实运行、截图和录屏仍由现有 iOS 验收流程完成。

## 兼容策略

不删除或重命名现有 `game-engine.json` 字段。旧工程必须新增契约；缺少契约时明确失败并列出修复项。契约中的 `mode_id`、页面 ID、路径和证据路径全部使用项目相对路径，禁止链接到 `.codex-work` 之外的临时资源，资产必须位于正式工程目录。
