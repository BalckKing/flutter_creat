## 11. 测试与验收

### 11.1 行为优先测试

Logo 视觉核验还须按第 2.5、10.3 节实际查看原尺寸与图标尺寸，根据主题元素判断模拟现实、手绘、油画或艺术主画风是否选得合理，核对记录依据、提示词和成品一致，记录对应画风的精致度、造型、笔触/材质/光影、鲜明多色与平滑渐变的结果；不得有粗糙简笔、几何色块堆叠、简陋图案、3D 造型或明显 AI 生成感。确认 Logo 不能呈现冷峻或单调色调；生成选项中的“高质量”和文件尺寸本身不代表视觉合格。

对关键逻辑、状态转移和容易回归的行为优先使用失败测试驱动实现；文案、尺寸等低风险可逆调整使用对应的视觉或静态检查。根据实际实现覆盖以下适用行为；只有主题不需要的可选能力可以标记 `N/A`，摄像机、相册、麦克风必须实现，缺设备时只标记对应验证受限。ATT 无追踪时的 `Not applicable` 必须有适用性核验依据。外部工具缺失时记录限制并继续可执行验证，不机械补写无关测试：

- 开发流程核验：检查实际思维导图的展示记录、获批版本和用户明确确认的对话来源，确认创建项目、修改代码、安装依赖、提交 Logo、构建与部署均在该确认之后；这项检查核对工作记录，不为 App 增加确认页面或个人同意记录。
- Podfile 权限宏核验：检查实际插件/版本、宏与调用 API 的对应、既有 `post_install` 是否保留、宏设置失败记录及后续 `pod install`/iOS 打包尝试。配置失败场景下流程仍须进入打包尝试；宏或权限路径缺口单独标记未验证，不得因宏配置失败直接终止打包，也不得因此把构建或权限标为通过。
- Logo 优先与配色核验：检查实际任务/文件时间与执行记录，正常路径必须先完成高质量单张生成、根据主题元素从模拟现实/手绘/油画/艺术中选择并记录一种主画风、Logo 校验、真实色块提取及鲜明主题/渐变定制，再创建 Flutter 工程与实现页面；最小产物目录不等于工程创建。核对页面实际参数、完整提示词、鲜艳满幅背景、无文字图形、`1024x1024` RGB PNG、无 Alpha，以及原始 HEX → 衍生色 → App/About 令牌和可见渐变的一致性；至少三个实际页面/组件的 iPhone 截图证明主题令牌被消费。失败回退单列退出证据与暂定配色，不能把它写成正常完成，不为本项机械补写无关单元测试。
- 导图完整性核验：按第 3.5 节重查用户需求、导图、页面、路由、状态、数据、资源与验收的一致性；需求映射全覆盖，已知遗漏、矛盾、断链和语法错误均已修复，明确区分计划与真实实施结果。
- Logo 替换落地核验：按第 10.4 节对照品牌位置映射，检查 iPhone 桌面图标、启动品牌图、Loading/Entry 封面与现有 App/About 品牌位置已实际使用本次 Logo 或其派生图；核对资源声明、AppIcon 集合、安装构建及冷启动截图，并在 AppListing 改名后复验站点图片哈希和渲染。只下载 Logo、生成文件或执行热重载不能视为完成；内容照片封面仍保留其主题素材。
- Logo 命名核验：对照用户提供的项目名称与实际文件操作记录，核对下载/导出成品为 `<项目名称>.png`，先以项目名导入工程 `assets/` 后才改为 `logo.png`，最终引用统一为 `assets/logo.png`；必要的文件名字符替换和格式转换有据可查，项目名版本未额外打包，Logo 画面仍无文字。未实际下载/导入时仅记录待执行，不将文档规则冒充已完成操作。
- 冷启动与 Loading 分层核验：在当前 iPhone 构建上分别观察 iOS 原生静态 Launch Screen 和其后的 Flutter Loading。原生页应以完整静态品牌背景和主题装饰衬托较大 Logo、`PRYRIN`、项目名、一致的定位文案与装饰线，不能出现进度条、百分比、动画或交互。Flutter Loading 按第 7.1 节实际呈现整屏背景、品牌主视觉、2–3 项已实现功能预览、真实状态区和统一排版五层；Logo、项目名、同一定位文案、当前真实步骤、百分比及进度条齐全，不能以单张 Logo 大片留白、仅放大图片或换渐变底替代完整构图。
- 创意一致性检查：逐项核对 `Effective idea` 与实际核心功能、页面、领域模型和种子数据，确认保留 `Core intent` 与用户约束。创意来源、生成请求或同意与思维导图批准分别核验；未把生成内容伪称用户原话，未把示例或旧项目主题当成当前产品方向。
- Loading 读取本地主题、首次使用介绍展示记录和必需资源状态，按第 7.1 节预算进入 Entry 或可操作的错误页；检查慢读取、非关键失败、取消/重试与迟到回调，不读取登录状态或进行远程身份认证。
- Flutter 品牌首帧不被异步初始化扣住，不在 `runApp` 前等待仓储/扫描/网络，也不为展示 Loading 设置最小可见时长；必需准备完成后立即进入 Entry。用受控测试覆盖极快、正常与慢准备，快速分支允许 Loading 短暂出现或首帧已就绪，不能为截图、读完文案或播完动画人为延迟；受控慢准备/错误触发不进入正式启动行为。初始化装饰不新增远程资源依赖。
- Loading 的百分比和进度条只随实际必需里程碑完成而变，当前步骤与实际工作相符；验证并行准备、耗时步骤、快速启动、非关键项延后和启动操作取消/重试，不出现计时假进度、过早 100%、步骤与百分比不一致或为动画额外等待。VoiceOver 能读出步骤和进度值。
- 核心初始化错误时同时显示 `Try again` 和 `Clear Data`。分别验证重试仅重做失败阶段且旧回调失效，以及 Clear Data 进入同一个二次确认/清理恢复流程；确认框取消不改数据、不跳转，确认后真实清理成功才回 Entry。
- 首次与后续正常从关闭状态启动均显示 Entry；存在已确认但未完成的清除标记时先恢复清理，成功后才开放最终引导页的 `Continue`（引导页接入前的开发预览可用 `Enter`）。从后台恢复时保留当前有效页面或清理状态，不新增进入步骤，也不重新询问是否清除。
- 最终 Entry 的本地引导页点击 `Continue`（引导页接入前的开发期原生预览可用 `Enter`）后直接进入第一个选定 Tab，无邮箱、密码、协议勾选、认证请求或额外确认；桥接和回退都只执行一次，快速重复点击不重复入栈，首次使用介绍记录写入失败也不阻断进入。
- 开发期间 Terms/Privacy 可在 WebView 预览随包本地正文；AppListing 改名为 `aduit/` 并完成最终链接回接后，Entry 的 Terms/Privacy 点击须将 `aduit/intro.md` `All URL` 对应的原始字符串交给 WebView。用不发起网络请求的 stub/fake 模拟加载失败，显示可操作错误、返回与有限重试；不回退到本地正文、不访问真实 URL，失败不阻断 `Continue`。
- Settings 同一页面只显示 `Privacy Policy`、`Terms of Use`、`Support` 三个 WebView 入口；不得显示 `Home` 或链接首页引导页。最终 `aduit/site/index.html` 由引导页占用并只在 Entry 加载。
- AppListing 改名为 `aduit/` 后的首页引导页专项验收：检查 App 加载的是唯一源文件 `aduit/site/index.html`，原生成 About Home 内容已替换且未增加白名单外文件；读屏/可见文案均为英语、3–5 张卡片只显示一张、真实功能介绍与当前项目一致、配色与 App/Logo 一致。确认 HTML/CSS/JavaScript 全部内联、没有外部资源请求、字节数小于 262,144，且该计数包含所有 Base64 图片内容；每张显示的图片必须是 `data:image/...;base64,...`，逐个解码并确认图像格式、尺寸与可读性，再在无网络 WebView 验证实际显示。确认没有 Flutter assets、工程内相对图片路径、`file://`、远程图片 URL、CSS `url()` 或 `srcset` 图片依赖。设置 `viewport-fit=cover` 并实际使用 `env(safe-area-inset-top)` / `env(safe-area-inset-bottom)`。在 `390×667`、`390×844`、`1024×768`、`1440×900` 检查完整显示、无重叠/遮挡/裁切与底部两行协议文本；真实观察自动轮播、每个可点击分页点和减少动态时停播。用无网络 stub 分别验证 Bridge 可用时仅发送一次 `continue` 且不导航、Bridge 不存在时准确转向 `go://continue` 并由原生导航代理截获进入相同主流程；不能只查看静态 HTML 源码或生成器截图。
- Settings 的 `Clear Data` 首次点击只显示一个准确说明范围和不可撤销后果的确认框；只有点击 `Clear Data` 才开始清理，取消/确认前关闭时不停止任务、不改数据、不跳转。重复点击不叠加确认框或清除任务，无障碍焦点和破坏性按钮语义正确。
- 确认后停止采集/播放并隔离新写入，按第 8.5 节核对文件、主题记录、索引、临时/派生文件、设置、内存及 WebView/SDK 本地数据真实清理；清理成功才清空导航栈回到 Entry，主题恢复 `System`，其他偏好恢复默认，用户媒体为空，随包示例保留。返回手势/旧深链不能打开旧记录，再次点击 `Continue`（开发预览可为 `Enter`）与新的媒体保存均正常。

- Loading、Entry、`Continue`、`Clear Data`、确认/清理/失败、协议、空状态和错误状态的可见文案按第 6.6、11.4 节核验；覆盖中文、禁止词及同义内部实现表达、无障碍读出、素材内文字和运行时异常，不出现路径泄露或登录/登出提示。修正文案后同步 HTML、截图、快照与实际运行证据，不能只改字符串文件而保留旧显示。

### 11.2 素材采集测试

存在本次新增或修改的素材采集工具时，使用离线 HTTP fixture 和可注入客户端测试实际边界；直接使用已有合规本地素材时，不为测试而额外创建采集工具。CI 不得携带真实密钥或发起真实供应商请求。适用工具覆盖 DTO 解析、字段缺失、无结果、401/403/429、单次与总超时、日志脱敏、缓存去重、滚动窗口限流、`Retry-After` 超预算处理、非幂等请求防重复提交、主机/重定向/MIME/签名/大小拒绝、哈希去重和许可完整性。

- 使用适当的 profile/release 构建和可用性能工具记录证据，说明设备、模式、样本与限制；Debug 模式可以检查行为和布局，不作为发布性能结论。工具或真机缺失时报告未验证范围，继续结构与资源检查，不编造帧率、内存或启动耗时。

### 11.9 交付前质量复核与耗时对照

首个可运行版本、构建通过、最低轮次完成和投入比例达标均不是交付终点。完成主要实现与精修后，在宣布完成前执行一次单独的成果复核；直接查看当前文件、实际运行结果与最终资源，不能只重读智能体自己的完成总结。将结论写入项目根目录 `.codex-work/quality.md` 或其他非公开质量记录，并在最终报告引用；优先链接已有证据，不重复制作大份报告，不把该记录或任何审计材料加入 `aduit/`、公开站点或 App Bundle。

1. **范围与真实深度**：从已确认方案和后续用户指令反向核对全部必做需求，区分“已实现”“实际验证通过”和“尚未验证”。检查第 4.2 节的有效内容数量、至少三个不同结果的完整任务、每个已选 Tab 与二级页面；所有可见主动作均有真实结果，没有以空页面、静态卡片、假按钮或示例媒体替代真实功能。摄像机、相册、麦克风分别核对采集/导入、预览/试听、保存、重新访问、删除与异常回退。
2. **逐屏视觉与资源**：使用页面/状态检查矩阵列出所有 App 可控制页面、适用状态及 iPhone 尺寸/方向；核对当前 iPhone 构建的截图、实际交互与三轮修改证据。按第 6.7 节覆盖主题、尺寸与无障碍场景，并按第 6.8 节核对 Emoji 的真实展示、主题匹配、布局与读出，不要求穷举无意义的组合。按第 2.5、6.3–6.5 节核对 Logo 鲜艳色块、取色记录、主题令牌及 App/About 实际可见渐变，品牌色一致且文字/控件可读，不以配置里存在渐变代替页面已显示；再按第 6.9 节核对 Logo 结构/材质/光影自然度及明显生成瑕疵，并实际检查承载主题内容的主要列表包含有依据的混合尺寸、图片裁切焦点正确、视觉与 VoiceOver 顺序一致，同时保证 Settings/协议/权限等扫描列表保持整齐。实际查看最终图片与视频，核对两轮资源调整、许可、原始内容数量、重复分布、裁切、清晰度、封面和播放；按第 6.6、11.4 节核对各页与状态的实际显示文字、图片嵌字、视频字幕及无障碍文案，没有已知中文或内部术语残留。几张首页截图或清单中的文件数不能代表全部页面与素材已验收。最终 AppListing 生成位于本复核之后，先核对已有 About 页面与 Logo 的品牌关系，最终页面配色、文案及文件转移按第 12.1 节在最后一步复验。
3. **工程与平台证据**：核对当前产物的静态分析、适用测试、可用 iOS iPhone 构建与运行、离线/重启/返回/清除本地数据行为及第 11.8 节性能证据；新改动后原结果不再适用时补充针对性复验。按第 0.10、11.6、11.7 节对照 iPhone-only 配置实际生效值、明确的 iPhone 运行目标、构建产物 `UIDeviceFamily = [1]`、真实媒体结果、最终权限配置、ATT、隐私清单、协议与数据流；源码存在、插件安装或一次编译成功不能替代这些检查。证据标明对应版本、命令/场景、实际 iPhone 机型/iOS/ID 或静态检查环境、结果与路径，未生成产物或未实测的项据实标注。
4. **缺陷与完成条件**：已知崩溃、数据丢失、核心动作失效、三项媒体缺失、隐私/权限错误、明显遮挡溢出、不可读文字和无理由重复素材，均须修复并核对受影响范围后才可声称相应质量项通过。记录其他残余问题及其具体影响，不用模糊的“基本完成”掩盖缺陷。外部设备、服务或凭据缺失时沿用第 0.8 节状态，交付已完成的本地产物和准确缺口，不能把未验证变为通过；同样不能为等外部条件阻断所有独立工作。
5. **耗时与历史范围对照**：当本次制作耗时明显少于用户给出的同类历史参考（例如从约 8 小时降至约 3 小时）时，复核功能/内容范围、UI 覆盖、精修实际修改、独立素材、测试和硬件验证是否减少。只有具备真实记录时，才说明复用、并发或减少等待带来的节省；无法确认原因时明确注明，不编造效率提升。发现可执行工作被省略时立即补做；范围不同或验证尚缺时明确说明，不能仅用“模型更快”或“已完成三轮”解释差距。没有可信计时则记录耗时未核实，不伪造实际工时。

资源复核还必须逐项执行第 10.6 节：核对照片需求表、实际网站搜索与来源页、许可、文件和当前构建截图，报告独立真实照片数量/计划数量与每个展示位的覆盖。没有实际搜索网站、照片仅在磁盘未显示、使用 AI 拟真图/插画替代、许可不明或覆盖缺失时，相应照片要求不能通过；缺少 API Key 本身不能证明公开网页途径不可用。有限尝试后的真实外部阻断按要求记录并继续独立工作，不把这个回退当成照片质量已完成。

逐页图文深度另按第 6.10 节复核：将第 3.2 节所有页面/流程行与实际路由及状态对齐，核对各自的信息模块、非纯文字表达、真实素材/组件、点击结果与当前构建证据。覆盖详情、搜索、工具、Settings、媒体、空/失败态和自有协议页面，不能以首页精修或照片总数代替全页面完成；连续文字堆叠、假波形/统计、同图反复铺满或无关装饰须修正。缺乏运行证据的页面保持 `Not verified`，不把新增规划列当作实现证明；沿用既有质量矩阵记录结果，不额外增加用户确认或公开交付文件。

本复核步骤的“完成”表示适用检查已经执行、可修复缺陷已经整改或复验、外部阻断已经留下证据；它不要求把不可用的网络素材写成通过。照片或正式 Logo 仍为 `Blocked`/`Not verified` 时，继续进入第 12.1 节的远程 `ios-app-listing` AppListing/About 生成、第 12.2 节 Review Remarks 和目录整理；若远程 checkout 本身不可用，则仅将该材料阶段标为 `Blocked`，不得以资料包副本或手写页面替代。最终报告分别列出媒体缺口、远程技能状态与本地产物状态，不因照片检查未通过而提前结束工作流。

复核后只针对新发现问题及其影响范围整改和复验，保留仍有效的证据。全过程按已确认授权自主完成，不新增用户审批。制作 3 小时或 8 小时都不能自动判定合格；完成条件由需求覆盖、实际视觉与资源质量、功能结果及验证证据决定，仍有可修复的重要问题时继续工作，不设置为了凑工时的空等或无限审查循环。

完成 AppListing/About、协议链接、Review Remarks 和最终交付目录整理后，仍须按第 10.7 节另做一次最终图片加载检查，作为全流程最后执行步骤。此时必须检查最终构建中每个实际图片展示位是否正确加载、内容是否贴题、不同列表尺寸下主体是否完整可见、主要内容列表是否呈现合理的尺寸层级、Logo 是否有明显生成瑕疵，以及是否存在占位图或破损图；任何问题都要从第 16 节列出的第三方网站取得许可明确的主题图片、替换接入并重建复验。该轮检查需有当前 iPhone 页面截图和离线随包加载结果；没有 iPhone 运行证据就标记 `Blocked`/`Not verified`，不可报告整体最终检查通过。
