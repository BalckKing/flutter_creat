## 11. 测试与验收

### 11.1 行为优先测试

素材来源展示专项：按第 10.1.1 节检查 Detail、Player、Settings、About/Support、欢迎引导及生成法律页，确认无需公开署名的图片/视频没有图库名、作者、下载链接、来源清单、徽标/脚注或多余 Credits 入口。公开与无障碍文本、路由和最终 HTML 同步核对，AppListing 生成后再次检查，不能只隐藏按钮却保留来源页入口。内部来源/许可记录仍完整、素材仍实际显示和播放；有强制署名义务时，核验最小必要声明及规定位置，或在换用合规免署名素材并解除旧引用后再移除。不得删软件必要许可通知、隐私事实披露或把原素材继续使用但隐去必需声明当作通过。最终报告仅汇总核验状态与内部记录路径，不重复列举不必要的图库清单。

原生 AppIcon 必须按第 10.4.1 节单独验收，不能用 App 内 `assets/logo.png`、启动图、工具成功退出或资源目录截图代替。对实际使用的 scheme/target/configuration/flavor/SDK 核对解析后的图标集合与 bundle ID、最终 `.app`/适用归档的编译图标、对应安装身份和 iPhone 主屏幕截图；分别记录源图、配置、产物、显示的状态与证据。Debug/模拟器截图不证明 Release/iphoneos 归档；有效的当前 Xcode 单一 1024 图标模式不误判为缺少旧槽位。默认 Flutter 图标残留判为 `Failed`，缺运行证据判为 `Not verified`，不自动清除用户数据。所有图标输入、相关配置及最终构建变更之后，在第 10.7 节最后检查中更新受影响证据；图标缺口不阻断独立的 Listing/About/Remarks。

逐页面结构与装饰素材的验收是本节必查项：从页面清单核对每个独立页面均有按 page ID 分类的单独 Dart 页面文件；`main.dart` 仅作为启动入口，不承载所有页面定义。对每个 App 自有页面核对唯一 `page_id`、`assets/backgrounds/<page_id>/<page_id>_background.png`、`pubspec.yaml` 注册、对应页面 Widget 的实际 asset 引用、低透明度叠加/边缘装饰的可读性，以及当前 iPhone 构建中的加载截图。逐页面核对背景装饰素材路径、文件夹和命名是否与 `page_id` 一致。页面资源缺失、仅存在未引用、跨页错误复用、资源目录/名称与 page ID 不匹配，或以真实照片检查代替装饰图检查，都不能标为通过；生图服务受阻时只将受影响页面素材标记 `Blocked`/`Not verified`，继续其他页面和任务。

Logo 视觉核验还须按第 2.5、10.3 节实际查看原尺寸与图标尺寸，根据主题元素判断模拟现实、手绘、油画或艺术主画风是否选得合理，核对记录依据、提示词和成品一致，记录对应画风的精致度、造型、笔触/材质/光影、鲜明多色与平滑渐变的结果；不得有粗糙简笔、几何色块堆叠、简陋图案、3D 造型或明显 AI 生成感。确认 Logo 不能呈现冷峻或单调色调；生成选项中的“高质量”和文件尺寸本身不代表视觉合格。

对关键逻辑、状态转移和容易回归的行为优先使用失败测试驱动实现；文案、尺寸等低风险可逆调整使用对应的视觉或静态检查。根据实际实现覆盖以下适用行为；只有主题不需要的可选能力可以标记 `N/A`，摄像机、相册、麦克风必须实现，缺设备时只标记对应验证受限。ATT 无追踪时的 `Not applicable` 必须有适用性核验依据。外部工具缺失时记录限制并继续可执行验证，不机械补写无关测试：

- 开发流程核验：检查实际思维导图的展示记录、获批版本和用户明确确认的对话来源，确认创建项目、修改代码、安装依赖、提交 Logo、构建与部署均在该确认之后；这项检查核对工作记录，不为 App 增加确认页面或个人同意记录。
- Podfile 权限宏核验：检查实际插件/版本、宏与调用 API 的对应、既有 `post_install` 是否保留、宏设置失败记录及后续 `pod install`/iOS 打包尝试。配置失败场景下流程仍须进入打包尝试；宏或权限路径缺口单独标记未验证，不得因宏配置失败直接终止打包，也不得因此把构建或权限标为通过。
- Logo 优先与配色核验：检查实际任务/文件时间与执行记录，正常路径必须先完成高质量单张生成、根据主题元素从模拟现实/手绘/油画/艺术中选择并记录一种主画风、Logo 校验、真实色块提取及鲜明主题/渐变定制，再创建 Flutter 工程与实现页面；最小产物目录不等于工程创建。核对页面实际参数、完整提示词、鲜艳满幅背景、无文字图形、`1024x1024` RGB PNG、无 Alpha，以及原始 HEX → 衍生色 → App/About 令牌和可见渐变的一致性；至少三个实际页面/组件的 iPhone 截图证明主题令牌被消费。失败回退单列退出证据与暂定配色，不能把它写成正常完成，不为本项机械补写无关单元测试。
- 导图完整性核验：按第 3.5 节重查用户需求、导图、页面、路由、状态、数据、资源与验收的一致性；需求映射全覆盖，已知遗漏、矛盾、断链和语法错误均已修复，明确区分计划与真实实施结果。
- Logo 替换落地核验：按第 10.4 节对照品牌位置映射，检查 iPhone 桌面图标、原生启动品牌图、Welcome/Initialization 品牌画面与现有 App/About 品牌位置已实际使用本次 Logo 或其派生图；核对资源声明、AppIcon 集合、安装构建及冷启动截图，并在 AppListing 改名后复验站点图片哈希和渲染。只下载 Logo、生成文件或执行热重载不能视为完成；内容照片封面仍保留其主题素材。
- Logo 命名核验：对照用户提供的项目名称与实际文件操作记录，核对下载/导出成品为 `<项目名称>.png`，先以项目名导入工程 `assets/` 后才改为 `logo.png`，最终引用统一为 `assets/logo.png`；必要的文件名字符替换和格式转换有据可查，项目名版本未额外打包，Logo 画面仍无文字。未实际下载/导入时仅记录待执行，不将文档规则冒充已完成操作。
- 启动三页分层核验：在当前 iPhone 构建上分别观察 iOS 原生静态 Launch Screen、每次启动出现的 Flutter Welcome（`/welcome`，含 `Continue`）及清除成功后出现的 Initialization（`/entry`，含 `Entry`）。原生页是系统冷启动静态画面；Welcome 内部承载启动准备、真实步骤/百分比/进度、恢复、重试与错误，不创建独立 Flutter Loading 页面。Welcome 按第 7.1 节检查整屏主题构图、真实功能介绍和启动状态；Initialization 按第 7.2 节检查清除成功状态、`Entry` 与协议文案。通用协议文案仅初始化页显示，欢迎页及其 HTML 引导页不得显示；原生 Launch Screen 和任何启动准备状态均不显示。三页各自核验，不相互替代。
- 初始化页视觉专项：确认清除成功后显示的 Initialization 独立页面使用 Logo 衍生渐变、主题装饰和完整的非纯文字内容，不出现纯白色/近白空白画布；单独检查安全区、`Entry` 按钮与唯一的协议页脚不重叠、不裁切。Welcome 和原生启动页不得出现协议通用文案。
- 启动入口断言：每次启动都进入欢迎页并显示 `Continue`；Clear Data 确认后，清除成功后进入初始化页并显示 `Entry`。
- 创意一致性检查：逐项核对 `Effective idea` 与实际核心功能、页面、领域模型和种子数据，确认保留 `Core intent` 与用户约束。创意来源、生成请求或同意与思维导图批准分别核验；未把生成内容伪称用户原话，未把示例或旧项目主题当成当前产品方向。
- 每次启动进入 Welcome；准备状态读取实际必需配置，并留在 Welcome 页面内部。按第 7.1 节预算更新真实状态，准备就绪后启用 `Continue`；检查慢读取、非关键失败、取消/重试与迟到回调，不读取登录状态或进行远程身份认证。
- Flutter Welcome 首帧不被异步初始化扣住，不在 `runApp` 前等待仓储/扫描/网络，也不为展示准备状态设置最小可见时长；必需准备完成后在 Welcome 启用 `Continue`，不自动跳去 Initialization。用受控测试覆盖极快、正常与慢准备；不能为截图、读完文案或播完动画人为延迟；受控慢准备/错误触发不进入正式启动行为。页面装饰不新增远程启动依赖。
- Welcome 内部准备状态的百分比和进度条只随实际必需里程碑完成而变，当前步骤与实际工作相符；验证并行准备、耗时步骤、快速启动、非关键项延后和启动操作取消/重试，不出现计时假进度、过早 100%、步骤与百分比不一致或为动画额外等待。VoiceOver 能读出步骤和进度值。
- 核心初始化错误时同时显示 `Try again` 和 `Clear Data`。分别验证重试仅重做失败阶段且旧回调失效，以及 Clear Data 进入同一个二次确认/清理恢复流程；确认框取消不改数据、不跳转，确认后真实清理成功才回 Entry。
- 首次与后续正常从关闭状态启动均显示 Welcome（`Continue`）；只有 `Clear Data` 已确认且真实清理成功才切换到 Initialization（`Entry`）。存在已确认但未完成的清除标记时先恢复清理，成功后显示 Initialization；失败则保留可恢复清理状态，不展示成功页。从后台恢复时保留当前有效页面或清理状态，不新增进入步骤，也不重新询问是否清除。
- 每次启动的 Welcome 本地引导页点击 `Continue`（仅引导页接入前的开发期预览可用 `Enter`）后直接进入第一个选定 Tab，无邮箱、密码、协议勾选、认证请求或额外确认；桥接和回退都只执行一次，快速重复点击不重复入栈，首次使用介绍记录写入失败也不阻断进入。Initialization 的 `Entry` 也直接进入同一主流程。
- 开发期间 Terms/Privacy 可在 WebView 预览随包本地正文；AppListing 改名为 `aduit/` 并完成最终链接回接后，只有 Clear Data 成功后出现的 Initialization 页，其 Terms/Privacy 点击须将 `aduit/intro.md` `All URL` 对应的原始字符串交给 WebView。Welcome 和 HTML 引导页不得出现协议文案/链接。用不发起网络请求的 stub/fake 模拟加载失败，显示可操作错误、返回与有限重试；不回退到本地正文、不访问真实 URL，失败不阻断流程。
- Settings 同一页面只显示 `Privacy Policy`、`Terms of Use`、`Support` 三个 WebView 入口；不得显示 `Home` 或链接首页引导页。最终 `aduit/site/index.html` 由引导页占用并只在每次启动进入的 Welcome 加载；Clear Data 成功后的 Initialization 页不加载该 HTML。
- AppListing 改名为 `aduit/` 后的首页引导页专项验收：检查 App 加载的是唯一源文件 `aduit/site/index.html`，原生成 About Home 内容已替换且未增加白名单外文件；读屏/可见文案均为英语、3–5 张卡片只显示一张、真实功能介绍与当前项目一致、配色与 App/Logo 一致。确认 HTML/CSS/JavaScript 全部内联、没有外部资源请求、字节数小于 262,144，且该计数包含所有 Base64 图片内容；每张显示的图片必须是 `data:image/...;base64,...`，逐个解码并确认图像格式、尺寸与可读性，再在无网络 WebView 验证实际显示。确认没有 Flutter assets、工程内相对图片路径、`file://`、远程图片 URL、CSS `url()` 或 `srcset` 图片依赖。设置 `viewport-fit=cover` 并实际使用 `env(safe-area-inset-top)` / `env(safe-area-inset-bottom)`。在 `390×667`、`390×844`、`1024×768`、`1440×900` 检查完整显示、无重叠/遮挡/裁切，且确认 Welcome HTML 引导页不含协议通用文案或协议页脚；真实观察自动轮播、每个可点击分页点和减少动态时停播。用无网络 stub 分别验证 Bridge 可用时仅发送一次 `continue` 且不导航、Bridge 不存在时准确转向 `go://continue` 并由原生导航代理截获进入相同主流程；不能只查看静态 HTML 源码或生成器截图。
- Settings 的 `Clear Data` 首次点击只显示一个准确说明范围和不可撤销后果的确认框；只有点击 `Clear Data` 才开始清理，取消/确认前关闭时不停止任务、不改数据、不跳转。重复点击不叠加确认框或清除任务，无障碍焦点和破坏性按钮语义正确。
- 确认后停止采集/播放并隔离新写入，按第 8.5 节核对文件、主题记录、索引、临时/派生文件、设置、内存及 WebView/SDK 本地数据真实清理；清理成功才清空导航栈进入 Initialization 并显示 `Entry`，主题恢复 `System`，其他偏好恢复默认，用户媒体为空，随包示例保留。返回手势/旧深链不能打开旧记录，再次点击 `Entry` 后的 `Continue`（开发预览可为 `Enter`）与新的媒体保存均正常。
- 覆盖恢复标记写入失败、设备释放超时、磁盘/索引部分删除失败、默认重建失败、清理中重启、与保存/单条删除并发及迟到回调；错误不谎报成功、不提前进入 Initialization，重试不重复删除或重新弹确认，不让旧任务重建被删除数据。核验清除不删除系统相册原件、App 外导出文件或随包资源，不重置系统权限/ATT、不强制关闭 iOS App。
- Privacy Policy、Terms of Use 和 Support 三个 Settings 入口，以及 Clear Data 成功后 Initialization 页底部的 Terms/Privacy 文本链接，均由同一个 WebView 页面容器展示；Welcome HTML 引导页不带协议文案或链接，也不作为 Settings 入口。所有图片资源、封面和媒体容器均验证为非零圆角。
- 视觉回归检查覆盖高饱和多色混搭、`brandGradient`/`sunsetGradient`/`aquaGradient`/`neonMixGradient`、浅色/深色模式和减少动态回退；主要页面不得退化为单一色系。
- 渐变上的正文、图标和控件边界达到对比度要求；不合格区域使用稳定纯色或半透明表面层修正。
- Welcome、Initialization、`Continue`、`Entry`、`Clear Data`、确认/清理/失败、协议、空状态和错误状态的可见文案按第 6.6、11.4 节核验；覆盖中文、禁止词及同义内部实现表达、无障碍读出、素材内文字和运行时异常，不出现路径泄露或登录/登出提示。确认通用协议文案仅 Initialization 显示、Welcome 与其 HTML 引导页均不显示。修正文案后同步 HTML、截图、快照与实际运行证据，不能只改字符串文件而保留旧显示。
- 协议版本变化只更新正文与文档元数据；不要求重新勾选，不改变 `Continue` 的可用性，不生成个人协议同意记录。
- System、Light、Dark 正常持久化并同步到所有选定 Tab 和工具路由；取消清除保留原选择，成功清除恢复 `System` 并同步全局。
- 动态 Tab 路由、返回栈恢复、筛选、搜索、排序、无结果和重试。
- Detail 不存在的 ID、相关内容去重和长文本展开；素材声明按第 10.1.1 节只核验确有公开义务的项目。
- Player 加载、暂停、重试、中断、过期任务取消和控制器释放。
- 三个 Settings 入口、Initialization 底部 Terms/Privacy 链接、Welcome 引导页无协议页脚、四个固定 HTML 页面及其合并法律章节、开发期本地预览、最终四个 All URL 原始字符串注册映射、WebView 失败/返回/有限重试、标题、主题外壳和返回路径；明确验证 Settings 不含首页引导页。最终 URL 回归只用不发网络请求的 stub/fake，不回退到本地页面。
- 清单结构、资源存在、路径唯一、SHA-256 和消费页面引用。
- 图片加载回归按第 10.7.1 节验证真实组件的 pending/首帧/error 状态，在离线 fixture 中覆盖错误大小写/缺 key、未打包的子目录、损坏/伪图片和错误被 fallback 吞掉；测试必须捕捉失败，不能只断言 Widget 或占位容器存在。预加载错误、背景加载错误与懒加载项同样可观察，不把 `precacheImage` Future 结束当作解码成功。
- 第 4.2 节的内容数量、功能深度与三个完整任务流程，以及第 6.7 节 UI/资源投入、至少三轮 UI 精修和两轮资源调整的实际改动与证据。
- 第 10.5 节的图片/视频独立来源、近似重复组、消费位置、必要复用理由、清晰度、裁切、封面、真实播放与安装体积检查；换名、换裁剪和原片重叠截段不作为独立素材计数。

### 11.4 反向验收

扫描源码、依赖、路由、文案、资源名、模型、fixture 和快照，确认没有实现邮箱输入、登录/登出、密码、验证码、认证服务、个人协议同意记录、社交、收藏、云端媒体上传或个人资料能力；没有独立的 `Exit`、退出、登出按钮及旧 `exiting` 流程。每次启动进入 Welcome 并使用 `Continue`（引导页接入前的开发预览可用 `Enter`）；清除数据只通过 `Clear Data` → 二次确认 → 真实清理成功进入 Initialization 并显示 `Entry`，不能用其他名称恢复旧退出行为。普通返回、关闭预览和单条媒体删除仍须可用。摄像机、相册、麦克风与私有媒体索引是必做能力，不得作为违规的“用户创建内容”删除。词汇命中必须结合上下文判断；第三方依赖内部名称、明确说明不支持该能力的法律文案和测试描述不构成违规，不得因纯关键词命中删除有效产物或反复重写。`AppFlowState`、系统权限状态、清除恢复标记和协议 WebView 属于明确允许的能力。

显示文案另行验收，不把上述工程能力扫描当作 UI 文案通过证据：

- 提取实际消费的字符串、种子内容、HTML 可读正文、图片/视频文字、无障碍标签、权限用途字符串与 AppListing 公开文案，按第 6.6 节检查中文与禁词；英文忽略大小写，使用词边界、词形与路径识别，不因 `relocate` 等正常词包含相似字母就误删。新增及运行时拼接文案同样检查，原始异常不能直接拼进提示。
- 实际打开全部自有页面与适用状态，核对加载、空、失败、取消、清除确认/进展/失败、权限拒绝回退和 WebView 正文；使用截图检查自有图片嵌字与视频字幕，并抽查 VoiceOver 实际读出。存在旧版文案、中文自动回退、调试角标或内部错误详情时修改并复验。
- 对每个命中记录展示位置、来源与处理结果；区分 App 可控显示内容、工程标识、系统生成界面及用户原始内容。开发文档/文件路径中的 `lib`、`package`、`packages`、`local`、`device` 等并非 UI 文案，不进行全项目机械替换；协议中的必要事实仍须准确披露，用自然英文修正表达，不用删除整段或虚构数据行为消除命中。
- 已知自有显示违规须修复后才将文案检查标为 `Verified`；必需许可/法律名称有不可改写冲突或某状态未查看时单独记录待解决或未验证项，不自动豁免、不假称全量通过。保留结果与证据位置，页面或资源变化后只复查受影响范围，不把词汇检查等同于正式审核结论。

### 11.5 可选媒体轮换

只有智能体判断主题确实需要轮换时才启用，不询问用户是否开启。轮换是可选机制，第 10.5 节的资源多样性、去重和两轮资源调整始终必须执行，不能因未启用轮换而省略：

- 每个状态或分类至少四套专属图片/视频。
- 同一状态连续四次成功更新不得复用相同图片或视频。
- 不同状态的轮换池不能共享路径、SHA-256 或相同原始内容/视觉重复组；统一品牌和确有语义的一致内容展示按第 10.5 节说明复用，不混入轮换池凑数。
- 失败或取消不得推进轮换索引。

#### 最终 iOS 权限宏与 ATT 清理检查

在所有页面/素材最终检查之后、最终报告之前执行此项；它是最后一项 iOS 配置验收。检查必须依据当前依赖版本、实际代码调用和最终构建产物，不只搜索源文本或查看 Podfile：

1. 盘点实际相机、麦克风、照片导入/读取/保存 API 与插件版本，建立 `API → 插件实现 → Info.plist 用途键 → Podfile 宏 → Pods 解析后编译设置` 对照。使用 `permission_handler_apple` 且实际调用 PhotoKit library/read-write API 时，必须在 Podfile 权限配置中启用 `PERMISSION_PHOTOS=1`，并从 `Pods-Runner.*.xcconfig`、`xcodebuild -showBuildSettings` 或等价的最终编译设置证实该宏确实传入相应 target/configuration；缺失、拼写不符或未生效均是 `Failed`，修复并重跑 Pods/构建及复核，不能报告为通过。若仅通过 PHPicker/PhotosPicker/等价系统照片选择器取得用户所选项目且未调用 PhotoKit 整库 API，则明确记录该证据，不添加不必要的照片库读取用途键或宏。`PERMISSION_CAMERA=1`、`PERMISSION_MICROPHONE=1` 同样按实际插件和 API 需要核验，不凭固定模板盲目启用。
2. 对每个实际发布 target 核验最终 `Info.plist` 和解析后设置：真实使用的摄像机/麦克风/PhotoKit/仅添加能力具备对应且非空的英文用途说明；未使用的权限键与宏没有遗留。使用 `plutil -lint` 或等价工具检查 plist。Podfile 改动失败时记录失败原因但仍继续 `pod install` 和 iOS 构建尝试；失败的宏及受影响权限路径保持 `Failed`/`Not verified`，不得因“构建仍继续”而标为通过。
3. 进行 ATT 清理：审阅 app 源码、依赖锁文件/解析依赖、插件注册、WebView 脚本、原生 target 链接设置、最终 `Info.plist` 与 `PrivacyInfo.xcprivacy`。若没有 Apple 定义的追踪行为，删除 `AppTrackingTransparency` import/依赖/API/请求、`NSUserTrackingUsageDescription`、IDFA 读取及不需要的追踪 SDK；最终源码和配置扫描不得有可执行 ATT 请求或追踪初始化残留，tracking manifest 标记与域名须如实为关闭/空。用 `rg`、Xcode build settings、依赖清单及可用二进制符号检查留证，单纯没有出现授权弹窗不算清理通过。
4. 如核验发现实际追踪，不能隐瞒或只删除弹窗。优先移除/禁用追踪 SDK 和行为，再从依赖、代码、隐私清单、网络行为复核无追踪；若追踪无法移除，则保留合规所需 ATT 并如实标记该项 `Blocked`/`Not verified`，不能声称 ATT 已去除或无追踪。
5. 将证据、所查 API/插件版本、宏应否启用及解析值、最终用途键、ATT/追踪扫描结果、构建命令/产物和剩余缺口记录到 `.codex-work/quality.md`。宏配置失败不阻止 CocoaPods/iOS 打包尝试，但缺失必需宏、无依据的权限或未经验证的权限路径不得标 `Verified`。

对权限分支与状态机使用可注入服务进行自动化验证；摄像机采集、录音质量、音频会话及真实系统弹窗应在可用 iPhone 真机上完成验收，记录 iPhone 机型、iOS 版本、实际 ID、构建版本与证据。iPhone 模拟器不具备对应硬件时，完成界面、服务边界与错误回退检查，将尚未完成的硬件验证标记 `Blocked`，继续其他任务；不得使用假媒体冒充采集成功，不得使用其他设备替代 iPhone，也不得将强制功能标为本次不需要。硬件关键路径未实测时不声称全部验证或正式上架就绪。

### 11.7 iOS 隐私与协议一致性核验

- 对每个发布 target 的最终 `Info.plist` 与实际访问 API 建立映射，检查必需用途字符串、系统选择器最小权限、错误处理和插件自动请求行为；使用 `plutil -lint` 等检查实际 plist 文件，不能只检查源模板。
- 按真实 API 与 SDK 使用维护 `PrivacyInfo.xcprivacy`，核对 `NSPrivacyTracking`、`NSPrivacyTrackingDomains`、`NSPrivacyCollectedDataTypes` 和 `NSPrivacyAccessedAPITypes` 的适用项、类型与值；Required Reason API 只能填写 Apple 允许且符合实际用途的理由。隐私清单不代替 `Info.plist` 权限字符串、ATT 或用户协议。
- 对照 Apple 当前第三方 SDK 清单检查需要的隐私清单与签名；核验归档包含正确 target 的清单，并检查 Xcode 可生成的聚合隐私报告及可用的归档验证结果。未生成 Archive 时明确未验证，不以源文件存在视为通过。

### 11.8 性能与资源预算核验

- 规划时为目标 iPhone 与核心任务记录启动、滚动、图片解码、视频首帧、导入/保存响应、内存和安装体积的实际预算；通过 iPhone 真机与实际构建测量调整，不臆造统一性能结论，不用其他设备性能作为 iPhone 的通过依据。第 7.1、7.6、7.7 节的等待预算仍为行为上限，不是性能通过证据。
- 列表按需构建，缩略图按展示尺寸解码，大图/批量导入使用有界处理；设置图片缓存、派生文件与媒体控制器的上限，不同时为整库预加载视频。资源筛选与压缩不能以模糊、裁切错误或不可读文本换取体积指标。
- 核验连续滚动、打开/返回详情、反复播放、相机/录音进出及大文件导入，检查帧耗时、可观察卡顿、内存增长和设备资源释放；稳定复现场景先定位原因，再修复并比较同场景结果。
- 使用适当的 profile/release 构建和可用性能工具记录证据，说明设备、模式、样本与限制；Debug 模式可以检查行为和布局，不作为发布性能结论。工具或真机缺失时报告未验证范围，继续结构与资源检查，不编造帧率、内存或启动耗时。

### 11.9 交付前质量复核与耗时对照

首个可运行版本、构建通过、最低轮次完成和投入比例达标均不是交付终点。完成主要实现与精修后，在宣布完成前执行一次单独的成果复核；直接查看当前文件、实际运行结果与最终资源，不能只重读智能体自己的完成总结。将结论写入项目根目录 `.codex-work/quality.md` 或其他非公开质量记录，并在最终报告引用；优先链接已有证据，不重复制作大份报告，不把该记录或任何审计材料加入 `aduit/`、公开站点或 App Bundle。

1. **范围与真实深度**：从已确认方案和后续用户指令反向核对全部必做需求，区分“已实现”“实际验证通过”和“尚未验证”。检查第 4.2 节的有效内容数量、至少三个不同结果的完整任务、每个已选 Tab 与二级页面；所有可见主动作均有真实结果，没有以空页面、静态卡片、假按钮或示例媒体替代真实功能。摄像机、相册、麦克风分别核对采集/导入、预览/试听、保存、重新访问、删除与异常回退。
2. **逐屏视觉与资源**：使用页面/状态检查矩阵列出所有 App 可控制页面、适用状态及 iPhone 尺寸/方向；核对当前 iPhone 构建的截图、实际交互与三轮修改证据。按第 6.7 节覆盖主题、尺寸与无障碍场景，并按第 6.8 节核对 Emoji 的真实展示、主题匹配、布局与读出，不要求穷举无意义的组合。按第 2.5、6.3–6.5 节核对 Logo 鲜艳色块、取色记录、主题令牌及 App/About 实际可见渐变，品牌色一致且文字/控件可读，不以配置里存在渐变代替页面已显示；再按第 6.9 节核对 Logo 结构/材质/光影自然度及明显生成瑕疵，并实际检查承载主题内容的主要列表包含有依据的混合尺寸、图片裁切焦点正确、视觉与 VoiceOver 顺序一致，同时保证 Settings/协议/权限等扫描列表保持整齐。实际查看最终图片与视频，核对两轮资源调整、许可、原始内容数量、重复分布、裁切、清晰度、封面和播放；按第 6.6、11.4 节核对各页与状态的实际显示文字、图片嵌字、视频字幕及无障碍文案，没有已知中文或内部术语残留。几张首页截图或清单中的文件数不能代表全部页面与素材已验收。最终 AppListing 生成位于本复核之后，先核对已有 About 页面与 Logo 的品牌关系，最终页面配色、文案及文件转移按第 12.1 节在最后一步复验。
3. **工程与平台证据**：核对当前产物的静态分析、适用测试、可用 iOS iPhone 构建与运行、离线/重启/返回/清除本地数据行为及第 11.8 节性能证据；新改动后原结果不再适用时补充针对性复验。按第 0.10、11.6、11.7 节对照 iPhone-only 配置实际生效值、明确的 iPhone 运行目标、构建产物 `UIDeviceFamily = [1]`、真实媒体结果、最终权限配置、必需的 `PERMISSION_PHOTOS=1` 宏是否在解析设置中生效、ATT/追踪残留清理、隐私清单、协议与数据流；源码存在、插件安装或一次编译成功不能替代这些检查。证据标明对应版本、命令/场景、实际 iPhone 机型/iOS/ID 或静态检查环境、结果与路径，未生成产物或未实测的项据实标注。
4. **缺陷与完成条件**：已知崩溃、数据丢失、核心动作失效、三项媒体缺失、隐私/权限错误、明显遮挡溢出、不可读文字和无理由重复素材，均须修复并核对受影响范围后才可声称相应质量项通过。记录其他残余问题及其具体影响，不用模糊的“基本完成”掩盖缺陷。外部设备、服务或凭据缺失时沿用第 0.8 节状态，交付已完成的本地产物和准确缺口，不能把未验证变为通过；同样不能为等外部条件阻断所有独立工作。
5. **耗时与历史范围对照**：当本次制作耗时明显少于用户给出的同类历史参考（例如从约 8 小时降至约 3 小时）时，复核功能/内容范围、UI 覆盖、精修实际修改、独立素材、测试和硬件验证是否减少。只有具备真实记录时，才说明复用、并发或减少等待带来的节省；无法确认原因时明确注明，不编造效率提升。发现可执行工作被省略时立即补做；范围不同或验证尚缺时明确说明，不能仅用“模型更快”或“已完成三轮”解释差距。没有可信计时则记录耗时未核实，不伪造实际工时。

资源复核还必须逐项执行第 10.6 节：核对照片需求表、实际网站搜索与来源页、许可、文件和当前构建截图，报告独立真实照片数量/计划数量与每个展示位的覆盖。没有实际搜索网站、照片仅在磁盘未显示、使用 AI 拟真图/插画替代、许可不明或覆盖缺失时，相应照片要求不能通过；缺少 API Key 本身不能证明公开网页途径不可用。有限尝试后的真实外部阻断按要求记录并继续独立工作，不把这个回退当成照片质量已完成。

逐页图文深度另按第 6.10 节复核：将第 3.2 节所有页面/流程行与实际路由及状态对齐，核对各自的信息模块、非纯文字表达、真实素材/组件、点击结果与当前构建证据。覆盖详情、搜索、工具、Settings、媒体、空/失败态和自有协议页面，不能以首页精修或照片总数代替全页面完成；连续文字堆叠、假波形/统计、同图反复铺满或无关装饰须修正。缺乏运行证据的页面保持 `Not verified`，不把新增规划列当作实现证明；沿用既有质量矩阵记录结果，不额外增加用户确认或公开交付文件。
