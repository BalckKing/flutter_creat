#### 最终 iOS 权限双向校验（最后执行）

全部实现、AppListing/About、协议回接、Review Remarks、目录整理、图片显示与依赖清理完成后，最终报告前执行。以当前实际可达功能、代码调用、依赖版本和最终构建为准，从功能正查所需配置，再从每条配置反查真实用途；验收目标是“该有的完整有效，不该有的全部移除”，不是固定添加三种媒体权限。

1. **实际能力清单**：遍历全部页面、操作、服务、原生代码、插件及其原生实现，建立 `功能/入口 → API → 插件及版本 → 是否需授权 → Info.plist/本地化用途键 → Podfile 宏 → entitlement/capability → 隐私清单 → 触发/拒绝行为 → 证据` 表。相机、相册、录音只是条件项；定位、通知等其他实际使用的受保护能力也须纳入。用户已选但尚未实现的功能记录为缺失，不能通过删除其权限掩盖；未选能力记录不适用，允许三项媒体或全部受保护能力均不存在。
2. **补齐必需项并证实生效**：每个实际需要系统授权的 API 必须有正确、非空且符合真实主题用途的英文说明、请求/状态处理及所需配置。按具体 API 区分 `NSCameraUsageDescription`、`NSMicrophoneUsageDescription`、`NSPhotoLibraryUsageDescription` 和 `NSPhotoLibraryAddUsageDescription`，不套用全部用途键。使用 `permission_handler_apple` 且实际调用 PhotoKit library/read-write API 时启用 `PERMISSION_PHOTOS=1`；`PERMISSION_CAMERA=1`、`PERMISSION_MICROPHONE=1` 也只在当前插件/API 需要时启用。必须核对 Pods 解析后的宏与编译设置，例如 `Pods-Runner.*.xcconfig`、`xcodebuild -showBuildSettings` 或等价证据，并记录每个实际宏的解析值；缺失、拼写错误、配置错 target 或未生效均为 `Failed`。保留既有 `post_install` 与继承配置，修复后重跑 Pods/构建和受影响路径。
3. **移除无用途项**：逐条反查最终用途键及 `InfoPlist.strings`、启用宏、授权请求/状态/设置引导、插件注册/依赖、entitlements、capabilities、后台模式及隐私声明。仅为不存在功能准备的内容必须删除，不能保留“以后可能用到”的相机/照片/麦克风权限。确需保留的插件应关闭未用受保护功能的编译开关；移除无用宏，插件必须显式禁用时只保留正确的 `=0` 设置，不能误启用。若未用 API 仍被插件默认链接，裁剪、禁用或更换/移除该组件并重验，不能编造用途字符串消除构建检查。保留其他实际功能与依赖依法必需的隐私清单和 Required Reason API 理由，不把所有声明一律删除。
4. **核对无需授权的场景**：仅用 PHPicker/PhotosPicker/等价系统照片选择器取得选中项目且未调用 PhotoKit 整库 API 时，不额外请求整库授权或添加其用途键/启用宏。显示随包图片不需要照片库权限，播放音频不需要麦克风，拍静态照片不自动需要麦克风；按实际插件实现核实。无摄像机、相册、录音功能且没有其他受保护 API 时，最终不存在相关用途键、请求、启用宏或专用权限插件，并以代码、依赖和产物证据确认；不能靠首次启动没有弹窗就判定无多余权限。
5. **追踪保持移除**：按第 0.7 节检查源码、解析依赖/插件注册、原生链接、脚本、实际数据流、最终 `Info.plist` 与 `PrivacyInfo.xcprivacy`，清除 `AppTrackingTransparency` 请求/链接、`ATTrackingManager`/`requestTrackingAuthorization`、`NSUserTrackingUsageDescription`、IDFA 读取、启用的追踪权限宏和追踪初始化。该项只确认移除，不创建 ATT 授权入口、弹窗或四状态测试。仍追踪的组件须禁用、移除或替换，不恢复该流程作为回退；未解决证据如实记录。
6. **检查最终产物与实际行为**：核验所有发布 target 的解析配置及可用 `.app`/Archive 内最终 plist、entitlements、嵌入清单和链接结果，执行 `plutil -lint` 等有效性检查，不只搜索模板。用当前 iPhone 构建走查每个实际受保护功能的首次触发、允许、拒绝/受限、取消及恢复；系统选择器按其实际分支检查。Welcome/Initialization 不集中索权，无权限功能的应用不出现无关授权弹窗。缺真机/系统状态/产物证据时标 `Blocked`/`Not verified`，不编造验证结果，也不要求为未选功能做硬件测试。
7. **材料与重建复核**：将实际权限/数据流与 `aduit/intro.md`、`aduit/review/remarks.md`、公开隐私政策及可用商店隐私答案逐项比对，去除不存在功能和多余权限的声明，补齐实际用途；保持原始四个 URL 不变。配置、依赖或资源变化后重新解析、构建并复测受影响路径，按第 10.7.1 节刷新最终构建上受影响图片、图标与启动证据，最后再次核对产物权限矩阵后才交付；配置未改动且证据仍有效时不机械重复构建。
8. **记录与判定**：将功能范围、每项 `Required/Present/Removed/Not applicable`、具体键/宏及解析值、裁剪/移除路径、构建与设备版本、运行结果和残余缺口记录到 `.codex-work/ios-permissions.md`，并从 `.codex-work/quality.md` 链接；记录不得进入 `aduit/` 或 App bundle。Podfile 宏写入/校验失败仍须保留语法有效版本并继续 `pod install` 和 iOS 打包尝试，但与权限运行结果分开报告。遗漏必需权限、残留无用途权限、实际功能不可用或证据不足均不得标记 `Verified`；只将受影响项如实标记，继续其他可执行任务。


仅对实际存在的权限分支与状态机使用可注入服务进行自动化验证；实际选用的摄像机采集、录音质量、音频会话及真实系统弹窗应在可用 iPhone 真机上完成验收，记录 iPhone 机型、iOS 版本、实际 ID、构建版本与证据。iPhone 模拟器不具备对应硬件时，完成界面、服务边界与错误回退检查，将尚未完成的硬件验证标记 `Blocked`，继续其他任务；不得使用假媒体冒充采集成功，不得使用其他设备替代 iPhone，也不得将已选功能因缺硬件改为本次不需要；未选功能没有对应硬件验证义务。实际硬件关键路径未实测时不声称全部验证或正式上架就绪。

3. **工程与平台证据**：核对当前产物的静态分析、适用测试、可用 iOS iPhone 构建与运行、离线/重启/返回/清除本地数据行为及第 11.8 节完整视觉与功能证据；新改动后原结果不再适用时补充针对性复验。按第 0.10、11.6、11.7 节对照 iPhone-only 配置实际生效值、明确的 iPhone 运行目标、构建产物 `UIDeviceFamily = [1]`、实际存在的媒体结果、按功能裁剪后的最终权限配置，以及实际 API/插件确需时 `PERMISSION_PHOTOS=1` 宏是否在解析设置中生效、追踪组件残留清理、隐私清单、协议与数据流；源码存在、插件安装或一次编译成功不能替代这些检查。证据标明对应版本、命令/场景、实际 iPhone 机型/iOS/ID 或静态检查环境、结果与路径，未生成产物或未实测的项据实标注。
4. **缺陷与完成条件**：已知崩溃、数据丢失、核心动作失效、已选必做功能缺失、隐私/权限错误、明显遮挡溢出、不可读文字和无理由重复素材，均须修复并核对受影响范围后才可声称相应质量项通过。记录其他残余问题及其具体影响，不用模糊的“基本完成”掩盖缺陷。外部设备、服务或凭据缺失时沿用第 0.8 节状态，交付已完成的本地产物和准确缺口，不能把未验证变为通过；同样不能为等外部条件阻断所有独立工作。
5. **耗时与历史范围对照**：当本次制作耗时明显少于用户给出的同类历史参考（例如从约 8 小时降至约 3 小时）时，复核功能/内容范围、UI 覆盖、精修实际修改、独立素材、测试和硬件验证是否减少。只有具备真实记录时，才说明复用、并发或减少等待带来的节省；无法确认原因时明确注明，不编造效率提升。发现可执行工作被省略时立即补做；范围不同或验证尚缺时明确说明，不能仅用“模型更快”或“已完成三轮”解释差距。没有可信计时则记录耗时未核实，不伪造实际工时。

资源复核还必须逐项执行第 10.6 节：核对照片需求表、实际网站搜索与来源页、许可、文件和当前构建截图，报告独立真实照片数量/计划数量与每个展示位的覆盖。没有实际搜索网站、照片仅在磁盘未显示、使用 AI 拟真图/插画替代、许可不明或覆盖缺失时，相应照片要求不能通过；缺少 API Key 本身不能证明公开网页途径不可用。有限尝试后的真实外部阻断按要求记录并继续独立工作，不把这个回退当成照片质量已完成。

逐页图文深度另按第 6.10 节复核：将第 3.2 节所有页面/流程行与实际路由及状态对齐，核对各自的信息模块、非纯文字表达、真实素材/组件、点击结果与当前构建证据。覆盖详情、搜索、工具、Settings、媒体、空/失败态和自有协议页面，不能以首页精修或照片总数代替全页面完成；连续文字堆叠、假波形/统计、同图反复铺满或无关装饰须修正。缺乏运行证据的页面保持 `Not verified`，不把新增规划列当作实现证明；沿用既有质量矩阵记录结果，不额外增加用户确认或公开交付文件。

本复核步骤的“完成”表示适用检查已经执行、可修复缺陷已经整改或复验、外部阻断已经留下证据；它不要求把不可用的网络素材写成通过。照片或正式 Logo 仍为 `Blocked`/`Not verified` 时，继续进入第 12.1 节的远程 `ios-app-listing` AppListing/About 生成、第 12.2 节 Review Remarks 和目录整理；若远程 checkout 本身不可用，则仅将该材料阶段标为 `Blocked`，不得以资料包副本或手写页面替代。最终报告分别列出媒体缺口、远程技能状态与本地产物状态，不因照片检查未通过而提前结束工作流。

复核后只针对新发现问题及其影响范围整改和复验，保留仍有效的证据。全过程按已确认授权自主完成，不新增用户审批。按第 0.2.3 节不设工程总制作时长和精修轮次上限，制作 3 小时或 8 小时都不能自动判定合格；完成条件由需求覆盖、实际视觉与资源质量、功能结果及验证证据决定。先关闭功能与平台故障，再处理逐页观察到且可执行的细节改善，不把对齐、间距、文字拥挤、图片裁切、图标/Emoji 不一致、动效衔接等问题一律留到以后；实际修改后复验仍有具体缺陷就继续。所有适用门槛通过、已发现可修复问题关闭且当前复核没有新的具体问题时，完成后续材料、最终图片与权限步骤再交付，不为了主观“完美”无限检查或新增范围，不空等凑工时；客观受阻保持真实状态，继续独立工作，不宣称全部通过。

完成 AppListing/About、协议链接、Review Remarks 和最终交付目录整理后，仍须按第 10.7 节另做一次最终图片加载检查，作为最终 iOS 权限校验之前的显示验收步骤。此时必须检查最终构建中每个实际图片展示位是否正确加载、内容是否贴题、不同列表尺寸下主体是否完整可见、主要内容列表是否呈现合理的尺寸层级、Logo 是否有明显生成瑕疵，以及是否存在占位图或破损图；显示异常先按第 10.7.1 节定位并修正引用/打包/解码/布局原因，只有确认照片文件缺失、损坏、错题或许可不合格时才从第 16 节列出的第三方网站取得许可明确的主题图片、替换接入并重建复验。该轮检查需有当前 iPhone 页面截图和离线随包加载结果；没有 iPhone 运行证据就标记 `Blocked`/`Not verified`，不可报告整体最终检查通过。 以 `.codex-work/image-load-audit.json` 逐项对照最终构建的真实成功帧、可见截图和离线结果，禁止把 fallback 当成功。其后权限配置检查若改动配置并重建，旧显示证据失效，须对受影响范围重新执行第 10.7.1 节后才报告最终结果。

上述最终图片加载检查完成后、最终报告之前，再执行第 11.6 节“最终 iOS 权限双向校验”，作为最后一项平台配置验收；既检查必需项完整，也检查无关项清零。权限宏必须按实际 API 判断并用解析后的 Pods 编译设置验证；凡需要 PhotoKit 整库读取而缺少 `PERMISSION_PHOTOS=1` 的结果均为失败，不得留作警告；系统照片选择器独立导入不要求该宏。按第 0.7 节从最终代码、依赖/链接设置、Info.plist 和隐私清单中移除追踪组件及授权残留，不创建相关授权测试。宏配置失败仍须继续 Pods/构建尝试，但验收报告须单独保留失败状态，不将其掩盖为整体通过。

### 11.10 Apple 4.3/5.6 审核风险专项

在生成 AppListing、About 和 Review Remarks 后、最终报告前执行一次完整专项，并将结果写入 `.codex-work/app-review-risk.md`。专项必须检查：

1. 产品身份：Bundle ID、显示名称、App Store Connect 记录、截图、Intro、About、Support 与 Remarks 是否描述同一个真实产品；是否误生成地区/品牌/主题克隆或多个应用记录。
2. 实质差异化：对照 `.codex-work/differentiation-brief.md`，逐项确认目标问题、领域模型、主题专属核心动作、任务顺序、首个有用结果和可回访成果都在当前代码、数据和 iPhone 截图中出现。只换 Logo、配色、图片、字体、文案、卡片尺寸或导航外壳时判定为 `4.3 risk: Failed`。
3. 诚实运行：扫描隐藏审核模式、远程动态换功能、虚假账号/计费/服务/权限、假按钮、假统计、死链接、白屏、崩溃、占位图、数据丢失和核心流程失败；普通用户路径与审核路径必须一致。
4. 评价与发现：扫描自定义评分弹窗、诱导或激励好评、非 Apple 评价接口、搜索/榜单/引荐/安装量操纵和垃圾营销内容。发现任一项即阻止发布结论。
5. 材料事实：Intro、About、Support、Remarks、截图和 App Store 字段只能使用已核实功能、设备、服务、地区、权限和开发者信息；未知信息不得用猜测补齐，`Not verified` 不得写成完成。

核心失败项即使不影响其他本地产物，也必须标记 `Release readiness: Blocked`，并列出证据、影响范围、整改动作和复验结果。只有全部适用项有证据且没有关键失败，才能标记 `Release readiness: Ready for submission`。
