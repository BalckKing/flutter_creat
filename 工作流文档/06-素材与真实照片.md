## 10. 素材、许可和凭据规则

### 10.1 资源清单

维护 `assets/media/resource_manifest.json`。每个随包资源记录：

`provider`、`providerAssetId`、`mediaType`、`localAssetPath`、`sourcePageUrl`、`mediaUrl`、`creator`、`attribution`、`license`、`licenseUrl`、`query`、`retrievedAt`、`sha256`、`dimensions`、`duration`、`reviewStatus` 和 `consumerScreens`。公开或随包 URL 不含密钥、临时签名或私有访问令牌；下载地址无法安全持久化时留空并说明原因，保留非敏感来源页与资源 ID，不能用虚构 URL 补字段。

使用 `provider + providerAssetId + sha256` 去重。文件路径、MIME、扩展名和清单值必须一致。

另记录 `sourceIdentity`、`derivedFrom`、`visualDuplicateGroup`、`posterAssetId`、`consumerPlacements` 与 `reuseReason`，用于追踪原始内容、裁切/转码派生版本、近似重复组、视频封面及每次实际展示位置；视频片段同时记录原片 ID 与时间范围。没有适用值时明确标记原因，不能编造供应商 ID、许可或检测结果。用户私有拍摄/导入/录音仍只进入独立的私有媒体索引，不进入此公开资源清单。

另记录 `contentKind`（`photograph`、`video`、`illustration`、`icon` 等）、`captureOrigin`（`real_capture`、`generated` 或 `unverified`）、`subject`、`requirementIds` 与 `searchEvidenceId`。真实照片分类须有来源信息与实际查看依据，不能将网站收录的 AI 图、插画或来源不明图片自动归为真实摄影。来源页没有供应商 ID 时使用可追溯的来源标识并说明，不能为了填字段捏造 ID。照片需求与最终文件、页面消费位置必须能相互追溯。

### 10.2 仅开发期访问第三方供应商

Pexels 和 Pixabay 仅用于开发/CI 发现资源，已发布 iOS App 不得调用它们的搜索、刷新、埋点或媒体 API。

曾经出现在文档中的真实凭据视为已暴露，不继续使用或传播。先核实其属于本项目及受影响消费者，只在已有授权与供应商管理能力均可用时撤销和轮换对应凭据，不撤销无关或范围不明的共享密钥；无法完成时记录该项 `Blocked`，使用无需该凭据的素材方案继续，不以轮换阻断整个项目。真实密钥不得写入源码、Dart defines、plist、xcconfig、assets、fixture、共享 URL、日志、崩溃报告或二进制。

只能使用未跟踪的环境变量或 CI Secret：

```text
PEXELS_API_KEY=<configure-locally-never-commit>
PIXABAY_API_KEY=<configure-locally-never-commit>
```

采集工具必须使用 HTTPS 主机白名单、有限重定向、MIME 和文件签名校验、文件大小限制、安全文件名、SHA-256、缓存、去重和许可核对。Logo 开发生成入口 http://stargate.local:3100/image 是本规格明确允许的本地 HTTP 服务，仅用于开发生成，不因上述 HTTPS 规则被拒绝，也不进入已发布 App 的运行时请求。供应商必须通过查询参数接收凭据时，仅在采集工具内即时构造请求并对日志脱敏，不写入文档或公开链接。遵守供应商限流和 `Retry-After`；认证错误和参数错误不得自动重试。

### 10.3 品牌资源

`/image` 返回 HTML 属于生成界面的正常响应，不能仅凭这次 GET 就判断生图服务失败。使用可用浏览器打开该界面，读取当前实际模型/连接配置并提交生成，再从结果中的图片下载、`url`、`dataUrl` 或 `b64_json` 取得图片字节。确需调用接口时，必须以该界面当前实际请求为依据，不把页面路径当接口、不猜测 API 路径或模型，也不从网页脚本示例推断已配置的服务。沿用已有会话授权，不输出凭据；没有可用配置/操作工具时记录具体限制后走有界回退。图片先下载至临时文件，成功解码并完成规格核验后才替换正式 Logo；错误响应不能覆盖已有有效图片。

下载/导出成品按第 2.5 节先命名为 `<用户提供的项目名称>.png`；验收后以该名称导入目标工程 `assets/`，再改名为 `logo.png`。在 `.codex-work/brand-assets.md` 记录实际下载/导出路径 → 工程内项目名路径 → 最终 `assets/logo.png`，关联同一图片的哈希与必要后处理；不把项目名版本额外声明为运行资源。正式取色、封面、图标和 Listing 继续从 `assets/logo.png` 派生，文件名要求不改变 Logo 图像无文字的要求。

Logo 的视觉验收遵循第 2.5 节：根据主题元素在模拟现实、手绘、油画、艺术四种画风中选择并实际核对，记录所选主画风及元素依据；模拟现实须结构、比例、材质与光影可信，手绘须线条精细且有层次，油画须笔触细腻、颜料层次丰富且主体清晰，艺术画风须表现手法、构图和色彩语言明确并保持主题辨识。实际查看原尺寸与图标尺寸，按所选画风检查造型与视觉逻辑、材质和光影的协调性，至少三种鲜明颜色与多色平滑渐变真实可见，小尺寸仍可识别；不能呈现冷峻、灰暗或近乎单色的整体色调。几何色块堆叠拼贴、粗糙简笔、简陋通用图案、禁止 3D，以及融化/断裂细节、重复纹理、随机碎片、伪文字、明显 AI 生成感、无依据塑料感或强光效等不得通过。Logo 是品牌图形，允许与画风一致的笔触和艺术化提炼，不要求照片写实；文件规格与取色记录正确不能代替视觉验收。

实际生成失败或最终图片无效时，先执行第 2.5 节的模型参数切换：从当前已配置的可用图像模型中选择支持相同规格的替代项，核对页面选择值或真实请求的 `model` 字段已经改变，再在原预算内提交。保留高质量、单张与 `1024x1024` 设置并重新验收输出；只改提示词不算切换模型。切换仍失败或无可用替代模型时再记录正式 Logo 阻断，继续本地页面、Listing 和 Remarks。

正式品牌使用由 http://stargate.local:3100/image 以高质量、每次 1 张生成并经过必要本地后处理的 `assets/logo.png` 作为唯一源。验证色彩鲜艳、背景满幅且无白底、主题意象、完全不含文字或项目名称、比例、无 Alpha 通道、由真实色块定制的主题色/渐变及其对比度、AppIcon 尺寸、启动资源、Loading、Entry 和平台引用；App 内展示 Logo 时同样使用圆角容器。Logo 必须为 `1024x1024` RGB PNG，由智能体自主校验，不等待用户审批。正常路径的首次 Logo 校验、色块提取和主题定制是 App 开发前置步骤；只有第 2.5 节真实失败回退时才先做暂定品牌的本地开发，正式品牌发布仍依赖合格 Logo。最终 AppListing 的生成与 About 配色复验在第 12.1 节完成，随后按第 12.2 节生成英文审核备注。

主题色落地必须留下证据链：Logo 原始 HEX → Flutter 主题令牌 → 实际页面/组件 → iPhone 截图。至少三个实际页面/组件消费 Logo 派生色，覆盖主页面、真实操作页和至少一个其他 App 页面；将源码引用与截图位置记入 `.codex-work/brand-palette.md`，不能只以已定义色值或 About 页着色作为落地证明。

### 10.4 Logo 实际替换、品牌封面与图标核验

生成或下载 Logo 不等于完成替换。工程建立后必须实际更新引用、派生资源与构建配置；交付前再核验最终构建，不能仅保存 `assets/logo.png` 或只替换其中一个页面。所有项目操作均限定在当前目标工程内。

本节的“品牌封面”指代表当前 App 身份的图片，包括 iPhone 桌面 App 图标、启动品牌图、Loading/Entry 欢迎页封面，以及现有 App/About 品牌展示位；逐项记录实际路径和用途。内容卡片、分类、文章或视频的实物/实景封面仍按第 10.5、10.6 节使用相关第三方素材，不得全部换成 Logo。由正式 Logo 派生品牌封面属于品牌后处理，不属于另用生图服务生成内容图片。

1. **列出全部替换位置**：扫描旧 Logo、默认 Flutter 图标、开发临时品牌图、旧封面及其引用，结合实际页面查看，建立 `.codex-work/brand-assets.md` 映射表，记录展示位置、旧资源/引用、最终源/派生文件、消费组件或平台配置及验收证据。检查 Dart 页面、`pubspec.yaml`、iOS 资源目录、`Contents.json`、启动 storyboard/配置和 About HTML，不能只按文件名中是否含 logo 搜索。
2. **接入正式品牌源与封面**：直接展示 Logo 的位置统一使用 `assets/logo.png`；Loading/Entry 的品牌封面须实际呈现本次 Logo。现有横向或竖向品牌封面需要适配时，从该源图派生并以已提取品牌渐变补齐背景，保持主体完整、不拉伸、不裁掉关键图形；派生文件及生成关系记入映射表，更新资源声明和页面真实引用。已有品牌展示位逐项替换，不为凑数新增无关页面，也不以换背景色或改文件名冒充换图。
3. **复验唯一品牌源**：校验 `assets/logo.png` 为 `1024x1024`、`image/png`、RGB 且无 Alpha 通道/透明度数据，并按第 2.5 节查看实际画质、鲜明渐变、满幅背景与无文字图形；记录源文件 SHA-256。配色与派生资源均追溯到该文件，不能用预设主题色反向改图后声称已取色。
4. **实际生成并启用 iOS 图标**：从正式 Logo 导出当前 Xcode 所需的 iPhone/App Store 图标，写入 `ios/Runner/Assets.xcassets/AppIcon.appiconset` 并更新 `Contents.json`；检查实际构建配置选中的 AppIcon 集合。使用项目已有且适用的图标生成工具时须实际执行并核对产物，仅添加工具配置不算完成。同步并实际更新 iOS 原生 `LaunchScreen.storyboard`/对应资源：静态显示放大的 Logo、独立 `PRYRIN` 字标、与 Flutter Loading 一致的品牌定位文案及品牌装饰线；不得在原生启动页加入动画、进度条或伪造加载步骤，不得把 `PRYRIN` 或定位文案合并进 Logo 图片。不生成其他设备或平台的图标、样机图与截图。
5. **同步 About 的实际图片**：最终生成 AppListing 并整理为 `aduit/` 后，重新将正式 `assets/logo.png` 同步为 `aduit/site/img/logo.png`，比较文件哈希，修正四个 HTML 页面的 Logo/品牌封面引用并实际查看本地渲染。站点品牌封面通过该图片与内联样式实现，继续保持 `site/img/` 只有 `logo.png`，不新增 cover 文件或其他白名单外资源；生成器不得把旧 AppIcon 或旧品牌图覆盖回来。
6. **检查实际构建与显示**：重新构建并安装当前 iPhone 版本，检查构建资源、桌面 App 图标、iOS 静态冷启动页（Logo 尺寸、`PRYRIN`、定位文案、装饰线）、Flutter Loading 的真实步骤/百分比/进度条、减少动态状态、Entry 封面及其他现有品牌位置；保存对应截图。原生图标和启动资源不能仅凭热重载验收；若仍显示旧图，先核对实际源、构建目标、资源集及安装版本，再进行有针对性的重新导出/构建与复验，不自动卸载含用户数据的 App，也不盲目反复清理。
7. **清理旧引用并完成交付核验**：确认新资源已实际使用后，移出不再使用的旧品牌文件；必要恢复副本保存在 `.codex-work/`，不混入运行资源或发布包。重新扫描源码、资源声明与构建产物，并对照映射表逐项核验，不误删仍使用的内容封面或必要派生图标。最后的第 10.7 节必须再次检查品牌封面与平台图标；有旧图、默认图标或临时封面残留时修复并复验，不标记完成。
8. **记录真实结果**：报告生成参数/时间、提示词、源哈希、派生关系、主题映射、实际替换文件/引用、构建版本、桌面图标与封面截图。已有品牌展示位不得以“文件已存在”标为 `Verified`；没有对应位置时说明事实，缺少 iPhone 运行环境时将显示验证记为 `Blocked`/`Not verified`，继续可执行的文件与配置校验，不改用其他设备。

### 10.5 图片、视频多样性与资源精修

图片和视频是内容与视觉质量的一部分，必须投入充分的实际筛选、替换与适配工作，优先为不同内容、分类和主页面使用不同的真实素材。按以下规则验收，不靠重复素材、无关视频或大量下载凑丰富度：

1. **先分配再采集**：根据用户创意与页面模块建立资源需求表，记录展示用途、主题对象、构图/色调、比例、最低清晰度、计划独立素材数量和体积预算；按第 10.6 节明确需要真实照片的展示位和跨网站搜索计划。优先区分各主 Tab、分类与主要内容的封面和重点展示位；实际包含视频的页面须有与其内容相符的独立片段。没有视频用途的产品不强加视频模块，三项媒体必做能力仍保留。
2. **检查完全重复与近似重复**：联合检查原始来源 ID、原片/派生关系、文件 SHA-256，并通过接触表逐张比较图片与视频封面；对视频抽取多个代表帧并实际播放检查。工具可用时补充感知哈希或相似度检查，人工复核候选重复；不可用时继续来源、哈希与视觉核验并记录方法，不伪称已执行算法。不同供应商收录的同一内容也视为重复候选。
3. **禁止伪造独立素材**：同一原图仅改文件名、尺寸、裁剪、滤镜、镜像或压缩仍计作同一来源内容；同一原片的重叠截段、循环拼接、调速、改色或换封面也不能冒充多个独立视频。统计独立素材时按原始内容和确认的视觉重复组计数，不能仅按路径或文件哈希计数。
4. **控制可见复用**：同一首屏、网格、相邻卡片和推荐列表中，不得让不同内容无理由共用同一张图、同一段视频或明显近似封面；主要 Tab 和不同分类的重点展示位优先不重复。复用 Logo/统一图标、同一内容在列表与详情中的一致展示、同一视频的真实封面及有明确语义的复用可以保留，必须注明对应位置和理由。用户自行导入的重复私有媒体不因这些随包资源规则被擅自删除。
5. **逐屏适配与真实播放**：检查图片的主体、来源真实性/主题准确性、实际列表尺寸下的焦点裁切、比例、圆角、清晰度、叠字对比度与浅/深色表现；按第 6.9 节分别查看 `featured`、`standard`、`compact` 尺寸下的关键对象是否完整可辨。不能只在单一原始尺寸或单张接触表中检查；不同尺寸应使用合适比例和裁切，不拉伸、不误导内容，也不借变尺寸反复复用同一图片。视频封面必须来自对应片段或准确表达该片段，核验解码、方向、播放/暂停、首帧、时长、音量、中断和控制器释放。缩略图与原图合理分层，视频按用途压缩与裁切，在质量、安装体积、内存和加载时间之间取得可验证的平衡；主题确需字幕时同步检查字幕。
6. **至少两轮实际调整**：按第 6.7 节执行候选筛选和页面适配两轮，记录淘汰、替换、裁切、封面与压缩决策及前后证据。若复查仍有明显重复、模糊、错题或错误播放，继续修正；不把“轮次已满”视为资源质量通过。
7. **许可和离线保证**：每个最终随包资源有可核对来源、许可、归因和清单引用，发布 App 使用审核后的本地资源。某供应商不可用时按第 10.6 节切换其他合规来源，不直接取消真实照片需求；有限尝试仍失败时仅以明确标记的开发资源继续其他工作，受影响照片要求保持 `Blocked`。不得用版权不明、损坏素材或未标注占位图充当正式成果，不复用一张图填满所有内容，也不把媒体上传给 Stargate。
8. **交付去重结果**：分别报告图片数、视频数、独立来源内容数、展示次数、完全重复组、近似重复组、已替换项、必要复用位置/理由、许可与性能检查结果。重复率的分母和排除项须说明，未执行的检查如实记录；无理由的可见重复必须修正后才能标记对应资源验收 `Verified`。

### 10.6 必须搜索、下载并展示第三方真实照片

本项目必须从第三方网站或其正式资源 API 搜索、核验许可并下载 App 内容区随包展示的真实摄影与主题照片，展示与用户主题有关的实物、人物、场景或实际活动。Stargate `http://stargate.local:3100/image` 只用于生成 Logo，绝不可用于生成或替代 App 内容照片、摄影封面、摄影背景、视频帧或其他本地主题照片；内容照片必须来自第三方来源页并留存许可证据。真实实物图指实际摄影，不是“看起来像照片”的 AI 图、矢量图、Emoji、渐变色块、占位图或 App 界面截图。Logo 与内容照片的来源不可混用；插画、原生图标、代码绘制的矢量符号、装饰图形、主题渐变和 Emoji 可按视觉规格用于界面，不要求从照片网站取得，也不能计作真实照片或替代必需照片。

1. **规划明确照片需求**：将此要求纳入完整思维导图与需求覆盖表。为首页重点展示、内容分类、主要列表/卡片、详情或真实任务示例中需要说明主题对象的位置建立下表，每个选定的主题内容类别必须有贴题的真实照片；Settings、协议和纯操作控件不强加装饰照片。工具型产品也要在适用的主题说明或任务示例中实际展示真实场景，不能把全部照片需求记为 `N/A`，也不为凑图增加无关业务模块。根据内容规模确定独立照片数量并随方案一并确认，不以只下载一张无关图片算完成。

   | 需求 ID | 页面/展示位 | 真实主题对象 | 必需独立照片数量 | 英文查询词/目标网站 | 比例/清晰度/预算 | 许可/归因方式 | 最终资源 ID/实际截图/状态 |
   | --- | --- | --- | --- | --- | --- | --- | --- |
   | `[R-photo]` | `[screen + placement]` | `[actual object or scene]` | `[count based on distinct content]` | `[query + source]` | `[display requirements]` | `[verify from source]` | `[planned before approval; actual evidence after implementation]` |

2. **真正执行网站搜索**：思维导图确认、Logo 优先阶段结束后，根据实际主题对象、用途、拍摄视角和构图生成英语关键词，使用可用搜索工具、浏览器或网站正式 API 查询 Pexels、Pixabay、Unsplash、Wikimedia Commons 等合规来源。选择摄影分类，查看候选来源页与图像本身；搜索结果摘要、首页链接、网站列表或写下查询词不等于完成搜索与素材使用。无关风景、错误物种/商品、带无授权品牌/肖像、明确标注 AI 生成、插画和水印预览均淘汰。图片必须准确对应所展示的内容，不能凭相似外观给无依据的对象贴标签。
3. **没有 API Key 也不能跳过**：只检查凭据是否存在，不输出密钥；可用时使用正式 API，不可用时继续用公开网页发现素材、核对来源页并按网站许可和允许的下载方式取得文件。一个来源失败、限流、无结果或素材不适用时，尝试其他独立来源；宣布网站照片不可取得前至少实际尝试两个独立的合规来源，并记录其查询和可观察结果。403、429、超时、登录墙、验证码或许可证据缺失时切换来源或同主题英语同义查询，不绕过访问限制、不反复请求同一失败地址，不用来源不明的搜索缩略图替代。完全没有可用网络/浏览工具时，记录该能力缺失证据，不虚构已经搜索过两个网站。沿用第 0.6 节的请求与重试上限，失败后继续独立开发，不无限等待。
4. **先核许可，再下载原始文件**：搜索引擎仅用于定位来源，图片公开可见不代表可用于 App。逐项核对源文件的使用许可、App 随包再分发、商业使用、修改与归因条件以及适用肖像/商标限制；不能只引用网站首页的一句“免费”。不允许相应用途或无法确认许可时换候选。取得正式允许下载的图片，检查 MIME/签名、尺寸、文件完整性和哈希，按比例裁切/压缩并保留来源关系；按第 10.1 节登记，许可要求署名时用符合自然英语策略的准确署名兑现义务。
5. **落盘并实际接入 App**：图片保存到 `Target project root/assets/media/<module>/`，更新 `pubspec.yaml`、资源清单、种子数据与页面资源映射，让确认方案中的真实照片展示位真正加载这些文件。不能只把图下载进临时目录、写入 JSON 却不绑定页面，或仍用旧插画/色块覆盖照片；不以运行时外链热链代替随包资源。首装且未拍摄/导入任何内容时，核心内容页面也须可看到主题照片；样例与用户私有媒体保持明确区分。
6. **保存搜索到展示的证据**：在目标工程 `.codex-work/resource-search.md` 或等价非公开记录中保存真实查询词、网站与访问方式、查询/下载时间、候选来源页、许可依据、选用/淘汰原因和失败结果；不存密钥或私有令牌。记录照片需求→来源资源→实际文件→页面/展示位→当前构建截图的映射，使用接触表检查来源与重复。搜索记录不放进 `aduit/`；内容照片也不放进 `aduit/site/img/`，该目录继续只保留 `logo.png`。
7. **在真实页面验收**：对照照片需求表检查已下载的独立真实照片、语义匹配和页面实际消费；按第 10.5 节完成两轮筛选/适配、去重、裁切、清晰度、文字对比度与浅深色检查。在可运行环境中逐项打开主要展示位，保存能看到照片的截图，并断网检查随包加载；模拟器不可用时继续文件、配置和引用核验，但运行展示验证保持 `Blocked`，不得用接触表冒充 App 截图。下载数量、文件存在、图片 Widget 存在或漂亮渐变都不能单独证明通过。
8. **失败回退不取消需求**：有限跨来源尝试后仍无法合法取得的照片，逐项记录缺失数量、失败证据与影响，暂用明确标记的开发资源继续独立功能、UI、测试、AppListing、About 整理与 Review Remarks，不新增素材选择审批。已有许可明确且可追溯第三方来源的真实照片可复用并记录，但新任务仍实际执行本节的网站发现与适配流程，不能只抄旧资源。必需照片缺失、许可不明或仅有插画时，照片需求为 `Blocked` 或 `Failed`，不能通过改写计划、删掉照片展示位或称“原创资源已完成”消除缺口；对应资源质量不得标为 `Verified`。这种阻断只影响照片质量和正式发布就绪判断，不得使本地 `AppListing/`、`aduit/` 或 `aduit/review/remarks.md` 停止生成。
9. **最终报告单列结果**：报告实际搜索的网站/关键词、独立真实照片数量、计划数量与覆盖率、来源/许可、实际页面截图与离线验证，区分真实摄影、AI/插画、图标和用户私有媒体；清楚列出未覆盖展示位。仅有资料包/技能修改时，不声称已为某个 App 搜索下载或替换照片。

### 10.7 所有任务完成后的最终图片加载检查

此项是完整工作流的最后一个执行步骤，必须在 App、资源、AppListing/About、协议 URL 回接、Review Remarks、交付目录清理及此前质量复核均完成后、最终报告之前执行。不得用早期截图、资源清单或构建成功替代最终检查；并按第 6.9 节检查主要主题列表的尺寸层级和各尺寸下的图片焦点，以及最终 Logo 的自然度与明显生成瑕疵。

本次最终检查还必须按第 10.4 节对照品牌映射表复验 iPhone 桌面图标、启动品牌图、Loading/Entry 封面及 App/About 现有品牌位置均使用本次正式 Logo 或其可追溯派生图。品牌残留按第 10.4 节修复；内容照片缺失按下列第三方来源规则修复，两者不能互相替代。

1. 对照当前最终构建的页面/状态矩阵和 `consumerScreens`，逐项打开每个实际图片展示位，等待图片完成解码后确认其正确显示；核对主体、裁切、分辨率、方向、色彩、主题相关性、圆角/遮挡和浅深色表现。在 `featured`、`standard`、`compact` 等实际尺寸下分别确认主题对象没有被裁掉或拉伸，列表大小层级和条目顺序清楚。实际查看当前 iPhone 运行截图或屏幕；截图应能辨认具体图片内容，不以文件存在、Widget/引用存在或缩略图接触表代替运行展示证据。
2. 最终可见状态不得包含占位图、通用空白缩略图、破损图片图标、错误内容、未替换的临时资源或仅用于开发的示意图片。真正的空状态可使用语义合适的图标与文案，但不能把图标/色块记作主题照片，也不能显示图片占位框冒充已加载资源。
3. 对缺失、解码失败、错题、明显重复或占位的主题图片，必须从第 10.6 节与第 16 节列出的第三方来源 Pexels、Pixabay、Unsplash、Wikimedia Commons 搜索并取得许可明确的相关主题真实照片；检查来源页、实际许可和文件签名/尺寸，下载到工程的内容资源目录，记录来源与归因，更新清单及页面映射并重新构建。不可用 Stargate、生图服务、搜索缩略图、热链、AI 拟真图或插画替代真实主题照片；Logo 仍只从 Stargate 生成。按第 0.6 节用有限预算完成跨来源尝试；如果仍被网络、许可或工具阻断，记录 `Blocked`/`Not verified` 后结束本轮修复，继续已可执行的本地 Listing、About 和审核备注，不原地无限重试。
4. 替换或新增任一资源后，重新运行受影响页面并复验实际加载、离线随包读取、引用路径、重复情况与最终截图；随后重新核对资源清单和白名单，确保额外素材没有进入 `aduit/site/`。继续修复直到所有适用展示位正确加载且没有占位图；若有限尝试后仍无法取得合规照片，停止该照片分支并保留真实失败记录，不阻断其它本地交付。若 iPhone 运行环境确实不可用，仍完成来源、签名、清单、路径和静态引用核验，但将运行加载状态标为 `Blocked`/`Not verified`，记录证据，不声称此最后一步已通过。
5. 将最终核验日期、构建版本、实际 iPhone 型号/iOS/UDID 或受阻原因、检查的页面/展示位、加载结果、发现并替换的资源及其来源/许可、最终截图路径写入 `.codex-work/quality.md` 或对应执行记录，并在最终报告中逐项总结。实际未拉取、未显示或未核验的图片不得标 `Verified`。
6. **清查本地依赖中的 `aduit/` 副本并核对资源边界**：按当前工程实际解析结果检查 Flutter `path` 依赖、`.dart_tool/package_config.json` 指向的本地 package 根、`ios/.symlinks/plugins/`、`ios/Pods/`、`build/` 及最终 App bundle 等依赖或生成目录；同时检查符号链接和被复制的资源。若这些依赖树/构建产物内存在目录名精确为 `aduit` 的副本，只删除该 `aduit/` 子目录或链接，再检查引用并重建复验；不得删除其父 package、其他依赖或项目之外的数据，也不得用宽泛通配符清理。最终依赖目录与 App bundle 中不得残留 `aduit/` 目录副本。明确排除并保留项目根目录 `<Target project root>/aduit/`，其 AppListing 交付结构仍须符合第 12.2 节白名单；不得把整个目录复制进应用依赖或资源包。App 运行时品牌图使用 `assets/logo.png`；第 12.2 节要求的 `aduit/site/img/logo.png` 只作为 Listing 交付副本保留。Entry/Settings 的协议链接直接使用 `aduit/intro.md` 的 `All URL` 原始地址；通过无网络 stub 核对链接映射，不访问或探测真实 URL。协议 HTML 仅作为 Listing 交付文件，不复制或打包进 Flutter 依赖，也不作为 App 内协议页面的访问目标。Entry 引导页仍按第 12.1 节使用单一 `aduit/site/index.html` 源文件；如需复制到 Flutter 资源中，只复制该引导页文件，不复制整个 `aduit/` 或其中的协议页。记录扫描范围、移除的精确路径、保留的根目录、构建结果及协议/Logo 引用核验结果；依赖扫描未完成时据实标为 `Blocked`/`Not verified`。
