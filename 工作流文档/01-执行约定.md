
# Flutter iOS iPhone App 详细产品、UI 与工程规格

> 本文档用于产品设计、UI 设计、Flutter 开发、QA、合规和发布准备。目标是产出一个具有丰富内容、完整功能和可观察行为的真实 App，而不是只包含几张卡片的简化 Demo。

> 设备范围固定为运行 iOS 的 iPhone。产品方案、思维导图、工程目标、页面适配、运行测试、截图、图标和上架材料均只包含 iPhone，按第 0.10 节配置并核验；不得因 Flutter 默认支持多平台、已有其他设备或工具自动选择而扩展范围。

> Logo 美术要求：按第 2.5 节围绕实际主题精细设计主体、轮廓、材质和光影，充分使用协调的鲜明多色与平滑渐变，达到精细好看的完成度；不采用几何色块堆叠拼贴、粗糙简笔或简陋通用图案。取色分析不要求将 Logo 画成分区色块。

> 默认执行模式：取得创意与用户提供的项目名称 → 绘制并展示具体思维导图与方案 → 用户确认 → 第一项项目任务：生成 Logo、校验并提取色块 → 用 Logo 配色制定鲜明主题色与渐变 → 全权开发 → 质量复核后优先尝试远程 `feature/1.2.1-A1` AppListing 来源；失败时使用 `/Applications/config/ios-app-listing`，两者均不可用时按第 12 节完整输出契约继续生成 AppListing 与 About 页面 → 校对配色并改名/整理为 `aduit/` → 在 `aduit/site/index.html` 中替换并接入本地自包含引导页 → 回接协议链接 → 按实际证据生成英文 `aduit/review/remarks.md`，不要求域名、不公开部署。启动时将创意与项目名称一并收集，仅询问缺失项；已有用户创意直接使用，用户明确要求生成创意时直接生成，但项目名称始终由用户提供，不由智能体命名。完全没有创意且尚未要求生成时，询问用户提供主题或授权生成，不默认选题。本文件不预设产品主题。必须先让用户看到基于实际采用创意的完整思维导图并取得明确确认，再开始开发；同意生成创意不等于批准开发。确认后，在当前任务与目标项目范围内连续自主执行，不再逐项询问意见或审批。Logo 仅通过 http://stargate.local:3100/image 生成，质量为高、数量为 1 张、尺寸为 `1024x1024`、PNG 无 Alpha 通道；色彩鲜艳、背景满幅覆盖、不留白底，并且不含任何文字、字母、项目名称、标语、水印或其他品牌名称。

> 强制质量要求：开发前的思维导图必须完整覆盖用户创意与全部必做要求，并通过需求、页面、路由、状态、数据、资源和验收的交叉核对，修复已知错漏后才展示确认。App 内容必须丰富；摄像机拍摄、系统相册导入和麦克风录音均按用户创意自由选用，可以任意组合或全部不包含。仅对已选功能要求完整实现，不得只放入口、权限弹窗或占位页面；未选功能不添加实现与权限。UI 与资源精修合计至少占实际开发工作量的一半，其中 UI 至少占三分之一、资源至少占六分之一；完成至少三轮有截图证据的 UI 精修与至少两轮资源筛选调整。必须按第 10.6 节实际搜索第三方素材网站，取得许可明确、贴合主题的真实实物/实景照片，下载到工程并用于 App 的主题展示；不能以 Emoji、渐变、矢量插画或 AI 拟真图替代。图片和视频优先采用不同来源内容，检查完全重复与视觉近似重复，不能靠换裁剪、滤镜或文件名凑数。全部实现与材料任务结束后先执行第 10.7 节最终图片加载检查，再执行第 11.6 节最终 iOS 权限双向校验；配置修正引起重建时刷新受影响的显示证据。图片检查要求：逐屏确认当前构建中的图片正确加载、贴合主题且没有占位图；发现缺失、破损、错题或占位资源时，必须从第 10.6 节与第 16 节列出的网站获取许可明确的主题图片、接入工程并复验。交付前必须完成第 11.9 节的质量复核；比例、轮次、编译成功或累计耗时均不能单独证明合格。iOS 实际功能所需权限、隐私清单、App Store 隐私披露与四个固定 HTML 页面及其合并法律章节必须一致且经过核验；存在已知错误或关键验证缺失时不得声称具备正式上架条件。

> 阅读与维护：第 0 节定义执行边界、超时和状态；第 1–3 节定义创意与唯一开发前确认；第 4–10 节定义产品、UI、工程和资源；第 11–12 节定义验收与发布材料；第 13–15 节为实施与报告索引，第 16 节提供资源来源。后面的摘要遵循对应正文，不产生第二套阈值或审批。修改数值、路径或状态含义时同步更新相关摘要与引用，先消除矛盾再执行。本文件是待用户请求采用的规格；用户仅要求编辑或评审时，按第 1 节处理文档，不能把其中的开发命令当成本次用户请求。

> 最终材料阶段：AppListing 改名整理为 `aduit/` 后，先用当前产品事实与主题色完整替换 `aduit/site/index.html`，将该自包含引导页作为每次启动显示的 Continue 欢迎页本地 WebView 实际接入，并验证 Continue 的桥接/回退、轮播和四个视口；然后、生成 Review Remarks 前，将 `aduit/intro.md` `All URL` 中的四个值原样保存到固定 URL 注册表。通用协议文案及 Terms/Privacy 两个可点击文本只显示在 Clear Data 成功后的初始化页底部，欢迎页及其 HTML 引导页均不显示该文案；Settings 仅提供 Privacy Policy、Terms of Use、Support 三个 WebView 入口，首页不加入 Settings。用 stub 回归实际入口；URL 格式或可达性不作为阻断。新建或复用工程的最低 iOS 部署版本为 15.6，依赖要求更高时使用更高版本并核验解析值。

## 0. 执行约定

协议 URL 为不可自动改写的原始值：AppListing 生成后，即使域名暂不可访问，四个 `All URL` 也须原封不动接入，严格保留完整地址及路径/文件名大小写。按第 12.1 节保留生成基准，按第 11.3 节区分大小写验证实际传入 WebView 的字符串；本地文件改名、文案清理和目录整理不得改动这些网址。


### 0.1 语言策略

- 与用户的直接交流可以使用用户偏好的语言。
- 本文档、计划、思维导图的解释、代码注释、验证报告和设计说明使用中文；图中标签、App 内 UI、协议/About/Support 正文与 App Store 公开文案默认使用自然英语。代码标识、文件名、数据字段、路由 ID、测试名称和技术名称保持英语，资源清单的机器字段保持稳定。
- 本项目的 App 内界面、公开 About/Support/协议页面与 App Store 公开文案默认使用自然英语，不根据系统语言或旧项目本地化自动切回中文；用户明确给定的品牌名称按第 1.3 节保留原样，不擅自翻译。本规格中文说明、开发计划和验证记录不属于 App UI。可见文案边界与校验统一见第 6.6、11.4 节，用户后续明确命名优先于默认品牌命名策略。
- 工程源文件、类、枚举、状态值和无障碍语义节点 ID 使用英语标识；顶层项目目录按第 1.3 节使用用户名称。VoiceOver 标签、提示与读出内容使用自然英语，准确读出用户品牌名称、描述作用和状态，不读出代码标识或文件名。

### 0.2 请求优先级

1. 用户当前请求、先确认思维导图再全权执行的要求与已给出的操作授权；用户后续明确发出的修改指令优先。
2. 用户提供的 App 创意、目标与核心功能，或按第 1.1 节由用户明确要求智能体生成的创意；已有用户约束始终优先，产品主题不由本文件、模板或旧项目预设。
3. 用户已提供的 UI 风格与导航要求；缺失时按第 5.1 节由智能体依据主题和任务自主确定，不默认使用底部导航。
4. 本文档对架构、隐私、资源、测试和发布的约束。
5. 参考链接只用于研究一般信息层级、交互模式和视觉方法，不照搬具体品牌、Logo、文案或完整页面设计；素材使用另按第 10、16 节核验许可，不能因研究参考可访问就视为有转载权。

在上述优先级下，必须保持 UI 丰富、功能完整和接近上架质量，不得压缩成少量卡片和按钮。第 3.4 节的思维导图整体确认是开发前必须完成的步骤，不能被全权授权、模板、相关技能或连续推进规则跳过。取得该确认后，其他工作流偏好的确认步骤均改为智能体记录决策后继续执行；最终 AppListing 生成、配色校对、改名、Review Remarks 编写与白名单核验均由智能体自主完成，不询问域名或额外审批。示例页面、内容模型、旧项目数据和自主决策权限只用于辅助实现，不得覆盖用户创意或把不同创意统一改造成同一种产品。

### 0.3 账号、认证与社区边界

首期版本不包含账号、邮箱输入、登录、认证或登出功能。App 每次启动均先显示 Welcome（路由 `/welcome`，含 `Continue`）；AppListing 改名后，该页实际显示 `aduit/site/index.html` 的本地引导 WebView。用户点 `Continue` 后直接打开已选定的主任务目的地；该页的 `AppBridge` 和 `go://continue` 两条路径都必须回到同一既有进入逻辑。只有确认 `Clear Data` 且真实清理成功后才转到独立 Initialization（路由 `/entry`，含 `Entry`）；其底部才显示通用协议文本。欢迎页、嵌入的 HTML 引导页和原生启动页均不显示该协议文本。Settings 清除流程取消时留在原页面且不修改数据。取消独立的 `Exit`、退出或登出按钮，不用其他名称另建保留数据的退出入口。普通页面返回、关闭预览和单条媒体删除仍按各自流程工作。上述操作不建立身份、不保存个人资料，也不代表远程认证。完整规则见第 7.7、8.5 节。不得创建以下能力、路由、按钮、文案、模型、fixture 或测试：

- 邮箱输入、邮箱/密码/手机号登录、第三方登录、社交账号、验证码、邮箱所有权验证、账号恢复、云端账号管理、登出或账号删除。
- 登录页、登录状态、认证服务、会话凭据或任何要求用户输入身份信息的流程。
- `User`、`Account`、`Profile`、`Avatar`、`Nickname` 或同义个人实体；允许使用 `AppFlowState` 表示 `entry`、`active` 和 `clearing` 等本机流程状态。
- 关注、粉丝、喜欢、收藏、评论、私信、社区分享或个人内容流。
- 向服务器上传用户媒体、个人页面、云端账号同步或跨设备同步；本地拍摄、相册导入、录音、预览、保存与删除属于允许自主选用的能力，不视为账号或社区功能，也不是每个项目的必做项。
- 为制造首装弹窗而申请权限，或申请与真实功能无关的定位、通讯录、通知等权限。若选用摄像机、相册或麦克风，必须有真实用途，按第 0.7 节在用户主动使用对应功能时处理授权，不在 Welcome 的启动准备或 Initialization 页面集中弹窗。

隐私政策、用户协议和支持文档可从 Settings 查看；只有清除成功后的 Initialization 页面底部显示用户协议与隐私政策通用文本链接。AppListing 的 `index.html` 改名后作为本地引导页替换到每次启动出现的 Welcome 中，不作为 Settings 入口，也不带通用协议文案。用户点击 Welcome 的 `Continue` 或 Initialization 的协议链接时不得要求勾选、不得阻止进入 App、不保存个人同意记录，也不创建 `AgreementRecord`。文档只能准确描述实际的设置、资源和运行行为，不得声称存在登录、账号或认证。

真实开发者联系地址可以作为协议/Support 的只读联系信息或经用户点击打开的系统联系链接；这不等于邮箱登录。不得加入邮箱身份输入、收集邮箱的登录表单或伪造地址。若支持渠道确会接收用户主动发送的信息，隐私政策据实说明该渠道的数据处理，不宣称不存在实际发生的支持通信。

摄像机拍照、相册选择/管理、麦克风录音统一为可选能力。功能组合可围绕用户创意自由、多样化或随机设计，可以选择任意一项、多项，也可以三项全部不包含；不设最低媒体能力数量，不固定为记录/媒体类 App，不为了满足模板强行加入这些功能。用户已明确要求的功能优先，其他范围由智能体自主决定，纳入原有思维导图整体确认，不增加逐项询问。未选用的能力不创建入口、页面、路由、服务、状态、依赖、示例数据或权限；所选功能必须真实可用，按实际 API 配置最小权限并完整处理拒绝/取消/失败。功能自由选择不代表权限可以随机配置；最终必须执行第 11.6 节的功能与 iOS 权限双向核验。其他受保护能力也只在实际功能需要时配置，运行时仍遵守最终 App 用户的系统授权选择。

### 0.4 项目创建与 Git 边界

- 思维导图确认前只确定并记录项目路径，不创建或改动 App 项目。确认后，先按第 2.5 节执行 Logo 生成与配色提取，允许为保存产物创建最小目标目录；正常路径完成该步骤后才创建 Flutter 工程、安装项目依赖与实现页面。已有工程先检查状态，保留用户已有文件，再按相同 Logo 优先顺序更新品牌与后续实现。
- 启动时先记录 `Invocation cwd`（读取技能或切换目录前的 Codex 工作目录）、`Workflow resource root`（规范文档的目录）以及安装器同步的远程 `ios-app-listing` checkout 路径、`User project name` 和 `Target project root`。资源目录与工程输出目录是不同概念；读取规范、打开附件、运行安装器或进入技能脚本目录都不能改变工程输出位置，也不能把安装器的 `SCRIPT_DIR`、技能目录或规范所在文件夹当成工程根目录。
- 路径优先级：用户在当前请求明确指定的完整工程目录 → 当前任务此前明确指定的完整工程目录 → Codex 当前选定项目/工作目录（`Invocation cwd`）。对于所有新建项目，将已确定的目标文件夹本身直接作为 Flutter 工程根目录，源码、`pubspec.yaml`、`assets/`、`aduit/` 与 `.codex-work/` 均直接创建在该文件夹内；不要再创建或嵌套一个以项目名称命名的子文件夹。项目名称只用于 App 显示名和合法化后的 Flutter 内部标识，不用于给目标文件夹再套目录。明确给出 `--project-dir` 或完整工程目录时也直接使用该目录本身。
- 未指定目录时，优先复用当前任务中名称/创意相符的既有工程；若本次确为新建工程，则将当前选定的 Codex 工作目录本身作为 `Target project root`，不在其下生成名称子目录。若当前目录是资料包、技能安装目录或其子目录，且用户没有明确指定它作为输出位置，才使用当前用户 `Documents/FlutterProjects/` 下的一个直接工程目录并记录自动回退依据；该直接工程目录也是工程根目录，不再套项目名称子目录。绝不因查到旧计划、旧主题或任意 `pubspec.yaml` 就将另一项目当成本次目标。
- 将最终绝对工程路径与用户项目名称写入待确认方案。所有 Flutter 创建、依赖、测试和构建命令显式设置 `workdir` 或显式目标参数；AppListing 脚本即使从技能目录运行，也必须使用 `--target` 指向 `Target project root`。生成的源码、`assets/`、`aduit/`、`AppListing/` 与 `.codex-work/` 都属于目标工程；不得出现在资源目录中。目标路径不可用时记录真实问题并处理，不静默改到资料包内。
- 创建后立即核验目标目录的 `pubspec.yaml`、内部标识、iOS 显示名称与实际绝对路径，并确认资料包未新增工程产物；不一致时先修正再继续，不把错误位置的工程当作完成。
- 新建 Flutter 工程时显式使用 `--platforms=ios`，再按第 0.10 节限制为 iPhone；不生成其他平台工程。创建期间不启动模拟器，工程创建实际完成后，按第 0.9 节复用一个现有 iPhone 模拟器进行页面测试，不批量启动或新建模拟器。
- 不初始化、关联或创建 Git/GitHub 仓库，不创建分支、提交、远程代码仓库或 Pull Request。
- 所有源码、资源、JSON、开发期 HTML 协议本地预览页和测试直接写入目标文件夹；默认使用本地文件与本地数据源。
- 本文档中若出现仓库、分支、提交、远程代码仓库等要求，一律改为目标文件夹内的本地文件流程。

### 0.5 先确认思维导图，再全权执行

- 启动前按第 1.1、1.3 节取得创意与用户项目名称；缺失时合并询问，不要求填写完整产品简报。已有用户创意直接使用，已明确要求生成则直接生成，但不能自行生成项目名称。这是必需输入询问，不是方案审批；收到输入只表示可以开始规划，不表示思维导图已经获批。
- 智能体先自主完成主题解释、UI 风格与导航选择、核心旅程、路由、页面、数据、资源和验证方案，再按第 3 节绘制具体思维导图，在对话中展示图与必要说明。开发前只请求一次整体确认，将主题、UI/导航、页面与方案合并在这一步，不拆成多轮选择或审批。
- 确认前只允许只读调研、查看已有项目与可用工具、编写独立的规划文档；不得创建或修改 App 代码、安装依赖、提交 Logo 生成、生成或采集素材、启动构建或部署。展示思维导图后暂停开发并等待用户明确回复；用户要求调整时先更新图与方案，再等待对最新版本的确认。

- 应用名使用用户提供的项目名称；导航目的地、页面、数据、依赖、Logo 提示词和实施方式围绕实际采用的创意自主细化。确认前说明鲜艳 Logo 与由其提取配色的设计方法，不预先锁定与产物无关的最终主题色。确认后从实际 Logo 提取色块并制定主题色与渐变，不新增配色审批；缺少非必需输入时使用符合该创意的默认值。用户明确要求生成时可以自主提出产品主题；笼统的全权操作授权不能代替该要求，也不能据此替换用户已有创意、名称或已确认的核心用途。
- 相关技能中的方案确认与本次思维导图确认合并；本节确认完成后，其他实现许可或集成选项等流程要求若与用户全权操作授权冲突，按用户授权直接决策并执行，不新增询问关卡，也不得据此跳过初次思维导图确认。AppListing 只按第 12.1 节使用安装器从远程指定分支同步的完整 `ios-app-listing` checkout，以本地生成参数运行；缺失或不同步时不得切换资料包副本或手写流程。Review Remarks 按第 12.2 节基于事实自主编写，不触发域名询问或公开部署。
- 本规格中的协议查看、系统权限弹窗和 App 内操作确认，属于最终 App 用户的运行时交互，仍须实现；它们不代表开发过程需要向委托用户询问意见。协议查看不得变成登录、勾选或身份确认关卡。
- 全权操作不补齐不存在的凭据、服务或平台权限。遇到客观不可用的能力时，执行第 0.6 节的回退规则，交付可完成的部分并记录具体限制，不要求用户做决定；AppListing 与 About 页面依远程指定分支、本机 `/Applications/config/ios-app-listing`、完整输出契约的顺序持续生成，不以域名或公开部署为前置条件。任何来源或生成校验故障均不取消后续 `aduit/` 整理、引导页和 Review Remarks。

### 0.6 连续推进、超时与失败回退

1. 按第 0.8 节分别记录方案批准、执行、验证与交付状态，并记录依赖和下一步。`Awaiting confirmation` 专指开发前已展示思维导图、尚未取得整体确认的状态；此时应暂停开发。确认后，计划、设计说明和进度输出不是结束点，有可执行任务时继续调用工具并实际完成。
2. 完成思维导图确认后，Logo 生成、真实产物校验、色块提取及主题色/渐变定制是第一项项目实施任务，正常路径完成后才开始 Flutter 工程、页面、资源采集与其他实现，不再将 Logo 与这些开发任务并发。访问 `http://stargate.local:3100/image` 得到网页 HTML 只说明打开了生成界面，不是图片结果；必须在界面中提交真实生成任务，并从任务结果、下载响应或明确的图片数据中取得文件，再检查 MIME、文件签名、尺寸、RGB/Alpha 与可解码性。不能把 `/image` 页面、HTML、JSON、错误页或重命名的非图片保存成 `assets/logo.png`。等待采用第 4 条有界查询，可以继续只读检查与独立规划，不提前实施 App；五候选比较、最终 Logo 验收及取色完成，或达到真实失败/超时退出条件并留存证据后，立即进入下一步。开发期 About/Support/协议页面集成到 `aduit/` 并随事实变化更新；页面正文始终保持完整成品文案，开发状态和未确认信息只记入内部记录。页面生成不依赖线上服务成功；正式 Logo 确实不可用时，记录正式品牌验证为 `Blocked`，保留已有可解码的 iPhone 品牌图，必要时在 `.codex-work/` 记录一个明确标记 `unverified` 的开发期品牌源供本地页面继续生成，不能把它称为正式 Logo、取色通过或发布就绪，也不能因此停止本地产物。最终 AppListing 与对应 About 页面按第 12.1 节仅使用已同步远程 `ios-app-listing` checkout 生成本地产物，校对配色后改名/整理为 `aduit/`；远程 skill 缺失或不同步时保留证据并将 AppListing 阶段标为 `Blocked`，不得读取资料包副本或手写等价页面；再按第 12.2 节生成审核备注。整个过程不查询或替换域名、不公开部署、不等待线上访问。独立任务也不能以依赖隔离为由在确认前实施。
3. 开发期外部页面与单次网络请求默认最多 60 秒；同一可恢复故障最多重试 2 次，即最多 3 次尝试，普通请求操作从首次尝试起的总墙钟预算最多 180 秒，包含请求与退避。Logo 等另有总预算的异步作业按其专节处理，单次查询仍遵守请求上限。退避建议为 5 秒、15 秒；`Retry-After` 是最早允许重试的时间，不能为了满足预算提前请求，超出预算则记录允许恢复时间并继续独立工作，不原地等待。认证错误、参数错误、已知缺失凭据和不可用工具不原样重试。只对幂等读取或已核实可安全重试的操作自动重试；Logo 提交、部署或其他产生副作用的请求超时时，先检查真实任务/目标状态，不盲目重复提交。App 运行时的协议加载与启动分别采用第 7.6、7.1 节的更短预算，不沿用开发期 60 秒等待。
4. Logo 五候选优先阶段从首次访问生成服务起设定 30 分钟墙钟截止时间，包含打开页面、提交、查询和重试；不通过扣除只读检查或规划耗时延长该期限。记录截止时间与下次允许检查时间，查询间隔不少于约 30 秒，单次等待/工具调用不超过 60 秒并持续提供有意义的进度；工具支持非阻塞状态查询时优先使用。正常路径中，未校验真实 Logo 并完成配色提取前不推进 App 实现；期限到达后停止主动等待与重复查询，按第 2.5 节记录限制并继续可完成工作。若之后任务边界或服务事件直接提供真实完成结果，可一次性获取、校验、提取配色并更新受影响主题，不另开等待循环、不重复提交。
5. 依赖安装、构建和测试命令至少每 60 秒检查输出与进程状态。有实质进展时继续；连续 5 分钟无进展时先诊断进程、网络和锁，再修复或切换可用方案。同一失败最多 3 轮，每轮必须有新的证据或改动，禁止原样循环。
6. 工具或本地技能文件缺失时先检查实际可用能力与已知位置；能直接实现的本地任务使用等价流程，但 AppListing 是例外：只接受安装器同步的远程 `ios-app-listing` checkout，不能用等价本地实现。缺少素材 API 凭据或资源下载技能时，按第 10.6 节继续尝试可用的公开网页搜索、素材来源页与合法下载途径，不能直接跳过第三方真实照片搜索。遇到 403、429、超时、登录墙或无许可证据时立即记录可观察结果，切换另一个合规来源或英语同义查询；不要绕过访问控制、反复请求同一失败地址或把搜索缩略图当文件。经有限跨来源尝试仍不可用时，可用明确标记的开发资源继续独立页面、About 整理和 Review Remarks；真实照片要求保持 `Blocked`，不能以原创插画替代后标为通过。Logo 的生成来源始终遵守第 2.5 节，不更换供应商。
7. 确认后的外部故障只影响依赖它的子任务，继续完成所有无依赖任务。故障记录包含失败步骤、可观察错误、尝试次数、替代结果和影响；不得新增未经要求的“等待确认”，也不得只写“等待服务”后结束整项任务。第 3.4 节的初次思维导图确认是唯一的流程性等待点；图库或 Logo 失败只使对应素材/品牌验收保持 `Blocked`/`Not verified`，不阻断基于已核实事实的独立开发与质量记录。远程 `ios-app-listing` checkout 缺失、来源/分支/revision 不符或执行失败时，仅将 AppListing 及其依赖的 About/目录整理阶段标为 `Blocked`，不得读取资料包副本、旧安装或以手写页面替代；安装器恢复同步后从该阶段继续。若远程生成器发现 Logo 候选缺失，按远程技能自身的输出契约记录失败并继续其允许的验证步骤，不把缺图称为已通过。
8. 任务恢复或上下文压缩后先检查创意状态、来源、生成请求或同意来源、思维导图版本、确认来源和第 0.8 节执行记录：已确认时核对文件与进程的真实状态，从下一步继续，不重做仍有效的已验证步骤、不重新要求确认；创意仍缺失时保留原输入等待状态，不重复询问，不将其误记为思维导图待确认。已有有效生成请求且尚未生成时直接生成，已有创意则继续规划；方案尚未展示时为 `Draft`，已展示但未确认时保持 `Awaiting confirmation`。AppListing 阶段核对技能生成状态、配色核验、目录改名与站点白名单；Review Remarks 阶段核对事实来源、生成状态和完整白名单，从最近一个未完成步骤继续，不引入域名状态或线上部署等待。只复验新改动影响的范围；证据过期或实现已变时不能沿用旧结论。确认后只有全部可执行任务均已完成，且剩余事项确实依赖不可用的外部条件时，才以真实状态交付。有限诊断耗尽不代表已知本地缺陷自动通过，应尝试有依据的替代路径并准确记录残余缺陷。

本节的超时与重试上限只约束无进展等待和故障处理，不是整个 Flutter 工程的制作时限，也不能用于压缩 UI、资源或质量验收。不得在累计运行 3 小时、首次构建成功或最低迭代轮次完成时自动结束；按第 11.9 节核对实际成果。用户提到以往制作约 8 小时等历史耗时，只作为投入与范围对照参考；没有明确总时限要求时，不擅自将其改为最低等待时长或截止时间。

Logo 实际生成失败时，先按第 2.5 节在同一 Stargate 服务的生成参数中切换为其他实际可用的图像模型，再决定是否使用开发资源回退；无需另行询问。按第 2.5 节先生成覆盖四种画风的五张独立候选；五次初始提交与最多两次补图共享最多 7 次生成提交及整组 30 分钟墙钟预算，不按候选、模型或并发重置；状态不明的提交先查任务，不盲目重复。无可用替代模型或预算耗尽时如实记录并继续本地交付。

### 0.7 按实际功能配置 iOS 权限与数据使用规则

开发者的全权授权不代替最终 App 用户的 iOS 系统授权。按实际使用的 API、最低 iOS 版本、Flutter 插件及其原生实现确定配置；发布前以 Apple 最新官方要求复核，不能照抄旧模板。最低部署版本按第 0.10 节设置与验收。

下表是按需选用的 API 配置参考，不是项目必须实现的功能清单。先从最终实现建立“实际功能 → 调用 API/插件及版本 → 是否需要系统授权 → 用途键/权限宏/entitlement/capability/隐私清单 → 授权时机 → 验证证据”映射，逐项补齐必需配置并清除未使用项。没有受保护能力的项目可以没有任何相机、照片库或麦克风用途键、请求代码和启用宏；也不为此安装权限插件。显示随包图片或播放已有音视频不等于使用相册、摄像机或录音权限。

| 能力 | 配置与授权 | 正确触发与拒绝处理 |
| --- | --- | --- |
| 摄像机拍摄（仅实际选用时） | `NSCameraUsageDescription`；实际访问摄像机前检查并请求系统授权 | 用户点击主题相关拍摄动作时才请求；拒绝或受限时保留实际存在的其他路径与已有内容，不假设 App 另有相册功能；无设备时明确说明 |
| 麦克风录音 | `NSMicrophoneUsageDescription`；使用当前系统与插件支持的录音授权 API | 用户点击录音时才请求；拍照不连带申请麦克风，带声音录像确实需要时分别处理两种权限 |
| 相册选择与导入 | 优先使用 `PHPickerViewController`、`PhotosPicker` 或原生实现等价的 Flutter 系统选择器；仅取得用户选中的项目，不额外请求整库权限 | 用户点击导入时显示选择器；取消不报错。处理格式、大小、方向及 iCloud 项目下载失败，不伪造导入成功 |
| PhotoKit 相册读取 | 只有确实需要枚举或管理照片库时才使用 `.readWrite` 并配置 `NSPhotoLibraryUsageDescription` | 接受 `.limited` 授权并提供系统管理已选照片的入口；不得要求开放全部照片才允许使用 App |
| 保存到系统相册 | 若实现此项，按仅添加需求使用 `.addOnly` 并配置 `NSPhotoLibraryAddUsageDescription`；最终按实际 API 核验 | 仅在用户主动保存到相册时请求；拒绝不影响保存在 App 私有目录的内容，不能误报已保存到系统相册 |

权限用途字符串必须为自然、具体的英语，说明该主题中的真实用途，例如拍摄什么、导入后用于什么、录音如何使用；不得写成 `Need permission`、虚构用途或复制与产品不符的示例。检查每个实际发布 target 的最终 `Info.plist`、构建变量和插件配置，防止声明缺失、拼写错误、空字符串或未使用权限残留；新增本地化时同步 `InfoPlist.strings`。

系统照片选择器仅授予选中项目的访问时，不因存在“相册选择”功能就添加整库权限；只有实际调用 PhotoKit 读写/仅添加 API 时才按其访问级别配置用途键与宏。拍照不连带申请麦克风，只有带音频录制才需要相应录音授权；音频播放不请求麦克风。其他功能如确需受保护系统能力，按实际 API 的最新要求扩充映射，不只检查三种媒体权限。依赖默认带入而功能未使用的受保护 API，应裁剪、禁用或更换/移除对应插件，不能靠增加无用途权限说明消除打包问题。

#### Podfile 权限宏设置（尽力配置，不阻断打包）

Flutter 工程创建并确认实际权限插件及版本后，检查 `ios/Podfile`，在运行 `pod install` 和 iOS 构建前执行一次权限宏配置。若使用 `permission_handler_apple`，按当前插件文档和实际调用 API，在既有 `post_install` 中幂等设置所需宏；摄像机、PhotoKit 照片库读取、麦克风分别使用其对应的 `PERMISSION_CAMERA=1`、`PERMISSION_PHOTOS=1`、`PERMISSION_MICROPHONE=1`。仅图片选择器不需要整库读取时，不启用 PhotoKit 读取宏。保留已有 Hook、`$(inherited)` 与其他构建设置，不重复创建 `post_install`，不套用与当前插件版本不符的宏。

宏写入、自动配置脚本或宏语法校验失败时，不得因此终止工作流或跳过打包：保留/恢复最后一个语法有效的 `Podfile`，记录失败步骤与原因，继续对该有效文件执行 `pod install` 和 Flutter iOS 构建/归档尝试。宏配置命令的失败状态与 CocoaPods/构建命令的真实结果分开记录；不得用忽略所有错误的方式掩盖独立的安装或构建失败。失败的宏不得报告为已配置，受影响的权限运行路径须标记为未验证或受阻；仍需核对最终 `Info.plist`、解析后的 iOS 构建设置及实际运行授权路径，不以 Podfile 文本单独判定权限完整。

本流程不集成追踪功能，也不申请 ATT 权限。权限矩阵、思维导图、状态模型、页面、启动准备及测试计划均只处理实际实现所需的受保护能力，不创建追踪授权入口、弹窗、四状态流程或触发条件，也不将其列为待实现功能。

默认只在 App 私有目录处理和保存用户媒体，不传给服务器、分析 SDK、AI 服务或 Stargate；Stargate 仅用于开发期 Logo 与主题背景装饰，不上传用户拍摄、导入或录制的私有媒体。用户媒体默认排除 App 的 iCloud/设备备份并核验文件保护与删除行为，不声称已控制用户系统相册自身的备份。系统选择器仍可能按用户操作下载 iCloud 照片；应说明这与 App 上传用户媒体不同。权限状态以系统为准，不凭本地布尔值推定授权。

### 0.8 执行记录、状态与恢复

执行记录只服务开发，不是 App 用户账号、协议同意记录或运行时数据。确认前写入独立规划文档；确认后统一在项目根目录的非公开工作目录（例如 `.codex-work/`）维护，记录真实路径，不把执行记录、质量报告、品牌取色记录、备份或其他开发文件写入 `aduit/`。仅第 12.2 节生成的最终 `aduit/review/remarks.md` 是审核材料白名单例外，不得用其他新增文件保存台账，也不要为了建台账重复复制全文或创建 Git 产物。

| 维度 | 可用值 | 判定边界 |
| --- | --- | --- |
| `Idea status` | `Awaiting idea choice`、`Awaiting user idea`、`Generating`、`Ready` | 分别为已询问是否生成且未收到明确回答、用户选择自行提供但尚未给出创意、按明确请求正在生成、已有可用于规划的具体创意；与思维导图批准状态分开 |
| `Name status` | `Awaiting user name`、`Ready` | 第 1.3 节用户项目名称缺失、已取得可追溯的用户名称；主题已生成不代表名称已取得 |
| `Plan approval` | `Draft`、`Awaiting confirmation`、`Approved` | 只依据第 3.4 节，批准版本及确认来源单独保存 |
| `Decision source` | `Confirmed`、`Selected`、`Assumption` | 分别为用户明确给定、自主选定、缺失细节的假设，不表示已经实施或获批 |
| `Task status` | `Pending`、`Running`、`Done`、`Blocked`、`Deferred`、`Not applicable` | `Done` 表示操作已完成；`Blocked` 记录具体依赖或故障；暂缓与不适用需有范围依据，必做项不得借此排除 |
| `Verification` | `Verified`、`Not verified`、`Failed`、`Blocked`、`Not applicable` | `Verified` 必须对应当前产物的实际通过证据；未运行、失败、无法运行和不适用分别记录 |
| `Delivery` | `Local only`、`Published`、`Not published` | 本地完成不等于已上线；`Published` 只表示实际发布完成，公开访问仍须另行验证 |

例如摄像机可以是 `Task status: Done / Verification: Blocked`（缺真机），About 可以是 `Task status: Done / Verification: Verified / Delivery: Local only`。`Not implemented` 用于明确尚无实现的结果说明，不能用来描述已实现但未实测；`Deferred` 不等于不适用。正文出现简写状态时必须说明是哪个任务或验证项。

每条执行记录至少包含任务 ID、对应需求 ID、当前产物/路径、上述适用状态、依赖、证据、最近动作和下一步。外部作业另记任务 ID/位置、开始时间、截止时间与下次允许检查时间；最终材料阶段记录 AppListing 技能生成、About 页面配色核验、目录改名/整理、Review Remarks 事实来源、白名单核验及本地产物路径。关键错误记录可观察信息，日志脱敏，不记录密钥、用户私有媒体或无关个人信息。里程碑、真实阻断、确认来源和恢复点变化时更新，不为每个点击制造文档工作。

创意输入另记第 1.1 节的 `Idea origin`、`User idea`、`Generated idea`、`Effective idea`、用户约束、是否已询问及生成请求或同意的对话来源。用户同意生成后尚未产出具体创意时，设为 `Idea status: Generating`，记录生成任务 `Running` 并立即处理，不继续停在输入等待状态；创意形成后设为 `Idea status: Ready`，`Plan approval` 仍为 `Draft`，不能自动变成 `Approved`。

名称与路径另记第 1.3 节的 `User project name`、`Name source`、`Name status`、显示名称/目录名/内部标识映射，以及第 0.4 节的 `Invocation cwd`、`Workflow resource root`、用户指定路径原文与最终 `Target project root`。任务恢复时同时检查创意和名称：只要必需输入仍缺失，就保留原等待状态；不要从文件名、资料目录、旧计划或主题生成结果推断用户已给出名称。确认后所有产物与命令都以记录的工程根目录为准，不能因读取技能而改动输出位置。

并发以依赖为依据：先完成 Logo 优先阶段与主题色/渐变定制，或记录第 2.5 节规定的真实失败回退，之后独立页面、资源筛选和本地协议可交错推进；同一文件、资源清单、构建目录或品牌引用的修改按先后顺序合并并核验。没有安全的后台能力时用短状态查询与任务交错，不虚构后台进程、子任务或完成通知。提交与等待分开，任何阶段退出都不能丢失其他任务的下一步。

### 0.9 模拟器启动时机、复用与数量限制

1. **先完成工程创建**：Logo 优先阶段后创建 Flutter 工程时，不启动 Simulator、不 boot 模拟设备、不安装或启动 App，不用模拟器等待创建进程。只读查看已有设备列表和状态允许先做。新工程以创建命令实际成功退出、必需目录/文件完整且创建阶段依赖解析完成为准，至少核对 `pubspec.yaml`、`lib/main.dart` 和 iOS 工程；创建失败或仍在运行时先修复，不通过打开模拟器掩盖问题。复用已有工程时核对相同的基本就绪条件，不重建已有项目。
2. **就绪后测试页面**：工程创建完成，且当前待测页面已具备可构建、可运行版本后，才启动或连接现有模拟器，安装运行并检查页面。允许逐步开发、逐页测试，不要求等所有功能或全部精修完成后才运行；构建不需要已启动模拟器时，可先完成构建再启动测试设备。
3. **只复用现有 iPhone**：先只读查看设备类型、运行时与启动状态，筛选运行 iOS 的现有 iPhone 模拟器；用户已指定且符合该范围的设备优先，否则复用已启动且兼容的 iPhone。没有合适的已启动 iPhone 时，只启动一个已存在且运行时可用的 iPhone。记录型号、iOS 版本和 UDID，后续运行、截图、UI 检查和测试均明确指向同一 iPhone，不使用默认设备选择，不新建、克隆或批量启动设备；已启动的其他设备不能成为回退目标。
4. **同一时间只使用一个**：本任务同一时间最多使用或启动 1 个 iPhone 模拟器；UI 精修、截图与交互测试共享它，避免多个运行器同时安装/启动 App 或争抢截图。工具提供并行测试、自动克隆或多个 UI worker 时，使用其实际支持的串行/单 worker 配置关闭这些行为，不猜测参数。小屏、标准屏、大屏 iPhone 或其他支持的 iOS 版本按风险选择现有 iPhone 并依次测试，先结束当前测试会话再切换，不因数量限制削减必要的 iPhone 适配检查。
5. **保留无关会话**：记录测试前已有设备状态与本任务启动的设备；任务前已运行或属于用户/其他任务的模拟器不擅自关闭、重置、删除或清空数据，不使用全局 shutdown/erase。需要切换时，仅停止本任务 App/运行器，按需关闭本任务自行启动且无其他会话使用的设备；验证结束后释放本任务测试进程与媒体资源，保留用户已有会话。
6. **不可用时有限回退**：没有兼容的现有 iPhone、iOS 运行时缺失或启动失败时，按第 0.6 节有限诊断并记录受限范围，不改用其他设备或平台，不连续启动多个实例、不临时创建新设备或下载运行时；继续可执行的静态分析、单元/Widget 检查及无需模拟器的 iOS 构建，不把未实际运行的页面标为已测试通过，也不以工具限制卡住所有独立工作。

将创建命令退出结果、工程就绪证据、选用设备/UDID、复用或启动时间、逐台测试顺序与具体结果写入第 0.8 节已有执行记录；第 6.7、11.3、13 节的页面检查统一遵守本节，不新增设备选择或逐轮测试审批。

1. **固定支持范围**：只开发运行 iOS 的 iPhone App，真机和模拟器均须为 iPhone。方案、思维导图、导航、页面矩阵、设备选择器、执行摘要、产品截图、样机图、About/Support 与 App Store 文案只描述 iPhone；不得展示其他设备选项、版本、适配分支、平台切换或下载入口。若工具输出混合设备清单，先过滤，只将 iPhone 用于选择和对用户呈现；不得把其他设备列成备选或回退方案。
2. **创建与复用**：新建时显式使用 `flutter create --platforms=ios`。复用工程时核对当前 App 的实际平台目标和设备范围；移除本任务已有的其他平台构建/启动配置，对需移出的本任务产物先做可恢复归档，保护无关用户文件。
3. **原生配置**：在实际参与构建的配置中，使应用 target 和 UI 测试 target 的 Debug、Profile、Release 及自定义配置最终解析为 `TARGETED_DEVICE_FAMILY = 1`，`SUPPORTED_PLATFORMS` 仅为 `iphoneos iphonesimulator`，并令 `SUPPORTS_MACCATALYST = NO`。不得启用面向其他设备或平台的兼容选项；若工程或工具存在此类设置，必须关闭并核验最终解析值。核对继承值与覆盖值，不以源 `Info.plist` 手写字段代替 Xcode 设备 family 设置。
