## 4. 根据主题自动生成的产品定义

根据用户创意确定主题后，智能体自动填写以下内容并纳入待确认的思维导图与方案，整体确认后实施；内容单位、数据模型和核心旅程随创意变化，不机械复用示例产品：

- `Working app name`。
- `One-sentence promise`。
- `Primary user and context`。
- `Core user journey`。
- `Content unit and seed-data strategy`。
- `Core success signal`。
- `Differentiation brief`：明确目标用户和触发时刻、具体问题/现有替代做法、独特结果、标志性动作、首个有用结果、可保存并回访的主题成果，以及至少一条影响内容组织或交互顺序的主题规则。证据不足的用户/竞品结论标为假设或未验证，不编造。
- `Signature action and retained artifact`：用一个来自当前创意的实际操作与结果说明 App 的独特性；成果优先复用核心任务已有的本地数据，不为差异化强加社交、登录、收藏、云同步或独立日志模块。
- `Out-of-scope capabilities`。
- `Open assumptions and their consequences`。

### 4.1 核心旅程

以下流程是通用骨架，不是固定产品方案。核心动作、内容单位、详情页和工具应按用户创意替换或裁剪；与创意无关的浏览、搜索、阅读、播放等能力不加入实现。

产品必须先定义自己的核心循环，再把它映射到页面和导航：主题任务入口 → 标志性动作 → 清楚可见的首个有用结果 → 保存/更新一个有意义的成果或延续状态 → 需要时回访并继续任务。首个有用结果尽量在约一分钟内到达；超出时应由真实任务步骤解释，并尽可能提前呈现有用进展。此时限是设计目标，不是虚假性能承诺或新的等待/确认步骤。核心成果应来自该主题及现有本地数据边界，不得默认增加社交、账号、云端上传或通用收藏/历史功能。

```text
Launch
  -> Show the static native iOS Launch Screen during system cold start
  -> Show the Welcome page on every app launch; render required preparation status inside this same page
  -> When required preparation is ready, tap Continue and open the selected primary task destination directly
  -> Start the theme-specific core task (do not assume browsing/searching is the main activity)
  -> Perform the signature action and show its first useful, observable result
  -> Save/update the named theme-specific artifact or carry-forward state
  -> Reopen or continue from that result when it serves the user's task
  -> Use detail, search, filter, calculation, reading, or playback only when the chosen task needs it
  -> Adjust a theme-related preference if useful and show observable feedback
  -> Tap Clear Data in Settings and review the confirmation
  -> Cancel and keep using the current page without changing data
     OR confirm Clear Data, stop media, and clear app-owned local data
  -> On verified success, reset preferences and show the separate Initialization page, Entry
  -> Tap Entry to open the selected primary task destination
  -> On failure, show the remaining work and offer a recoverable retry
```

每个转移都必须产生 UI 反馈。只有数据层变化、页面没有可见状态变化，不算完成。

术语与页面边界固定如下，整个 App 恰好有三个不同的启动/返回页面：

1. **iOS 原生启动页**：系统冷启动期间显示的静态原生画面；随后交给 Flutter，不承担交互、进度或清除后返回。
2. **欢迎页（Welcome，`/welcome`）**：每次启动 App 后必定进入的 Flutter 页面，包含 `Continue`。启动所需准备、当前步骤、百分比、进度条及失败后的 `Try again`/`Clear Data` 都是此页面内部状态，不创建独立 Flutter Loading 页面或 `/loading` 路由。准备就绪后 `Continue` 可进入主流程。
3. **初始化页（Initialization，`/entry`）**：只在 `Clear Data` 确认且真实清理成功后显示的 Flutter 页面，包含 `Entry`；点击 `Entry` 进入主流程。此页是清除后的返回目标，不是欢迎页，也不作为正常启动入口。它底部显示通用协议文案；欢迎页不显示该协议文案。

冷启动路径固定为“iOS 原生启动页 → 欢迎页”。清除成功路径固定为“初始化页”；不得将任意两页合并、互换或另造第四个启动页面。清除返回初始化页不重放原生启动页；下次启动仍先显示欢迎页。详见第 7 节。

最终介绍复用本节的产品定义与任务链作为核对索引，并以实际实现为准：按第 12.1 节说明每个主要模块处理的内容、具体动作、用户结果、实际媒体用途（如有）和成果回访方式，而非只列功能名。全部描述写入现有 `aduit/intro.md` 的 `## Description`；不把计划写成已实现能力；按第 12.1 节清除重复 URL 栏目及多余网址，仅在 `All URL` 保留四个完整原始地址，四值原文不变；Intro/Remarks 的教育类展示标签按第 12.1 节统一为 `Popular Science`（科普），其他类别与事实不变。

### 4.2 内容丰富度与真实使用深度

- 产品方案必须列出内容与功能覆盖表：用户任务、主页面模块、内容数量、细节深度、交互结果及验收方式。拍摄、导入、录音仅在实际选用时接入有意义的主题流程，例如记录观察、补充素材或添加语音说明；这些只是可选设计方法，不固定主题，也不要求三项出现。
- 每项核心页面和主要目的地都必须映射到差异化 brief 或清楚标为支持职责：说明它服务哪个主题任务、为何需要此页面/目的地、承载什么真实结果。至少一个主要任务需呈现主题专属的数据/内容模型或交互规则；把通用界面换成 Logo、渐变、卡片、Emoji 或插画，不算产品差异。
- 标志性动作应是对当前创意最自然的操作，能尽早给用户一个明确结果；具名成果应可在本地保存并再次打开/继续。相机、相册和麦克风可自由选择任意组合或全部不选。仅已选路径需要连接实际主题成果，说明各自信息价值，不增加无关入口或通用媒体仓库。
- 竞品或市场比较只陈述有来源的事实；没有核验材料时，记录为“未验证”，以产品内可见的任务流程与数据结构评估差异，不把竞品调研设置为继续开发的前提。
- 至少提供三个有不同用户结果的完整任务流程，每个流程具备入口、操作、结果、再次查看和错误/取消处理；流程由主题任务决定，不要求媒体能力；若选用媒体，可共同服务一个核心流程或分布在不同流程，不用重复页面凑数。
- 内容浏览型产品至少覆盖三个有实际差异的主题分类，每类至少八条经过整理的有效内容，详情提供结构化正文与可执行动作；重复标题、同图换名和无意义占位不计数。工具型产品至少提供三个实用工作流，每个有两组真实可用的示例输入与结果；无需为了数量强行加入无关内容列表。混合产品对其实际包含的模块分别验收。
- 主内容页应有清晰的主任务、多个有区分的内容/工具模块和可继续探索的二级层次；拍摄、录音等聚焦操作页以操作清晰为先，不强行堆卡片。搜索、筛选、排序、说明、详情和本地媒体管理按任务需要组织，所有可见动作必须有真实结果。
- 全页面图文覆盖按第 6.10 节执行：为每个 App 可控制页面及适用状态规划实际信息模块和有意义的非纯文字表达，不能只给首页加图、让详情/搜索/Settings/工具/空态仍是文字堆叠。摄影、图解、真实媒体预览、状态插画与分组控件随页面职责选择；详情有至少三个不同信息价值的模块，聚焦操作与确认框保持简洁且完整，不能用无关功能、重复段落或虚构数据凑丰富度。规划项纳入第 3.2 节追踪表并逐页验收。
- 页面清单按唯一 `page_id` 分类，逐项写明页面类别/路由、独立 Dart 页面文件、页面专属装饰资源 `assets/backgrounds/<page_id>/<page_id>_background.png`、装饰的透明叠加或边框位置及验收方式；所有页面均需专属文件与专属装饰素材，不得把页面实现都堆进一个 Dart 文件或复用一张装饰图而不标明实际差异。
- 对每个主要内容浏览页规划有语义依据的卡片尺寸层级，例如重点精选项使用较大的图文卡片、普通条目使用标准卡片、辅助或快速浏览项使用紧凑行；每个主要内容列表至少呈现两种清楚可见的尺寸，不同主要页面合计覆盖三种层级（内容规模允许时）。多个主要页面都是内容列表时，必须在跨主要页面方案中安排至少两种有意区分的主编排，例如垂直分组列表、双列网格、精选大卡加横向滚动、瀑布流/不规则卡片或分段式复合布局；不要求每个主要页面都完全不同，也不机械禁止复用 `ListView` 等基础组件，但主要视觉节奏、卡片比例、信息密度或浏览方式必须有真实差异。单个页面可以复合使用多种编排，并允许卡片长短不齐、大小不一、图片比例不同；`featured` / `standard` / `compact` 等尺寸角色必须由内容重要性、任务优先级、信息密度、媒体比例或排序依据决定，并记录原因、顺序、尺寸约束和响应式降级。禁止随机错落、只为装饰改变尺寸、固定高度截断文字、拉伸图片或让不规则布局破坏 VoiceOver/Dynamic Type；Settings、协议、权限和纯选择/比较等扫描型列表继续使用整齐易扫读的统一行样式。
- 复合页面须写明各区域层级、排列顺序和共享/独立滚动边界；小屏或大字号时可降级为单列或更紧凑的流式布局，但保留至少两级内容层次和原有任务/阅读顺序，不将卡片随机重新排序。
- 首次使用即有可浏览的原创或许可明确的示例；若包含用户私有媒体功能，则从空状态起步并引导实际创建；示例媒体清楚标识，不能冒充用户拍摄或录制内容。未选媒体能力时不建私有媒体空库。
- 不得因需要精修 UI 就削减已确认的内容与选定功能，也不得为了填满屏幕重复卡片、插入无关功能或改变用户创意。实际内容覆盖与质量未达标时继续完善，并如实记录未完成项。

## 5. 动态信息架构与导航

### 5.1 按主题选择导航模式与 UI 风格

底部导航栏不是默认骨架，也不是必做功能；允许完全没有 Tab 的 App。根据当前主题、用户任务、内容结构、访问频率、任务连续性和 iPhone 操作方式选择整体 UI 与导航，不将每个创意都转换成“底部三到五个 Tab + 首页卡片列表”。用户已明确指定的导航/风格优先，缺失部分由智能体自主设计。

用户未明确指定导航时，在内部比较至少两种结构上不同、对当前任务可行的导航方案，再选定最合适的一种，随既有思维导图展示选择依据与关键路径，不让用户额外选择导航菜单、不新增审批。比较应涉及如何进入主要任务、切换目的地及返回，不只比较底栏外观。至少包含一个无固定底部导航栏的可行方案；若确实不适用，说明具体任务原因。底部导航可以被选用，但须有多个高频、平级目的地及切换需求的具体依据，不能以“移动 App 通常如此”作为理由，也不为追求差异随机选择难用的结构。

可采用任何适合主题的视觉表达与组合，以下仅为参考，不是固定菜单或主题到样式的一对一模板：

| 核心组织需求 | 可考虑的导航与界面组织 |
| --- | --- |
| 围绕一个主要任务创建/处理成果 | 单一工作台、画布或工具界面，配上下文工具栏与按需 Sheet |
| 按章节或专题理解内容 | 可浏览的目录、顶部栏目、分段切换、杂志式编排与层级返回 |
| 按先后步骤完成实际任务 | 步骤式流程、阶段路径、可返回的任务面板，不强加全局 Tab |
| 从主题对象或空间关系开始 | 对象总览、关系图、地图或展陈式入口，选中对象后进入详情/操作；仅在主题真实需要时采用 |
| 多个需要频繁切换的平级任务 | 有明确文字标签的顶部/底部导航、紧凑悬浮 Dock 或混合导航，依实际触达与可用性选择 |
| 多个低频辅助目的地 | 清晰的菜单、目录入口或按需面板，与主任务层级区分，不把所有入口堆进持久底栏 |

导航形式、首屏构图、内容组织、排版、图片比例、材质/边框、控件与动效共同形成贴合主题的视觉语言，可以采用编辑式、展陈式、仪表/工具式、手工/艺术式等有依据的组合；不固定为“渐变卡片墙”，也不把底栏换成悬浮胶囊就当作产品结构创新。Logo 色板、渐变、圆角、真实本地图片和内容丰富度仍按当前要求落实，但不据此强制同一布局；第 6.9 节的列表尺寸规则仅用于实际存在的内容列表，不为满足它凭空增加浏览页或卡片列表。

- 每个主要目的地承担明确的主题任务，命名、入口位置、首屏与返回路径可理解；数量由真实任务决定，可以只有一个主工作区，不为凑 Tab 添加空壳页面。
- Settings、协议及实际选定的媒体功能保持完整与可达性，可以通过标题栏、上下文操作、目录或按需面板进入，不强制独立 Tab；不新增账户/个人资料功能。
- Welcome 的 `Continue` 与清除成功后 Initialization 的 `Entry` 都进入选定的主任务入口；其目标可以是工作台、目录、画布或选定目的地，无需先进入 Tab 容器。三种启动/返回页面和协议文案边界不变。
- 自定义导航提供明确可点击的文字/图标与选中状态；不只依赖手势、装饰或不可见热点。验证 iPhone 单手触达、至少 44×44pt 操作区域、SafeArea、Dynamic Type、VoiceOver 顺序、减少动态与 Light/Dark。
- 每个目的地记录入口、路由、返回栈、选中/恢复规则及适用的滚动、查询/筛选、任务草稿状态；Sheet 关闭、详情返回、清除数据和系统返回不能丢失有效状态或重建重复页面。按实际功能维护状态，不为无 Tab 的项目添加无用 selectedTab 状态。
- 信息架构和导航壳层由主题方案装配；只有选用 Tab 时才使用 `BottomNavigationBar`、`NavigationBar`、`CupertinoTabScaffold` 等相应组件，不在通用根 App 中预装。仅制作 iPhone 布局，允许适合 iPhone 的菜单/抽屉与窄屏面板，不引入其他设备的侧栏/分栏版本。
- 在 `.codex-work/navigation-design.md` 记录方案比较、选定模式、主题依据、视觉构图、入口/返回映射与实际截图/交互证据；最终核对成品是否真正落实所选结构，不能只改方案文字或隐藏底栏但保留空白占位。

### 5.2 中央路由注册表

路由根据用户创意、选定导航模式和实际目的地生成，并纳入思维导图整体确认；用户已明确给出的导航要求优先，不再单独要求用户选择或确认 Tab。确认后建立路由注册表。以下仅为路由示例，与创意无关的路由不创建；`/tab/<tab-id>` 仅在实际选用 Tab 时适用，不要求所有项目使用 Tab 命名或容器：

```text
/welcome
/entry
/workspace
/destination/<destination-id>
/detail/<content-id>
/player/<content-id>
/capture/camera
/import/photos
/record/audio
/media/<local-media-id>
/search
/filter
/settings
/about
/support
/policy/privacy
/policy/terms
/policy/disclaimer
/policy/content-copyright
/webview/<document-id>
```

统一注册页面路由 ID、参数解析、访问边界、返回规则，以及会影响 App 导航/生命周期的 Dialog、Sheet 和 Tab 动作；`routes.dart` 为默认注册入口，已有项目可复用等价路由模块。`/welcome` 是每次启动入口，承载启动准备状态及 `Continue`；`/entry` 专指清除成功后出现、带 `Entry` 动作和底部协议文案的初始化页。二者不得复用同一页面实例或改名互换。页面通过统一导航接口发出动作，不重复拼接路径或自行重建 Continue、清除确认和清除后到 `/entry` 的规则。局部、无导航副作用的提示可由共享组件承载，不强迫所有 UI 代码堆到一个文件。`/about`、`/support`、`/policy/*` 和 `/webview/<document-id>` 均由同一个 `policy_webview_page` 加载注册文档；未知 ID、失效参数和不存在的内容必须有安全的错误/返回路径，不能解释成任意 URL 或本机文件路径。

最终 AppListing 改名整理为 `aduit/` 后、生成 Review Remarks 前，先按第 12.1 节将 `aduit/site/index.html` 的生成 About Home 完全替换为单文件自包含产品引导页，并将该随包文件作为 Welcome 页的本地 WebView 内容；引导页每张显示的图片均编码为 Base64 data URI 内嵌到该 HTML，不能引用项目 assets、相对图片路径、`file://` 或远程图片 URL，以确保文件经中转后独立可显示。`Continue` 经 AppBridge 或原生拦截的 `go://continue` 执行原有进入逻辑。此欢迎引导页不显示协议同意文案或 Terms/Privacy 页脚链接。完成引导页验收后，将 `aduit/intro.md` 的 `All URL` 区域列出的四个 URL 原样复制到 App 的固定 URL 注册表，并绑定对应文档名称；在初始化页 `/entry` 底部显示通用协议文案，并把 Terms/Privacy 两段分别链接到对应原始 URL。Settings 只显示 Privacy Policy、Terms of Use、Support 三个入口；欢迎页/引导页和初始化页均不作为 Settings 入口。不得规范化、补全、替换、探测或因格式/可达性异常而跳过注册值；不开放任意 URL 输入或导航。回归时仅用不发起网络请求的 WebView stub/fake 核验注册值、Settings 不含首页、初始化页两个协议目标、错误态与返回路径，不访问或探测真实目标。最终 App 运行时由用户主动点击后才请求对应地址；请求失败时显示可读错误与返回/重试操作，主流程不受影响。

### 5.3 返回行为

- 从详情或播放器返回时，保留来源目的地及其导航/任务状态、搜索词、筛选、排序、视图模式和滚动位置。
- 从 Support 或协议内容返回时，保留 Settings 滚动位置和主题状态。
