## 4. 根据主题自动生成的产品定义

根据用户创意确定主题后，智能体自动填写以下内容并纳入待确认的思维导图与方案，整体确认后实施；内容单位、数据模型和核心旅程随创意变化，不机械复用示例产品：

- `Working app name`。
- `One-sentence promise`。
- `Primary user and context`。
- `Core user journey`。
- `Content unit and seed-data strategy`。
- `Core success signal`。
- `Out-of-scope capabilities`。
- `Open assumptions and their consequences`。

### 4.1 核心旅程

以下流程是通用骨架，不是固定产品方案。核心动作、内容单位、详情页和工具应按用户创意替换或裁剪；与创意无关的浏览、搜索、阅读、播放等能力不加入实现。

```text
Launch
  -> Read local theme preference and introduction display history
  -> Prepare local data repository and audited resources
  -> Show Entry (the final local guide has a Continue button; development preview may use Enter)
  -> Tap Continue (or the pre-listing Enter preview) and open the selected primary tab directly
  -> Browse, search, filter, calculate, read, or play the core content
  -> Open detail or complete the primary action
  -> Adjust a theme-related preference if useful
  -> Recompute affected screens and show observable feedback
  -> Tap Clear Data in Settings and review the confirmation
  -> Cancel and keep using the current page without changing data
     OR confirm Clear Data, stop media, and clear app-owned local data
  -> On verified success, reset preferences and return to the same Entry
  -> On failure, show the remaining work and offer a recoverable retry
```

每个转移都必须产生 UI 反馈。只有数据层变化、页面没有可见状态变化，不算完成。

### 4.2 内容丰富度与真实使用深度

- 产品方案必须列出内容与功能覆盖表：用户任务、主页面模块、内容数量、细节深度、交互结果及验收方式。核心用途之外仍必须把拍摄、导入、录音接入有意义的主题流程，例如记录观察、补充素材或添加语音说明；这些只是设计方法，不固定产品主题。
- 至少提供三个有不同用户结果的完整任务流程，每个流程具备入口、操作、结果、再次查看和错误/取消处理；三项媒体能力可以共同服务一个核心流程，也可以分布在不同流程，不用重复页面凑数。
- 内容浏览型产品至少覆盖三个有实际差异的主题分类，每类至少八条经过整理的有效内容，详情提供结构化正文与可执行动作；重复标题、同图换名和无意义占位不计数。工具型产品至少提供三个实用工作流，每个有两组真实可用的示例输入与结果；无需为了数量强行加入无关内容列表。混合产品对其实际包含的模块分别验收。
- 主内容页应有清晰的主任务、多个有区分的内容/工具模块和可继续探索的二级层次；拍摄、录音等聚焦操作页以操作清晰为先，不强行堆卡片。搜索、筛选、排序、说明、详情和本地媒体管理按任务需要组织，所有可见动作必须有真实结果。
- 对每个主要内容浏览页规划有语义依据的卡片尺寸层级，例如重点精选项使用较大的图文卡片、普通条目使用标准卡片、辅助或快速浏览项使用紧凑行；每个主要内容列表至少呈现两种清楚可见的尺寸，不同主要页面合计覆盖三种层级（内容规模允许时）。在思维导图/页面规格中记录条目为何属于该层级、图片比例与裁切、文案密度和顺序。大小不能随机轮换、仅为填屏而变化，不能靠重复或无关内容制造丰富感；Settings、协议、权限和纯选择/比较列表继续使用整齐易扫读的统一行样式。
- 首次使用即有可浏览的原创或许可明确的示例；用户的本地媒体从空状态起步，并通过引导可完成创建。示例媒体必须清楚标识，不能冒充用户拍摄或录制的内容。
- 不得因需要精修 UI 就削减内容和三项媒体能力，也不得为了填满屏幕重复卡片、插入无关功能或改变用户创意。实际内容覆盖与质量未达标时继续完善，并如实记录未完成项。

## 5. 动态信息架构与导航

### 5.1 Tab 设计规则

- Tab 名称根据主题生成，由智能体自主选定；用户已明确指定的导航要求优先。
- 没有必选默认集合，也没有硬编码数量上限。
- 持久 Tab 必须各自承担不同用户任务，不得把单纯的设置分组做成 Tab。
- 智能体可以出于可用性建议更少的 Tab，但建议不是限制。
- 当产品需要很多目的地时，使用适合 iPhone 的主 Tab、二级 Tab、Sheet 或嵌套路由保持可达性；不生成其他设备的大屏侧栏或分栏版本。
- 不得使用账户相关名称伪装个人数据功能。
- 每个选中的 Tab 都必须出现在路由图、页面清单、状态模型和验收测试中。

### 5.2 中央路由注册表

路由根据用户创意和智能体推荐的 Tab 生成，并纳入思维导图整体确认；用户已明确给出的导航要求优先，不再单独要求用户选择或确认 Tab。确认后建立路由注册表。以下仅为路由示例，与创意无关的路由不创建：

```text
/loading
/entry
/tab/<selected-tab-id>
/detail/<content-id>
/player/<content-id>
/capture/camera
/import/photos
/record/audio
/media/<local-media-id>
/search
/filter
/settings
/about
/support
/policy/privacy
/policy/terms
/policy/disclaimer
/policy/content-copyright
/webview/<document-id>
```

统一注册页面路由 ID、参数解析、访问边界、返回规则，以及会影响 App 导航/生命周期的 Dialog、Sheet 和 Tab 动作；`routes.dart` 为默认注册入口，已有项目可复用等价路由模块。页面通过统一导航接口发出动作，不重复拼接路径或自行重建 Continue、清除确认和成功返回欢迎页的规则。Entry 与欢迎页是同一个 `/entry` 页面，不创建第二个同义目的地。局部、无导航副作用的提示可由共享组件承载，不强迫所有 UI 代码堆到一个文件。`/about`、`/support`、`/policy/*` 和 `/webview/<document-id>` 均由同一个 `policy_webview_page` 加载注册文档；未知 ID、失效参数和不存在的内容必须有安全的错误/返回路径，不能解释成任意 URL 或本机文件路径。

最终 AppListing 改名整理为 `aduit/` 后、生成 Review Remarks 前，先按第 12.1 节将 `aduit/site/index.html` 的生成 About Home 完全替换为单文件自包含产品引导页，并将该随包文件作为 Entry 的本地 WebView 内容；引导页每张显示的图片均编码为 Base64 data URI 内嵌到该 HTML，不能引用项目 assets、相对图片路径、`file://` 或远程图片 URL，以确保文件经中转后独立可显示。`Continue` 经 AppBridge 或原生拦截的 `go://continue` 执行原有进入逻辑。完成引导页验收后，将 `aduit/intro.md` 的 `All URL` 区域列出的四个 URL 原样复制到 App 的固定 URL 注册表，并绑定对应文档名称。Settings 只显示 Privacy Policy、Terms of Use、Support 三个入口；引导页/原 About Home 均不作为 Settings 入口。欢迎页只提供 Terms/Privacy 文本链接。不得规范化、补全、替换、探测或因格式/可达性异常而跳过注册值；不开放任意 URL 输入或导航。回归时仅用不发起网络请求的 WebView stub/fake 核验实际入口传入 URL、Settings 不含首页、错误态与返回路径，不访问或探测真实目标。最终 App 运行时由用户主动点击后才请求对应地址；请求失败时显示可读错误与返回/重试操作，主流程不受影响。

### 5.3 返回行为

- 从详情或播放器返回时，保留来源 Tab、搜索词、筛选、排序、视图模式和滚动位置。
- 从 Support 或协议内容返回时，保留 Settings 滚动位置和主题状态。
- 从协议 WebView 返回时，保留来源页面、主题状态和滚动位置；协议查看不改变 App 访问状态。
- 从最终 Entry 引导页点击 `Continue` 后（或在改名前的开发期原生预览点击 `Enter`），用同一替换导航进入第一个选定 Tab，避免返回栈重复堆叠 Entry。
- 从 Settings 点击 `Clear Data` 只打开确认对话框；取消或确认前关闭对话框，保留原页面、主题和所有数据。确认后按第 7.7、8.5 节清理，真实成功才清空返回栈并回到 Entry；主题与筛选等偏好恢复默认，随包内容保留。清理进行中或失败时不得返回旧内容页、通过深链打开旧记录或提前进入主 Tab。
- 页面销毁时取消异步任务，或忽略其过期结果。
