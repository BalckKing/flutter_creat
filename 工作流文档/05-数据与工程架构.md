## 8. 状态、数据与持久化

### 8.1 状态层

- `AppState`：启动阶段、主题模式、首次使用介绍展示记录、选定 Tab 和全局错误。
- `AppFlowState`：仅存于内存的 `entry`、`active`、`clearing` 流程状态，包含防重复导航和写入隔离，不含身份信息或认证凭据。确认框打开时仍为 `active`；确认后进入 `clearing`，删除已开始后的失败/恢复仍保持此状态，只有清理成功才转为 `entry`。恢复标记写入失败且尚未开始删除时，按第 7.7 节安全恢复 `active`。新进程按第 7.1 节检查恢复标记后进入正常欢迎页或清理恢复流程。
- `ClearDataState`：确认框是否已打开、清除操作 ID、停止媒体、删除数据、重置默认值、核验、失败和完成阶段，以及真实进展与可重试性；持久化的最小恢复标记按第 8.5 节定义，不持久化页面/身份状态。
- 每个选定 Tab 一个状态对象：查询、筛选、排序、视图、内容、加载、空、错误和成功值。
- `DetailState`：内容加载、展开区段、相关内容和归因。
- `PlayerState`：媒体来源、位置、控制器生命周期、重试和中断。
- `PolicyState`：本地文档读取状态、错误原因、标题和文档版本；版本属于文档元数据，不是个人同意记录。
- `CaptureState`、`ImportState`、`RecordingState`：对应权限、设备准备、采集中、预览、保存、取消、错误和已释放状态；回调带操作标识，旧任务不得覆盖新状态。
- `LocalMediaState`：已保存媒体、主题关联、预览/播放、删除与存储错误；`PermissionState` 从系统读取相机、录音、必要的 PhotoKit 状态与 ATT 状态，彼此独立。

### 8.2 本地持久化白名单

只持久化确实能改善核心体验的数据：

- 主题模式。
- 首次使用介绍展示记录；只调整 Entry 内容展示，不作为进入条件。
- 如果需要，保存英文 locale 标记。
- 与主题相关的筛选偏好。
- 主题确实需要时保存当前浏览或媒体位置。
- 用户明确保存的照片、导入文件、录音、主题关联与必要元数据，以及准确的格式、尺寸或时长；文件仅放在 App 私有目录，临时采集不作为已保存内容。

不得持久化邮箱、密码、验证码、登录状态、认证令牌、个人协议同意记录、远程账号凭据、社交、云端媒体上传、社区或个人资料数据，不建立用户账号实体。`AppFlowState` 不写入本地存储，也不从旧登录记录恢复；本地导入、采集与私有媒体索引按上述白名单保存。保存/删除事务和全量清除可持久化最小故障恢复信息，仅用于保证数据一致性，不记录身份、媒体正文或个人协议同意；成功后移除相应标记。白名单中的用户数据与偏好均属于第 8.5 节的全量清除范围。

### 8.3 内容模型

根据用户创意生成聚焦而完整的领域模型。以下 `ContentItem` 仅是内容浏览类 App 的字段示例，不是所有主题的必选模型；模型名称、实体关系和字段均由实际核心功能决定，不得为了套用示例把产品改成阅读或媒体浏览工具。

```text
ContentItem {
  id,
  title,
  subtitle,
  category,
  tags,
  description,
  mediaRefs,
  duration,
  source,
  license,
  attribution,
  searchableText,
  sortWeight,
  consumerScreens
}
```

列表的 `featured`、`standard`、`compact` 等视觉角色属于页面展示策略或 ViewModel，不是领域事实；只在确有策展/排序意义时存储相应稳定标记，不把屏幕像素尺寸、卡片高宽或随机样式写入核心领域实体。用共享的列表呈现策略将语义角色映射到可响应式调整的布局尺寸，并保证排序、筛选、数据身份和 VoiceOver 顺序不受外观层级意外改变。

每个可见条目都必须对应本地模型；随包媒体对应资源清单条目，用户运行时拍摄、导入和录制的媒体使用私有本地索引，不写入随包清单、公开归因页或日志。私有媒体模型至少记录 `id`、`sourceType`、`localPath`、`mediaType`、`createdAt`、`sizeBytes`、适用的 `dimensions`/`duration` 与主题记录关联，不保存无用途的定位或身份元数据。缺失字段或文件必须产生可观察的空/错误状态，不得静默忽略。

### 8.4 本地媒体事务、存储与故障恢复

- 区分随包只读资源、可清理的派生缓存、待提交临时采集和用户已保存媒体；永久文件放在稳定的 App 私有目录，不使用系统可能回收的临时目录。主题记录持久化稳定媒体 ID，由服务解析当前沙盒路径，不依赖安装后可能变化的绝对沙盒前缀。
- 保存使用唯一操作 ID，先写临时文件并校验实际格式、可读性及必要元数据，再在同一文件系统完成原子移动并提交索引/主题关联。文件操作与数据库不假称天然处于同一事务；使用可恢复的暂存记录或等价提交协议，只有文件与关联均提交后才向 UI 报告成功。失败保留可重试的当前预览或回滚本操作，重复点击不生成重复记录。
- 启动或进程中断后核对待提交操作、缺失文件、孤立暂存文件与索引，不误把用户内容当缓存清掉；恢复不能阻塞全部启动，按第 7.1 节延后处理非关键扫描。对已保存内容的损坏提供具体错误与恢复路径，不静默覆盖或伪造空列表。
- 删除只针对用户明确选中的媒体 ID，先停止其预览/播放，处理所有实际关联，再清理该媒体文件、派生内容与索引。可用删除标记支持失败重试，部分清理失败不能显示已全部删除；不得删除其他记录仍引用的文件、系统相册原件或无关项目数据。
- 方案记录可接受的单文件大小、导入批量、录音时长、缓存和空间预算，按目标设备及主题确定，运行前检查实际空间并处理写入期间耗尽。使用流式复制/受限解码处理大文件，导入取消、录音停止和确认后的全量清除均有反馈；普通取消与空间管理只清理本操作临时文件，不擅自删除已保存媒体，用户明确确认的全量清除另按第 8.5 节执行。
- 文件保护、备份排除、缩略图与临时文件的生命周期一并核验；目录遍历、文件名碰撞、失效路径和过期回调不能覆盖已有内容。日志只记录脱敏操作与错误，不输出私有媒体路径、正文、缩略图或音频数据。
- 保存、单条删除、存储恢复与全量清除共享写入协调机制。全量清除先阻止新事务，再让已进入提交阶段的操作完成或可靠回滚，随后删除其目标内容；迟到回调不得提交到已重置的数据集。不能让启动恢复服务在清除期间重新导入孤立文件或重建已删除记录。
- 导入与采集只保留主题确实需要的元数据；不需要的位置、设备标识等嵌入元数据应从 App 自有副本安全移除，并复验方向、色彩和可读性，不改动系统相册原件。不能只删除索引字段就声称已去除文件内 EXIF 等信息。

### 8.5 全量清除范围与中断恢复

为每个实际使用的本地存储登记所有者、位置、清理方式和验证依据，所有清理限制在已核实的 App 自有数据项与目录；不靠广泛递归删除整个沙盒、共享容器、系统照片库或开发工作目录完成清理。新增数据类型、SDK 或缓存时同步更新此清单、确认文案、隐私政策和验收用例。

| 数据范围 | 清除或保留规则 |
| --- | --- |
| 用户媒体与主题数据 | 删除 App 私有的拍摄照片、导入副本、录音、可变主题记录、关联、索引与元数据；共享引用在全量清除中统一处理，不留下孤立副本 |
| 临时和派生内容 | 删除暂存/未提交文件、缩略图、波形、转码文件、App 私有的迁移/恢复副本与旧版本数据、运行时下载缓存及磁盘/内存缓存；旧后台任务不能重新生成 |
| 本地设置 | 清除主题、介绍展示记录、locale 偏好、筛选、排序、视图、浏览/播放位置等实际持久化项，重新初始化默认值；不保留旧偏好 |
| WebView 与第三方本地状态 | 清理实际存在的 App 自有 WebView 缓存、Cookie、网站存储及 SDK 本地缓存；使用平台/插件支持的接口，核验覆盖范围，不清除系统浏览器或其他 App 的数据 |
| 随包只读内容 | 保留 Logo、AppIcon、许可素材、种子内容、About/Support、协议及版本信息；重新从种子源构建默认内容，不重新下载、不冒充用户媒体 |
| App 外的数据与系统状态 | 不删除系统相册原件、已经导出到 App 外的文件或现存备份，不重置 iOS 摄像机/相册/麦克风授权与 ATT；后续状态从系统读取 |
| 开发产物与恢复标记 | 不涉及源码、资源源文件或开发目录 `aduit/`；运行时恢复标记仅在全部清理与重建核验通过后移除，失败时保留 |

清除操作使用稳定的操作 ID 和数据版本/代次，恢复标记在破坏性步骤开始前以原子写入/替换方式可靠落盘，并验证实际提交状态；只包含恢复所需的操作、阶段和未完成项，不记录媒体正文、身份或协议同意。该标记与待清数据分离，不能被清理设置/数据库的步骤先行删除。逐阶段更新并验证实际结果，数据库连接、事务、旁路文件与 SDK 存储按实际实现关闭/清理，不能只清空 UI 列表或删除一个数据库文件就算完成。

进程关闭、崩溃或后台中断后，先读取标记并隔离旧数据，幂等继续已确认的清除，不再次询问是否清除；已完成步骤可核对后跳过，缺失目标视为该项已删除，真实错误仍须重试或显示可恢复失败。清除过程中无网络也能执行。默认数据重建使用随包源，只恢复示例与默认设置，不恢复被删除的用户媒体；恢复服务、旧事务和迟到回调不得跨数据代次提交。

成功判定须同时核对用户文件、主题记录、索引/关联、派生文件、临时项、偏好、WebView/SDK 存储、内存状态和设备释放；任一实际目标未清理就不能标记成功。移除恢复标记是最后的持久化完成步骤，完成前不开放 `Enter`。不承诺物理安全擦除、删除系统备份或删除 App 无法管理的副本，隐私政策与 UI 必须使用准确的范围说明。

### 8.6 数据版本与升级兼容

种子清单、用户数据与偏好使用明确版本；更新 App 时迁移应保留已有用户媒体与稳定 ID、关联和合法偏好，不把升级当作清除。迁移先验证可读性与恢复路径，失败保留原数据并给出可恢复错误，不以解析失败、未知字段或缺失文件为由静默重置；临时迁移副本也纳入 App 自有数据与备份边界。存在未完成清除时优先处理该操作，禁止迁移或恢复旧副本重新带回已删除内容。只有当前结构确有迁移需求时实现对应迁移，不添加无用途的数据库层。

## 9. Flutter 工程架构

以下是新项目的默认边界与示意结构；复用已有项目时保留与这些边界兼容的架构、状态管理和命名，不为凑目录机械重写。新增 Dart 文件采用 `lower_snake_case`；已有外部引用文件改名时同步引用并验证，不能仅按示意树批量重命名。

本工程只生成 iOS 平台目标，应用设备 family 固定为 iPhone；最低 iOS 部署版本为 15.6，默认设置为 15.6，实际依赖要求更高时保留更高版本并记录依据。创建参数、各构建配置、运行目标与产物检查统一按第 0.10 节执行。架构树不新增其他平台目录、入口、适配层或打包脚本；可注入服务与单元/Widget 测试仍按本节实现，不用跨平台运行代替 iPhone 验收。

`ios/Podfile` 是 iOS 权限插件的构建配置来源之一。依照第 0.7 节，在确认插件和 API 后尽力设置最小权限宏；若宏配置失败，使用最后一个语法有效版本继续安装 Pods 并尝试打包，同时单独记录宏状态和权限验证缺口。宏配置失败本身不是停止打包的条件。
