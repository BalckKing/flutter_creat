## 6. 视觉系统与 UI 质量

### 6.1 视觉方向

按第 5.1 节从主题、核心任务与内容形态确定 UI 风格、导航和首屏构图，允许采用任何适合当前主题且在 iPhone 上清晰可用的风格及组合。信息密度、留白、排版、控件和媒体组织随任务调整；底部导航、卡片墙或高密度列表都不是统一骨架，聚焦工具可以采用更克制的操作界面，内容浏览可以采用更丰富的编排。以下质量要求适用于所选风格，不要求所有项目长成同一种界面：

- 首屏必须展示真实主题内容和明确的下一步动作。
- 每个 App 可控制页面及其适用状态都必须按第 6.10 节实现有用的图文内容与视觉层次，覆盖二级页面、工具、Settings、空/错误状态和 Sheet/Dialog；不能只美化 Welcome 或 Initialization，其余页面退化成标题加大段正文或孤立按钮。
- 层级清楚：页面标题、核心任务、内容分组、辅助信息、次要操作。
- 先定义与主题内容有关的视觉语法：核心对象如何被表现、内容如何分组/排序、重点状态如何区分、哪些图形/动效具有具体含义。使视觉决策服务差异化 brief 和核心循环；不能把只更换 Logo、渐变、圆角卡片、Emoji 或背景装饰视为产品差异。
- 鼓励使用与理解内容有关的图片、视频封面、轻量背景和状态色。
- 必须根据用户创意加入多种贴合主题的 Emoji，丰富欢迎页、内容分类/模块和适用状态反馈的视觉效果；具体使用与验收按第 6.8 节执行，不能只在设计说明中写计划而不实际显示。
- 视觉基调必须鲜艳、鲜明且有层次，以第 2.5 节从最终 Logo 提取的主色、辅助色与强调色作为项目配色依据；使用协调的高饱和强调与稳定阅读表面，不套用与 Logo 无关的固定色表，不用灰暗或杂乱的配色削弱品牌。
- 渐变是主要视觉语言之一，用于品牌背景、Welcome/Initialization、主要 CTA、选中态、卡片强调区和 WebView 外层容器；条件允许时优先采用第 6.5 节的动态渐变，渐变必须服务于层级，不得让内容变得难以阅读。
- 全项目按第 6.5 节建立可见的多色渐变体系，结合真实内容图片、主题图形、表面明暗与品牌色点缀形成丰富但有秩序的视觉效果；渐变不能只停留在令牌或设计稿，不能无差别铺满所有区域，也不能削弱文字对比度。
- 每个 App 自有页面都必须呈现至少一种与当前主题相关的背景装饰图案，使用 `http://stargate.local:3100/image` 按页面主题绘制；图案作为低透明度叠加纹样，或布置为边缘/卡片周围的装饰边框，不得遮住正文、控件、相机取景或录制状态。实际生成与素材目录、命名、接入规则见第 6.11 节。
- 所有由 AI 生成并实际用于项目的图像（包括 Logo、插画和装饰图）不得使用简约线条、细轮廓、扁平几何或单纯色块堆叠作为整体风格或主要主体；必须根据主题制作细节充分、层次丰富、完成度高的图像，使用鲜明而协调的色彩、质感/笔触与完整构图。线条或色块可作为丰富画面中的次要细节，但不可成为简化主体的替代方案。此要求不改变第 10.6 节必须使用可核验许可的真实第三方摄影这一要求，AI 图不能冒充真实照片。
- 不要用空白营销 Hero 代替 App 的核心体验。
- 智能体先生成符合创意且色彩鲜艳的 Logo，再从其实际色块定制 App 与 About 主题色及渐变，说明原始色、衍生色的用途与选择理由；确认前只规划方法，正常路径的最终色值不能先于 Logo 提取。

### 6.2 主题模式

Settings 必须提供 `System`、`Light` 和 `Dark`，默认值为 `System`。选择结果必须同步到所有选定主要目的地、Welcome、Initialization、详情、播放器、空状态、错误状态以及协议 WebView 外层容器；取消清除确认时保持原主题，清除成功后恢复 `System` 并立即同步到初始化页与后续页面。

### 6.3 设计令牌

在 `lib/common_module/theme/app_theme.dart` 定义全局令牌，页面中禁止散落硬编码。该文件是全项目唯一的品牌色彩调用入口：完成最终 Logo 导入后，从 `assets/logo.png` 的实际像素提取代表色，再写入 `AppPalette`/`AppTheme` 与共享浅色、深色和渐变令牌；页面、组件和 HTML 主题映射只能通过该文件消费品牌色，不能另行复制一套色值。

- Flutter 布局尺寸按逻辑像素定义，WebView CSS 尺寸单独注明 CSS px，不把物理像素、pt、dp 和 CSS px 混为一组数值。
- 间距：4、8、12、16、20、24、32、40、48 个逻辑像素。
- 圆角：4、8、12 个逻辑像素；主要内容面最大 16。
- 所有 App 自有界面及 About/协议/引导 HTML 中的图片展示位统一使用清晰可见的圆角，覆盖 Logo、列表配图、详情大图、缩略图、视频封面、用户导入图片、相机预览和图片查看器；禁止漏用圆角或 `borderRadius: 0`。统一通过 `mediaRadius` 令牌管理，默认 12 个逻辑像素，紧凑缩略图可用 8、大图可用 16，同类展示位保持一致；HTML 使用对应的 CSS px 令牌。
- 圆角必须真正裁剪图片及其叠层：Flutter 使用共享媒体容器与 `ClipRRect` 或等价实际裁剪，加载/错误状态、角标和渐变遮罩均不能溢出；仅设置外框 `borderRadius` 而图片仍露出尖角不合格。HTML 的图片与容器同步设置 `border-radius`，容器使用 `overflow: hidden`，边框计入尺寸；放大查看、轮播切换和转场过程中也保持圆角。页面背景装饰图在所属容器内裁剪，不露出独立直角贴图。
- 可以在图片卡片、缩略图、封面和媒体预览周围适当增加细边框，统一使用 Logo 衍生的半透明品牌色或协调渐变，默认宽度为 1 个逻辑像素（HTML 为 1 CSS px）；按浅/深色表面调整可辨度，边框与图片共用圆角，不叠加多重粗边、不遮挡主体，也不挤压内容或点击区域。
- 圆角属于展示规则，不改坏原始图片：`assets/logo.png` 继续满足 1024×1024、无 Alpha，不能把透明圆角写进主 Logo；AppIcon 源图保持完整，由 iOS 应用系统蒙版。原生 Launch Screen 的品牌图使用符合静态启动规范的圆角展示或匹配背景的静态派生图，不加入运行时代码；系统相册选择器等系统界面保持原生样式。
- 点击区域：iPhone 上至少 44×44pt，在 Flutter 中按对应逻辑尺寸实现。图标外观尺寸可更小，但不能缩小可点击区域。
- 正文基准字号至少 16 个逻辑像素，HTML 正文至少 16 CSS px，行高约 1.45–1.6；保留系统文字缩放，不用固定字号绕过 Dynamic Type。
- 动效：反馈 80-150ms，转场 220-350ms，列表交错 300-450ms；支持减少动态效果。
- 对比度：普通正文至少 4.5:1，有意义的图标和控件边界至少 3:1。
- 色彩令牌包含来自 `assets/logo.png` 的主色、辅助色、强调色，以及至少 2 个中性文字色、2 个稳定表面色和实际所需语义状态色；品牌强调保持鲜明、可区分但不过度鲜艳。按实际 Logo 色块数量建立原始色表，分类与状态需要扩展时只加入有依据的协调衍生色并注明，不能为满足色相数量硬塞无关颜色。若提取结果冷色主导、缺少暖色鲜明色或无法形成可读渐变，必须在实现前重新生成或重选 Logo；冷色主导的颜色不进入主题令牌，也不得成为页面背景、主要 CTA 或主品牌渐变。
- 必须包含可见品牌渐变，渐变令牌至少包含 `brandGradient`、`sunsetGradient`、`aquaGradient` 和 `neonMixGradient`；名称是工程标识，不预设与 Logo 无关的色相。色标来自 Logo 原始色或已记录的协调衍生色，每个渐变记录来源、方向、色标、适用组件、浅色模式和深色模式版本。
- 渐变上的文字、图标和控件边界必须单独通过对比度检查，动态渐变核对整个变化范围而非单张截图；无法达到对比度时，增加纯色/半透明表面层，不使用渐变直接承载长段正文。动态渐变的位移/色标变化、速度、缓动、暂停条件与同配色静态回退统一使用主题令牌，不能各页自行设定不一致动画。
- 图标：使用同一矢量图标族并配置无障碍标签；Emoji 必须按第 6.8 节用于主题内容与状态的视觉点缀，不替代导航、播放、设置、返回或破坏性操作图标。集中定义 Emoji 的语义映射、字号、间距与对齐规则，禁止页面随机选取或散落不一致样式。

### 6.4 响应式与无障碍

- 遵守安全区和系统栏。
- 仅适配支持的小屏、标准屏和大屏 iPhone，覆盖 iPhone 的竖屏和横屏、安全区、系统栏、键盘与屏幕遮挡区域，不得横向溢出；按第 0.10 节不制作其他设备布局、样机或截图。
- 支持 Dynamic Type、VoiceOver、减少动态和增强对比度。
- 实际使用的卡片、网格、工具栏、播放器与导航控件具备稳定的尺寸约束；仅选用底部导航时为其预留安全区，不在无底栏方案中保留空白底栏占位。内容高度随真实内容和 Dynamic Type 自适应。
- 长文本自然换行；标签、按钮和卡片不得重叠、裁切或不可预测地挤压相邻内容。
- 颜色不能是唯一状态信号，必须同时使用文字、图标或语义。

### 6.5 色彩与渐变应用

- **渐变实际覆盖**：以最终选中 Logo 的真实代表色建立至少四种用途清晰的共享渐变，如 `brandBackground`、`featureSurface`、`primaryAction` 和 `accentBorder`，每种使用 2–4 个有来源的色标，并分别记录原始 HEX 与必要的明度衍生值。主要 App 自有页面须实际显示品牌背景渐变和至少一个与任务相关的渐变强调区（卡片头、主要操作、选中态或边框），不能只给 Welcome 加渐变或只在主题文件里定义。按各页任务改变色标组合、方向和面积；相机取景、正文及重要操作保留稳定高对比表面，系统界面保持原生。逐页用当前构建截图核对覆盖，不能让大片不透明纯色表面将所有渐变遮住。
- **全局取色落地**：`assets/logo.png` 完成校验后立即由取色脚本或等价可复核步骤生成原始 HEX 记录，并把结果写入 `lib/common_module/theme/app_theme.dart`，由 `AppTheme` 暴露全局色彩与渐变调用；不得在页面文件、`main.dart` 或 HTML 组件中硬编码另一套品牌色。若最终 Logo 仍是冷色主导，必须重新生成或重选 Logo 后再写入 `app_theme.dart`。品牌色要有暖色基底、鲜明层次和渐变，但饱和度与明度保持克制，避免过度鲜艳、刺眼或影响正文可读性的视觉效果。
- **浅色模式整体底色**：Light 及 System 当前解析为浅色时，所有 App 自有页面的整体背景必须使用包含最终 Logo 暖色配色的协调渐变，覆盖 Welcome、Initialization、内容/详情、工具、媒体外围、Settings 和自有 HTML 页面；不能使用纯白整页底色，也不能只在白底角落添加暖色点缀。优先选取第 2.5 节真实色板中的暖色及有记录的衍生色，按页面任务调整明度、饱和度与渐变方向，不统一套用无关的固定暖色表。“包含 Logo 配色”指颜色来源，不要求叠加或平铺 Logo 图片，仍遵守第 6.12 节减少重复的规则。
- **阅读表面与实现**：正文、卡片和控件保持稳定高对比，可使用有品牌暖色倾向的浅色表面；不能让大片纯白容器覆盖渐变后实际仍呈现白底。统一管理浅色背景渐变、表面及文字令牌，避免 `Scaffold`、滚动区域、加载/空/错误态或 HTML 默认样式回退纯白。照片中的白色及系统原生界面不受背景禁白限制；媒体操作与法律正文仍以清晰阅读为先。iOS 原生启动页按当前外观匹配品牌背景，暖色渐变仅通过静态资源实现，不添加动画。
- **深色模式照常**：Dark 及 System 当前解析为深色时，沿用现有深色背景、层次、品牌渐变和对比度规则，不强制换成浅亮暖色底；主题切换与持久化行为不变。Flutter 与 HTML 同步响应当前外观，动态渐变继续遵守减少动态和页面生命周期规则。
- 全项目多使用与 Logo 派生主题色对应的协调多色渐变：实际从 Logo 代表色生成主色、辅色和强调色令牌，在背景、分区强调、内容卡片及操作反馈中有层次地贯穿各主要页面，而非只用于 Welcome 启动准备状态或仅声明未使用的颜色。按页面任务差异化渐变方向、面积与明暗，避免所有页面复制同一背景；正文与控件仍保持对比度。每页另须实际显示其主题背景装饰图案，按第 6.11 节逐页生成、存储并接入。
- **点击粒子反馈为必做交互**：主任务中至少选择两个真实可达、语义不同且有即时反馈价值的点击位（优先覆盖主任务 CTA 与完成/保存/确认动作）；若当前产品实际只有一个可操作点击位，则该唯一点击位必须实现。每个选定位必须按主题实现精细烟花、喷泉或拖尾效果，使用 Flutter `AnimationController` 驱动 `CustomPainter`，在手势 `onTapUp` 坐标处生成粒子；每粒子具备可控位置、速度、重力、颜色和拖尾，并以 Logo 派生色板着色。粒子层必须穿透触摸、不遮挡后续操作、不延迟原动作结果，并排除 VoiceOver；跟随页面/应用生命周期停止和释放控制器，尊重系统减少动态设置（关闭粒子与拖尾，保留静态按下反馈）。效果只绑定已选的语义点击位，不得套在每个按钮上。项目统一按高端 iPhone 目标实现，不以低端性能为理由删减效果或降级为占位闪烁；仍须保持合理的绘制边界与结束条件，避免无界粒子泄漏。必须在当前 iPhone 构建中逐个点击并保存点击前/粒子进行中/结果落地的证据，验证对比度、减少动态、前后台切换和重复点击。若产品确实没有可操作点击位，才记录 `N/A` 及原因。
- iOS 原生冷启动页、每次启动显示的 Welcome 与清除成功后显示的 Initialization 三者背景均不得为纯白色或接近纯白的空白画布；使用 Logo 衍生的鲜明渐变、品牌色深浅层次或主题装饰，Light 模式也以浅彩渐变/柔和品牌底色避免纯白单调。Native Launch Screen 是系统冷启动静态画面；Welcome 是每次启动出现、内含准备状态及 `Continue` 的 Flutter 页面；Initialization 是仅在确认清除成功后出现、含 `Entry` 的独立 Flutter 页面。不得创建第四个 Flutter Loading 页面。协议通用文案只显示在 Initialization 底部，Welcome 与其内嵌 HTML 引导页均无该文案。
- 启动与初始化装饰应有内容依据、方向和主次，不用大面积空白、孤立 Logo 或无目的装饰填充；稳定正文与控件放在高对比表面层，确保普通文字对比度至少 4.5:1、控件边界至少 3:1。
- 每个主要页面至少使用一个多色强调区域和一个稳定纯色阅读区域；同一页面连续模块不得全部使用同一颜色或同一渐变。
- Welcome 页面内部的启动准备状态可使用多色渐变背景、项目名和可观察的真实进度；渐变动效只做轻微位移或明暗变化，开启减少动态时切换为静态渐变。该状态不是独立页面。
- 主要 CTA 使用由 Logo 配色形成的鲜明渐变或高饱和品牌纯色，并同时提供文字、图标、按下态、禁用态和焦点态；不可只靠颜色区分可操作性。
- 卡片、图片、视频封面和媒体容器继续使用圆角；渐变只作为容器背景或叠加层，不覆盖图片主体到无法辨认。
- Welcome、Initialization、Settings、协议 WebView 和 About 页面可共享品牌渐变，但正文、主题所需的表单输入和 Initialization 协议文本必须放在稳定的高对比表面上。
- 渐变方向、色标和透明度必须使用主题令牌管理，禁止在页面组件中散落硬编码颜色。
- App 的 Welcome、Initialization、主内容强调区与 About 品牌区域实际显示协调渐变和鲜明色彩；按第 2.5 节配色记录逐项核对 Logo → 原始色块 → 主题令牌 → 页面共享样式，不能只声明“含渐变”却全部显示无层次的纯色页。
- **条件允许时动态化**：App 与 About 支持的品牌背景、Welcome、Initialization 和主内容强调区优先采用缓慢、平滑的动态渐变，例如渐变方向轻微移动或在已选品牌色标间柔和过渡；默认约 8–12 秒完成一次平稳循环，可按实际效果调整。变化只使用 Logo 提取色与已记录的衍生色，不变成无关彩虹轮换、强烈闪烁或快速明暗跳变；不要求每张卡片和每个按钮都持续动画。
- **保护主要任务**：正文、协议、清除确认及拍摄/录音/播放的主要控件保持稳定高对比表面，不让动态背景干扰阅读、取景或操作。页面不可见或 App 进入后台时停止动画，返回前台仅恢复当前可见区域；避免为列表各项创建持续运行的独立动画，按第 11.8 节核验对启动、滚动、媒体处理与资源占用的影响。
- **静态回退**：遵守 iOS/Flutter 的减少动态设置，以及 About 网页的 `prefers-reduced-motion`；仅当用户开启减少动态时，切换为同品牌配色的静态渐变，保留视觉层次与鲜明色彩。项目统一按高端 iPhone 目标验收，不因低端设备假设主动删减或降级动态效果。检测与回退自动执行，不要求用户或委托方新增选择；记录实际动态展示、暂停/恢复、回退及未验证范围，不把静态截图冒充动态效果已验收。

### 6.6 人性化文案

- **去套话与重复内容**：App、About/Support、引导卡片、Intro 和 Remarks 都以当前主题的具体对象、真实动作、结果与限制写作。不同卡片、条目和章节各自提供新的信息，不把同一句口号改几个形容词后反复出现，不机械套用相同开头、固定三段结构或泛化结尾。避免堆砌 `unlock`、`seamless`、`ultimate`、`transform your journey` 等无事实支撑的营销套话；这些词的正常具体用法不作机械禁词。按钮/导航名称、法定声明与必要事实保持一致，不为“去重”擅自改名或删掉必要披露。
- **生成后逐段编辑**：先核对事实，再按实际页面/条目阅读正文；结合原始资料写出不同的具体说明、示例和可执行步骤，不虚构数据或只做同义词替换。规范大小写、空白和标点后检查整句重复，再人工检查语义近似的段落与连续条目，合并冗余、补足各条真实差异；保留可读、自然的句式变化，不用夸张词、长排比、堆砌破折号或生硬转折制造“精致感”。详细 Intro 仍按实际功能覆盖，不为凑字符反复复述；Remarks 仍简短分点且遵守其内容边界。编辑记录留在 `.codex-work/copy-review.md`，以实际修改和事实核对为依据，不声称通过所谓 AI 检测或保证文字来源。
- 所有可见文本使用自然、简短、友好的英语，优先说明用户下一步可以做什么，不使用生硬的系统术语、内部状态名或责备语气。
- 第 6.8 节要求的图形 Emoji 可以与自然英语搭配，但不能作为替代清晰文案的唯一标签；不使用带中文或禁用术语的文字型表情、贴纸和素材。Emoji 的可访问名称与提示同样使用自然英语，仍须通过本节的显示文案检查。
- **显示范围**：本节适用于 App 可控制的标题、Tab、按钮、正文、内容示例、输入提示、确认框、加载/空/错误提示、Toast、Snackbar、通知（实际实现时）、VoiceOver 标签与提示，以及 WebView 中的 About/Support/协议、AppListing 公开文案、截图、图片内嵌文字与视频字幕。不能只检查首页或按钮；最终 App 的状态分支和公开网页都须核对。
- **禁止中文及内部术语**：不得在上述显示文本中出现中文，以及 `H5`、`SDK`、广告、第三方框架、技术实现、内部模块、`lib`、`package`、`packages`、`local`、`device`、测试、模板、马甲、过审等文字。英文不分大小写检查，按独立词及词形/代码路径核对，同时检查同义的内部实现表达，例如 `Local Data`、`Device Storage`、`test mode`、`testing`、`template`、`framework`、`internal module`、`implementation`、`reskin`、`white-label`、`review bypass`、`ads`、`advertisement`、`advertising`；框架、语言和容器名称如 `Flutter`、`Dart`、`WebView` 也不作为用户可见功能说明。不得通过缩写、换大小写、插入符号或同义改写继续向用户展示这些开发概念。使用主题相关的内容名称、清晰操作与真实结果替代表述。
- **工程信息留在工程中**：技术名称、目录、类名、模块标识、测试和模板说明可以保留在源码、配置、文件路径、日志及中文开发报告中，不能直接作为可见标题、错误文本或无障碍读出。保持实际 `lib/`、`package/`、`packages/` 与其他依赖路径，不为消除文案关键词重命名工程结构、删依赖或破坏许可；屏蔽原始异常、文件路径、堆栈、HTTP/平台错误详情和调试标签，用自然英文说明可采取的动作，脱敏诊断另记。`Development only`、`Local only`、`Blocked`、`Verified` 等开发状态仅记在内部清单/报告中，不作为 App UI 标签、资源水印或公开网页正文；存在开发占位或发布缺口时保留准确的内部状态，不能因此冒充正式产物。
- **About 与协议必须是完整成品文案**：About Home、Privacy Policy、Terms & Conditions、Support 的正文、页面标题、描述元数据、图片替代文本及无障碍标签均不得出现作为页面状态/作者标记的 `Draft`、`WIP`、`TBD`、`TODO`、`Placeholder`、`Pending confirmation`、`Coming soon`、方括号填空项、作者备注或尚未完成提示。真实产品功能名称只有在项目事实支持时才可使用，不得把它当作页面的工作状态标签。每页应能独立阅读，结构、日期、导航/锚点、产品说明和支持内容应像已认真编写的正式页面；不能用视觉精致的壳子包住空白、泛化段落或待填写字段。
- **事实缺口留在内部记录**：不得猜测支持邮箱、开发者/运营主体、司法辖区、数据接收方、保留期限或受众年龄。缺少确认值时，省略无法可靠撰写的声明/联系区，不在 HTML 放置“待补充”文字；在生成摘要中逐项记录缺口，并将法律公开审阅状态标记为未完成。页面生成与离线核验继续进行，但不能将缺失法定信息的文本称为已完成法律审阅或可直接公开发布。
- **真实披露与系统界面**：以本规则改写自有 UI 和公开网页，权限用途字符串也使用具体、自然的英语；隐私政策仍准确说明数据的采集/处理、接收方、保存/删除、备份边界和系统选择，用 `saved in this app`、`photos you select` 等用户能理解的表达说明实际行为。保留法定披露、真实接收方/权利人名称与许可义务，不能为了词库隐藏实际追踪或数据传输，也不能假称未发生的行为；确有不可改写的必需名称时记录准确冲突，不擅自删掉。iOS 系统权限框、系统相册选择器、系统设置及用户自行拍摄/导入/录制的内容不由 App 文案控制，不覆盖系统文字、不改用户原始内容，也不强制修改用户系统语言。以上是本项目文案约束，不是 Apple 官方禁词表，不能据此声称保证通过审核。
- 加载文案示例：`Getting things ready…`、`Just a moment…`；失败文案示例：`We couldn't load this page. Try again.`；空状态文案必须说明当前没有内容以及可采取的动作。
- 主题所需的表单错误应直接说明原因，例如 `Choose an item to continue.`，不要只显示 `Invalid input`；Entry 页面不添加身份输入表单。
- 最终引导页的继续按钮文案固定为 `Continue`；仅引导页接入前的开发预览可用原生 `Enter` 控件。Settings 的全量清除入口固定为 `Clear Data`；确认框使用 `Cancel` 与 `Clear Data`，不能把清除含糊标为 `OK` 或普通返回。协议入口使用文档名称，其他按钮使用清晰动词，如 `View`, `Back` 和 `Try again`。不显示退出、登录、登出、邮箱认证或协议勾选提示。
- 文案不得暴露实现细节或使用夸张承诺；正式协议正文保持法律准确性，入口和状态提示保持易懂。

### 6.6.1 主题化排版与 UI 极致优化

- **先建立排版系统**：在实现页面前定义并记录 `display`、`heading`、`body`、`metadata`、`action` 五类文字角色，分别规定字体、字重、字号、行高、颜色、最大行宽和上下间距。页面、组件、弹窗、空/错误状态、Settings、About/Support 和内嵌引导页都使用同一套角色令牌，不在单个页面临时拼接字号或颜色。
- **标题的斜体与渐变**：页面标题、主要功能标题和章节标题使用有意的斜体或斜切字形，体现主题气质但保持字形完整、易读和可复制；短标题和可承载渐变的关键标题在对比度允许时同时使用由正式 Logo 实际色板派生的渐变文字或渐变描边，只有经过对比度测量仍不合格时才回退到同色板的纯色标题，并记录回退原因。渐变只取已记录的 Logo HEX 与其可解释的衍生色，逐页检查静态和动态范围的可读性。禁止把渐变用于大段正文、错误详情或需要快速扫描的密集信息。
- **至少三种有依据的字体风格**：整个项目至少落地三种可复用、能被用户感知且与层级对应的字体风格：主题化斜体/斜切展示标题、稳定易读的正文/操作文字，以及与正文有明确区别的元数据/标签/强调文字（可使用不同字重、宽度、大小写或一款随包且许可明确的展示字体）。短标题、长标题、正文、列表、Settings、About/Support、协议和引导页都要从这套角色选择，不是每个文字节点随机更换字体、颜色或装饰，也不能依靠字体变化掩盖内容重复。
- **自然大小写与重点词**：主文本、段落、列表开头和空状态说明使用 sentence case，首个字母按英语规则大写；不把每个词都写成 Title Case，也不使用全大写制造层级。需要强调的事实、动作或结果用 `Text.rich`/`InlineSpan`（或等价的语义文本组件）局部换用 Logo 强调色、字重、斜体、细下划线或克制的背景高亮，并确保 VoiceOver 按自然语序读出。颜色不能成为唯一语义信号，必须同时有文字、字重、图标或位置差异。
- **字体来源与可访问性**：仅使用系统字体或已随包、许可明确的字体，不依赖运行时下载字体。尊重 Dynamic Type、VoiceOver、粗体文字、增加对比度、Reduce Motion 和安全区；字体放大时允许自然换行和滚动，不能固定高度截断、压缩字距、裁切字形、让装饰覆盖正文或改变无障碍阅读顺序。正文和控件始终保持可核对的对比度，动态渐变在整个动画范围内也必须可读。
- **组件状态与细节**：每个按钮、链接、输入和可选项都提供清楚的正常、按下、禁用、焦点、成功和错误状态，状态变化不依靠颜色单独表达。统一圆角、边框、阴影、图标基线、内外间距和图片裁切；长短不齐、大小不一的内容卡片必须有内容重要性、媒体比例或信息密度依据，不能随机错落。任何页面都不得出现重叠、溢出、跳动布局、不可点击控件或被安全区遮挡的文字。
- **覆盖全部页面与状态**：排版系统必须落到 Welcome、Initialization、主内容页、详情、工具、Settings、About/Support、协议页、Sheet/Dialog，以及加载、空、失败、权限拒绝、清除确认和成功返回等适用状态。不能只精修首屏；每页都要有与主题内容相关的视觉层次、图片/图示或组件结构，同时保持法律正文的稳定阅读体验。
- **精修证据**：至少完成三轮“在 iPhone 当前构建运行并截图 → 逐屏检查排版与层级 → 实际修改 → 再运行核验”，记录每轮变化和前后证据。覆盖小屏、标准屏、大屏 iPhone、横竖屏、Light/Dark/System、Dynamic Type、VoiceOver、Reduce Motion 和长文本；若发现标题渐变对比度、强调语义、字形裁切或页面密度不合格，必须继续修改并复验，不能以源码令牌存在或设计稿作为完成证据。

清除流程的统一可见文案为：入口与确认动作 `Clear Data`，确认标题 `Clear Data?`，取消 `Cancel`，进行中 `Clearing data…`，失败 `We couldn't clear all your data. Try again.`。确认正文按第 7.7 节准确列明删除范围与不可撤销后果，不出现 `local` 或 `device`；这只更新显示文字，清除数据、二次确认、成功进入 Initialization 及失败恢复的实际行为保持一致。

### 6.7 必须投入充分工作量的 UI 精修

UI 设计、实现后的美化与资源调整是主要工作阶段，不能在“功能能跑”时直接交付。规划与执行均须为 UI 与资源精修合计保留至少一半的实际开发工作量，其中 UI 设计、细节调整与不同 iPhone 尺寸检查至少占三分之一，图片/视频的筛选、替换、裁切、封面和播放优化至少占六分之一；分配时不重复计算同一项工作。按页面与资源批次记录实际操作、修复、前后对比和检查结果；具备可靠时间记录时补充真实耗时，没有时只报告可核对的工作量，不虚报分钟或用空等、重复无改动截图满足要求。

投入比例是资源分配要求，不能单独证明精修充分：总工作量较小时仍须完成全部页面、适用状态、素材检查和真实迭代，不得以“已占一半”为由跳过任何质量要求。规划时记录功能实现、UI、资源、验证各阶段的预估工作及依据；执行时记录实际完成项、真实计时或明确标注的估算。缩短服务等待、并发和复用可以减少总耗时，但不得因此删减内容、减少精修覆盖或取消验收；不能从运行时间自动推断质量提高或降低。

必须完成至少三轮“运行并截图 → 逐屏评审 → 实际修改 → 再运行核验”，每轮都记录问题、修改及前后截图路径：

1. **整体构图与内容层级**：精修核心主页面、Welcome、Initialization、Settings 及实际存在的其他任务页面；拍摄、相册导入前后与录音页面仅在选用时纳入，检查布局节奏、信息密度、导航、主次动作、留白、安全区和真实内容呈现。
2. **品牌与细节**：逐项调整字体尺度与字重、行距、间距、图标一致性、第 6.8 节 Emoji 的主题匹配/大小/基线/密度、圆角、图片裁剪、渐变、对比度、按钮和输入状态；逐屏更换不贴题、模糊、主体裁切错误或重复明显的图片/视频，调整真实视频封面与文字叠层，避免所有页面套用同一种卡片布局。系统选择器与权限弹窗保留原生样式，只精修 App 可控制的周边流程。
3. **状态、动效与适配**：覆盖 Light/Dark/System、小屏/标准屏/大屏 iPhone、iPhone 横竖屏、长文本、Dynamic Type、VoiceOver、减少动态，以及加载、空、失败、权限拒绝/受限、录制中、保存中、清除确认、清理中、清理失败和成功状态；核验键盘避让、滚动、返回和媒体生命周期。破坏性清除使用清楚的文字与语义，不仅靠红色区分；确认框的初始焦点不得默认落在清除动作上，清除成功进入 Initialization 后恢复合理的无障碍焦点。

核心流程必须在 iPhone 运行环境中逐屏查看，截图只作为证据，不能代替点击与交互检查。模拟器检查按第 0.9、0.10 节在工程创建完成后进行，三轮精修共享一个现有 iPhone，其他必要 iPhone 尺寸/支持的 iOS 版本依次切换，不为每页或每轮新开模拟器。明显遮挡、溢出、文字截断、不可读对比度、无法点击、错误加载层级或媒体控件错位必须修复；新改动引入的问题再次针对性核验。完成三轮后仍有影响使用或明显视觉质量的问题时继续精修，不能把三轮当作自动通过标准。

前后对比使用相同页面、示例数据、设备尺寸和可比状态，注明构建版本；补充说明轮次之间实际改变的内容。投入比例在规划时分配到可核对的任务，执行时按同一工作量口径核算；没有可靠计时就使用预先记录的任务估算与实际完成记录，并注明估算，不凭事后拆细 UI 任务数量制造比例。等待外部服务、无改动重复截图和反复运行相同检查不计精修投入。

UI 三轮迭代之外，按第 10.5 节至少完成两轮有实际筛选或调整的资源工作，可以与 UI 检查并发：第一轮按主题、模块和构图筛选并淘汰低质/重复候选；第二轮在真实页面与播放环境中调整裁剪、封面、清晰度、体积和重复分布。每轮记录替换前后资源 ID、原因、实际消费位置及结果，不能只下载一批素材后不再检查，也不能以重复采集同图证明投入。

开发者自主完成上述迭代，不向用户逐轮请求审批。实际不可用的设备或运行工具只影响相应验证项，记录未验证范围并继续其他精修，不用静态检查冒充完整视觉验收。

完成最低轮次后，按第 11.9 节进行一次与页面实现、三轮精修分开的交付前质量复核，直接检查当前构建、页面和最终随包资源。复核发现遗漏或明显视觉问题时继续实际调整并复验，不因预计提前完成而马上交付；已经有当前有效证据且没有新问题的检查不机械重复，也不通过空等、休眠或无意义修改凑满工时。

### 6.8 Emoji 视觉丰富度与使用规范

- **实际展示**：项目必须使用多种与已采用创意相符的图形 Emoji，至少覆盖欢迎页、主内容页的分类/模块，以及适用的空状态或成功反馈；每个主要内容目的地选择有意义的位置，不要求每个按钮、拍摄/录音控件或协议正文都添加。规划时记录展示位置、语义与搭配文案，实施后以真实页面截图核验，不用开发文档里的 Emoji 充当已实现证据。
- **主题与层级**：由智能体围绕真实内容选择 Emoji，不固定产品主题。拍摄、相册、录音的引导区域可分别点缀 📸、🖼️、🎙️，内容分类则根据实际对象选取；这些仅为示例。优先用于欢迎语、分组标题、分类标记和状态插图，数量与尺寸服务于层级，避免全屏堆叠、无关表情或所有卡片重复同一符号。
- **清晰操作**：Emoji 必须与清楚的英语内容或操作名称配合；导航、播放、返回、设置与清除等操作仍保留统一矢量图标及明确文字。最终引导页按钮 `Continue`、`Clear Data`、`Cancel` 等固定文案保持原样，装饰放在独立区域，不把 Emoji 拼入这些固定标签；仅开发预览可使用原生 `Enter` 控件。破坏性清除、权限拒绝和失败提示使用准确、中性的表达，不用庆祝表情弱化后果。
- **统一样式**：集中维护语义映射与大小、行高、间距、对齐规则；同一语义跨页面稳定复用，不为追求数量随机轮换。使用原生 Unicode Emoji，检查最低支持 iOS 版本的实际字形、完整组合序列和显示宽度；缺字、方框或错误断行时换用兼容 Emoji，保持其英语标签，不依赖新增网络服务。
- **适配与动效**：在 Light/Dark/System、小屏/标准屏/大屏 iPhone、iPhone 横竖屏及大字号下检查基线、裁切、换行、阅读层次与点击区域，Emoji 不遮挡图片主体、文案或媒体控件。默认使用静态 Emoji；确有反馈动效时沿用第 6.3、6.4 节规则，支持减少动态，不持续闪烁或无意义循环。
- **无障碍与文案**：纯装饰 Emoji 从 VoiceOver 语义中排除，防止同一标题重复读出；传递分类或状态信息时为整个组件提供自然英语名称与状态，不靠表情或颜色单独传达含义，不让系统默认的 Emoji 读名替代操作标签。按第 6.6、11.4 节检查显示与读出内容，不夹带中文、内部术语或被禁止的文字型表情。
- **资源与验收**：Emoji 是视觉补充，不能替代 Stargate 正式 Logo、主题图片/视频、真实内容或已选功能，也不计入独立图片/视频数量或资源调整轮次。同一语义的合理复用不视为第 10.5 节的素材重复，但不能用换 Emoji 掩盖重复封面；将实际展示、主题匹配、布局与 VoiceOver 结果纳入三轮 UI 精修及第 11.9 节质量复核，不新增用户审批。

### 6.9 图片自然度与内容列表尺寸层级

- **Logo 生成质量**：Logo 仍按第 2.5 节只在 Stargate 生成；按主题元素分别撰写模拟现实、手绘、油画、艺术表现四种画风，每种生成 3 张，共 12 张独立候选；逐张查看并记录生成痕迹，从全部候选比较选出最自然且符合主题的一张，不能只生成同一画风或以首张成功图结束。按第 2.5 节分别核验可信的结构/材质/光影、精细手绘线条、油画笔触/颜料层次或明确的艺术表现语言；均须精致、有层次、小尺寸可辨，不做 3D。鲜明、非单调的 Logo 配色至少呈现三种易辨鲜明颜色与协调渐变；检查并修复明显 AI 生成感、畸变/融化的形状、断裂轮廓、重复纹理、随机碎片、伪文字、物理关系不成立的细节、塑料质感和无依据的强光晕。这里的“自然可信”按所选画风的造型和视觉逻辑判断，允许协调的笔触和艺术化提炼，不要求照片写实，也不削弱鲜明渐变。
- **主题色落地证据**：颜色链路必须可追溯为 `Logo 原始 HEX → Flutter 主题令牌 → 实际页面/组件 → iPhone 截图`；至少三个实际 Flutter 页面/组件消费 Logo 派生色，覆盖主页面、真实操作页和至少一个其他 App 页面。不能只证明取过色或定义过令牌，须以当前构建中的页面截图证明颜色实际可见。
- **内容图片来源和真实感**：内容照片继续严格按第 10.6 节从第三方网站取得有许可依据的真实摄影；不得用 AI 生成的拟真图、插画或图形化合成图冒充真实照片。候选图片必须准确对应页面描述的物体/场景；来源页、拍摄主体、透视/比例和可见细节应相互吻合，不选明显错题、异常结构、过度处理或有可疑生成痕迹的照片。Logo 的生成规则不得扩展为生成内容照片的许可。
- **按语义变化尺寸**：每个主要内容列表在多条内容可用时至少包含两种明显不同的卡片尺寸；主要浏览体验跨页面按实际内容层次覆盖 `featured`（重点大卡）、`standard`（常规卡）和 `compact`（紧凑行/小卡）三档（若创意内容不支持某档，记录原因），不要求每个页面都同时出现三档。尺寸差异通过图片面积、卡片高度或版面跨度让用户一眼可辨，不能只改边框/阴影。精选、常规、辅助角色必须由内容重要性、用户任务或浏览密度决定，记录映射与先后顺序；禁止随机高低错落、纯装饰性尺寸变化、同一条目在相邻位置换尺寸凑数量，或让大卡抢走用户的主要任务。
- **跨主要页面的主编排与复合布局**：同一列表内建立可预测的视觉节奏，重点卡强调、普通卡承载完整信息、紧凑项帮助快速浏览。多个主要内容目的地都是浏览型列表时，跨主要页面至少安排两种有意区分的主编排，例如垂直分组列表、双列网格、精选大卡加横向滚动、瀑布流/不规则卡片或分段式复合布局；不要求每个主要页面都完全不同，也不机械禁止复用 `ListView` 等基础组件，差异应体现在主要视觉编排、卡片比例、信息密度和浏览节奏。单个页面可以复合使用多种展示形式，允许卡片长短不齐、大小不一、图片比例和内容高度不同，但必须可预测且由内容重要性、任务优先级、信息密度、媒体比例或排序理由决定。记录每个主要页面的主编排、复合结构、`featured`/`standard`/`compact` 或其他尺寸角色、排序依据及小屏响应式降级；禁止随机错落、仅为装饰改尺寸、固定高度导致文字截断、图片拉伸或破坏语义/VoiceOver 顺序。搜索结果、相册选择、权限说明、Settings、协议等以快速扫描/准确选择为目的的行列表保持统一行高与对齐，不为“大小不一”而损害可用性。
- **复合区域与滚动边界**：同一页面可按任务组合精选大卡、横向轨、双列网格、瀑布流/不规则卡片、标准列表和紧凑条目，写明区域顺序、层级与每区的尺寸角色。纵向内容默认共享一个主滚动上下文，横向轨可独立横滚；确需独立同向滚动区域时，必须记录理由、可见边界和手势/焦点交接方式，避免争抢滚动、内容不可达或丢失返回位置。长短和大小随真实文字、媒体比例与角色自然变化，不强制随机高低，也不将长文字卡片锁定为固定高度；图片保留焦点和正确比例，视觉、滚动与 VoiceOver 顺序一致。小屏/Dynamic Type 下按记录的断点改为单列或紧凑编排，保留内容层级、全部操作及清晰阅读路径。
- **图片与布局适配**：为各尺寸层级分别核对素材分辨率、宽高比、焦点位置与裁切；使用适当的 `BoxFit`/容器比例和可读叠层，不拉伸、不切掉关键主题对象、不因大图卡片反复复用同一图片。不同尺寸下标题、副文、标签和 Emoji 保持层次，文本随内容和大字号增长而扩展，不固定卡片高度导致截断；缩略图按展示尺寸解码，维持加载、空与错误状态一致。
- **无障碍和 iPhone 适配**：混合尺寸不能改变内容的语义顺序；视觉顺序、滚动顺序、VoiceOver 焦点顺序和导航焦点次序应相符，点击区域至少 44×44pt，Dynamic Type 下无遮挡、截断或水平溢出。在支持的小屏/标准屏/大屏 iPhone、横竖屏、浅/深色与大字号下实际检查每种卡片角色及断点；必要时将大卡改为紧凑布局或单列流式排列，但继续保留至少两级清晰层次。
- **验收证据**：页面规格记录每个主要列表的主编排、是否复合、层级、排序理由、组件尺寸/比例与对应资源；当前构建的精修截图覆盖同页长/短、大/中/紧凑项及至少两类不同主编排的页面。逐条检查图片自然度/主题准确性、尺寸区别是否清晰但协调、不同主要页面的编排差异、复合区域顺序、层级及共享/独立滚动边界、点击路径、响应式降级、裁切、内容密度、Dynamic Type、VoiceOver 和 iPhone 边界；发现突兀、随机、重复、错题或生成瑕疵须实际调整并复验。按第 11.9 节列出已检查的列表和图片证据，不以设计稿或写有三档名称的清单冒充运行效果。

### 6.10 全页面内容丰富度与图文表达

本节是所有页面的共同验收要求。每页围绕实际用户任务，同时具备清晰的内容分组、至少一种有意义的非纯文字表达，以及完整可用的操作或阅读路径。非纯文字表达按页面职责选择真实主题摄影、内容图解、示意插画、缩略图、数据可视化、真实媒体预览、状态图形或带图标的分组控件；不是要求所有页面塞入相同大图。单纯换背景色、加渐变、把同一段文字拆进多个容器、满页 Emoji 或反复贴 Logo 不能单独算作内容丰富。

主要流程中的内容结构和视觉层级还必须体现当前主题自己的分类、证据关系、步骤顺序、对象状态或结果表达。复用通用组件可以，但组件必须显示真实主题数据并服务该页面的核心循环；若只替换标题、图片和品牌色而任务路径与结果仍完全通用，应继续调整内容模型/页面结构，不以额外装饰掩盖。

| 页面职责 | 必须实际落地的内容与视觉表达 |
| --- | --- |
| 主要内容目的地、分类与浏览页 | 首屏呈现贴题主视觉/精选图文项和明确主任务，页面内有可区分的内容模块、简明元信息与继续探索入口；图文列表按第 6.9 节使用有依据的尺寸层级。不同页面围绕各自任务设计，不只更换同一布局的标题、图片与颜色。 |
| Detail、知识与说明页 | 结构化正文结合至少一种帮助理解的主题图片、步骤图、关系图、对比图或带图示的实例；页面提供概览、关键知识/步骤、应用实例/相关内容等至少三个有不同信息价值的模块，具体组合服从主题。首屏应能看到主题视觉或图解及核心摘要，长文下部继续有合适的图文节奏；不能仅是标题加数段正文，也不能把段落逐个加边框算作图文模块。 |

| 拍摄、导入、录音、媒体管理与 Player | 以真实取景、已选缩略图、预览/封面、真实录音计时/采样反馈及类型图标作为主要视觉，配合主题用途、分组操作和准确状态；未录音的空态采用主题插画/图标、具体用途和清晰创建入口，不显示假波形、假时长、假照片或假用户记录。聚焦操作区保持干净，不用装饰覆盖取景、播放器或录制控件。 |

| Sheet/Dialog 与清除确认 | 以有语义的图标/状态标识、明确标题、短而完整的说明、清楚的操作层级表达；风险提示与后果说明优先，不强塞摄影大图、卡片列表或额外步骤。Clear Data 仍只使用既定的一个二次确认框，取消与确认行为不变；系统权限弹窗和系统相册选择器不重绘、不覆盖。 |
| About、Support 与协议阅读 | 自有页面使用一致的品牌页头、正式 Logo、清晰目录/锚点、章节层级和适用的信息分组；Support 可按实际支持内容提供步骤/问题分类。法律正文完整、稳定、高对比，不插入无关照片、轮播或动效打断阅读，不改写已回接协议 URL 或尝试控制外部页面内容。App 容器和失败态仍满足本表，站点文件白名单不变。 |

**逐页规划与实施**：页面追踪表为每个页面、Sheet/Dialog 和适用状态明确视觉内容、信息模块、资源/组件及验收依据，不能填写“同首页”或泛写“精美卡片”。主要内容页、详情页必须有与自身内容对应的资源或图解，其他类型按本表选择具体表达；采用共享组件时保留当前页面的真实数据、用途和内容层级。页面背景装饰也逐页登记稳定 page ID、素材路径、透明度/边框位置、组件实际引用和验收截图。系统原生界面只记录调用与周边流程，不能把无法控制的系统页面列为已重绘。

**内容与素材真实性**：正文有事实依据，示例可用，元信息/进度/统计来自真实内容或结果；图解结构与文字一致，有意义的图片提供可读替代说明，纯装饰不进入 VoiceOver。主题实物/实景摄影按第 10.6 节从已列第三方网站搜索、核许可、下载并实际接入，不用 AI 图、Emoji、Logo 或空白占位代替必需摄影；Stargate 可生成 Logo 与本节限定的页面背景装饰，但页面装饰不能冒充真实摄影、内容封面或主题实物图。插画、代码绘制图解与矢量图标可用于解释内容，不能冒充真实摄影。按第 10.5 节避免跨页无理由重复同一图或同一构图，允许必要品牌复用并记录理由。

**密度、可用性与验收**：丰富是信息完整且易理解，不是填满所有空隙；首屏突出主任务，次要内容自然滚动或渐进展开，不挤压文字、隐藏操作或强制自动播放。保持英文文案、Logo 色板、圆角、稳定阅读表面、iPhone 安全区、Dynamic Type、VoiceOver、减少动态和资源预算。按第 11.3、11.9 节逐页核对当前构建与正常/空/失败等适用状态，记录页面 ID → 内容模块 → 非纯文字表达/真实资源 → 交互 → 截图及结果；只有首页好看、素材已下载但未显示、文字容器堆叠或纯文字页漏检均不能通过对应视觉项。可修复的单调页面须实际调整并复验；外部素材/运行限制只影响对应项并如实记为 `Blocked`/`Not verified`，继续不依赖它们的工作。

### 6.11 页面背景装饰图案

背景成品先保存到本项目专属暂存目录 `~/Downloads/<sanitized-project-name>/backgrounds/<page_id>/`（本机为 `/Users/admin/Downloads/<sanitized-project-name>/backgrounds/<page_id>/`），再校验并复制到当前 `Target project root/assets/backgrounds/<page_id>/`；开始任何图片任务前必须先创建该项目目录，不能直接写入公共 Downloads 根目录，也不能引用其他项目的背景。Logo 候选、内容照片和导出文件分别使用同一项目目录下的 `logo-candidates/`、`content/`、`exports/` 子目录。浏览器强制写入默认下载目录时，只追踪并立即迁移本任务实际下载的确切文件到项目专属目录，不扫描、搬走或覆盖其他文件；验证格式、许可、哈希和去重后再移入页面 assets 并登记，不让 Downloads 路径成为运行期引用。重名时按候选/任务映射处理，不能覆盖其他页面或项目资源；文件名继续遵守第 10.1.2 节短名规则。

为每个 App 自有页面实际制作一张与该页主题、内容和任务相符的背景装饰图案，使用 `http://stargate.local:3100/image` 生成每页对应的背景装饰图案。此处是该服务在 Logo 之外的限定用途：只生成随包使用的界面装饰背景，不生成或替代主题实物/实景照片、内容主图、摄影封面、视频帧或用户媒体；上述真实摄影仍须从第 16 节列出的第三方来源获取并核对许可。

以页面自身的视觉重点设计细致、有层次、色彩鲜明且不单调的纹样、纹理、插画式装饰或边框构图；符合项目主题与 Logo 色板，不采用仅有简约线条、细轮廓、扁平几何或纯色块堆叠的简化画面。按每个页面的实际显示比例选择生成规格，使用高质量结果；图像生成服务不可用时按第 0.6 节有限尝试、记录并继续独立任务，不伪称已生成。

每个页面使用唯一稳定的 `page_id`（小写 `snake_case`），按以下规则落盘：`assets/backgrounds/<page_id>/<page_id>_background.png`，例如 `assets/backgrounds/entry/entry_background.png`。每个页面独立存放、名称与页面 ID 对应，不把图案散放在 `lib/`、项目根目录或 `aduit/site/img/`，不跨页面重复同一张图；共享页面组件只共享渲染代码，不共享页面专属图片。将每个资源显式加入 `pubspec.yaml`，并在 `.codex-work/page-inventory.md` 记录按页面 ID 分类的装饰素材、页面类别/路由、Dart 文件、图片路径、生成任务与提示词摘要、实际透明度/裁切或边框位置、组件对该装饰素材的实际引用和当前 iPhone 验收证据，形成页面 ID → 装饰素材 → 页面注册与实际引用的可追溯链路。

Flutter 页面以主题渐变为底，将生成图片作为低透明度图层或边缘框饰实际叠加；图像不带 Alpha 时使用 Flutter 透明度/混合或裁切处理，不要求生图服务输出透明通道。透明度以能辨认纹理且文字/控件对比度仍合格为准，常规起点为 8%–20%，不得无依据地调到不可见。装饰层应忽略触摸、从无障碍语义树排除并随页面生命周期停止非必要动效；摄像机实时取景区、录音/播放主控区与法律正文阅读区只允许在外围边缘使用，不得干扰用户任务。每页均需检查小屏、大屏、浅/深色、大字号下的可读性、裁切与安全区。

工程根目录 `welcome.html`（唯一运行与交付引导文件）仍须自包含、禁止引用相对/远程图片路径且总 UTF-8 字节数严格小于 262,144。若引导 HTML 自身显示页面装饰，必须从 `assets/backgrounds/welcome/welcome_background.png` 派生并将优化后的图片以内嵌 Base64 data URI 写入根目录 HTML，逐个解码验收并纳入大小预算；源素材仍保留在 `assets/backgrounds/welcome/`，不得以外链取代。若由 Flutter 外层展示该装饰，则 HTML 不得出现工程内资源路径。

### 6.12 Logo 使用边界与原创 UI 插画

减少 Logo 在内部 UI 中的重复出现，以品牌色、排版和主题插画维持统一感，不靠反复贴 Logo 丰富页面。

- **品牌位置**：保留第 10.4 节要求的 AppIcon、iOS 原生启动页、Welcome、Initialization 和已有 About/品牌展示位；同一可见屏幕原则上只出现一处 Logo。Welcome 的 Flutter 外层与内嵌 HTML 统一安排品牌展示，不重复叠加；3–5 张介绍卡片按各自功能选图，不逐卡重复 Logo。不为每个导航栏、列表项、按钮、空态、错误态或背景水印额外放置 Logo。
- **自主绘制**：可按已确认主题与页面用途，自主绘制内容插画、分类图、步骤/关系图和空/错误/成功状态图，无需另行询问素材意见。允许代码绘图、SVG 或 `CustomPainter` 等适用方式；围绕当前内容设计主体、构图和细节，不把 Logo 换色、裁剪、镜像或添加边框后冒充新图。插画保持 Logo 派生色板、鲜明渐变和精细层次，避免仅靠简约线条、几何色块堆叠或重复同一构图；信息图的结构须准确，不能为装饰编造数据。
- **资源分类与接入**：导出的原创图片放在 `assets/illustrations/<feature_or_page_id>/<purpose>.png` 或 `.svg`，目录与文件使用有语义的小写 `snake_case`，例如 `assets/illustrations/notebook/empty_notebook.png`。使用工程支持的渲染方式，更新 `pubspec.yaml` 和实际页面引用；运行时绘制代码按功能/页面分类，不集中到 `main.dart`，也不把未导出的绘图声称为已落盘图片。在页面/资源清单中记录用途、原创绘制方式、文件或绘图组件、消费页面和当前构建证据。
- **用途边界**：原创插画用于解释内容和表达状态，不冒充真实摄影、用户私有媒体或已完成的录制/测试结果；第 10.6 节必需的第三方真实照片继续搜索、核许可并实际展示。Stargate 仍仅用于 Logo 与第 6.11 节的页面背景装饰，本节不扩大生图网站用途。
- **显示与交付**：沿用圆角裁剪、适当主题细边框、无障碍和资源预算要求。Welcome HTML 使用的原创图片必须优化后以 Base64 内嵌，计入总字节数严格小于 262,144 的预算；原图留在 App 的 assets 分类目录，不放进 `aduit/site/img/`，不扩大交付白名单。
- **逐页复核**：对照实际页面/状态截图与资源接触表，检查 Logo 展示次数、必要品牌复用理由及插画的语义、差异和实际加载；优先将无理由重复的 Logo 替换为对应原创插画、图解或合规主题照片。只有文件已生成、换了文件名或仍被 Logo 覆盖均不算完成；共享语义控件图标可保留；项目自有内容图在列表与详情等独立展示位也按第 10.5 节使用不同独立素材，不以裁切/改色冒充新图，不擅自改造用户私有媒体。

## 7. 页面级 UI 与功能规格

整个 App 的启动/清除返回体验必须恰好三个不同页面：iOS 原生启动页、Welcome 欢迎页、Initialization 初始化页。另须实现 Settings（含 `Clear Data` 和二次确认）及协议 WebView；其余任务页面按实际主题和选定功能设计。拍照、相册、录音及本地媒体管理均非固定配置，按第 0.3 节允许任意组合或全部不包含，未选功能不生成页面/按钮/路由。启动准备只是欢迎页内部状态；启动准备状态必须显示在欢迎页内部，不创建 Loading 页面。`Clear Data` 确认清理成功后显示初始化页并提供 `Entry`；协议通用文案仅初始化页显示，欢迎页不显示任何协议文案；引导页不含协议通用文案。Detail、Player 等同样按实际任务采用；若选用录音，真实试听与结果管理仍须完成，不能用功能可选掩盖已选功能的缺失。客观设备限制按第 11.6 节记录，不得假装完成。

### 7.1 欢迎页（Welcome，`/welcome`）

职责与出现时机：这是每次启动 App 后进入的 Flutter 页面，也是 `Continue` 所在页面。其前面只有短暂静态的 iOS 原生启动页。启动准备过程、准备完成、恢复、错误、重试和清除等均为此欢迎页的页面内状态/覆盖层；不得另建 Flutter Loading 页面、`/loading` 路由或第四个启动页。App 从后台恢复时保留当前有效页面或清理状态，不额外回到欢迎页。只有用户确认 `Clear Data` 且清理成功后，才显示初始化页并提供 `Entry`；下次 App 启动仍进入欢迎页。

UI：以 3–5 张项目真实功能介绍卡片呈现品牌视觉、产品承诺和英文内容，使用 Logo 派生的多色渐变、细致主题装饰、图像/图解与适量 Emoji，并提供 `Continue` 主按钮。最终 AppListing 生成并整理为 `aduit/` 后，欢迎页实际显示工程根目录 `welcome.html` 的单文件本地 WebView；`aduit/site/` 内四页保持生成内容；其图片以 Base64 内嵌。页面必须在每次启动立即可见，不能因准备状态显示另一张页面。欢迎页不显示 `By continuing, you agree to our` 或 `Terms of Use and Privacy Policy` 协议同意文案，也没有 Terms/Privacy 页脚链接。它可以有 `Continue`，但只要必需准备未就绪，暂不执行到主流程的导航；就绪后启用。没有邮箱、账号、认证、协议勾选输入。

启动准备状态位于 Welcome 内部的独立状态区，按 SafeArea 保持卡片、进度、按钮和安全区清晰可见。显示当前真实步骤、数字百分比、品牌进度条；可在空间充足时附少量真实里程碑状态。必须准备的内容与顺序、百分比计算方式、10 秒预算、不可虚构进度规则详见下文。快速准备完成时可不显式停留在进度态，但仍先呈现 Welcome 首帧，并在可用时立即启用 `Continue`。不得因展示动画或读完文案延迟。

状态区行为：准备中显示真实步骤和最后已完成点；就绪时显示完成状态并启用 `Continue`；核心配置失败时在本页显示明确、可理解的原因及 `Try again`、`Clear Data`。Retry 使用新的操作 ID，错误旧回调不得覆盖新状态。`Clear Data` 打开既有二次确认，取消无副作用，只有真实清除成功后才导航到 Initialization。非关键资源失败不阻止使用主流程，并提供可恢复的局部提示。

将启动必需项与可延后项分开：主导航、最小内容索引和已保存主题为必需准备，大图解码、视频预加载、全库媒体扫描和本地文档完整性检查延后执行。必需准备默认总预算 10 秒；偏好读取失败使用安全默认值并保留原数据，单个非关键资源失败在 Welcome 提示局部问题。并发结果带启动操作 ID，取消/重试后旧回调不得覆盖新状态。

进度只由启动所必需的真实里程碑及其完成状态计算，例如恢复标记核验、已保存主题与偏好读取、最小导航/内容索引就绪、仓储可用；启动前列明必需里程碑总数，百分比按“已完成的必需里程碑数 / 必需里程碑总数”计算并取整。存在可测量的真实子任务时，可按其已完成量/总量计算，但不得凭估时或主观权重分配比例。可并行工作仍按实际完成状态更新，不为制造进度改成虚假串行或添加装饰性步骤。只有实际完成的工作才计入进度；未完成前不得显示 100%。不得用计时器、动画、固定延迟或猜测耗时推高百分比；可延后工作不计入启动进度。

欢迎页背景必须采用非白色的 Logo 衍生多色渐变，在 Light/Dark 下均有鲜明点缀与稳定阅读表面。可用轻柔光晕和低幅呼吸效果，不让装饰暗示进度；不可见/后台时暂停并释放不需要的动画。尊重系统“减少动态效果”：立即停用呼吸缩放、光晕脉动、渐变移动和进度过渡，保留静态品牌背景、真实步骤、数字百分比和进度条；系统设置改变时即时响应。所有 AI 图遵守第 6.1 节，禁止简约线条/色块堆叠。适配小屏、大字号与安全区，不重叠或裁切；正文对比度至少 4.5:1，错误操作点击区至少 44×44pt。状态提供 VoiceOver 可读标签和值，纯装饰从语义树排除。

#### iOS 原生启动页与三页验收

启动白屏与首帧连续性同时执行第 10.4.3 节：逐段定位原生画面、承接表面、Flutter 首帧及 Welcome 网页首绘；明确同页品牌承接、首屏就绪与总预算，保留可见错误恢复。Light/Dark 分别重复冷启动并检查后台恢复，不能仅凭一次成功截图或网页加载回调通过，也不能增加生产等待或额外启动页。

原生页实际接入统一执行第 10.4.2 节：解析实际构建组合的启动入口，核对 storyboard/原生资源及生成器覆盖，检查最终包和对应安装，再用连续冷启动录像核验新设计及到 Welcome 的衔接。该项独立于 AppIcon 与 Flutter UI；近白底小方图加名称、只改未启用的文件、预览或热重载均不通过。最后一次生成或相关配置/资源变更后重新构建验收，不能沿用旧证据。

iOS 原生启动页必须在 iPhone 冷启动中核验：采用静态 Launch Screen storyboard/资源，使用明显放大的正式 Logo、独立 `PRYRIN` 字标、来自已确认创意的定位文案、品牌装饰线及 Logo 衍生的非白色主题背景。`PRYRIN` 不替换用户提供的项目名称，Logo 不烘焙文字。原生页不显示交互、进度、步骤、百分比、呼吸/光晕动画或错误操作；它只在系统冷启动期间短暂出现，然后交给 Welcome。清除数据成功返回 Initialization 时不重新展示原生启动页。

在 `.codex-work/brand-assets.md` 记录原生启动页与 Welcome/Initialization 的素材、页面 ID、Logo 色板映射及实际引用。在当前构建上分别保留原生冷启动、Welcome 页面及其受控慢准备/错误状态、Initialization 页面和清除成功返回路径的运行截图或录屏，不能仅凭热重载、设计稿或页面代码声称已改善。准备时间不能为截图加入生产延时；慢准备/失败仅用测试入口或受控测试数据触发，不能进入正式行为。小屏/大屏 iPhone、大字号、Light/Dark、减少动态及运行中切换均需检查，不能出现留白、重叠、裁切、进度不实或不可操作错误；缺少运行条件时如实记录 `Not verified`，详见第 11.1、11.3 节。

### 7.2 初始化页（Initialization，`/entry`）

定义：初始化页是 Flutter 的单独页面，只在用户从 Settings 确认 `Clear Data` 且数据真实清理成功后展示；它有 `Entry` 主按钮。它不是每次启动出现的 Welcome 页、不是 iOS 原生启动页，也不是启动准备页。不得在正常冷启动或首次安装时把它当作 Welcome 展示。下次启动仍进入 Welcome。

UI：使用 Logo 派生的多色渐变、精致主题装饰、清晰的品牌/完成状态层级和足够的非纯文字视觉内容；显示适合真实清除结果的英文说明与 `Entry` 按钮，避免 Welcome 的 3–5 张引导卡片在此重复。初始化页底部安全区内居中显示 `By continuing, you agree to our` 换行 `Terms of Use and Privacy Policy` 这两行通用协议文本，在 `our` 后显式换行、无句末句号；第二行仅 `Terms of Use` 和 `Privacy Policy` 可点击，`and` 为普通文本：

```text
By continuing, you agree to our
Terms of Use and Privacy Policy
```

此页是唯一显示这段协议文案的位置。Welcome 和 根目录 `welcome.html` 引导页均不得显示或复制该协议页脚。协议链接仅在 AppListing 整理为 `aduit/` 后、生成 Review Remarks 前接入，直接使用 `aduit/intro.md` `All URL` 中对应原始值，不检查、规范化或修复目标；开发预览阶段可展示同样文案并经文档 ID 导航。协议提示不等于用户同意记录，不替代媒体权限。

行为：`Entry` 直接设 `AppFlowState` 为 `active` 并进入选定的主任务目的地，防止重复点击堆叠路由；不弹额外确认、不发起认证、不要求填资料或重新勾选协议。初始化页保留默认主题和随包示例；实际存在的用户私有数据/媒体列表为空，未选媒体功能不建立此类列表。清除成功后直接替换导航栈为该页；后台/重启恢复仍遵守“每次 App 启动进入 Welcome”，不从持久化标记将初始化页误当成普通启动首页。

### 7.3 按主题生成的主要任务页面

每个选定主要目的地必须说明，不论其入口是目录、工作台、工具栏、菜单、分段切换还是实际选用的 Tab：

1. 顶部层级和上下文操作。
2. 首屏和主要 CTA。
3. 内容模块和卡片结构。
4. 在主题确实需要时使用搜索、筛选、排序、视图或播放控件。
5. 空、加载、部分失败、离线和成功状态。
6. 消费的数据模型和资源 ID。
7. 详情路由和返回行为。
8. 本地持久化内容。
9. 无障碍标签、焦点顺序和减少动态行为。
10. 按第 6.10 节列出本页及适用状态的非纯文字表达、实际信息模块、资源/组件引用和逐页视觉验收依据；不能只写“丰富内容”或复用首页描述。

页面必须消费真实种子数据或审核通过的本地资源。静态占位卡片不算完成。

### 7.4 Detail

UI：返回操作、稳定媒体比例、标题、副标题、分类、时长或有用户价值的元数据、结构化内容区段、主要操作与相关内容。图片/视频的图库来源、作者和许可不作为默认展示字段；仅按第 10.1.1 节处理确有义务的必要署名，不展示内部资源清单。

图文深度：按第 6.10 节将正文组织为至少三个有不同信息价值的模块，并实际加入有助理解的主题图片、图解、步骤或实例；视觉与当前 `contentId` 的内容一致，不能只在顶部放一张通用封面、下部仍是连续无层次段落。

行为：按 `contentId` 加载，处理不存在的 ID，返回时保留来源状态，支持展开长文本，并对复制或重试操作提供可见反馈。

### 7.5 Player（主题需要媒体时）

UI：媒体区域、标题、播放/暂停、进度、剩余时间、静音/音量；仅在实际支持时显示全屏控制和下一条内容。图片/视频来源和许可按第 10.1.1 节处理，不默认展示图库名、下载链接或来源声明。

生命周期：退出路由、进入后台、中断或替换时释放控制器；取消过期加载。运行时播放审核后的随包本地资源或用户私有媒体，不调用第三方素材供应商 API；文件缺失、损坏或解码失败时显示真实错误并允许重试/返回，有相关且有效的本地替代内容时才提供替代，不反复切换同一损坏文件。

### 7.6 Settings 与工具路由

Settings 包含外观、主题相关偏好、版本、构建号和三个统一的 WebView 入口按钮；不默认创建图片/视频来源列表、素材归因页或 Credits 入口。素材的必要声明按第 10.1.1 节处理，软件依法须保留的许可通知不受影响：

- `Privacy Policy`：打开隐私政策 WebView。
- `Terms of Use`：打开用户协议 WebView。
- `Support`：打开 Support 页面 WebView。

三个按钮必须集成在同一个 Settings 页面中，并通过同一个 `policy_webview_page` 展示对应内容。`aduit/site/index.html` 在最终交付中只保留生成器提供的 About Home 页面；工程根目录 `welcome.html` 才是每次启动出现的 Welcome 唯一运行引导文件。根目录引导页不创建 Settings 按钮、不写入 Settings 列表，也不显示协议通用文案。Settings 另设独立的 `Clear Data` 按钮，放在清楚区分的数据区域，配简短删除范围说明；点击后按第 7.7 节二次确认并清理，成功后进入 Initialization。清除由原生 Flutter 流程执行，不通过 WebView 或远程服务处理，不保留另一个退出或登出入口。不得展示邮箱身份输入、账号、个人资料、收藏、社区或登录状态；开发者支持联系方式按第 0.3 节处理。

公开交付内容固定为四个 HTML 页面：`index.html`（生成器提供的 About Home 页面）、`PrivacyPolicy.html`、`Terms&Conditions.html` 和 `Support.html`，并仅配套 `img/logo.png`。`Disclaimer` 与 `Content & Copyright Notice` 仅作为清晰标题和目录入口合并到 `Terms&Conditions.html` 或 `PrivacyPolicy.html`，不单独生成额外 HTML 文件；`aduit/site/` 的物理文件始终只有这四个 HTML 页面与 `img/logo.png`。`aduit/review/remarks.md` 是单独的 App Review 交付材料，不是应用页面，不注册为文档 ID、不加载到 WebView、不在 App UI 中展示。开发期间四页可作为本地随包 HTML 预览；最终 AppListing 改名为 `aduit/` 后，工程根目录 `welcome.html` 是唯一运行引导文件并加载到每次启动进入的 Welcome 本地 WebView；`aduit/site/index.html` 继续作为四个站点页面之一保留，不作为运行时引导源。四个 `All URL` 值原样保存到固定 URL 注册表。Settings 仅显示 Privacy Policy、Terms of Use、Support 三个入口，不显示或链接引导页；只有 Clear Data 成功后出现的 Initialization 页面底部提供 Terms 与 Privacy 的文本入口。三个 Settings 入口和两个 Initialization 协议链接使用同一个 `policy_webview_page` 容器；Welcome 及其 HTML 引导页均不显示协议通用文案或协议页脚。URL 缺失、无法加载时显示可读错误状态、返回与有限重试。协议版本变化只更新正文和版本日期，不要求重新勾选，也不改变 Welcome 的 `Continue` 可用性。不得因域名或链接问题等待公开部署。

WebView 实现边界：

URL 原文保护按第 12.1 节执行：四个 `All URL` 完整字符串严格区分大小写；即使暂不可访问，也须原封不动保存并传递。不得把 URL 或路径转成全小写/全大写，不得根据页面标题重拼 `PrivacyPolicy.html`、`Terms&Conditions.html`、`Support.html`；只允许必要的源码转义，运行时值必须与生成器原文精确相等。协议地址错误态和重试均复用同一原始值，不能在失败回退中偷偷重写网址。


- 固定 URL 注册表按名称保存 `All URL` 中的四个原始值；Settings 只暴露 Privacy Policy、Terms of Use、Support 三个入口，只有 Clear Data 成功后出现的 Initialization 才暴露 Terms/Privacy 两个文本链接；Welcome 与其 HTML 引导页不显示协议通用文案或协议链接。About Home 不出现在 Settings。实际入口只接受固定文档 ID。Disclaimer 与 Content & Copyright Notice 映射到现有法律页的章节锚点，不新增物理文件。注册值必须与第 12.1 节 `All URL` 中四个值逐字对应。
- 开发期可从已注册的本地随包路径加载页面，不启动远程首屏请求。完成最终回接后，仅在用户主动点击某协议入口时，将对应的原始 URL 字符串交给 WebView；注册值按普通字符串原样保存和传递，不执行 URI 预解析/有效性检查作为导航前置条件。若 WebView 平台不能解析或加载失败，取消当前请求并使其操作 ID 失效，显示可读错误和返回操作。不得清理、修复、重写或跳过该值；重试仅由用户明确点击触发，不循环请求。
- 不开放任意 URL 输入或本机任意文件读取。最终四个 `All URL` 值为显式注册目标；不得因格式不常见而规范化或替换。任何其他导航按既有 WebView 安全边界处理，不运行来源不明脚本、不加入宽泛 ATS 例外。仅本地随包的 Welcome 首页引导 WebView 可启用一个最小原生消息桥，并且只接受精确消息 `continue`；Bridge 不可用时只拦截精确目标 `go://continue`，两者均触发 Welcome 的既有主流程，不能开放通用方法或任意 URL。本地引导页所有脚本均为随包单文件内联内容。回归测试以无网络 stub/fake 验证 Initialization 协议传入字符串、Welcome Continue 两条路径与失败路径，不向真实协议目标发请求。
- 三个 Settings 协议页面和 Clear Data 成功后 Initialization 页底部的两条协议链接提供实际 App 导航入口；工程根目录 `welcome.html` 是唯一运行引导页，只在每次启动进入的 Welcome 加载；`aduit/site/index.html` 仅作为生成器提供的 About Home 页面保留，不写入 Settings 或其他协议链接列表。Welcome 与引导页均不显示协议通用文案。Disclaimer 与 Content & Copyright Notice 必须在现有法律页面中有清晰标题或目录链接，不能创建额外文件。公开页面不加载追踪脚本或第三方字体/嵌入资源来制造未披露请求；开发期本地预览不依赖网络字体、图片或 CDN。最终协议 URL 回接后按实际 WebView 数据流复核隐私声明。
- 原生系统选择器和权限弹窗保留系统交互；WebView 不承担摄像机或麦克风采集，也不请求这些权限。正文文字缩放、长文滚动、最终 URL 的用户点击路径、返回目标、开发期离线预览及最终地址失败状态均实际检查；URL 回归用 stub，不发起真实请求。

#### AppListing 完成后的协议链接回接

本小节是最终链接回接步骤，优先于上文仅适用于开发期本地 WebView 的说明。在 About/AppListing 本地生成并改名/整理为 `aduit/`、根目录 `welcome.html` 引导页完成替换与接入后、生成 Review Remarks 前，必须实际回接 Initialization 底部协议文案并更新 Initialization 与 Settings 链接目标。只有 Clear Data 成功后出现的 Initialization 页面使用以下固定两行；每次启动进入的 Welcome 及其 HTML 引导页均不显示协议通用文案或协议页脚。文案在 `our` 后显式换行，不依赖自动折行，不增加句号：

```text
By continuing, you agree to our
Terms of Use and Privacy Policy
```

第二行的 `Terms of Use` 与 `Privacy Policy` 是独立可点击的文字链接，分别使用 `aduit/intro.md` 的 `All URL` 中对应原始值，`and` 为普通文本；仅在 Initialization 页面底部安全区内居中显示，不遮挡该页 `Entry`。Welcome 的 HTML 引导页只包含产品介绍卡片和 `Continue`，不显示协议通用文案或协议页脚。协议提示不添加复选框或额外确认，不保存个人协议同意记录；该协议提示不替代摄像机、相册、麦克风授权。Settings 只显示三个入口：`Privacy Policy`、`Terms of Use`、`Support`，分别使用 All URL 中对应值；不显示或链接首页引导页。将四个 `All URL` 值全部逐字复制到应用固定 URL 注册表，即使对应首页的 About Home URL 没有用户可见入口也保留原始值。所有值按原始字符串保存和传递，不以 URI 预解析或有效性检查作为复制、保存或导航前置条件；不得验证、规范化、补全、替换或因无法访问/格式异常而删除。注册值保存在 App 的固定配置中，不新增 `aduit/` 白名单以外文件。

三个 Settings 入口及 Initialization 的两个协议入口统一通过现有 `policy_webview_page` 加载各自注册 URL。失效或不可访问的 URL 只影响当前 WebView，显示易懂的错误态并提供返回与有限重试；不得阻断 App 启动、Welcome 引导页 `Continue`、Settings 其他功能或清除数据。回归时用不发起网络请求的 WebView stub/fake 核验实际入口传入 URL、首页引导页不出现在 Settings、Welcome 无协议文案、失败与返回状态，不访问或探测真实地址。完成后针对 Welcome 引导页、Initialization、Settings 三个入口和主流程进行定向回归。

### 7.7 清除本地数据（二次确认后进入初始化页）

1. **首次点击只显示确认框**：Settings 的 `Clear Data` 打开标题为 `Clear Data?` 的对话框，提供 `Cancel` 与破坏性 `Clear Data`。二次确认指点击入口后，再在这一个对话框内明确确认，不连续弹出两个确认框；点击入口时不能提前删除、停止当前任务或改变路由。
2. **准确说明后果**：确认正文须只列本 App 实际保存的数据类别；若有照片副本、导入媒体或录音才纳入，否则不出现相关删除声明。说明实际记录和设置将被删除，无法通过 App 撤销，随后进入 Initialization；系统相册原件和已导出文件不受影响。可采用 `This will permanently remove photos, videos, recordings, records, and settings saved in this app, then show the Entry page. Originals in Photos and exported files are not affected. This cannot be undone.`，按实际媒体类型与数据范围调整，不出现 `local`、`device` 或内部存储术语，不宣称能擦除设备备份或远端副本。
3. **取消不产生副作用**：点击 `Cancel`，或在确认前使用允许的返回/关闭动作，只关闭确认框并保留 Settings、滚动位置、主题、媒体和偏好；无确认回复、超时和系统权限结果都不能代替 `Clear Data`。连续点击入口只显示一个确认框。
4. **确认后安全清理**：将 `AppFlowState` 设为 `clearing`，立即防重复并阻止新保存、导入与编辑；最小恢复标记成功落盘后才开始破坏性清理，使旧操作结果失效。仅停止/释放实际存在且正在使用的摄像机、录音、播放或音频会话，取消/隔离实际导入、文档加载与旧异步任务；未选功能不创建空服务以供清理，关闭旧预览及相关 Sheet，按第 8.4、8.5 节收尾在途事务并删除 App 自有可变数据；清理完成前不允许旧回调重新写入记录、文件、缓存或偏好。
5. **清理中可观察且防重复**：显示 `Clearing data…` 和真实阶段状态，禁用重复提交及进入主流程的动作；完成量来自实际步骤，不虚报百分比。确认后删除可能已部分执行，不提供会把残余内容当作完整数据的普通取消/返回；系统后台或关闭 App 不等于取消，重启按恢复标记继续。重试复用同一清除操作，不新增确认框或叠加删除任务。
6. **只有真实成功才返回**：全部目标数据与缓存清理、设备释放、默认状态重建和残留核验通过后，按第 8.5 节移除恢复标记，清空整个导航栈与旧页面状态，设为 `entry` 并替换到 `/entry`；默认主题为 `System`，介绍展示记录、筛选和播放位置均恢复初始值。返回手势和旧深链不能打开已清除内容；再次点击 Initialization 的 `Entry` 后进入选定主任务入口，随包示例仍可用，实际实现的创建/保存操作仍能正常完成，不为未选功能添加入口。
7. **失败可恢复且不谎报成功**：恢复标记写入报错时先核对真实提交状态；确定未提交且未开始删除时，清理本次不完整暂存标记、解除写入隔离并恢复 `active`，留在原 Settings 显示可重试错误，不能声称已清除。若标记实际已提交则按已确认操作继续；无法判断时保留隔离并显示可恢复错误，不盲目重启操作。删除已开始后的部分失败保留标记、剩余阶段与写入隔离，展示 `We couldn't clear all your data. Try again.` 及可操作的重试，不得显示成功、提前进入 Initialization 或自动恢复主页面。记录脱敏错误与实际未完成项，不在 UI 暴露文件路径或内部事务信息；iOS 不调用进程终止接口或强制关闭 App。

媒体停止/释放单次默认最多等待 5 秒；超时按失败处理并继续跟踪原任务，不把超时视为释放完成、不丢弃任务引用、不并发重启同一任务。其他清理按阶段/有界批次推进，连续 15 秒没有可观察进展时转为可操作的异常恢复状态，说明仍未完成；底层任务尚未结束时先核对状态，不允许重试与旧任务同时删除。实际仍在进展的批次可以继续，不以 5 秒或 15 秒强制宣称全量清理完成。清除是设备端操作，不等待网络、域名或开发期外部服务。

### 7.8 摄像机拍摄（仅选用时适用）

- 必须提供与主题任务相连的拍摄入口、真实摄像机预览、拍摄、结果预览、重拍、取消与确认保存；支持设备实际具备的前后摄像头和闪光灯状态，无对应能力时隐藏或禁用控件。
- 处理初始化失败、授权拒绝/受限、设备缺失、方向变化、后台切换、连续点击和空间不足；不使用静态图冒充实时预览，不以权限弹窗出现视为功能完成。
- 保存后结果必须出现在对应主题记录或本地素材列表，可再次打开、查看并删除；照片方向、缩略图和实际文件一致。录像可按主题增加，拍照本身不得连带采集音频。

### 7.9 相册导入（仅选用时适用）

- 使用系统相册选择器选择图片，按主题需要支持多选或视频；导入后提供缩略图、加载进度、预览、取消与保存到主题记录的动作，不先申请不必要的整库访问权限。
- 处理取消、空选择、有限访问（使用 PhotoKit 时）、HEIC/JPEG/PNG 等声明支持的格式、超大图、方向、损坏文件和 iCloud 项目下载失败；异步导入可以取消，失败不遗留半条记录或临时文件。
- 必须将用户选择的可用文件安全复制到 App 私有目录并验证后再标记成功，不长期依赖选择器的临时 URL；对不支持的格式清楚提示。只有实际实现系统相册导出时才增加相应权限与状态。

### 7.10 麦克风录音与本地媒体管理（按实际选用范围适用）

录音相关要求仅在实际选用录音时适用；仅有拍照或导入时只实现所需媒体管理，不连带添加录音、音频会话或麦克风权限；全部未选时整节不适用。

- 必须实现真实录音、明确的录制状态、计时、停止、试听、重录、取消、保存与删除；波形/音量反馈如显示必须来自实际采样。暂停/继续只在底层可靠支持时提供，不做无效按钮。
- 保存格式与编码必须兼容 iOS；录音结果能在主题记录或本地素材列表中重新打开并播放，显示准确时长。处理权限拒绝、音频会话中断、蓝牙/耳机切换、后台、空间不足、保存失败与重复点击。
- 仅为实际存在的拍摄、导入或录音结果提供所需的本地媒体管理：按实际来源显示类型与缩略图/波形、预览、主题关联和删除，不为凑三种来源补建未选功能。删除同步清理记录、文件、派生缩略图及临时缓存。权限撤销不删除已保存文件，不建立个人账号或社区内容流；三项均未选用时不创建私有媒体仓库。
- 第一次使用时提供清晰空状态、示例用途和可达入口；拒绝某一权限仍能使用已有内容与其他已获授权能力。不得自动录制、后台偷录或自动上传。
