## 6. 视觉系统与 UI 质量

### 6.1 视觉方向

采用内容优先、高信息密度、沉浸但可读的移动端方向：

- 首屏必须展示真实主题内容和明确的下一步动作。
- 层级清楚：页面标题、核心任务、内容分组、辅助信息、次要操作。
- 鼓励使用与理解内容有关的图片、视频封面、轻量背景和状态色。
- 必须根据用户创意加入多种贴合主题的 Emoji，丰富欢迎页、内容分类/模块和适用状态反馈的视觉效果；具体使用与验收按第 6.8 节执行，不能只在设计说明中写计划而不实际显示。
- 视觉基调必须鲜艳、鲜明且有层次，以第 2.5 节从最终 Logo 提取的主色、辅助色与强调色作为项目配色依据；使用协调的高饱和强调与稳定阅读表面，不套用与 Logo 无关的固定色表，不用灰暗或杂乱的配色削弱品牌。
- 渐变是主要视觉语言之一，用于品牌背景、Loading、主要 CTA、选中态、卡片强调区和 WebView 外层容器；条件允许时优先采用第 6.5 节的动态渐变，渐变必须服务于层级，不得让内容变得难以阅读。
- 不要用空白营销 Hero 代替 App 的核心体验。
- 智能体先生成符合创意且色彩鲜艳的 Logo，再从其实际色块定制 App 与 About 主题色及渐变，说明原始色、衍生色的用途与选择理由；确认前只规划方法，正常路径的最终色值不能先于 Logo 提取。

### 6.2 主题模式

Settings 必须提供 `System`、`Light` 和 `Dark`，默认值为 `System`。选择结果必须同步到所有选定 Tab、Loading、Entry、详情、播放器、空状态、错误状态以及协议 WebView 外层容器；取消清除确认时保持原主题，清除成功后恢复 `System` 并立即同步到欢迎页与后续页面。

### 6.3 设计令牌

在 `common_module/theme/` 定义令牌，页面中禁止散落硬编码：

- Flutter 布局尺寸按逻辑像素定义，WebView CSS 尺寸单独注明 CSS px，不把物理像素、pt、dp 和 CSS px 混为一组数值。
- 间距：4、8、12、16、20、24、32、40、48 个逻辑像素。
- 圆角：4、8、12 个逻辑像素；主要内容面最大 16。
- 所有在 App 内展示的图片资源、Logo、视频封面、缩略图和媒体容器必须使用非零圆角，统一通过 `mediaRadius` 令牌裁剪；禁止直角图片或 `borderRadius: 0`。平台要求的 AppIcon 外部蒙版可按系统规范处理，不视为 App 内图片展示。
- 点击区域：iPhone 上至少 44×44pt，在 Flutter 中按对应逻辑尺寸实现。图标外观尺寸可更小，但不能缩小可点击区域。
- 正文基准字号至少 16 个逻辑像素，HTML 正文至少 16 CSS px，行高约 1.45–1.6；保留系统文字缩放，不用固定字号绕过 Dynamic Type。
- 动效：反馈 80-150ms，转场 220-350ms，列表交错 300-450ms；支持减少动态效果。
- 对比度：普通正文至少 4.5:1，有意义的图标和控件边界至少 3:1。
- 色彩令牌包含来自 Logo 的主色、辅助色、强调色，以及至少 2 个中性文字色、2 个稳定表面色和实际所需语义状态色；品牌强调保持鲜艳且可区分。按实际 Logo 色块数量建立原始色表，分类与状态需要扩展时只加入有依据的协调衍生色并注明，不能为满足色相数量硬塞无关颜色。
- 必须包含可见品牌渐变，渐变令牌至少包含 `brandGradient`、`sunsetGradient`、`aquaGradient` 和 `neonMixGradient`；名称是工程标识，不预设与 Logo 无关的色相。色标来自 Logo 原始色或已记录的协调衍生色，每个渐变记录来源、方向、色标、适用组件、浅色模式和深色模式版本。
- 渐变上的文字、图标和控件边界必须单独通过对比度检查，动态渐变核对整个变化范围而非单张截图；无法达到对比度时，增加纯色/半透明表面层，不使用渐变直接承载长段正文。动态渐变的位移/色标变化、速度、缓动、暂停条件与同配色静态回退统一使用主题令牌，不能各页自行设定不一致动画。
- 图标：使用同一矢量图标族并配置无障碍标签；Emoji 必须按第 6.8 节用于主题内容与状态的视觉点缀，不替代导航、播放、设置、返回或破坏性操作图标。集中定义 Emoji 的语义映射、字号、间距与对齐规则，禁止页面随机选取或散落不一致样式。

### 6.4 响应式与无障碍

- 遵守安全区和系统栏。
- 仅适配支持的小屏、标准屏和大屏 iPhone，覆盖 iPhone 的竖屏和横屏、安全区、系统栏、键盘与屏幕遮挡区域，不得横向溢出；按第 0.10 节不制作其他设备布局、样机或截图。
- 支持 Dynamic Type、VoiceOver、减少动态和增强对比度。
- 卡片、网格、工具栏、播放器和底部导航使用稳定尺寸。
- 长文本自然换行；标签、按钮和卡片不得重叠、裁切或不可预测地挤压相邻内容。
- 颜色不能是唯一状态信号，必须同时使用文字、图标或语义。

### 6.5 色彩与渐变应用

- 每个主要页面至少使用一个多色强调区域和一个稳定纯色阅读区域；同一页面连续模块不得全部使用同一颜色或同一渐变。
- Loading 使用多色渐变背景、项目名和可观察的加载动画；动画渐变只做轻微位移或明暗变化，开启减少动态时切换为静态渐变。
- 主要 CTA 使用由 Logo 配色形成的鲜明渐变或高饱和品牌纯色，并同时提供文字、图标、按下态、禁用态和焦点态；不可只靠颜色区分可操作性。
- 卡片、图片、视频封面和媒体容器继续使用圆角；渐变只作为容器背景或叠加层，不覆盖图片主体到无法辨认。
- Entry、Settings、协议 WebView 和 About 页面可共享品牌渐变，但正文、主题所需的表单输入和协议文本必须放在稳定的高对比表面上。
- 渐变方向、色标和透明度必须使用主题令牌管理，禁止在页面组件中散落硬编码颜色。
- App 的 Loading、Entry、主内容强调区与 About 品牌区域实际显示协调渐变和鲜明色彩；按第 2.5 节配色记录逐项核对 Logo → 原始色块 → 主题令牌 → 页面共享样式，不能只声明“含渐变”却全部显示无层次的纯色页。
- **条件允许时动态化**：App 与 About 支持的品牌背景、Loading、Entry 和主内容强调区优先采用缓慢、平滑的动态渐变，例如渐变方向轻微移动或在已选品牌色标间柔和过渡；默认约 8–12 秒完成一次平稳循环，可按实际效果调整。变化只使用 Logo 提取色与已记录的衍生色，不变成无关彩虹轮换、强烈闪烁或快速明暗跳变；不要求每张卡片和每个按钮都持续动画。
- **保护主要任务**：正文、协议、清除确认及拍摄/录音/播放的主要控件保持稳定高对比表面，不让动态背景干扰阅读、取景或操作。页面不可见或 App 进入后台时停止动画，返回前台仅恢复当前可见区域；避免为列表各项创建持续运行的独立动画，按第 11.8 节核验对启动、滚动、媒体处理与资源占用的影响。
- **静态回退**：遵守 iOS/Flutter 的减少动态设置，以及 About 网页的 `prefers-reduced-motion`；用户开启减少动态、渲染能力受限或实际性能检查显示明显卡顿/额外负担时，切换为同品牌配色的静态渐变，保留视觉层次与鲜明色彩。检测与回退自动执行，不要求用户或委托方新增选择；记录实际动态展示、暂停/恢复、回退及未验证范围，不把静态截图冒充动态效果已验收。

### 6.6 人性化文案

- 所有可见文本使用自然、简短、友好的英语，优先说明用户下一步可以做什么，不使用生硬的系统术语、内部状态名或责备语气。
- 第 6.8 节要求的图形 Emoji 可以与自然英语搭配，但不能作为替代清晰文案的唯一标签；不使用带中文或禁用术语的文字型表情、贴纸和素材。Emoji 的可访问名称与提示同样使用自然英语，仍须通过本节的显示文案检查。
- **显示范围**：本节适用于 App 可控制的标题、Tab、按钮、正文、内容示例、输入提示、确认框、加载/空/错误提示、Toast、Snackbar、通知（实际实现时）、VoiceOver 标签与提示，以及 WebView 中的 About/Support/协议、AppListing 公开文案、截图、图片内嵌文字与视频字幕。不能只检查首页或按钮；最终 App 的状态分支和公开网页都须核对。
- **禁止中文及内部术语**：不得在上述显示文本中出现中文，以及 `H5`、`SDK`、广告、第三方框架、技术实现、内部模块、`lib`、`package`、`packages`、`local`、`device`、测试、模板、马甲、过审等文字。英文不分大小写检查，按独立词及词形/代码路径核对，同时检查同义的内部实现表达，例如 `Local Data`、`Device Storage`、`test mode`、`testing`、`template`、`framework`、`internal module`、`implementation`、`reskin`、`white-label`、`review bypass`、`ads`、`advertisement`、`advertising`；框架、语言和容器名称如 `Flutter`、`Dart`、`WebView` 也不作为用户可见功能说明。不得通过缩写、换大小写、插入符号或同义改写继续向用户展示这些开发概念。使用主题相关的内容名称、清晰操作与真实结果替代表述。
- **工程信息留在工程中**：技术名称、目录、类名、模块标识、测试和模板说明可以保留在源码、配置、文件路径、日志及中文开发报告中，不能直接作为可见标题、错误文本或无障碍读出。保持实际 `lib/`、`package/`、`packages/` 与其他依赖路径，不为消除文案关键词重命名工程结构、删依赖或破坏许可；屏蔽原始异常、文件路径、堆栈、HTTP/平台错误详情和调试标签，用自然英文说明可采取的动作，脱敏诊断另记。`Development only`、`Local only`、`Blocked`、`Verified` 等开发状态仅记在内部清单/报告中，不作为 App UI 标签、资源水印或公开网页正文；存在开发占位或发布缺口时保留准确的内部状态，不能因此冒充正式产物。
- **About 与协议必须是完整成品文案**：About Home、Privacy Policy、Terms & Conditions、Support 的正文、页面标题、描述元数据、图片替代文本及无障碍标签均不得出现作为页面状态/作者标记的 `Draft`、`WIP`、`TBD`、`TODO`、`Placeholder`、`Pending confirmation`、`Coming soon`、方括号填空项、作者备注或尚未完成提示。真实产品功能名称只有在项目事实支持时才可使用，不得把它当作页面的工作状态标签。每页应能独立阅读，结构、日期、导航/锚点、产品说明和支持内容应像已认真编写的正式页面；不能用视觉精致的壳子包住空白、泛化段落或待填写字段。
- **事实缺口留在内部记录**：不得猜测支持邮箱、开发者/运营主体、司法辖区、数据接收方、保留期限或受众年龄。缺少确认值时，省略无法可靠撰写的声明/联系区，不在 HTML 放置“待补充”文字；在生成摘要中逐项记录缺口，并将法律公开审阅状态标记为未完成。页面生成与离线核验继续进行，但不能将缺失法定信息的文本称为已完成法律审阅或可直接公开发布。
- **真实披露与系统界面**：以本规则改写自有 UI 和公开网页，权限用途字符串也使用具体、自然的英语；隐私政策仍准确说明数据的采集/处理、接收方、保存/删除、备份边界和系统选择，用 `saved in this app`、`photos you select` 等用户能理解的表达说明实际行为。保留法定披露、真实接收方/权利人名称与许可义务，不能为了词库隐藏实际追踪或数据传输，也不能假称未发生的行为；确有不可改写的必需名称时记录准确冲突，不擅自删掉。iOS 系统权限框、系统相册选择器、系统设置及用户自行拍摄/导入/录制的内容不由 App 文案控制，不覆盖系统文字、不改用户原始内容，也不强制修改用户系统语言。以上是本项目文案约束，不是 Apple 官方禁词表，不能据此声称保证通过审核。
- 加载文案示例：`Getting things ready…`、`Just a moment…`；失败文案示例：`We couldn't load this page. Try again.`；空状态文案必须说明当前没有内容以及可采取的动作。
- 主题所需的表单错误应直接说明原因，例如 `Choose an item to continue.`，不要只显示 `Invalid input`；Entry 页面不添加身份输入表单。
- 进入按钮文案固定为 `Enter`，Settings 的全量清除入口固定为 `Clear Data`；确认框使用 `Cancel` 与 `Clear Data`，不能把清除含糊标为 `OK` 或普通返回。协议入口使用文档名称，其他按钮使用清晰动词，如 `View`, `Back` 和 `Try again`。不显示退出、登录、登出、邮箱认证或协议勾选提示。
- 文案不得暴露实现细节或使用夸张承诺；正式协议正文保持法律准确性，入口和状态提示保持易懂。

清除流程的统一可见文案为：入口与确认动作 `Clear Data`，确认标题 `Clear Data?`，取消 `Cancel`，进行中 `Clearing data…`，失败 `We couldn't clear all your data. Try again.`。确认正文按第 7.7 节准确列明删除范围与不可撤销后果，不出现 `local` 或 `device`；这只更新显示文字，清除本地数据、二次确认、成功返回欢迎页及失败恢复的实际行为保持一致。

### 6.7 必须投入充分工作量的 UI 精修

UI 设计、实现后的美化与资源调整是主要工作阶段，不能在“功能能跑”时直接交付。规划与执行均须为 UI 与资源精修合计保留至少一半的实际开发工作量，其中 UI 设计、细节调整与不同 iPhone 尺寸检查至少占三分之一，图片/视频的筛选、替换、裁切、封面和播放优化至少占六分之一；分配时不重复计算同一项工作。按页面与资源批次记录实际操作、修复、前后对比和检查结果；具备可靠时间记录时补充真实耗时，没有时只报告可核对的工作量，不虚报分钟或用空等、重复无改动截图满足要求。

投入比例是资源分配要求，不能单独证明精修充分：总工作量较小时仍须完成全部页面、适用状态、素材检查和真实迭代，不得以“已占一半”为由跳过任何质量要求。规划时记录功能实现、UI、资源、验证各阶段的预估工作及依据；执行时记录实际完成项、真实计时或明确标注的估算。缩短服务等待、并发和复用可以减少总耗时，但不得因此删减内容、减少精修覆盖或取消验收；不能从运行时间自动推断质量提高或降低。

必须完成至少三轮“运行并截图 → 逐屏评审 → 实际修改 → 再运行核验”，每轮都记录问题、修改及前后截图路径：

1. **整体构图与内容层级**：精修核心主页面、Loading、Entry、Settings、拍摄、相册导入前后与录音页面，检查布局节奏、信息密度、导航、主次动作、留白、安全区和真实内容呈现。
2. **品牌与细节**：逐项调整字体尺度与字重、行距、间距、图标一致性、第 6.8 节 Emoji 的主题匹配/大小/基线/密度、圆角、图片裁剪、渐变、对比度、按钮和输入状态；逐屏更换不贴题、模糊、主体裁切错误或重复明显的图片/视频，调整真实视频封面与文字叠层，避免所有页面套用同一种卡片布局。系统选择器与权限弹窗保留原生样式，只精修 App 可控制的周边流程。
3. **状态、动效与适配**：覆盖 Light/Dark/System、小屏/标准屏/大屏 iPhone、iPhone 横竖屏、长文本、Dynamic Type、VoiceOver、减少动态，以及加载、空、失败、权限拒绝/受限、录制中、保存中、清除确认、清理中、清理失败和成功状态；核验键盘避让、滚动、返回和媒体生命周期。破坏性清除使用清楚的文字与语义，不仅靠红色区分；确认框的初始焦点不得默认落在清除动作上，成功返回欢迎页后恢复合理的无障碍焦点。

核心流程必须在 iPhone 运行环境中逐屏查看，截图只作为证据，不能代替点击与交互检查。模拟器检查按第 0.9、0.10 节在工程创建完成后进行，三轮精修共享一个现有 iPhone，其他必要 iPhone 尺寸/支持的 iOS 版本依次切换，不为每页或每轮新开模拟器。明显遮挡、溢出、文字截断、不可读对比度、无法点击、错误加载层级或媒体控件错位必须修复；新改动引入的问题再次针对性核验。完成三轮后仍有影响使用或明显视觉质量的问题时继续精修，不能把三轮当作自动通过标准。

前后对比使用相同页面、示例数据、设备尺寸和可比状态，注明构建版本；补充说明轮次之间实际改变的内容。投入比例在规划时分配到可核对的任务，执行时按同一工作量口径核算；没有可靠计时就使用预先记录的任务估算与实际完成记录，并注明估算，不凭事后拆细 UI 任务数量制造比例。等待外部服务、无改动重复截图和反复运行相同检查不计精修投入。

UI 三轮迭代之外，按第 10.5 节至少完成两轮有实际筛选或调整的资源工作，可以与 UI 检查并发：第一轮按主题、模块和构图筛选并淘汰低质/重复候选；第二轮在真实页面与播放环境中调整裁剪、封面、清晰度、体积和重复分布。每轮记录替换前后资源 ID、原因、实际消费位置及结果，不能只下载一批素材后不再检查，也不能以重复采集同图证明投入。

开发者自主完成上述迭代，不向用户逐轮请求审批。实际不可用的设备或运行工具只影响相应验证项，记录未验证范围并继续其他精修，不用静态检查冒充完整视觉验收。

完成最低轮次后，按第 11.9 节进行一次与页面实现、三轮精修分开的交付前质量复核，直接检查当前构建、页面和最终随包资源。复核发现遗漏或明显视觉问题时继续实际调整并复验，不因预计提前完成而马上交付；已经有当前有效证据且没有新问题的检查不机械重复，也不通过空等、休眠或无意义修改凑满工时。

### 6.8 Emoji 视觉丰富度与使用规范

- **实际展示**：项目必须使用多种与已采用创意相符的图形 Emoji，至少覆盖欢迎页、主内容页的分类/模块，以及适用的空状态或成功反馈；每个主要内容 Tab 选择有意义的位置，不要求每个按钮、拍摄/录音控件或协议正文都添加。规划时记录展示位置、语义与搭配文案，实施后以真实页面截图核验，不用开发文档里的 Emoji 充当已实现证据。
- **主题与层级**：由智能体围绕真实内容选择 Emoji，不固定产品主题。拍摄、相册、录音的引导区域可分别点缀 📸、🖼️、🎙️，内容分类则根据实际对象选取；这些仅为示例。优先用于欢迎语、分组标题、分类标记和状态插图，数量与尺寸服务于层级，避免全屏堆叠、无关表情或所有卡片重复同一符号。
- **清晰操作**：Emoji 必须与清楚的英语内容或操作名称配合；导航、播放、返回、设置与清除等操作仍保留统一矢量图标及明确文字。`Enter`、`Clear Data`、`Cancel` 等固定按钮文案保持原样，装饰放在独立区域，不把 Emoji 拼入这些固定标签；破坏性清除、权限拒绝和失败提示使用准确、中性的表达，不用庆祝表情弱化后果。
- **统一样式**：集中维护语义映射与大小、行高、间距、对齐规则；同一语义跨页面稳定复用，不为追求数量随机轮换。使用原生 Unicode Emoji，检查最低支持 iOS 版本的实际字形、完整组合序列和显示宽度；缺字、方框或错误断行时换用兼容 Emoji，保持其英语标签，不依赖新增网络服务。
- **适配与动效**：在 Light/Dark/System、小屏/标准屏/大屏 iPhone、iPhone 横竖屏及大字号下检查基线、裁切、换行、阅读层次与点击区域，Emoji 不遮挡图片主体、文案或媒体控件。默认使用静态 Emoji；确有反馈动效时沿用第 6.3、6.4 节规则，支持减少动态，不持续闪烁或无意义循环。
- **无障碍与文案**：纯装饰 Emoji 从 VoiceOver 语义中排除，防止同一标题重复读出；传递分类或状态信息时为整个组件提供自然英语名称与状态，不靠表情或颜色单独传达含义，不让系统默认的 Emoji 读名替代操作标签。按第 6.6、11.4 节检查显示与读出内容，不夹带中文、内部术语或被禁止的文字型表情。
- **资源与验收**：Emoji 是视觉补充，不能替代 Stargate 正式 Logo、主题图片/视频、真实内容或三项媒体功能，也不计入独立图片/视频数量或资源调整轮次。同一语义的合理复用不视为第 10.5 节的素材重复，但不能用换 Emoji 掩盖重复封面；将实际展示、主题匹配、布局与 VoiceOver 结果纳入三轮 UI 精修及第 11.9 节质量复核，不新增用户审批。

### 6.9 图片自然度与内容列表尺寸层级

- **Logo 生成质量**：Logo 仍按第 2.5 节只在 Stargate 生成，要求鲜明配色、细致品牌造型和协调渐变；主体结构与主题比例应清楚、合理，材质、反射、阴影和光源彼此一致。检查并修复明显生成痕迹，包括畸变/融化的形状、断裂轮廓、重复纹理、随机碎片、伪文字、物理关系不成立的细节、塑料质感和无依据的强光晕。这里的“自然可信”是造型和视觉逻辑可信，不把 Logo 变成照片，也不削弱鲜明渐变。
- **内容图片来源和真实感**：内容照片继续严格按第 10.6 节从第三方网站取得有许可依据的真实摄影；不得用 AI 生成的拟真图、插画或图形化合成图冒充真实照片。候选图片必须准确对应页面描述的物体/场景；来源页、拍摄主体、透视/比例和可见细节应相互吻合，不选明显错题、异常结构、过度处理或有可疑生成痕迹的照片。Logo 的生成规则不得扩展为生成内容照片的许可。
- **按语义变化尺寸**：每个主要内容列表在多条内容可用时至少包含两种明显不同的卡片尺寸；主要浏览体验跨页面按实际内容层次覆盖 `featured`（重点大卡）、`standard`（常规卡）和 `compact`（紧凑行/小卡）三档（若创意内容不支持某档，记录原因），不要求每个页面都同时出现三档。尺寸差异通过图片面积、卡片高度或版面跨度让用户一眼可辨，不能只改边框/阴影。精选、常规、辅助角色必须由内容重要性、用户任务或浏览密度决定，记录映射与先后顺序；禁止随机高低错落、纯装饰性尺寸变化、同一条目在相邻位置换尺寸凑数量，或让大卡抢走用户的主要任务。
- **整体节奏与页面差异**：在同一列表内建立可预测的视觉节奏，重点卡强调、普通卡承载完整信息、紧凑项帮助快速浏览；整套 App 至少让主要内容页呈现两种有意区分的列表编排，避免所有页面只有完全相同尺寸的重复卡片，也避免每个页面随意套不同花样。搜索结果、相册选择、权限说明、Settings、协议等以快速扫描/准确选择为目的的行列表保持统一行高与对齐，不为“大小不一”而损害可用性。
- **图片与布局适配**：为各尺寸层级分别核对素材分辨率、宽高比、焦点位置与裁切；使用适当的 `BoxFit`/容器比例和可读叠层，不拉伸、不切掉关键主题对象、不因大图卡片反复复用同一图片。不同尺寸下标题、副文、标签和 Emoji 保持层次，文本随内容和大字号增长而扩展，不固定卡片高度导致截断；缩略图按展示尺寸解码，维持加载、空与错误状态一致。
- **无障碍和 iPhone 适配**：混合尺寸不能改变内容的语义顺序；视觉顺序、滚动顺序、VoiceOver 焦点顺序和 Tab 次序应相符，点击区域至少 44×44pt，Dynamic Type 下无遮挡、截断或水平溢出。在支持的小屏/标准屏/大屏 iPhone、横竖屏、浅/深色与大字号下实际检查每种卡片角色及断点；必要时将大卡改为紧凑布局或单列流式排列，但继续保留至少两级清晰层次。
- **验收证据**：页面规格记录每个主要列表的层级、排序理由、组件尺寸/比例与对应资源；精修截图覆盖同页大/中/紧凑项及至少两类主要页面。逐条检查图片自然度/主题准确性、尺寸区别是否清晰但协调、裁切、内容密度、滚动/点击、VoiceOver 和 iPhone 边界；发现突兀、随机、重复、错题或生成瑕疵须实际调整并复验。按第 11.9 节列出已检查的列表与图片证据，不以设计稿或写有三档名称的清单冒充运行效果。

## 7. 页面级 UI 与功能规格

每个选定 Tab 都必须生成专属章节，并实现 Loading、Entry、Settings（含 `Clear Data` 和二次确认）、协议 WebView，以及完整的摄像机拍摄、相册导入、麦克风录音与本地媒体管理流程。三项媒体能力为必做项，不因主题差异标记 `Deferred` 或 `N/A`；Detail、通用 Player 等其他页面按用户创意实现，录音的预览播放仍然必须实现。客观设备限制按第 11.6 节记录，不得假装完成。

### 7.1 Loading

UI：采用从已验收 Logo 色板衍生的深色多段渐变背景，在 Logo 后方使用柔和光晕，并以缓慢、低幅度的呼吸动画突出 Logo；显示品牌图形、用户提供的项目名、依据已确认创意写出的简短定位文案、当前真实加载步骤、百分比和进度条。定位文案须简洁、英语、具体可信，不夸大功能；不得把文案或 `PRYRIN` 烘焙进无文字 Logo。加载页不能只显示 Logo。

行为：先检查第 8.5 节的未完成清除恢复标记，再并行读取主题模式、首次使用介绍展示记录、本地清单和仓储准备状态。正常从关闭状态启动时，准备完成后进入 Entry；首次与后续启动使用同一进入流程，首次使用记录只影响介绍内容。存在已确认但未完成的清除时，先进入可观察的清理恢复流程，成功后才开放欢迎页的 `Enter`，不重新询问是否清除，也不恢复旧内容。启动不读取登录状态、不进行远程身份认证，也不搜索远程媒体；从后台恢复时保留当前有效页面或清理状态，不额外要求点击 `Enter`。即使本地准备很快完成，Loading 也保持可见约 200–500ms（默认约 300ms）的短暂视觉延迟；准备较慢时不额外阻塞。

将启动必需项与可延后项分开：主导航、最小内容索引和已保存主题为必需准备，大图解码、视频预加载、全库媒体扫描和本地文档完整性检查延后执行。必需准备默认总预算 10 秒；偏好读取失败使用安全默认值并保留原数据，单个非关键资源失败进入 Entry 后提示局部问题。并发结果带启动操作 ID，取消/重试后旧回调不得覆盖新状态。

进度只由启动所必需的真实里程碑及其完成状态计算，例如恢复标记核验、已保存主题与偏好读取、最小导航/内容索引就绪、仓储可用；启动前列明必需里程碑总数，百分比按“已完成的必需里程碑数 / 必需里程碑总数”计算并取整。存在可测量的真实子任务时，可按其已完成量/总量计算，但不得凭估时或主观权重分配比例。可并行的工作仍按实际完成状态更新，不为制造进度改成虚假串行或添加装饰性步骤。只有实际完成的工作才计入进度；显示当前正在执行的真实步骤，未完成前不得显示 100%。不得用计时器、呼吸动画、固定延迟或猜测的耗时推高百分比。某个步骤仍在进行时，百分比与进度条停留在最后一个真实完成点，步骤文案说明正在处理什么。必需准备完成后才到 100% 并进入下一状态；可延后的大图解码、视频预加载、全库媒体扫描和本地文档完整性检查不计入启动进度。

核心配置确实无法使用时进入可操作错误态，显示 `Try again` 与 `Clear Data`：前者以新的启动操作 ID 重试失败步骤或从一致启动状态重新准备，旧回调不得覆盖当前状态；后者打开现有 `Clear Data?` 二次确认并复用第 7.7、8.5 节的完整清理和恢复流程，取消不产生副作用，只有确认后的真实清理成功才返回 Entry。不得永久播放加载动画，也不得把损坏数据静默重置为空。

默认动效使用 Logo 后方光晕和轻微 Logo 呼吸，不让装饰动效暗示加载进度。尊重系统“减少动态效果”设置；开启时立即停用呼吸缩放、光晕脉动、渐变移动和进度动画，改为同色静态深色渐变/固定光晕与即时更新的静态进度显示，真实步骤与百分比仍完整可见。运行期间系统设置变化也要即时响应，不要求重启 App。进度条和当前步骤提供 VoiceOver 可读标签、值与状态；颜色不能是唯一进度信号。

状态：准备中、就绪、可恢复资源问题、离线、重试、不可恢复的本地配置错误。

#### iOS 原生冷启动页

iOS 原生 Launch Screen 必须实际改为静态品牌布局，并在 iPhone 冷启动中核验：使用比现有布局明显更大的正式 Logo，另行显示文字 `PRYRIN`、与 Flutter Loading 相同且来自已确认创意的简短定位文案，以及一条使用品牌色的装饰线。`PRYRIN` 是独立字标，不替换用户提供的项目名，不要求 Logo 含字；装饰线纯属装饰，不伪装成进度条。采用 iOS 原生 Launch Screen storyboard/资源和安全区约束，不用 Flutter 首屏假装原生冷启动页。该页面保持完全静态，不显示当前步骤、百分比或动态进度，不播放呼吸/光晕动画，也不添加交互；其职责是与系统启动阶段衔接，随后交给 7.1 节的 Flutter Loading 展示真实加载状态。深色品牌表面与渐变取自同一主题色板；如启动页平台限制不适合动态渐变，使用可访问性良好的静态品牌背景，不降低 Logo、文字和系统状态区的可读性。

### 7.2 Entry（欢迎页）

UI：品牌视觉、产品承诺、最多三个能力亮点、英文界面文案和带安全区内边距的 `Enter` 主按钮。提供 `Terms of Use` 与 `Privacy Policy` 文本入口，点击后使用统一 WebView 查看正文；主按钮始终清楚可见，不设置邮箱、密码、验证码、账号或协议勾选输入。

最终底部协议文案在完成 About/AppListing 本地生成并整理为 `aduit/` 后、Review Remarks 前，按下文“AppListing 完成后的协议链接回接”统一替换；不能只修改网页正文而遗漏 App 欢迎页。两行内容固定为第一行 `By continuing, you agree to our`、第二行 `Terms of Use and Privacy Policy`，在 `our` 后显式换行，无句末句号。整块位于欢迎页底部安全区内并居中，保证可读性、无截断且不遮挡 `Enter`；第二行仅 `Terms of Use` 与 `Privacy Policy` 分别可点击，`and` 为普通文本。

行为：点击 `Enter` 后直接将内存中的 `AppFlowState` 设为 `active`，替换 Entry 路由并进入第一个选定 Tab。不弹出额外页面或确认、不发起认证请求、不要求填写资料或先查看协议；防止快速重复点击创建多个主页面。首次使用介绍展示记录可在进入后保存，保存失败不阻断进入。从协议页返回时保留 Entry 的主题和展示状态。

清除本地数据真实成功后再次展示同一个 Entry，使用默认外观与初始介绍状态；用户仍可直接点击 `Enter` 重新进入，随包示例正常显示，用户本地媒体列表为空。不把 Entry 包装为“演示登录”或“访客登录”，也不因清除重新要求协议勾选或系统授权。

### 7.3 自动生成的 Tab 页面

每个选定 Tab 必须说明：

1. 顶部层级和上下文操作。
2. 首屏和主要 CTA。
3. 内容模块和卡片结构。
4. 在主题确实需要时使用搜索、筛选、排序、视图或播放控件。
5. 空、加载、部分失败、离线和成功状态。
6. 消费的数据模型和资源 ID。
7. 详情路由和返回行为。
8. 本地持久化内容。
9. 无障碍标签、焦点顺序和减少动态行为。

页面必须消费真实种子数据或审核通过的本地资源。静态占位卡片不算完成。

### 7.4 Detail

UI：返回操作、稳定媒体比例、标题、副标题、来源/署名、分类、时长或元数据、结构化内容区段、主要操作、相关内容和许可信息。

行为：按 `contentId` 加载，处理不存在的 ID，返回时保留来源状态，支持展开长文本，并对复制或重试操作提供可见反馈。

### 7.5 Player（主题需要媒体时）

UI：媒体区域、标题、来源、播放/暂停、进度、剩余时间、静音/音量；仅在实际支持时显示全屏控制和下一条内容。

生命周期：退出路由、进入后台、中断或替换时释放控制器；取消过期加载。运行时播放审核后的随包本地资源或用户私有媒体，不调用第三方素材供应商 API；文件缺失、损坏或解码失败时显示真实错误并允许重试/返回，有相关且有效的本地替代内容时才提供替代，不反复切换同一损坏文件。

### 7.6 Settings 与工具路由

Settings 包含外观、主题相关偏好、资源/归因、版本、构建号、许可和三个统一的 WebView 入口按钮：

- `Privacy Policy`：打开隐私政策 WebView。
- `Terms of Use`：打开用户协议 WebView。
- `Support`：打开 Support 页面 WebView。

三个按钮必须集成在同一个 Settings 页面中，并通过同一个 `policy_webview_page` 展示对应内容。About Home 仍作为 `index.html` 保留在生成的站点中，但不创建 Settings 按钮、不写入 Settings 列表。Settings 另设独立的 `Clear Data` 按钮，放在清楚区分的数据区域，配简短删除范围说明；点击后按第 7.7 节二次确认并清理，成功后返回欢迎页。清除由原生 Flutter 流程执行，不通过 WebView 或远程服务处理，不保留另一个退出或登出入口。不得展示邮箱身份输入、账号、个人资料、收藏、社区或登录状态；开发者支持联系方式按第 0.3 节处理。

公开交付内容固定为四个 HTML 页面：`index.html`（About Home）、`PrivacyPolicy.html`、`Terms&Conditions.html` 和 `Support.html`，并仅配套 `img/logo.png`。`Disclaimer` 与 `Content & Copyright Notice` 仅作为清晰标题和目录入口合并到 `Terms&Conditions.html` 或 `PrivacyPolicy.html`，不单独生成额外 HTML 文件；`aduit/site/` 的物理文件始终只有这四个 HTML 页面与 `img/logo.png`。`aduit/review/remarks.md` 是单独的 App Review 交付材料，不是应用页面，不注册为文档 ID、不加载到 WebView、不在 App UI 中展示。开发期间四页可作为本地随包 HTML 预览；最终 AppListing 改名为 `aduit/` 后，四个 `All URL` 值仍原样保存到固定 URL 注册表。Settings 仅显示 Privacy Policy、Terms of Use、Support 三个入口，不显示或链接 About Home；Entry 仅提供 Terms 与 Privacy 的文本入口。三个 Settings 入口和两个 Entry 链接使用同一个 `policy_webview_page` 容器；URL 缺失、无法加载时显示可读错误状态、返回与有限重试。协议版本变化只更新正文和版本日期，不要求用户重新勾选，也不改变 `Enter` 的可用性。不得因域名或链接问题等待公开部署。

WebView 实现边界：

- 固定 URL 注册表按名称保存 `All URL` 中的四个原始值；Settings 只暴露 Privacy Policy、Terms of Use、Support 三个入口，Entry 只暴露 Terms/Privacy 两个文本链接，About Home 不出现在 Settings。实际入口只接受固定文档 ID。Disclaimer 与 Content & Copyright Notice 映射到现有法律页的章节锚点，不新增物理文件。注册值必须与第 12.1 节 `All URL` 中四个值逐字对应。
- 开发期可从已注册的本地随包路径加载页面，不启动远程首屏请求。完成最终回接后，仅在用户主动点击某协议入口时，将对应的原始 URL 字符串交给 WebView；注册值按普通字符串原样保存和传递，不执行 URI 预解析/有效性检查作为导航前置条件。若 WebView 平台不能解析或加载失败，取消当前请求并使其操作 ID 失效，显示可读错误和返回操作。不得清理、修复、重写或跳过该值；重试仅由用户明确点击触发，不循环请求。
- 不开放任意 URL 输入、本机任意文件读取或非必要的 JavaScript/原生桥接。最终四个 `All URL` 值为显式注册目标；不得因格式不常见而规范化或替换。任何其他导航按既有 WebView 安全边界处理，不运行来源不明脚本、不加入宽泛 ATS 例外。回归测试以无网络 stub/fake 验证传入字符串与失败路径，不向真实目标发请求。
- 三个 Settings 页面和欢迎页两条 Entry 链接提供实际 App 导航入口；`index.html`（About Home）作为站点交付文件保留，但不写入 Settings 或其他 App 链接列表。Disclaimer 与 Content & Copyright Notice 必须在现有法律页面中有清晰标题或目录链接，不能创建额外文件。公开页面不加载追踪脚本或第三方字体/嵌入资源来制造未披露请求；开发期本地预览不依赖网络字体、图片或 CDN。最终协议 URL 回接后按实际 WebView 数据流复核隐私与 ATT 结论。
- 原生系统选择器和权限弹窗保留系统交互；WebView 不承担摄像机或麦克风采集，也不请求这些权限。正文文字缩放、长文滚动、最终 URL 的用户点击路径、返回目标、开发期离线预览及最终地址失败状态均实际检查；URL 回归用 stub，不发起真实请求。

#### AppListing 完成后的协议链接回接

本小节是最终链接回接步骤，优先于上文仅适用于开发期本地 WebView 的说明。在 About/AppListing 本地生成、配色核对并整理为 `aduit/` 后、生成 Review Remarks 前，必须实际替换当前 App 的 Entry 底部协议文案并更新 Entry 与 Settings 链接目标。Entry 使用以下固定两行，显式在 `our` 后换行，不依赖自动折行，不增加句号：

```text
By continuing, you agree to our
Terms of Use and Privacy Policy
```

第二行的 `Terms of Use` 与 `Privacy Policy` 是独立可点击的文字链接，分别使用 `aduit/intro.md` 的 `All URL` 中对应原始值，`and` 为普通文本；底部布局、居中与安全区按第 7.2 节核验。不添加复选框或额外确认，不保存个人协议同意记录；该协议提示不替代摄像机、相册、麦克风授权或 ATT 系统选择。Settings 只显示三个入口：`Privacy Policy`、`Terms of Use`、`Support`，分别使用 All URL 中对应值；不显示或链接 About Home。将四个 `All URL` 值全部逐字复制到应用固定 URL 注册表，即使 About Home 值没有用户可见入口也保留原始值。所有值按原始字符串保存和传递，不以 URI 预解析或有效性检查作为复制、保存或导航前置条件；不得验证、规范化、补全、替换或因无法访问/格式异常而删除。注册值保存在 App 的固定配置中，不新增 `aduit/` 白名单以外文件。

三个 Settings 入口及 Entry 的两个入口统一通过现有 `policy_webview_page` 加载各自注册 URL。失效或不可访问的 URL 只影响当前 WebView，显示易懂的错误态并提供返回与有限重试；不得阻断 App 启动、`Enter`、Settings 其他功能或清除数据。回归时用不发起网络请求的 WebView stub/fake 核验实际入口传入 URL、About Home 不出现在 Settings、失败与返回状态，不访问或探测真实地址。完成后针对 Entry、Settings 三个入口和主流程进行定向回归。

### 7.7 清除本地数据（二次确认后返回欢迎页）

1. **首次点击只显示确认框**：Settings 的 `Clear Data` 打开标题为 `Clear Data?` 的对话框，提供 `Cancel` 与破坏性 `Clear Data`。二次确认指点击入口后，再在这一个对话框内明确确认，不连续弹出两个确认框；点击入口时不能提前删除、停止当前任务或改变路由。
2. **准确说明后果**：确认正文须说明将删除本 App 保存的照片副本、导入媒体、录音、主题记录和设置，无法通过 App 撤销，随后回到欢迎页；系统相册原件和已导出文件不受影响。可采用 `This will permanently remove photos, videos, recordings, records, and settings saved in this app, then return you to the welcome page. Originals in Photos and exported files are not affected. This cannot be undone.`，按实际媒体类型与数据范围调整，不出现 `local`、`device` 或内部存储术语，不宣称能擦除设备备份或远端副本。
3. **取消不产生副作用**：点击 `Cancel`，或在确认前使用允许的返回/关闭动作，只关闭确认框并保留 Settings、滚动位置、主题、媒体和偏好；无确认回复、超时和系统权限结果都不能代替 `Clear Data`。连续点击入口只显示一个确认框。
4. **确认后安全清理**：将 `AppFlowState` 设为 `clearing`，立即防重复并阻止新保存、导入与编辑；最小恢复标记成功落盘后才开始破坏性清理，使旧操作结果失效。停止摄像机、录音、播放和音频会话，取消/隔离相册导入、文档加载与旧异步任务，关闭旧预览及相关 Sheet，按第 8.4、8.5 节收尾在途事务并删除 App 自有可变数据；清理完成前不允许旧回调重新写入记录、文件、缓存或偏好。
5. **清理中可观察且防重复**：显示 `Clearing data…` 和真实阶段状态，禁用重复提交及进入主 Tab 的动作；完成量来自实际步骤，不虚报百分比。确认后删除可能已部分执行，不提供会把残余内容当作完整数据的普通取消/返回；系统后台或关闭 App 不等于取消，重启按恢复标记继续。重试复用同一清除操作，不新增确认框或叠加删除任务。
6. **只有真实成功才返回**：全部目标数据与缓存清理、设备释放、默认状态重建和残留核验通过后，按第 8.5 节移除恢复标记，清空整个导航栈与旧页面状态，设为 `entry` 并替换到 `/entry`；默认主题为 `System`，介绍展示记录、筛选和播放位置均恢复初始值。返回手势和旧深链不能打开已清除内容；再次点击 `Enter` 从第一个选定 Tab 开始，随包示例仍可用，新的拍摄/导入/录音仍能保存。
7. **失败可恢复且不谎报成功**：恢复标记写入报错时先核对真实提交状态；确定未提交且未开始删除时，清理本次不完整暂存标记、解除写入隔离并恢复 `active`，留在原 Settings 显示可重试错误，不能声称已清除。若标记实际已提交则按已确认操作继续；无法判断时保留隔离并显示可恢复错误，不盲目重启操作。删除已开始后的部分失败保留标记、剩余阶段与写入隔离，展示 `We couldn't clear all your data. Try again.` 及可操作的重试，不得显示成功、提前回欢迎页或自动恢复主页面。记录脱敏错误与实际未完成项，不在 UI 暴露文件路径或内部事务信息；iOS 不调用进程终止接口或强制关闭 App。

媒体停止/释放单次默认最多等待 5 秒；超时按失败处理并继续跟踪原任务，不把超时视为释放完成、不丢弃任务引用、不并发重启同一任务。其他清理按阶段/有界批次推进，连续 15 秒没有可观察进展时转为可操作的异常恢复状态，说明仍未完成；底层任务尚未结束时先核对状态，不允许重试与旧任务同时删除。实际仍在进展的批次可以继续，不以 5 秒或 15 秒强制宣称全量清理完成。清除是设备端操作，不等待网络、域名或开发期外部服务。

### 7.8 摄像机拍摄

- 必须提供与主题任务相连的拍摄入口、真实摄像机预览、拍摄、结果预览、重拍、取消与确认保存；支持设备实际具备的前后摄像头和闪光灯状态，无对应能力时隐藏或禁用控件。
- 处理初始化失败、授权拒绝/受限、设备缺失、方向变化、后台切换、连续点击和空间不足；不使用静态图冒充实时预览，不以权限弹窗出现视为功能完成。
- 保存后结果必须出现在对应主题记录或本地素材列表，可再次打开、查看并删除；照片方向、缩略图和实际文件一致。录像可按主题增加，拍照本身不得连带采集音频。

### 7.9 相册导入

- 使用系统相册选择器选择图片，按主题需要支持多选或视频；导入后提供缩略图、加载进度、预览、取消与保存到主题记录的动作，不先申请不必要的整库访问权限。
- 处理取消、空选择、有限访问（使用 PhotoKit 时）、HEIC/JPEG/PNG 等声明支持的格式、超大图、方向、损坏文件和 iCloud 项目下载失败；异步导入可以取消，失败不遗留半条记录或临时文件。
- 必须将用户选择的可用文件安全复制到 App 私有目录并验证后再标记成功，不长期依赖选择器的临时 URL；对不支持的格式清楚提示。只有实际实现系统相册导出时才增加相应权限与状态。

### 7.10 麦克风录音与本地媒体管理

- 必须实现真实录音、明确的录制状态、计时、停止、试听、重录、取消、保存与删除；波形/音量反馈如显示必须来自实际采样。暂停/继续只在底层可靠支持时提供，不做无效按钮。
- 保存格式与编码必须兼容 iOS；录音结果能在主题记录或本地素材列表中重新打开并播放，显示准确时长。处理权限拒绝、音频会话中断、蓝牙/耳机切换、后台、空间不足、保存失败与重复点击。
- 拍摄、导入、录音形成统一的本地媒体管理能力：按来源显示类型与缩略图/波形、预览、主题关联和删除；删除同步清理记录、文件、派生缩略图及临时缓存。权限撤销不删除已保存文件，不建立个人账号或社区内容流。
- 第一次使用时提供清晰空状态、示例用途和可达入口；拒绝某一权限仍能使用已有内容与其他已获授权能力。不得自动录制、后台偷录或自动上传。
