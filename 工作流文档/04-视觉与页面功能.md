## 6. 视觉系统与 UI 质量

### 6.1 视觉方向

项目 UI 由智能体围绕当前主题、核心任务、真实内容与 Logo 品牌色自主创作，风格、导航、构图、区域顺序、媒体比例、控件造型、材质和动效编排均按本项目设计。可自由组合不同视觉语言，参考示例不构成固定菜单或整页模板；每个项目和独立页面形成符合自身任务的样式。设计自由以完整成品的美观、精致、一致和清晰可用为验收标准，按第 6.7、11.3、11.9 节用实际 iPhone 页面持续精修。以下要求约束成品质量与真实实现，不指定统一外观：

- 首屏必须展示真实主题内容和明确的下一步动作。
- 每个 App 可控制页面及其适用状态都必须按第 6.10 节实现有用的图文内容与视觉层次，覆盖二级页面、工具、Settings、空/错误状态和 Sheet/Dialog；不能只美化 Welcome 或 Initialization，其余页面退化成标题加大段正文或孤立按钮。
- 层级清楚：页面标题、核心任务、内容分组、辅助信息、次要操作。
- **美观成品验收**：逐页实看构图比例、视觉焦点、留白与对齐、字体组合、Logo 派生配色与渐变、图片画质/裁切、图标/Emoji、材质细节和动效衔接；既要形成统一的品牌语言，也要有各页可辨认的构图与内容节奏。将具体问题、实际调整和当前构建前后对比纳入现有精修记录；画面粗糙、排版失衡、素材低质或动效不协调时继续修改并复验，不能仅凭主观评价或功能可运行宣告 UI 完成。
- 先定义与主题内容有关的视觉语法：核心对象如何被表现、内容如何分组/排序、重点状态如何区分、哪些图形/动效具有具体含义。使视觉决策服务差异化 brief 和核心循环；不能把只更换 Logo、渐变、圆角卡片、Emoji 或背景装饰视为产品差异。
- 鼓励使用与理解内容有关的图片、视频封面、轻量背景和状态色。
- 必须根据用户创意加入多种贴合主题的 Emoji，丰富欢迎页、内容分类/模块和适用状态反馈的视觉效果；具体使用与验收按第 6.8 节执行，不能只在设计说明中写计划而不实际显示。
- 视觉基调必须鲜艳、鲜明且有层次，以第 2.5 节从最终 Logo 提取的主色、辅助色与强调色作为项目配色依据；使用协调的高饱和强调与稳定阅读表面，不套用与 Logo 无关的固定色表，不用灰暗或杂乱的配色削弱品牌。
- 渐变是主要视觉语言之一，用于品牌背景、Welcome/Initialization、主要 CTA、选中态、卡片强调区和 WebView 外层容器；条件允许时优先采用第 6.5 节的动态渐变，渐变必须服务于层级，不得让内容变得难以阅读。
- 全项目按第 6.5 节建立可见的多色渐变体系，结合真实内容图片、主题图形、表面明暗与品牌色点缀形成丰富但有秩序的视觉效果；渐变不能只停留在令牌或设计稿，不能无差别铺满所有区域，也不能削弱文字对比度。
- 每个 App 自有页面都必须呈现至少一种与当前主题相关的背景装饰图案，使用 `http://stargate.local:3100/image` 按页面主题绘制；图案作为低透明度叠加纹样，或布置为边缘/卡片周围的装饰边框，不得遮住正文、控件、相机取景或录制状态。实际生成与素材目录、命名、接入规则见第 6.11 节。
- **背景点缀不得只写在规范里**：每个 Flutter 页面（含 `lib/welcome.dart`）、独立 `aduit/welcome.html`、四个 About HTML 页面和原生 Launch Screen 都必须在当前构建中实际显示背景图案或纹理点缀；背景图要能辨认但保持低透明度/局部裁切，不能只放在 `assets/`、只在 `pubspec.yaml` 注册，或被大面积不透明容器完全盖住。页面之间必须使用不同的图案构图、裁切位置或纹理细节，不能所有页面只换一个相同渐变。独立 HTML 可内嵌同一 Welcome 背景的派生图，不视作新增 App 页面；其他不同页面不得复用背景。每个视觉表面都要登记背景文件、至少两个 Logo 派生渐变令牌、至少三个实际 HEX 色值、代码引用和 iPhone 截图/录屏；缺一项即 `Blocked`/`Not verified`。
- 所有由 AI 生成并实际用于项目的图像（包括 Logo、插画和装饰图）不得使用简约线条、细轮廓、扁平几何或单纯色块堆叠作为整体风格或主要主体；必须根据主题制作细节充分、层次丰富、完成度高的图像，使用鲜明而协调的色彩、质感/笔触与完整构图。线条或色块可作为丰富画面中的次要细节，但不可成为简化主体的替代方案。此要求不改变第 10.6 节必须使用可核验许可的真实第三方摄影这一要求，AI 图不能冒充真实照片。
- 不要用空白营销 Hero 代替 App 的核心体验。
- 智能体先生成符合创意且色彩鲜艳的 Logo，再从其实际色块定制 App 与 About 主题色及渐变，说明原始色、衍生色的用途与选择理由；确认前只规划方法，正常路径的最终色值不能先于 Logo 提取。

### 6.2 主题模式

Settings 必须提供 `System`、`Light` 和 `Dark`，默认值为 `System`。选择结果必须同步到所有选定主要目的地、Welcome、Initialization、详情、播放器、空状态、错误状态以及协议 WebView 外层容器；取消清除确认时保持原主题，清除成功后恢复 `System` 并立即同步到初始化页与后续页面。

### 6.3 设计令牌

在 `lib/common_module/theme/app_theme.dart` 定义全局令牌，页面中禁止散落硬编码。该文件是全项目唯一的品牌色彩调用入口：完成最终 Logo 导入后，从 `assets/logo.png` 的实际像素提取代表色，再写入 `AppPalette`/`AppTheme` 与共享浅色、深色和渐变令牌；页面、组件和 HTML 主题映射只能通过该文件消费品牌色，不能另行复制一套色值。

- Flutter 布局尺寸按逻辑像素定义，WebView CSS 尺寸单独注明 CSS px，不把物理像素、pt、dp 和 CSS px 混为一组数值。
- 间距与容器圆角：依据当前主题、构图、信息密度和内容比例制定本项目统一尺度，不规定所有项目共用的间距表或容器圆角上限。同类组件沿用对应令牌，图片按下列实际圆角裁剪要求实现；点击区域、可读性与可访问性继续按实际画面验收。
- 所有 App 自有界面及 About/协议/引导 HTML 中的图片展示位统一使用清晰可见的圆角，覆盖 Logo、列表配图、详情大图、缩略图、视频封面、用户导入图片、相机预览和图片查看器；禁止漏用圆角或 `borderRadius: 0`。统一通过 `mediaRadius` 令牌管理，默认 12 个逻辑像素，紧凑缩略图可用 8、大图可用 16，同类展示位保持一致；HTML 使用对应的 CSS px 令牌。
- 圆角必须真正裁剪图片及其叠层：Flutter 使用共享媒体容器与 `ClipRRect` 或等价实际裁剪，加载/错误状态、角标和渐变遮罩均不能溢出；仅设置外框 `borderRadius` 而图片仍露出尖角不合格。HTML 的图片与容器同步设置 `border-radius`，容器使用 `overflow: hidden`，边框计入尺寸；放大查看、轮播切换和转场过程中也保持圆角。页面背景装饰图在所属容器内裁剪，不露出独立直角贴图。
- 可以在图片卡片、缩略图、封面和媒体预览周围适当增加细边框，统一使用 Logo 衍生的半透明品牌色或协调渐变，默认宽度为 1 个逻辑像素（HTML 为 1 CSS px）；按浅/深色表面调整可辨度，边框与图片共用圆角，不叠加多重粗边、不遮挡主体，也不挤压内容或点击区域。
- 圆角属于展示规则，不改坏原始图片：`assets/logo.png` 继续满足 1024×1024、无 Alpha，不能把透明圆角写进主 Logo；AppIcon 源图保持完整，由 iOS 应用系统蒙版。原生 Launch Screen 的品牌图使用符合静态启动规范的圆角展示或匹配背景的静态派生图，不加入运行时代码；系统相册选择器等系统界面保持原生样式。
- 点击区域：iPhone 上至少 44×44pt，在 Flutter 中按对应逻辑尺寸实现。图标外观尺寸可更小，但不能缩小可点击区域。
- 正文基准字号至少 16 个逻辑像素，HTML 正文至少 16 CSS px，行高约 1.45–1.6；保留系统文字缩放，不用固定字号绕过 Dynamic Type。
- 动效：反馈可参考 80–150ms，列表交错可参考 300–450ms；整页转场按第 6.14.1 节为各目标页面独立编排分段时长、曲线与交接，不统一套用一种 220–350ms 的淡入/滑动；支持减少动态效果。
- 对比度：普通正文至少 4.5:1，有意义的图标和控件边界至少 3:1。
- 色彩令牌包含来自 `assets/logo.png` 的主色、辅助色、强调色，以及至少 2 个中性文字色、2 个稳定表面色和实际所需语义状态色；品牌强调保持鲜明、可区分但不过度鲜艳。按实际 Logo 色块数量建立原始色表，分类与状态需要扩展时只加入有依据的协调衍生色并注明，不能为满足色相数量硬塞无关颜色。若提取结果冷色主导、缺少暖色鲜明色或无法形成可读渐变，必须在实现前重新生成或重选 Logo；冷色主导的颜色不进入主题令牌，也不得成为页面背景、主要 CTA 或主品牌渐变。
- 必须包含可见品牌渐变，渐变令牌至少包含 `brandGradient`、`sunsetGradient`、`aquaGradient` 和 `neonMixGradient`；名称是工程标识，不预设与 Logo 无关的色相。色标来自 Logo 原始色或已记录的协调衍生色，每个渐变记录来源、方向、色标、适用组件、浅色模式和深色模式版本。
- 渐变上的文字、图标和控件边界必须单独通过对比度检查，动态渐变核对整个变化范围而非单张截图；无法达到对比度时，增加纯色/半透明表面层，不使用渐变直接承载长段正文。动态渐变的位移/色标变化、速度、缓动、暂停条件与同配色静态回退统一使用主题令牌，不能各页自行设定不一致动画。
- 图标：使用同一矢量图标族并配置无障碍标签；Emoji 必须按第 6.8 节用于主题内容与状态的视觉点缀，不替代导航、播放、设置、返回或破坏性操作图标。集中定义 Emoji 的语义映射、字号、间距与对齐规则，禁止页面随机选取或散落不一致样式。

### 6.4 响应式与无障碍

- 遵守安全区和系统栏。
- 仅适配支持的小屏、标准屏和大屏 iPhone，覆盖 iPhone 的竖屏和横屏、安全区、系统栏、键盘与屏幕遮挡区域，不得横向溢出；按第 0.10 节不制作其他设备布局、样机或截图。
- 支持 Dynamic Type、VoiceOver、减少动态和增强对比度。
- 实际使用的卡片、网格、工具栏、播放器与导航控件具备稳定的尺寸约束；仅选用底部导航时为其预留安全区，不在无底栏方案中保留空白底栏占位。内容高度随真实内容和 Dynamic Type 自适应。
- 长文本自然换行；标签、按钮和卡片不得重叠、裁切或不可预测地挤压相邻内容。
- 颜色不能是唯一状态信号，必须同时使用文字、图标或语义。

### 6.5 色彩与渐变应用

**完整效果优先**：执行第 0.2.2、1.4 节硬件档位、按需性能指标与完整效果的硬门槛，不缩减任何已规划/要求的 UI 效果，不按性能预设粒子、拖尾、图层、模糊、图片质量或同时可见动效数量上限。实际卡顿/异常通过优化实现修复，保持完整的视觉与交互结果；不能关闭效果或换成占位/简化版凑通过。

- **渐变实际覆盖**：以最终选中 Logo 的真实代表色建立至少四种用途清晰的共享渐变，如 `brandBackground`、`featureSurface`、`primaryAction` 和 `accentBorder`，每种使用 2–4 个有来源的色标，并分别记录原始 HEX 与必要的明度衍生值。主要 App 自有页面须实际显示品牌背景渐变和至少一个与任务相关的渐变强调区（卡片头、主要操作、选中态或边框），不能只给 Welcome 加渐变或只在主题文件里定义。按各页任务改变色标组合、方向和面积；相机取景、正文及重要操作保留稳定高对比表面，系统界面保持原生。逐页用当前构建截图核对覆盖，不能让大片不透明纯色表面将所有渐变遮住。
- **全局取色落地**：`assets/logo.png` 完成校验后立即由取色脚本或等价可复核步骤生成原始 HEX 记录，并把结果写入 `lib/common_module/theme/app_theme.dart`，由 `AppTheme` 暴露全局色彩与渐变调用；不得在页面文件、`main.dart` 或 HTML 组件中硬编码另一套品牌色。若最终 Logo 仍是冷色主导，必须重新生成或重选 Logo 后再写入 `app_theme.dart`。品牌色要有暖色基底、鲜明层次和渐变，但饱和度与明度保持克制，避免过度鲜艳、刺眼或影响正文可读性的视觉效果。
- **浅色模式整体底色**：Light 及 System 当前解析为浅色时，所有 App 自有页面的整体背景必须使用包含最终 Logo 暖色配色的协调渐变，覆盖 Welcome、Initialization、内容/详情、工具、媒体外围、Settings 和自有 HTML 页面；不能使用纯白整页底色，也不能只在白底角落添加暖色点缀。优先选取第 2.5 节真实色板中的暖色及有记录的衍生色，按页面任务调整明度、饱和度与渐变方向，不统一套用无关的固定暖色表。“包含 Logo 配色”指颜色来源，不要求叠加或平铺 Logo 图片，仍遵守第 6.12 节减少重复的规则。
- **阅读表面与实现**：正文、卡片和控件保持稳定高对比，可使用有品牌暖色倾向的浅色表面；不能让大片纯白容器覆盖渐变后实际仍呈现白底。统一管理浅色背景渐变、表面及文字令牌，避免 `Scaffold`、滚动区域、加载/空/错误态或 HTML 默认样式回退纯白。照片中的白色及系统原生界面不受背景禁白限制；媒体操作与法律正文仍以清晰阅读为先。iOS 原生启动页按当前外观匹配品牌背景，暖色渐变仅通过静态资源实现，不添加动画。
- **深色模式照常**：Dark 及 System 当前解析为深色时，沿用现有深色背景、层次、品牌渐变和对比度规则，不强制换成浅亮暖色底；主题切换与持久化行为不变。Flutter 与 HTML 同步响应当前外观，动态渐变继续遵守减少动态和页面生命周期规则。
- 全项目多使用与 Logo 派生主题色对应的协调多色渐变：实际从 Logo 代表色生成主色、辅色和强调色令牌，在背景、分区强调、内容卡片及操作反馈中有层次地贯穿各主要页面，而非只用于 Welcome 启动准备状态或仅声明未使用的颜色。按页面任务差异化渐变方向、面积与明暗，避免所有页面复制同一背景；正文与控件仍保持对比度。每页另须实际显示其主题背景装饰图案，按第 6.11 节逐页生成、存储并接入。
- **禁止单一背景体系**：每个页面的背景必须由“Logo 派生的多色渐变 + 该页面专属图案/纹理 + 稳定阅读表面”组成，至少覆盖两个不同的渐变令牌并在页面代码中实际消费；页面间需改变图案主体、纹理、方向、透明度或边缘布局，使用户能明显辨认页面差异。纯色整页、相同背景图复制到多个页面、只在首屏显示装饰、或仅增加一个角落色点均不合格。静态预检与逐页运行证据必须证明背景点缀没有被容器遮挡，并在 Light/Dark/Reduce Motion 下仍有可见静态版本。
- **点击粒子反馈为必做交互**：主任务中至少选择两个真实可达、语义不同且有即时反馈价值的点击位（优先覆盖主任务 CTA 与完成/保存/确认动作）；若当前产品实际只有一个可操作点击位，则该唯一点击位必须实现。每个选定位必须按主题实现精细烟花、喷泉或拖尾效果，使用 Flutter `AnimationController` 驱动 `CustomPainter`，在手势 `onTapUp` 坐标处生成粒子；每粒子具备可控位置、速度、重力、颜色和拖尾，并以 Logo 派生色板着色。粒子造型、材质、透明度、光影和拖尾必须体现所代表的主题对象，不得用统一纯色小圆点/矩形块拼贴冒充精细粒子。粒子层必须穿透触摸、不遮挡后续操作、不延迟原动作结果，并排除 VoiceOver；跟随页面/应用生命周期停止和释放控制器，尊重系统减少动态设置（关闭粒子与拖尾，保留静态按下反馈）。主题点击位按任务语义设计，最低覆盖数量不是上限，可为更多适合的按钮/交互配置不同精细效果。项目按第 1.4 节五选一选定的 iPhone 档位实现（极低、低、中、高、极高；默认中端，性能无限制等表述映射极高），不得缩减任何 UI 效果，不设性能粒子数/拖尾长度/层数上限，也不降级为占位闪烁；仍须定义正确的绘制范围、结束条件和释放逻辑，避免泄漏，不能把正确释放解释为削减可见效果。必须在当前 iPhone 构建中逐个点击并保存点击前/粒子进行中/结果落地的证据，验证对比度、减少动态、前后台切换和重复点击。若产品确实没有可操作点击位，才记录 `N/A` 及原因。
- iOS 原生冷启动页、每次启动显示的 Welcome 与清除成功后显示的 Initialization 三者背景均不得为纯白色或接近纯白的空白画布；使用 Logo 衍生的鲜明渐变、品牌色深浅层次或主题装饰，Light 模式也以浅彩渐变/柔和品牌底色避免纯白单调。Native Launch Screen 是系统冷启动静态画面；Welcome 是每次启动出现、内含准备状态及 `Continue` 的 Flutter 页面；Initialization 是仅在确认清除成功后出现、含 `Entry` 的独立 Flutter 页面。不得创建第四个 Flutter Loading 页面。协议通用文案只显示在 Initialization 底部，Welcome 与独立 HTML 交付页均无该文案。
- 启动与初始化装饰应有内容依据、方向和主次，不用大面积空白、孤立 Logo 或无目的装饰填充；稳定正文与控件放在高对比表面层，确保普通文字对比度至少 4.5:1、控件边界至少 3:1。
- 每个主要页面至少使用一个多色强调区域和一个稳定纯色阅读区域；同一页面连续模块不得全部使用同一颜色或同一渐变。
- Welcome 页面内部的启动准备状态可使用多色渐变背景、项目名和可观察的真实进度；渐变动效按主题自由设计移动、色标过渡与层次，不因性能限制幅度或复杂度，开启减少动态时切换为静态渐变。该状态不是独立页面。
- 主要 CTA 使用由 Logo 配色形成的鲜明渐变或高饱和品牌纯色，并同时提供文字、图标、按下态、禁用态和焦点态；不可只靠颜色区分可操作性。
- 卡片、图片、视频封面和媒体容器继续使用圆角；渐变只作为容器背景或叠加层，不覆盖图片主体到无法辨认。
- Welcome、Initialization、Settings、协议 WebView 和 About 页面可共享品牌渐变，但正文、主题所需的表单输入和 Initialization 协议文本必须放在稳定的高对比表面上。
- 渐变方向、色标和透明度必须使用主题令牌管理，禁止在页面组件中散落硬编码颜色。
- App 的 Welcome、Initialization、主内容强调区与 About 品牌区域实际显示协调渐变和鲜明色彩；按第 2.5 节配色记录逐项核对 Logo → 原始色块 → 主题令牌 → 页面共享样式，不能只声明“含渐变”却全部显示无层次的纯色页。
- **按主题完整动态化**：App 与 About 支持的品牌背景、Welcome、Initialization 和主内容强调区采用贴合主题的完整动态渐变，可组合渐变方向、色标移动、光晕和呼吸层次；循环时长、幅度与复杂度按画面和交互节奏决定，不设统一性能上限。变化只使用 Logo 提取色与已记录的衍生色，不变成无关彩虹轮换、强烈闪烁或快速明暗跳变；不要求每张卡片和每个按钮都持续动画。
- **保护主要任务**：正文、协议、清除确认及拍摄/录音/播放的主要控件保持稳定高对比表面，不让动态背景干扰阅读、取景或操作。页面不可见或 App 进入后台时停止动画，返回前台仅恢复当前可见区域；列表项可按主题拥有独立动效，不因动画数量预先删减；按第 11.8 节核验实际显示、媒体操作与功能故障，修复保留完整效果，不要求用户未指定的性能取证。
- **静态回退**：遵守 iOS/Flutter 的减少动态设置，以及 About 网页的 `prefers-reduced-motion`；仅当用户开启减少动态时，切换为同品牌配色的静态渐变，保留视觉层次与鲜明色彩。项目按第 1.4 节选定的 iPhone 档位验收，不因低端设备假设主动删减或降级动态效果。检测与回退自动执行，不要求用户或委托方新增选择；记录实际动态展示、暂停/恢复、回退及未验证范围，不把静态截图冒充动态效果已验收。

### 6.14 主题化复杂动画与动态场景（硬门槛）

纯色块拼凑的动画和动态效果绝对禁止。逐页动画不能做成纯色矩形/圆片拼贴、几何色块排布或套用简单渐变再加缓动的演示文稿效果。动画主体须与该页主题中的真实对象、过程或空间关系一致，具备可辨认的材质/纹理/轮廓、前中后景层次、可解释的运动轨迹和有因果的状态变化；光晕、渐变、缩放、平移、模糊和淡入只作为层次或反馈的一部分，单独使用不算完整动态场景。禁止把纯色几何形状沿直线平移、依次弹入或交替换色冒充粒子/生长/天气/液态/空间运动；图形若代表种子、叶片、液滴、火焰、星体等具体对象，须按其形态与物理/主题规律构造，而不是用无材质色块代替。

- **逐屏动态覆盖**：除系统强制静态的 iOS 原生 Launch Screen 外，每个 App 页面至少两个可见且不同的动态元素。每个 App 自有 Flutter 页面、承载页面的主要交付 HTML 页面都必须在默认动态设置下展示至少两个彼此可辨、与页面内容有关且运动规律不同的可见动态元素/层；可以是同一完整场景中的独立运动对象或不同深度/过程层，不要求拆成两个装饰组件。两个元素必须有真实视觉结构，不能把同一渐变的两个色标、同一对象的阴影/光晕或按钮 hover/按下态分别计数。Welcome、Initialization、内容页、设置/协议等都要按其主题选择克制、符合任务的内容承载动态；正文、法律文本、表单和安全操作保持稳定易读，动态层不得遮挡、推动或抢夺交互。
- **动态场景构成**：为每页定义清楚的主题视觉锚点、主运动对象、辅助运动层、景深/遮挡关系、轨迹/方向、节奏和可观察的状态转换。按主题选合适的有机轮廓、真实纹理、层次材质、路径描边、粒子运动、流体/布料/生长/天气/地图路线/数据绘制等表现；不得为了“复杂”把无关特效堆满页面。背景光晕或渐变可增强体积与空间，但不能是主要运动内容。使用与该页任务相关的进入、进行、完成、撤销、切换或环境变化，让动画表达信息和反馈，不只循环播放抽象色块。
- **先出动画简报，再实现**：`.codex-work/ui-motion-gates.json` 为逐屏运动清单的唯一索引，每个页面/HTML 页面至少两项动态元素记录 `motion_id`、`page_id`、视觉意义、主/辅层角色、主体形态/材质/纹理、前后景关系、轨迹/触发/状态、实际技术手段、逐帧或时间线参数、时长/循环/缓动、边界/结束条件、动效资源路径与许可（如适用）、Reduce Motion 替代、代码引用、测试 ID 和当前 iPhone 证据。每页的动画提示词公式和全部实际数值写在对应 `.codex-work/exec/page/<page_id>.md` 的动效章节，思维导图相应节点按第 3.6 节引用；不使用只有“呼吸动画”“加粒子”等词的占位描述。
- **效果提示词公式（每个视觉/AI 生成动效任务提交前填写）**：`[主题风格与视觉锚点] + [具体主体/材质/轮廓] + [前/中/后景与层次关系] + [运动对象、轨迹和因果状态] + [技术手段] + [时间线/速度/数量/尺寸/透明度/色彩/曲线等数字参数] + [循环/完成/中断条件] + [减少动态替代] + [负面限制]`。从最终 Logo 的真实主题色与衍生令牌取色，实际 HEX 在取色后回填；不同页面参数和场景不能复制一份通用提示词。AI 生成的单张静态背景只能作为材质/纹理资源，不能冒充动态效果；若生成视频或动画资产，须检查逐帧结构稳定、内容许可、体积、原生离线播放及实际循环/暂停。
- **实现技术选型**：按主题、交互状态、交付格式、现有依赖兼容性与可验证性选合适方法，不为用包而用包，也不默认全部安装。优先评估下列候选并在 `.codex-work/dependencies.md` 记录实际选择、精确版本、维护状态/兼容性、许可证、采用范围、替代方案和未选原因；添加前以 pub.dev / 原项目权威源核对包名、版本、iOS 支持和许可，不能依据下表推断包一定存在或适用。

| 用途 | 可评估候选 | 适合的实际任务 |
| --- | --- | --- |
| 交互矢量/时间线动画 | `Rive`、`flutter_animate`、`Lottie`、`animator`、`simple_animations` | 可交互状态机、主题过渡、时间线编排；Lottie/Rive 文件须为实际页面内容服务 |
| 游戏循环/实体/物理场景 | `Flame`、`flame_forge2d` | 生长、流体、真实粒子/碰撞或持续世界模拟；普通 App 微交互不因此改造成游戏 |
| 着色器/辉光/粒子 | Flutter `FragmentProgram`、经核实的 `fragment_shader` / `shader_presets`、`confetti`、`particle_field`、`particles_flutter`、`shimmer` | 可视化需要 GPU 场景、粒子群、纸屑或局部材质变化；选择适合的单项组合并核对实际包 |
| 转场/液态 UI/文本 | `liquid_swipe`、`page_transition`、`glassmorphism`、`flutter_glass`、`motion_tab_bar`、`animated_text_kit` | 页面任务适合的切换、玻璃层、导航反馈或文字揭示；不能把整页包装成模板动效 |
| 3D/物理/数据可视化 | `three_dart`、`flutter_3d_controller`、`fl_chart` | 只有用户任务确需可旋转 3D 对象、真实物理或动态数据图表时才评估；仍遵守项目 Logo 明确禁止 3D 的规则 |
| Flutter 原生绘制与时间控制 | `CustomPainter`、`PathMetric`、`FragmentProgram`、`BlendMode`、`BackdropFilter`、`Ticker`、`AnimationController`、`Curves`、`Matrix4` | 自定义轮廓/路径生长、粒子、图层混合、材质模糊和变换；按已选硬件档位构造真实内容而非色块拼贴 |

- **参数必须可执行**：每个动态元素明确几何/素材来源、坐标参照、数量/尺寸/速度/方向/间距、透明度与 Logo 派生色、逐段时长、曲线、延迟/相位差、循环方式、触发条件、终点与取消/重播行为。使用物理/着色器时写明场参数、边界和状态输入；时间线/矢量资源记录文件、触发状态及状态机/关键帧。参数服务主题对象和屏幕布局，不能照抄统一数字；没有实际测量的效果参数不能写成运行测试结果。
- **减少动态与生命周期**：尊重系统 Reduce Motion。开启后停止连续/空间运动，提供同品牌、同内容信息量的完整静态构图或短淡化/无空间转换替代；不把静态回退算作默认动态验收。页面不可见、App 进入后台或用户离开时按契约暂停/取消，回到页面按定义恢复；正确释放 controller/纹理/资源。原生 Launch Screen 及原生承接层保持静态，不放动画、进度条或视频；承接层同款画面持续到 Welcome 实际首屏 ready 后 250 ms 再淡出，继续遵守第 10.4.3 节。
- **运行验收拒绝 PPT 风格**：在目标 iPhone 当前构建逐屏录制完整周期与真实操作，不只看设计稿/静态截图。核对至少两个运动层确实具有不同轨迹/因果变化、主体细节稳定、运动连续且与任务匹配，层间景深/遮挡正确，前景内容可读，交互/暂停/恢复/结束有效，Reduce Motion 替代正确。逐帧检查块状拼贴、突兀色块出现/消失、背景与对象脱节、重复纹理抖动、硬直线匀速滑行、只渐变/淡入位移缩放、首帧/末帧不连贯、掉帧造成可见跳帧等缺陷；任一缺陷先改动画结构/素材/参数并复录，不能以“已用 Rive/Shader/粒子包”代替结果验收。
- 动画证据必须分别覆盖动画前、进行中、结束/完成状态，并保留一段可观察完整循环与触发交互的 iPhone 录屏；截图只佐证画面细节，不单独证明动态通过。
- 页面中无适宜动态时，只允许 iOS 系统静态 Launch Screen 保持静态；其他页面按主题制作不妨碍任务的内容承载微场景（如材料纹理变化、真实图解阶段、局部路线/周期标记、页面专属粒子/环境层），仍须两个不同运动元素。不适用动态的主张不作为普通 App 页豁免。
- Native Launch Screen 为系统静态例外；它的同款承接层也保持静态直至按既有就绪时序淡出。

#### 6.14.1 每个目标页面的专属过场（硬门槛）

每个目标页面必须有专属过场动画，覆盖 Welcome 的 Continue、Initialization 的 Entry、主要目的地/工作区或 Tab 切换、详情/工具/结果/搜索/Settings、统一协议容器和独立任务 Sheet 的进入、退出与返回。按真实导航图逐条登记，不只给 push 路由加效果而让 replace、go、Tab/IndexedStack 切换直接跳变；实际没有的路由或功能不为动画创建。简单提示、原生系统选择器与同一逻辑页面的数据实例不虚构成新页面。

- **差异必须可见**：任意两个独立目标页的进入过场，至少在“主体承接/揭示机制、运动轨迹与空间关系、图层交接顺序与内容编排”三个维度中的两个有实质差异。仅换方向、颜色、时长、曲线、ID，或把同一 fade/slide/scale 包装器套给所有路由均不合格。可以按任务组合真实图像的共享主体承接与圆角形变、主题纹理路径揭示、场景景深交接、画布聚焦展开、图解分层汇入等；这些只是候选，不是轮流套用的固定菜单。遮罩用于揭示真实图文/纹理/场景，不把移动的纯色色块当作过场主体；仍按第 6.14 节拒绝 PPT 风格。
- **先退出、再承接、后落位**：各页执行文档写清来源页保留/退出的层、目标页如何显露、内容与操作何时落位，以及背景动画如何进入持续状态；可重叠编排，不增加空白中间页。记录各阶段实际毫秒、曲线、路径/遮罩/焦点、起止值、错峰、圆角与裁剪、可操作时机。同页再次进入使用一致的主题方案，按真实来源锚点适配，不每次随机抽动画；不同 contentId 不另算独立过场。
- **Flutter 实际接入**：通过现有中央路由注册表为目标页绑定独立 `transition_id`，可用 `PageRouteBuilder`、`CustomTransitionPage` 或当前路由包的等价能力；局部目的地/Tab 由相应导航状态驱动，不能靠初始化时一次入场代替每次切换。可共享控制器/绘制工具，不能共享一份不变的整页动画配置。建议自有工具短名为 `rt_fx.dart`、`bg_fx.dart`，放入实际合适的公共 motion 模块；路由仍按第 5.2 节统一注册，取色调用 `common_module/theme/app_theme.dart`。
- **返回、取消与连续操作**：返回使用与进入有因果关系的逆向/收束，接入 iPhone 侧滑返回的实际进度与取消，不在系统手势外再播一次动画；取消回到来源状态，完成只 pop 一次。Hero 标签按当前实例唯一，图像全程圆角裁剪，无飞错目标或重复 Hero。快速重复点击、跨页连续切换、后台/前台、弹层覆盖、路由销毁与 Reduce Motion 即时变化均要收束到唯一有效路由，不能叠加导航、丢滚动/筛选/草稿状态、残留透明挡板或出现黑白空帧。
- **既有安全边界保留**：Clear Data 真实成功后才进入 Initialization，过场不得重放已经清除的私有文字/媒体截图。系统 Launch Screen 不加动画，原生同款承接仍严格遵守 Welcome 实际就绪后保持 250ms 再淡出的时序，不为专属转场增加第二层停留或第四个 Loading 页面。协议只动画 Flutter 自有容器/标题/外围背景，不改四个原始 URL、不注入远端正文，不将 WebView 重新用于 Welcome。系统 Reduce Motion 开启时以无空间运动的切换或短淡化替代，保留信息、操作和状态。

#### 6.14.2 Flutter 实时背景场景（硬门槛）

每个 Flutter 页面必须实际运行主题化背景动效，不能只显示静态装饰图、一次入场、GIF/视频、渐变换色或几个光斑呼吸。保留第 6.11 节每页独立本地背景图案作为材质/纹理输入，再用 Flutter 的 `AnimationController`/`Ticker`、`CustomPainter`/`PathMetric`、`FragmentProgram` 等构造可观察的持续场景；可按真实需要选用已核验的 Rive/Flame，不能以装包代替接入。已有纹理资源全部留在项目 assets，运行不联网下载；着色器文件按 Flutter 声明方式打包。

- 每页背景至少有两个主题相关且运动规律不同的可见图层/元素，例如有材质的主体环境变化加不同深度的纹理/路径/主题粒子。按页面任务选择有机流动、材料纹理演化、路径生长、真实图像视差、主题气流/水流/叶片等；视差与光晕仅作为完整场景的一部分。不能把同一渐变的色标、同一主体的影子或纯色圆点计为不同元素，也不能靠瞬时转场或点击粒子替代进入后仍运行的背景。
- 各页面的背景主体、轨迹/场、景深或状态响应必须有可辨认差异，不把同一全屏背景组件仅换颜色后铺满项目。共享绘制能力允许，但本页的层次、素材、参数与行为必须独立绑定；内容翻页、筛选、任务阶段或操作结果可驱动有含义的场景变化，不伪造进度或统计。
- 每层写明实际素材/轮廓、坐标系、层级、速度/频率/相位/幅度、透明度、Logo 派生颜色、混合方式、循环接缝和交互输入。进入与退出同第 6.14.1 节连贯交接，返回按契约恢复，不能每次 rebuild 都重置场景或重新创建控制器。背景置于内容后方，使用等价 `IgnorePointer` 的触摸穿透、正确裁剪和语义排除；内容、法律正文、风险确认、媒体取景与主要操作保留稳定高对比阅读层。
- 不可见路由/Tab 与后台暂停，销毁释放 controller、shader/纹理与订阅，恢复仅启动当前可见场景；系统 Reduce Motion 即时切换成同主题、同信息量的完整静态构图。正确生命周期与无障碍不构成减少默认动效的理由；不新增帧率、内存或层数限制，不降低既定效果。原生启动画面/承接层仍为静态例外，交付 HTML 继续使用其既有独立实现，不能把 HTML 当作 Flutter 动态背景。

#### 6.14.3 逐页编排与运行验收

沿用 `.codex-work/ui-motion-gates.json`，增加 `page_transitions[]` 和 `background_motion[]` 两类记录；不另建重复台账。逐页思维导图连接来源/目标、转场、持续背景与返回/异常节点，本页执行文档保存完整数值与操作步骤，确认前为计划值，实施后回填真实代码和当前构建证据。

| 记录 | 必须包含的实际内容 |
| --- | --- |
| `page_transitions[]` | `transition_id`、来源/目标 page/route ID、导航方式、主体/揭示机制、轨迹/空间、图层交接顺序、分段时序/曲线/起止值、返回/侧滑取消、可操作时机、Reduce Motion、代码引用、测试 ID、录像片段与关键帧；列出与最接近另一目标页至少两项实质差异 |
| `background_motion[]` | `motion_id`、`page_id`、至少两个不同动态层、Flutter 实现手段、本地素材/着色器、图层角色及参数、循环/状态输入、转场交接、暂停/恢复/释放、静态替代、代码引用、测试 ID 与完整循环录屏 |

在既有 `.codex-work/ui-visual-gates.json` 的 `checks[]` 分别新增 `page_transitions`、`background_motion` 两个独立验收项，`targets` 必须覆盖全部 `kind: flutter` 的表面；普通 Flutter 页不能用 `exclusions` 豁免。各项引用实际实现文件、当前 iPhone 的非空 `.mp4`/`.mov` 录屏及具体观察结果，不能只引用截图、设计稿或执行文档。运行 `validate_visual_implementation.py` 检查门槛存在、逐页覆盖、文件引用及录屏要求；静态脚本不判断动画是否精致、录屏是否真实或不同页面是否确实不同，这些必须人工查看当前构建并复核代码。

沿真实导航图录制每种进入方式、对应返回/手势取消、主目的地切换、Continue、Entry、清除成功替换及独立任务弹层；每页再录一个可见完整背景循环与状态响应。查看转场前/交接中/落位后和背景各层运动，按最近似页面成对比较，覆盖重复点击、连续切换、前后台、Light/Dark、Reduce Motion 运行中切换、图片圆角与实际内容可读性。不能只录首页、只看过场结束截图或以统一淡入代替逐页差异。发现黑白帧、断层/循环跳变、色块拼贴、背景被遮住、触摸拦截、错误返回或旧数据闪现时，修复并复录；复用现有测试安装，不为每页新建包，证据不足不标 `Verified`，继续独立可执行任务。

### 6.6.1 主题化排版与 UI 极致优化

- **先建立排版系统**：在实现页面前定义并记录 `display`、`heading`、`body`、`metadata`、`action` 五类文字角色，分别规定字体、字重、字号、行高、颜色、最大行宽和上下间距。页面、组件、弹窗、空/错误状态、Settings、About/Support 和内嵌引导页都使用同一套角色令牌，不在单个页面临时拼接字号或颜色。
- **标题的斜体与渐变**：页面标题、主要功能标题和章节标题使用有意的斜体或斜切字形，体现主题气质但保持字形完整、易读和可复制；短标题和可承载渐变的关键标题在对比度允许时同时使用由正式 Logo 实际色板派生的渐变文字或渐变描边，只有经过对比度测量仍不合格时才回退到同色板的纯色标题，并记录回退原因。渐变只取已记录的 Logo HEX 与其可解释的衍生色，逐页检查静态和动态范围的可读性。禁止把渐变用于大段正文、错误详情或需要快速扫描的密集信息。
- **至少三种有依据的字体风格**：整个项目至少落地三种可复用、能被用户感知且与层级对应的字体风格：主题化斜体/斜切展示标题、稳定易读的正文/操作文字，以及与正文有明确区别的元数据/标签/强调文字（可使用不同字重、宽度、大小写或一款随包且许可明确的展示字体）。短标题、长标题、正文、列表、Settings、About/Support、协议和引导页都要从这套角色选择，不是每个文字节点随机更换字体、颜色或装饰，也不能依靠字体变化掩盖内容重复。
- **自然大小写与重点词**：主文本、段落、列表开头和空状态说明使用 sentence case，首个字母按英语规则大写；不把每个词都写成 Title Case，也不使用全大写制造层级。需要强调的事实、动作或结果用 `Text.rich`/`InlineSpan`（或等价的语义文本组件）局部换用 Logo 强调色、字重、斜体、细下划线或克制的背景高亮，并确保 VoiceOver 按自然语序读出。颜色不能成为唯一语义信号，必须同时有文字、字重、图标或位置差异。
- **字体来源与可访问性**：仅使用系统字体或已随包、许可明确的字体，不依赖运行时下载字体。尊重 Dynamic Type、VoiceOver、粗体文字、增加对比度、Reduce Motion 和安全区；字体放大时允许自然换行和滚动，不能固定高度截断、压缩字距、裁切字形、让装饰覆盖正文或改变无障碍阅读顺序。正文和控件始终保持可核对的对比度，动态渐变在整个动画范围内也必须可读。
- **组件状态与细节**：每个按钮、链接、输入和可选项都提供清楚的正常、按下、禁用、焦点、成功和错误状态，状态变化不依靠颜色单独表达。统一圆角、边框、阴影、图标基线、内外间距和图片裁切；长短不齐、大小不一的内容卡片必须有内容重要性、媒体比例或信息密度依据，不能随机错落。任何页面都不得出现重叠、溢出、跳动布局、不可点击控件或被安全区遮挡的文字。
- **覆盖全部页面与状态**：排版系统必须落到 Welcome、Initialization、主内容页、详情、工具、Settings、About/Support、协议页、Sheet/Dialog，以及加载、空、失败、权限拒绝、清除确认和成功返回等适用状态。不能只精修首屏；每页都要有与主题内容相关的视觉层次、图片/图示或组件结构，同时保持法律正文的稳定阅读体验。
- **精修证据**：至少完成三轮“在 iPhone 当前构建运行并截图 → 逐屏检查排版与层级 → 实际修改 → 再运行核验”，记录每轮变化和前后证据。覆盖小屏、标准屏、大屏 iPhone、横竖屏、Light/Dark/System、Dynamic Type、VoiceOver、Reduce Motion 和长文本；若发现标题渐变对比度、强调语义、字形裁切或页面密度不合格，必须继续修改并复验，不能以源码令牌存在或设计稿作为完成证据。

清除流程的统一可见文案为：入口与确认动作 `Clear Data`，确认标题 `Clear Data?`，取消 `Cancel`，进行中 `Clearing data…`，失败 `We couldn't clear all your data. Try again.`。确认正文按第 7.7 节准确列明删除范围与不可撤销后果，不出现 `local` 或 `device`；这只更新显示文字，清除数据、二次确认、成功进入 Initialization 及失败恢复的实际行为保持一致。

### 6.7 必须投入充分工作量的 UI 精修

执行第 0.2.3 节不限总制作时长的质量优先硬门槛。下述投入比例、三轮 UI 与两轮资源是最低要求，不是精修上限；每轮发现的可执行改进都要实际处理并复验，包含间距、对齐、裁切、图文节奏和交互反馈等细节。当前构建仍有明确可修复问题时继续工作，不能以达到轮次或预计工时为由结束；完整 UI 效果继续保留。

UI 设计、实现后的美化与资源调整是主要工作阶段，不能在“功能能跑”时直接交付。规划与执行均须为 UI 与资源精修合计保留至少一半的实际开发工作量，其中 UI 设计、细节调整与不同 iPhone 尺寸检查至少占三分之一，图片/视频的筛选、替换、裁切、封面和播放优化至少占六分之一；分配时不重复计算同一项工作。按页面与资源批次记录实际操作、修复、前后对比和检查结果；具备可靠时间记录时补充真实耗时，没有时只报告可核对的工作量，不虚报分钟或用空等、重复无改动截图满足要求。

投入比例是资源分配要求，不能单独证明精修充分：总工作量较小时仍须完成全部页面、适用状态、素材检查和真实迭代，不得以“已占一半”为由跳过任何质量要求。规划时记录功能实现、UI、资源、验证各阶段的预估工作及依据；执行时记录实际完成项、真实计时或明确标注的估算。缩短服务等待、并发和复用可以减少总耗时，但不得因此删减内容、减少精修覆盖或取消验收；不能从运行时间自动推断质量提高或降低。

必须完成至少三轮“运行并截图 → 逐屏评审 → 实际修改 → 再运行核验”，每轮都记录问题、修改及前后截图路径：

1. **整体构图与内容层级**：精修核心主页面、Welcome、Initialization、Settings 及实际存在的其他任务页面；拍摄、相册导入前后与录音页面仅在选用时纳入，检查布局节奏、信息密度、导航、主次动作、留白、安全区和真实内容呈现。
2. **品牌与细节**：逐项调整字体尺度与字重、行距、间距、图标一致性、第 6.8 节 Emoji 的主题匹配/大小/基线/密度、圆角、图片裁剪、渐变、对比度、按钮和输入状态；逐屏更换不贴题、模糊、主体裁切错误或重复明显的图片/视频，调整真实视频封面与文字叠层，避免所有页面套用同一种卡片布局。系统选择器与权限弹窗保留原生样式，只精修 App 可控制的周边流程。
3. **状态、动效与适配**：覆盖 Light/Dark/System、小屏/标准屏/大屏 iPhone、iPhone 横竖屏、长文本、Dynamic Type、VoiceOver、减少动态，以及加载、空、失败、权限拒绝/受限、录制中、保存中、清除确认、清理中、清理失败和成功状态；核验键盘避让、滚动、返回和媒体生命周期。破坏性清除使用清楚的文字与语义，不仅靠红色区分；确认框的初始焦点不得默认落在清除动作上，清除成功进入 Initialization 后恢复合理的无障碍焦点。

核心流程必须在 iPhone 运行环境中逐屏查看，截图只作为证据，不能代替点击与交互检查。模拟器检查按第 0.9、0.10 节在工程创建完成后进行，三轮精修共享一个现有 iPhone，其他必要 iPhone 尺寸/支持的 iOS 版本依次切换，不为每页或每轮新开模拟器。明显遮挡、溢出、文字截断、不可读对比度、无法点击、错误加载层级或媒体控件错位必须修复；新改动引入的问题再次针对性核验。完成三轮后仍有影响使用或明显视觉质量的问题时继续精修，不能把三轮当作自动通过标准。

前后对比使用相同页面、示例数据、设备尺寸和可比状态，注明构建版本；补充说明轮次之间实际改变的内容。投入比例在规划时分配到可核对的任务，执行时按同一工作量口径核算；没有可靠计时就使用预先记录的任务估算与实际完成记录，并注明估算，不凭事后拆细 UI 任务数量制造比例。等待外部服务、无改动重复截图和反复运行相同检查不计精修投入。

UI 三轮迭代之外，按第 10.5 节至少完成两轮有实际筛选或调整的资源工作，可以与 UI 检查并发：第一轮按主题、模块和构图筛选并淘汰低质/重复候选；第二轮在真实页面与播放环境中调整裁剪、封面、清晰度、体积和重复分布。每轮记录替换前后资源 ID、原因、实际消费位置及结果，不能只下载一批素材后不再检查，也不能以重复采集同图证明投入。

开发者自主完成上述迭代，不向用户逐轮请求审批。实际不可用的设备或运行工具只影响相应验证项，记录未验证范围并继续其他精修，不用静态检查冒充完整视觉验收。

完成最低轮次后，按第 11.9 节进行一次与页面实现、三轮精修分开的交付前质量复核，直接检查当前构建、页面和最终随包资源。复核发现遗漏或明显视觉问题时继续实际调整并复验，不因预计提前完成而马上交付；已经有当前有效证据且没有新问题的检查不机械重复，也不通过空等、休眠或无意义修改凑满工时。

### 6.8 图标、Emoji 与视觉点缀（硬门槛）

- **实际展示**：项目必须同时使用语义图标和多种与已采用创意相符的图形 Emoji，不能只做一类。Welcome、Initialization、每个主要内容目的地、普通详情/工具页及 Settings 均须有可见的语义图标，以及至少一处与当前任务有关的 Emoji 点缀；放在首屏的主题徽章、分组标题、分类标记、提示或状态区，不只藏在滚动末尾。适用的空状态或成功反馈也要落实，不要求每个按钮、拍摄/录音控件或协议正文都添加。规划时记录展示位置、语义与搭配文案，实施后以真实页面截图核验，不用开发文档里的 Emoji 充当已实现证据。
- **语义图标系统**：按主题选择统一的矢量图标族或自有图标语言，集中维护图标、尺寸、描边/填充、Logo 派生色、圆角底座及正常/选中/禁用状态。导航入口、主要操作、内容类别/分组、Settings 各功能行和状态提示须有匹配语义的图标，不以返回箭头、通用齿轮、圆点或同一个符号覆盖全部职责。图标可放在渐变徽章、主题色底座、图文卡片前导区或步骤节点中；同一语义保持一致，不随机混搭线性、实心和插画风格。矢量功能图标不属于 AI 插画，仍可使用清晰线条；不能据此放宽第 2.5、6.11 节对 AI 成图的限制。
- **图标与文字协作**：主要入口、功能行和关键动作采用图标加简短英语标签；用图标、标签组、步骤节点或真实数据图帮助扫读与理解，把必要解释留在对应内容区。图标不能替代必须说明的风险、权限用途或结果。常见紧凑返回/关闭等控件可只显示图标，但必须有自然英语的无障碍名称和足够触摸区；不用一长段说明代替正常图标导航，也不用 Emoji 代替清除等关键动作的语义图标。
- **主题与层级**：由智能体围绕真实内容选择 Emoji，不固定产品主题。拍摄、相册、录音的引导区域可分别点缀 📸、🖼️、🎙️，内容分类则根据实际对象选取；这些仅为示例。优先用于欢迎语、分组标题、分类标记和状态插图，数量与尺寸服务于层级，避免全屏堆叠、无关表情或所有卡片重复同一符号。
- **清晰操作**：Emoji 必须与清楚的英语内容或操作名称配合；导航、播放、返回、设置与清除等操作仍保留统一矢量图标及明确文字。最终引导页按钮 `Continue`、`Clear Data`、`Cancel` 等固定文案保持原样，装饰放在独立区域，不把 Emoji 拼入这些固定标签；仅开发预览可使用原生 `Enter` 控件。破坏性清除、权限拒绝和失败提示使用准确、中性的表达，不用庆祝表情弱化后果。
- **统一样式**：集中维护语义映射与大小、行高、间距、对齐规则；同一语义跨页面稳定复用，不为追求数量随机轮换。使用原生 Unicode Emoji，检查最低支持 iOS 版本的实际字形、完整组合序列和显示宽度；缺字、方框或错误断行时换用兼容 Emoji，保持其英语标签，不依赖新增网络服务。
- **适配与动效**：在 Light/Dark/System、小屏/标准屏/大屏 iPhone、iPhone 横竖屏及大字号下检查基线、裁切、换行、阅读层次与点击区域，Emoji 不遮挡图片主体、文案或媒体控件。默认使用静态 Emoji；确有反馈动效时沿用第 6.3、6.4 节规则，支持减少动态，不持续闪烁或无意义循环。
- **特殊页面与 HTML**：系统原生界面不重绘，Launch Screen 静态，不强塞 Emoji；法律、破坏性确认、权限/失败警示用准确语义图标。媒体聚焦控件不叠干扰装饰。`lib/welcome.dart` 使用 Flutter 图标、Unicode Emoji 和主题图片，保留原介绍 UI；独立 `aduit/welcome.html` 用内联 SVG/CSS/Emoji，原自包含、Base64 与严格小于 256 KiB 契约不变，但不接入 App。
- **无障碍与文案**：纯装饰 Emoji 从 VoiceOver 语义中排除，防止同一标题重复读出；传递分类或状态信息时为整个组件提供自然英语名称与状态，不靠表情或颜色单独传达含义，不让系统默认的 Emoji 读名替代操作标签。按第 6.6、11.4 节检查显示与读出内容，不夹带中文、内部术语或被禁止的文字型表情。
- **资源与验收**：Emoji 是视觉补充，不能替代 Stargate 正式 Logo、主题图片/视频、真实内容或已选功能，也不计入独立图片/视频数量或资源调整轮次。同一语义的合理复用不视为第 10.5 节的素材重复，但不能用换 Emoji 掩盖重复封面；将实际展示、主题匹配、布局与 VoiceOver 结果纳入三轮 UI 精修及第 11.9 节质量复核，不新增用户审批。
- **逐页验收**：在现有 `.codex-work/ui-visual-gates.json` 中分别填写 `icons` 与 `emoji` 检查项，关联适用页面、实际组件/图标映射/HTML、当前构建截图和观察结果。核对实际字形、首屏位置、语义、多样性与整体风格；仅有包依赖、共享映射、代码中的未使用 Emoji 或截图里不可见的装饰不能通过。只有上述特殊边界可以按具体表面在 `exclusions` 写明理由，普通内容页、Welcome、Initialization 或 Settings 不得统一排除。修复后重新运行并更新证据。

### 6.9 图片自然度与内容列表尺寸层级

- **Logo 生成质量**：Logo 仍按第 2.5 节只在 Stargate 生成；按主题元素分别撰写模拟现实、手绘、油画、艺术表现四种画风，每种生成 3 张，共 12 张独立候选；逐张查看并记录生成痕迹，从全部候选比较选出最自然且符合主题的一张，不能只生成同一画风或以首张成功图结束。按第 2.5 节分别核验可信的结构/材质/光影、精细手绘线条、油画笔触/颜料层次或明确的艺术表现语言；均须精致、有层次、小尺寸可辨，不做 3D。鲜明、非单调的 Logo 配色至少呈现三种易辨鲜明颜色与协调渐变；检查并修复明显 AI 生成感、畸变/融化的形状、断裂轮廓、重复纹理、随机碎片、伪文字、物理关系不成立的细节、塑料质感和无依据的强光晕。这里的“自然可信”按所选画风的造型和视觉逻辑判断，允许协调的笔触和艺术化提炼，不要求照片写实，也不削弱鲜明渐变。
- **主题色落地证据**：颜色链路必须可追溯为 `Logo 原始 HEX → Flutter 主题令牌 → 实际页面/组件 → iPhone 截图`；至少三个实际 Flutter 页面/组件消费 Logo 派生色，覆盖主页面、真实操作页和至少一个其他 App 页面。不能只证明取过色或定义过令牌，须以当前构建中的页面截图证明颜色实际可见。
- **内容图片来源和真实感**：内容照片继续严格按第 10.6 节从第三方网站取得有许可依据的真实摄影；不得用 AI 生成的拟真图、插画或图形化合成图冒充真实照片。候选图片必须准确对应页面描述的物体/场景；来源页、拍摄主体、透视/比例和可见细节应相互吻合，不选明显错题、异常结构、过度处理或有可疑生成痕迹的照片。Logo 的生成规则不得扩展为生成内容照片的许可。
- **按语义变化尺寸**：每个主要内容列表在多条内容可用时至少包含两种明显不同的卡片尺寸；主要浏览体验跨页面按实际内容层次覆盖 `featured`（重点大卡）、`standard`（常规卡）和 `compact`（紧凑行/小卡）三档（若创意内容不支持某档，记录原因），不要求每个页面都同时出现三档。尺寸差异通过图片面积、卡片高度或版面跨度让用户一眼可辨，不能只改边框/阴影。精选、常规、辅助角色必须由内容重要性、用户任务或浏览密度决定，记录映射与先后顺序；禁止随机高低错落、纯装饰性尺寸变化、同一条目在相邻位置换尺寸凑数量，或让大卡抢走用户的主要任务。
- **跨主要页面的主编排与复合布局**：同一列表内建立可预测的视觉节奏，重点卡强调、普通卡承载完整信息、紧凑项帮助快速浏览。多个主要内容目的地都是浏览型列表时，跨主要页面至少安排两种有意区分的主编排，例如垂直分组列表、双列网格、精选大卡加横向滚动、瀑布流/不规则卡片或分段式复合布局；每个独立页面的整体骨架必须按第 6.13 节区别，跨页面只有两种主编排不足以证明完成；可复用 `ListView` 等基础组件，但不能复用整页构图与区域关系。单个页面可以复合使用多种展示形式，允许卡片长短不齐、大小不一、图片比例和内容高度不同，但必须可预测且由内容重要性、任务优先级、信息密度、媒体比例或排序理由决定。记录每个主要页面的主编排、复合结构、`featured`/`standard`/`compact` 或其他尺寸角色、排序依据及小屏响应式降级；禁止随机错落、仅为装饰改尺寸、固定高度导致文字截断、图片拉伸或破坏语义/VoiceOver 顺序。搜索结果、相册选择、权限说明、Settings、协议等以快速扫描/准确选择为目的的行列表保持统一行高与对齐，不为“大小不一”而损害可用性。
- **复合区域与滚动边界**：同一页面可按任务组合精选大卡、横向轨、双列网格、瀑布流/不规则卡片、标准列表和紧凑条目，写明区域顺序、层级与每区的尺寸角色。纵向内容默认共享一个主滚动上下文，横向轨可独立横滚；确需独立同向滚动区域时，必须记录理由、可见边界和手势/焦点交接方式，避免争抢滚动、内容不可达或丢失返回位置。长短和大小随真实文字、媒体比例与角色自然变化，不强制随机高低，也不将长文字卡片锁定为固定高度；图片保留焦点和正确比例，视觉、滚动与 VoiceOver 顺序一致。小屏/Dynamic Type 下按记录的断点改为单列或紧凑编排，保留内容层级、全部操作及清晰阅读路径。
- **图片与布局适配**：为各尺寸层级分别核对素材分辨率、宽高比、焦点位置与裁切；使用适当的 `BoxFit`/容器比例和可读叠层，不拉伸、不切掉关键主题对象、不因大图卡片反复复用同一图片。不同尺寸下标题、副文、标签和 Emoji 保持层次，文本随内容和大字号增长而扩展，不固定卡片高度导致截断；缩略图按展示尺寸解码，维持加载、空与错误状态一致。
- **无障碍和 iPhone 适配**：混合尺寸不能改变内容的语义顺序；视觉顺序、滚动顺序、VoiceOver 焦点顺序和导航焦点次序应相符，点击区域至少 44×44pt，Dynamic Type 下无遮挡、截断或水平溢出。在支持的小屏/标准屏/大屏 iPhone、横竖屏、浅/深色与大字号下实际检查每种卡片角色及断点；必要时将大卡改为紧凑布局或单列流式排列，但继续保留至少两级清晰层次。
- **验收证据**：页面规格记录每个主要列表的主编排、是否复合、层级、排序理由、组件尺寸/比例与对应资源；当前构建的精修截图覆盖同页长/短、大/中/紧凑项及至少两类不同主编排的页面。逐条检查图片自然度/主题准确性、尺寸区别是否清晰但协调、不同主要页面的编排差异、复合区域顺序、层级及共享/独立滚动边界、点击路径、响应式降级、裁切、内容密度、Dynamic Type、VoiceOver 和 iPhone 边界；发现突兀、随机、重复、错题或生成瑕疵须实际调整并复验。按第 11.9 节列出已检查的列表和图片证据，不以设计稿或写有三档名称的清单冒充运行效果。

### 6.10 全页面内容丰富度与图文表达

下列按页面职责给出的内容要求不规定固定整页模板；每个独立页面仍按第 6.13 节设计不同骨架，主要内容按第 4.4 节充足展开并能连续翻页，不能复制整页结构只替换字段。

本节是所有页面的共同验收要求。每页围绕实际用户任务，同时具备清晰的内容分组、至少一种有意义的非纯文字表达，以及完整可用的操作或阅读路径。非纯文字表达按页面职责选择真实主题摄影、内容图解、示意插画、缩略图、数据可视化、真实媒体预览、状态图形或带图标的分组控件；不是要求所有页面塞入相同大图。单纯换背景色、加渐变、把同一段文字拆进多个容器、满页 Emoji 或反复贴 Logo 不能单独算作内容丰富。

主要流程中的内容结构和视觉层级还必须体现当前主题自己的分类、证据关系、步骤顺序、对象状态或结果表达。复用通用组件可以，但组件必须显示真实主题数据并服务该页面的核心循环；若只替换标题、图片和品牌色而任务路径与结果仍完全通用，应继续调整内容模型/页面结构，不以额外装饰掩盖。

**控制文字密度（硬门槛）**：普通页面首屏先给核心任务、短摘要、贴题主视觉和可识别操作，不连续堆放说明段落。浏览卡片、Welcome 引导卡片和功能入口以“短标题 + 一句核心说明 + 适用的简短元信息/标签”为默认结构，配合第 6.8 节图标与 Emoji；不把详细介绍、重复功能说明或整段操作手册塞进每张卡片。长内容按真实语义拆成概览、关键点、步骤/关系图、图文实例和深入阅读，次要细节可渐进展开或进入详情；主要操作无需先读完长文。不能只给原长段落加图标/边框后仍连续铺满整屏，也不能靠字号变小、固定高度裁切、行数省略或删除必要内容“减少文字”。大字号下允许自然换行和滚动，不用硬性文字/画面比例压缩可读性。风险、权限用途和法律正文保持完整；详细 Intro 与事实性 Remarks 继续各自的文档规则，不为了 App 界面简洁而压缩它们。减少重复文案与重新组织内容不构成削减第 0.2.2 节的 UI 效果。

**逐页规划与实施**：页面追踪表为每个页面、Sheet/Dialog 和适用状态明确视觉内容、信息模块、资源/组件及验收依据，不能填写“同首页”或泛写“精美卡片”。主要内容页、详情页必须有与自身内容对应的资源或图解，其他类型按本表选择具体表达；采用共享组件时保留当前页面的真实数据、用途和内容层级。页面背景装饰也逐页登记稳定 page ID、素材路径、透明度/边框位置、组件实际引用和验收截图。系统原生界面只记录调用与周边流程，不能把无法控制的系统页面列为已重绘。

**内容与素材真实性**：正文有事实依据，示例可用，元信息/进度/统计来自真实内容或结果；图解结构与文字一致，有意义的图片提供可读替代说明，纯装饰不进入 VoiceOver。主题实物/实景摄影按第 10.6 节从已列第三方网站搜索、核许可、下载并实际接入，不用 AI 图、Emoji、Logo 或空白占位代替必需摄影；Stargate 可生成 Logo 与本节限定的页面背景装饰，但页面装饰不能冒充真实摄影、内容封面或主题实物图。插画、代码绘制图解与矢量图标可用于解释内容，不能冒充真实摄影。按第 10.5 节避免跨页无理由重复同一图或同一构图，允许必要品牌复用并记录理由。

**密度、可用性与验收**：丰富是信息完整且易理解，不是填满所有空隙；首屏突出主任务，次要内容自然滚动或渐进展开，不挤压文字、隐藏操作或强制自动播放。保持英文文案、Logo 色板、圆角、稳定阅读表面、iPhone 安全区、Dynamic Type、VoiceOver、系统减少动态选择和第 0.2.2 节完整效果要求。按第 11.3、11.9 节逐页核对当前构建与正常/空/失败等适用状态，记录页面 ID → 内容模块 → 非纯文字表达/真实资源 → 交互 → 截图及结果；只有首页好看、素材已下载但未显示、文字容器堆叠或纯文字页漏检均不能通过对应视觉项。可修复的单调页面须实际调整并复验；外部素材/运行限制只影响对应项并如实记为 `Blocked`/`Not verified`，继续不依赖它们的工作。

文字密度另以 `.codex-work/ui-visual-gates.json` 的 `text_density` 检查项逐页记录首屏摘要、实际图文节奏、详细内容的可达路径与当前构建证据；长段连续堆叠、空有背景/Logo、图标/Emoji 未实际显示或靠截断隐藏文字均须修复后复验，不以“文案完整”作为文字墙通过的理由。

#### 6.10.1 拥挤页面的图片或 GIF 整改（硬门槛）

普通内容页、详情、工具说明或 Welcome 引导卡片出现连续长段、多个文字卡片紧挨、说明挤压主操作或缺少视觉停顿时，必须在梳理文案层级的同时加入或重新编排贴题图片、内容图解或 GIF，形成摘要、视觉解释、重点与深入内容之间的阅读节奏。静态对象/场景适合真实图片，过程、变化或步骤演示适合 GIF；按当前页面选择，不要求每页都有 GIF。图片/动图必须帮助理解当前内容，不能随意插入表情包、装饰性循环或把完整文字墙保留后再堆大图；仅加 Emoji、背景、Logo 或占位框不算完成这项整改。必要事实与详细内容保持完整可达。

新增媒体按第 10.1、10.5–10.7.1 节核对来源、许可、命名、独立展示位与真实本地加载；主题照片仍从既定第三方来源取得，不能用生成图冒充。GIF 用于说明真实过程时须与正文一致，不伪造产品功能、用户结果或统计。采用与页面层级相称的比例、留白、圆角及适用边框，不遮挡正文或操作；普通状态完整播放，不因性能推断降低质量或删减既定效果。GIF 按页面生命周期控制播放，系统减少动态开启时显示有意义的本地静态预览，关闭后恢复正常展示；不能仅设置动画时长为零却让 GIF 继续播放。可持续循环的动图提供可操作的暂停/继续入口，避免运动妨碍阅读。

原生 Launch Screen 保持静态，法律/风险/破坏性确认不强塞 GIF。`lib/welcome.dart` 的 GIF 与静态预览用已登记本地 assets，实际验收播放、离线、减少动态与生命周期。独立 `aduit/welcome.html` 若用 GIF，动图/预览均 Base64 内嵌且总文件严格小于 262,144 字节，不新增站点素材；不将 HTML 限制套到 Dart。

在既有页面追踪表标出拥挤位置、采用的图/动图、用途和真实路径；在 `text_density` 与 `media` 两项关联修改前后当前 iPhone 构建截图。GIF 还须有播放录屏或可辨认的不同帧证据，核对静态预览、暂停/恢复、Reduce Motion、离线与裁剪；首帧出现不等于动画已验证。仍然拥挤、动图不动、持续占位或素材错题时继续实际调整并复验，不以“已添加文件”结束。此项沿用现有 UI 精修与最终图片修复闭环，不增加审批或重复台账。

#### 6.10.2 非游戏项目的动态图覆盖（硬门槛）

非游戏项目主动、系统性地使用与主题和当前任务有关的动态图片，不等到文字拥挤才补图。对主要内容/功能页、重要详情、过程说明、操作结果以及合适的 Welcome/Initialization 逐页规划独立动态图展示位，优先表现真实过程、结构变化、操作方法或成果，让项目在多个主要场景中实际使用；不能整项目只放一张欢迎动图，或把所有动图换成同一个装饰循环。纯静态对象仍保留所需真实摄影，不能为动而动、遮盖核心操作或把不适合的法律正文/风险确认/系统界面强行动画化；原生 Launch Screen 继续静态。混合项目的非游戏模块适用本节，游戏场景按第 9.6 节制作实际引擎动画。

优先采用能在当前 Flutter/iPhone 解码与控制播放的本地 GIF、动态 WebP 或 APNG，并实际验证多帧；需要交互状态的插画可辅以 Rive/Lottie 等本地动画资源，但不能只用库名、代码位移或动态渐变代替应有的动态图素材。采用许可明确的成品，或由项目已有原创/许可素材制作有内容价值的动画；不得伪造过程、统计或产品结果，不能扩大生图服务既定用途。按主题/页面保存至 `assets/media/anim/<page_id>/<主题短名>.<格式>`，配有意义的本地静态预览；独立内容展示位不复用同图，制作过程及来源沿用第 10 节规范，运行期不联网加载。

在既有页面追踪表、资源清单和逐页执行文档登记主题/用途、格式、实际路径、展示位置、尺寸裁切、播放/暂停、循环/结束、预览、减少动态、离屏/后台与返回恢复；不适用页面写具体职责原因，不能用“已加背景动画”代替动态图覆盖。动态图不能替代第 6.14 节主题场景、每页专属转场或第 6.14.2 节 Flutter 实时背景，也不能把多个帧计成多个独立动态层。

在当前同一 iPhone 安装上逐项验证实际多帧播放、完整循环/结束、可操作暂停/恢复、离线加载、圆角/裁切、正文和控件可读性、减少动态静态预览及生命周期恢复，保留录屏或可辨识的不同帧证据，纳入现有 `media`/`text_density` 和第 10.7.1 节闭环。只有文件存在、首帧截图、静态 fallback 或动图已经下载均不能证明通过；无内容价值、重复、冻结、加载失败或挤压 UI 时替换/重排并复验，不缩减既定视觉效果。

### 6.11 页面背景装饰图案

背景成品先保存到本项目专属暂存目录 `~/Downloads/<sanitized-project-name>/backgrounds/<page_id>/`（本机为 `/Users/admin/Downloads/<sanitized-project-name>/backgrounds/<page_id>/`），再校验并复制到当前 `Target project root/assets/backgrounds/<page_id>/`；开始任何图片任务前必须先创建该项目目录，不能直接写入公共 Downloads 根目录，也不能引用其他项目的背景。Logo 候选、内容照片和导出文件分别使用同一项目目录下的 `logo-candidates/`、`content/`、`exports/` 子目录。浏览器强制写入默认下载目录时，只追踪并立即迁移本任务实际下载的确切文件到项目专属目录，不扫描、搬走或覆盖其他文件；验证格式、许可、哈希和去重后再移入页面 assets 并登记，不让 Downloads 路径成为运行期引用。重名时按候选/任务映射处理，不能覆盖其他页面或项目资源；文件名继续遵守第 10.1.2 节短名规则。

为每个 App 自有页面实际制作一张与该页主题、内容和任务相符的背景装饰图案，使用 `http://stargate.local:3100/image` 生成每页对应的背景装饰图案。此处是该服务在 Logo 之外的限定用途：只生成随包使用的界面装饰背景，不生成或替代主题实物/实景照片、内容主图、摄影封面、视频帧或用户媒体；上述真实摄影仍须从第 16 节列出的第三方来源获取并核对许可。

以页面自身的视觉重点设计细致、有层次、色彩鲜明且不单调的纹样、纹理、插画式装饰或边框构图；符合项目主题与 Logo 色板，不采用仅有简约线条、细轮廓、扁平几何或纯色块堆叠的简化画面。按每个页面的实际显示比例选择生成规格，使用高质量结果；图像生成服务不可用时按第 0.6 节有限尝试、记录并继续独立任务，不伪称已生成。

每个页面使用唯一稳定的 `page_id`（小写 `snake_case`），按以下规则落盘：`assets/backgrounds/<page_id>/<page_id>_background.png`，例如 `assets/backgrounds/entry/entry_background.png`。每个页面独立存放、名称与页面 ID 对应，不把图案散放在 `lib/`、项目根目录或 `aduit/site/img/`，不跨页面重复同一张图；共享页面组件只共享渲染代码，不共享页面专属图片。将每个资源显式加入 `pubspec.yaml`，并在 `.codex-work/page-inventory.md` 记录按页面 ID 分类的装饰素材、页面类别/路由、Dart 文件、图片路径、生成任务与提示词摘要、实际透明度/裁切或边框位置、组件对该装饰素材的实际引用和当前 iPhone 验收证据，形成页面 ID → 装饰素材 → 页面注册与实际引用的可追溯链路。

Flutter 页面以主题渐变为底，将生成图片作为低透明度图层或边缘框饰实际叠加；图像不带 Alpha 时使用 Flutter 透明度/混合或裁切处理，不要求生图服务输出透明通道。透明度以能辨认纹理且文字/控件对比度仍合格为准，常规起点为 8%–20%，不得无依据地调到不可见。装饰层应忽略触摸、从无障碍语义树排除并随页面生命周期停止非必要动效；摄像机实时取景区、录音/播放主控区与法律正文阅读区只允许在外围边缘使用，不得干扰用户任务。每页均需检查小屏、大屏、浅/深色、大字号下的可读性、裁切与安全区。

实际 `lib/welcome.dart` 直接使用 `assets/backgrounds/welcome/welcome_background.png`，登记 pubspec、引用并在当前构建验证；独立 `aduit/welcome.html` 可从同一 Welcome 背景派生优化内嵌图，保留 Base64 自包含与总 UTF-8 小于 262,144 字节限制。两份是同一个欢迎 UI 的实现与交付版本，不为同一视觉强行生成两张不同背景；HTML 不进 App。

### 6.12 唯一 Logo、其余成图转用与原创 UI 插画（硬门槛）

选定后只有 `selected_candidate` 是正式 Logo，唯一源为 `assets/logo.png`。其他生成图转为有明确用途的插画或装饰资源，以正式 Logo 的主题色、排版和渐变统一视觉，不在多个 App 页面反复贴同一 Logo。

- **正式 Logo 的展示范围与 HTML 例外**：AppIcon、原生启动页及同款承接层保留正式 Logo。`lib/welcome.dart` 仅保留一处品牌 Logo，其位置由本次构图决定，不额外叠第二张；独立 `aduit/welcome.html` 与四站点 HTML 继续使用原正式 Logo，`site/img/logo.png` 为小派生图。原生承接仍在 Welcome 真正就绪后保持 250 毫秒再淡出。Initialization、Settings、主内容、导航、列表、状态图、按钮、水印不反复贴 Logo，按本节用其他合格成图或主题插画；不能以每屏一张为理由重复。
- **逐张评估其余成图并尽量利用**：在 `.codex-work/logo-selection.md` 为每张非选中图补充实际用途复核：`candidate_id → role → 新名称/asset路径 → Flutter页面/展示位 → 真实引用/当前截图`；未用项逐张写明具体原因。未适合 AppIcon 不代表不能用于较大插画：质量合格、主题贴合、构图适用的成图优先用于不同 Flutter 页面的功能介绍、非摄影类插画封面、分类头图或空/成功状态，尽量用上全部适用成图；不为转用改动 HTML。明显生成瑕疵、错题、近似重复、画风不协调或没有合理位置的图保留内部及未用理由，不强行塞入页面，不为消耗图而增加无关功能，也不增加额外生图批次。
- **转用后另起名称**：非选中图进入工程前，按主题主体和实际用途改为可辨认短名，例如 `assets/illustrations/explore/forest_intro.png`、`assets/illustrations/notes/field_empty.png`；能够准确缩写的词按第 9.3.1、10.1.2 节处理。不得命名为 `logo2.png`、`logo_alt.png`、`backup_logo.png` 或另一套品牌/图标；不能只把所有文件改成 `c01` 等无用途编号。原始候选 ID、源哈希和旧新路径仅用于内部追溯，不展示给用户；正式取色、`app_theme.dart`、AppIcon 和 HTML Logo 始终来自选中图，转用图不能覆盖品牌源或改为另一套主题色。
- **实际接入与差异**：按页面/功能分类落在 `assets/illustrations/<feature_or_page_id>/<purpose>.png` 或工程实际支持的格式，注册资源并更新 Dart/数据的实际消费者，HTML 保持现有安排。每张转用图对应不同独立展示位，不把同一成图改名、改色、镜像、裁剪后铺满多个页面；需要衍生尺寸时保留来源关系并按同一图计数。图像必须作为内容插画融入布局，不能排成另一组应用徽标。运行时绘图代码按页面/功能分类，不集中到 `main.dart`。
- **质量和用途边界**：转用的是现有生成成果，不扩展 Stargate 的常规生成范围；仍只提交 Logo 与第 6.11 节页面背景装饰任务。可另行代码绘制主题图解或状态插画补齐需求，不能用正式 Logo 的变体冒充新图。所有生成图均不得冒充真实摄影、用户记录或测试证据；第三方实景/实物照片和摄影封面继续按第 10.6 节取得，页面独立背景仍按第 6.11 节生成、命名与验收，不由转用候选取消。
- **显示与交付**：保留主题色协调、圆角裁剪、适当细边框、可读性、VoiceOver 与离线加载要求。转用图只进入 App 的 assets 分类目录，不放入 `aduit/site/img/` 或仅用于最终五张项目截图的 `aduit/imgs/`，不扩大站点白名单；只打包实际使用的合格素材，原始候选和接触表留在内部。独立 `aduit/welcome.html` 的 Logo、Base64 自包含与体积限制仍按原规定，不因 Flutter 转用图而改写。
- **逐页复核**：结合接触表、内容哈希/近似图检查、实际代码及当前 iPhone 截图，分别统计正式 Logo 的展示位置、非选中成图的转用数/实际展示数及每张未用理由；核对 Dart Welcome 仅保留一处 Logo，位置按本次独有构图决定，未额外叠加，Initialization、Settings 和列表/详情没有又回退到重复 Logo，HTML 仍按原规则使用正式 Logo。只下载、改名、登记、声明但未实际显示不算转用完成；后续资源整理及最终构建后重查。无理由重复的 Logo 或可用成图未评估/未接入必须修正；缺少运行条件只标未验证并继续独立交付。

### 6.13 全项目逐页骨架差异与跨项目去重（硬门槛）

每个独立页面的骨架都不能重复，覆盖 Welcome、Initialization、主要目的地、各类详情/工具/结果/搜索/Settings、独立 Sheet 和实际自有 HTML；不能只给欢迎页换布局。同一项目逐页区别，后续新项目也须对照可取得的历史方案重新设计，不能固定轮流套用几套模板。主题统一由 Logo 色板、字体角色、控件语义和材质维持，布局差异由页面任务和内容关系决定；不得随意打乱阅读顺序、隐藏操作或增加无关功能。复杂度应体现为有意义的图文区域、复合编排、视觉层次、交互与状态，不能只叠装饰或堆文字。

**骨架的六个维度**：

| 字段 | 必须描述的结构 |
| --- | --- |
| `composition` | 主构图及空间分配，例如非对称展陈、编辑式分区、分层任务画布；不是风格名称或主题词 |
| `region_order` | 按实际视觉/阅读次序排列的区域角色数组，不用文案标题代替区域职责 |
| `media_structure` | 主视觉与图文的位置关系、比例、焦点及层次；替换图片主体不改变该维度 |
| `content_structure` | 内容的组织、分组、密度和层级；同一列卡片换名不改变该维度 |
| `action_structure` | 主次操作、结果反馈及状态区域的组合与相对位置；只改按钮文字不改变该维度 |
| `navigation_structure` | 页内浏览/分页/步骤与上下文导航的组织；系统返回按钮和统一全局导航可保持一致 |

任意两个独立页面至少三个维度有实质差异，且改变页面主要空间组织，不能只改三个字段的名称。换颜色、图片、文案、图标、字体、圆角、背景纹理、渐变方向、动画或少量间距均不能单独计为骨架差异；不能把代码文件拆开但仍使用同一个整页布局。简单的“标题 + 同规格列表 + 底部按钮”不能连续复制到不同页面。可按任务综合编辑式跨区、主题展陈、阶段路径、图文叠层、对照结构、画布和上下文工具等方法；示例不是固定菜单，不能随机拼接成不可用页面。

**规划与历史**：导图确认前在已有 `.codex-work/navigation-design.md` / 页面追踪记录中列出所有页面的六维结构、主题依据、主次区域及两两差异，Welcome 和 Initialization 各比较至少两种结构可行方案再选择，不另问用户。读取 `${CODEX_HOME:-$HOME/.codex}/flutter-engine-runner/layout-history.json` 中可取得的历史页面记录（缺少 CODEX_HOME 时使用用户的 `.codex`），索引使用 version=1 与 records 数组，每条包含 project（绝对工程路径）、id、layout、design_version 和 evidence；layout 使用本节六维结构。按绝对工程路径区分项目；对照既有页面而非只对照上个项目首页，变换主题后仍不能复用旧骨架。该文件是非公开设计索引，不在 Skill 安装目录，安装更新不得覆盖。恢复同一项目时沿用已确认且验收有效的设计，不因索引含本项目就强制重做；历史快照仅纳入其他项目，首次确实没有其他项目记录时建立首份记录；读取失败或历史不可取得时如实标为跨项目比对未验证，不能宣称与所有历史项目不同，也不能因此停止独立实施。最终只更新本项目记录，保留其他工程数据，串行读取最新索引、合并本项目记录，以临时文件加原子替换方式保存并复读核对，记录设计版本和证据，不扫描无关项目。

**实现与验收**：在 `.codex-work/ui-visual-gates.json` 每个 `surfaces[]` 项新增 `layout` 对象，含上表六个字段；五个非数组字段均为稳定、可复用的结构描述短值，`region_order` 为非空有序字符串数组。相同结构必须用相同描述，不能掺入项目名、颜色或随机 ID 绕过比较。顶层 `layout_history` 记录 `scope`（`available_records` / `first_record` / `unavailable`）及 `records` 数组；历史项包含 `project`、`id`、`layout`，复制实际可取得索引中其他工程的结构用于复核，排除本工程及同一视觉的冗余表示，`available_records` 不得是空数组。`first_record` 只适用于确实没有其他工程的历史，`unavailable` 保持未验证。运行 `validate_visual_implementation.py` 检查缺项、同构与六维差异；它只检查结构记录，不能自动判断真实视觉差异。必须另看当前 iPhone 的逐页全屏/滚动或分页截图、必要的操作录像及布局代码，对照去掉图片/颜色后的区域轮廓，记录与最近似页面的三个以上真实结构差异。已有 `layout` 验收项引用全部页面及比较证据；重复或只有字段差异就重新设计并复验，不以计划或改名声称通过。

**复用边界**：同一页面不同 `contentId`、分页批次、浅深色和加载/空/错误等状态属于同一个逻辑页面，不为每条数据复制一个骨架；每个独立页面类型仍必须不同；承担不同主题任务/信息结构的详情必须分别规划，不能将所有不同职责页面藏在同一 /detail/:id 模板下规避差异。按钮、导航语义、表单行、法律阅读排版及小组件可以共享，不能以共享控件为由复用整页。既有固定协议 WebView 是一个容器，切换四个 URL 不虚构成四个 App 骨架；四份自有 HTML 仍各自规划结构并保持法律阅读清楚。系统原生界面只记录系统负责的边界。仅以下同一视觉的不同表示允许完全一致：同款原生启动承接层相对原生页、仅交付的 `aduit/welcome.html` 相对 `lib/welcome.dart`。前者在台账标明 `role: native_cover` / `native_launch`，后者使用固定来源路径，并用 `same_layout_as` 指向对应表面 ID；不得给其他页面滥用此字段。

## 7. 页面级 UI 与功能规格

整个 App 的启动/清除返回体验必须恰好三个不同页面：iOS 原生启动页、Welcome 欢迎页、Initialization 初始化页。另须实现 Settings（含 `Clear Data` 和二次确认）及协议 WebView；其余任务页面按实际主题和选定功能设计。拍照、相册、录音及本地媒体管理均非固定配置，按第 0.3 节允许任意组合或全部不包含，未选功能不生成页面/按钮/路由。启动准备只是欢迎页内部状态；启动准备状态必须显示在欢迎页内部，不创建 Loading 页面。`Clear Data` 确认清理成功后显示初始化页并提供 `Entry`；协议通用文案仅初始化页显示，欢迎页不显示任何协议文案；引导页不含协议通用文案。Detail、Player 等同样按实际任务采用；若选用录音，真实试听与结果管理仍须完成，不能用功能可选掩盖已选功能的缺失。客观设备限制按第 11.6 节记录，不得假装完成。

### 7.1 欢迎页（Welcome，`/welcome`）

职责与出现时机：这是每次启动 App 后进入的 Flutter 页面，也是 `Continue` 所在页面。其前面是静态 iOS 系统启动页及同款原生承接层；必须按第 10.4.3 节维持原生画面至本页实际就绪后 0.25 秒，再淡出承接层。启动准备过程、准备完成、恢复、错误、重试和清除等均为此欢迎页的页面内状态/覆盖层；不得另建 Flutter Loading 页面、`/loading` 路由或第四个启动页。App 从后台恢复时保留当前有效页面或清理状态，不额外回到欢迎页。只有用户确认 `Clear Data` 且清理成功后，才显示初始化页并提供 `Entry`；下次 App 启动仍进入欢迎页。

**UI 自由构图与精修（硬门槛）**：按第 6.13 节重新设计 `lib/welcome.dart` 的项目专属骨架，不固定为顶部 Logo、中间一张卡片、底部分页点与按钮。从当前主题、真实功能、正式 Logo 色板与可用主视觉出发自由发挥；品牌/标题位置、主视觉比例、图文穿插、章节呈现、分页点、进度/恢复区及 `Continue` 的形态和位置均由本次构图决定，不预设固定上下顺序、三段式排布、统一对齐或底部按钮栏。遵守已确定的品牌使用边界，让主要进入动作始终清晰可发现、可操作。按第 6.13 节在既有导图确认前比较至少两种实质不同的构图，选定与主题最契合的一种，不新增逐版询问；不固定轮换某几套模板，也不在每次启动时随机改变已选布局。

保留 3–5 个真实功能英文介绍章节/卡片、自动切换与可点击分页点、Logo 派生多色渐变/动态渐变、独立主题装饰、图像/图解、图标/Emoji 和 `Continue`。“卡片”指可切换的功能介绍内容，不强制矩形卡片容器、相同尺寸、描边底板或单卡居中；可将章节融入贴题的复合空间关系，当前章节可含多区内容或相邻预览，按信息与素材安排主次。Flutter PageView/PageController 或等价呈现仅负责章节切换，不能反过来决定整页骨架。准备状态属于同页的独立信息职责，不要求固定占一排或使用统一底部托盘；进度与恢复可融入所选构图，但状态真实可读、按钮完整可见。

精致度必须落到实际成品：逐项调整主题图的选择与焦点裁切、图文比例、斜体/渐变标题及字体层级、重点词、留白与疏密、图标/Emoji、暖色渐变和透明材质、背景纹理/光晕层次，以及具有主题对象和动作含义的入场、章节与点击反馈；执行第 6.6.1、6.7 节现有精修闭环。不能用更多纯色块、装饰堆叠、文字墙或一套缓动动画冒充复杂设计，也不能只改配色与图片就宣称新布局。以当前 iPhone 构建逐章节、准备/就绪/错误状态核验实际效果，发现粗糙或不协调处继续修改复验。

最终 AppListing 整理后完成实际页面，并使独立交付但不使用的 `aduit/welcome.html` 对应本项目新选定的构图与内容；“相同 UI”仅表示这两份当前产物之间的设计一致，不是沿用旧项目或既有模板。不得为同步欢迎设计改动 `aduit/site/index.html`。页面每次启动在原生承接层下立即构建/布局/绘制，实际首屏就绪后保持原生画面 250 毫秒再淡出；准备状态同页显示，不另建页面。无协议文案/Terms/Privacy 页脚，无邮箱/账号/勾选输入；Continue 必需准备就绪且承接淡出后可用，直接 Dart 调用原进入流程。

**欢迎页不可滚动（硬门槛）**：实际 `lib/welcome.dart` 和独立 `aduit/welcome.html` 均禁止整页或内部纵向滚动，仅允许介绍卡片横向滑动。首屏同屏完整显示当前卡片、分页点、真实准备/错误恢复控件和 Continue，底部安全区内可操作，无重叠、遮挡或裁切。Flutter 不使用 SingleChildScrollView、纵向 ListView 或嵌套滚动兜底；横向 PageView 不受此禁令影响。HTML 禁止文档及内部纵向滚动，不能仅设置 overflow:hidden 隐藏溢出来假装通过。以响应式重排、合适图片比例和简洁不重复文案适配，保留原视觉效果与可读字号，不把正文整体缩成小字。须在四指定视口及所支持 iPhone 大字号下验证纵向滚动范围为零、按钮始终完整可见；失败必须调整复验。

启动准备状态位于 Welcome 内部的独立状态区，按 SafeArea 保持卡片、进度、按钮和安全区清晰可见。显示当前真实步骤、数字百分比、品牌进度条；可在空间充足时附少量真实里程碑状态。必须准备的内容与顺序、百分比计算方式、10 秒预算、不可虚构进度规则详见下文。快速准备完成时可不显式停留在进度态，但仍须按第 10.4.3 节在实际 Welcome 首屏就绪后保持原生画面 250 毫秒再淡出，过渡完成才恢复 `Continue` 操作；不能因速度快而省略。除此强制衔接外，不为展示动画或读完文案添加延迟。

状态区行为：准备中显示真实步骤和最后已完成点；就绪时显示完成状态并启用 `Continue`；核心配置失败时在本页显示明确、可理解的原因及 `Try again`、`Clear Data`。Retry 使用新的操作 ID，错误旧回调不得覆盖新状态。`Clear Data` 打开既有二次确认，取消无副作用，只有真实清除成功后才导航到 Initialization。非关键资源失败不阻止使用主流程，并提供可恢复的局部提示。

将启动必需项与可延后项分开：主导航、最小内容索引和已保存主题为必需准备，大图解码、视频预加载、全库媒体扫描和本地文档完整性检查延后执行。必需准备默认总预算 10 秒；偏好读取失败使用安全默认值并保留原数据，单个非关键资源失败在 Welcome 提示局部问题。并发结果带启动操作 ID，取消/重试后旧回调不得覆盖新状态。

进度只由启动所必需的真实里程碑及其完成状态计算，例如恢复标记核验、已保存主题与偏好读取、最小导航/内容索引就绪、仓储可用；启动前列明必需里程碑总数，百分比按“已完成的必需里程碑数 / 必需里程碑总数”计算并取整。存在可测量的真实子任务时，可按其已完成量/总量计算，但不得凭估时或主观权重分配比例。可并行工作仍按实际完成状态更新，不为制造进度改成虚假串行或添加装饰性步骤。只有实际完成的工作才计入进度；未完成前不得显示 100%。不得用计时器、动画、固定延迟或猜测耗时推高百分比；可延后工作不计入启动进度。

欢迎页背景必须采用非白色的 Logo 衍生多色渐变，在 Light/Dark 下均有鲜明点缀与稳定阅读表面。可用轻柔光晕和低幅呼吸效果，不让装饰暗示进度；不可见/后台时暂停并释放不需要的动画。尊重系统“减少动态效果”：立即停用呼吸缩放、光晕脉动、渐变移动和进度过渡，保留静态品牌背景、真实步骤、数字百分比和进度条；系统设置改变时即时响应。所有 AI 图遵守第 6.1 节，禁止简约线条/色块堆叠。适配小屏、大字号与安全区，不重叠或裁切；正文对比度至少 4.5:1，错误操作点击区至少 44×44pt。状态提供 VoiceOver 可读标签和值，纯装饰从语义树排除。

#### iOS 原生启动页与三页验收

启动白屏与首帧连续性同时执行第 10.4.3 节：逐段定位原生画面、承接表面、Flutter 首帧及 Dart Welcome 实际首绘；明确同页品牌承接、首屏就绪与总预算，保留可见错误恢复。Light/Dark 分别重复冷启动并检查后台恢复，不能仅凭一次成功截图或单个 Flutter 首帧回调通过；必须实现就绪后 0.25 秒保持和原生遮罩淡出，除此以外不增加生产等待或额外启动页。

原生页实际接入统一执行第 10.4.2 节：解析实际构建组合的启动入口，核对 storyboard/原生资源及生成器覆盖，检查最终包和对应安装，再用连续冷启动录像核验新设计及到 Welcome 的衔接。该项独立于 AppIcon 与 Flutter UI；近白底小方图加名称、只改未启用的文件、预览或热重载均不通过。最后一次生成或相关配置/资源变更后重新构建验收，不能沿用旧证据。

iOS 原生启动页必须在 iPhone 冷启动中核验：采用静态 Launch Screen storyboard/资源，使用明显放大的正式 Logo、独立 `PRYRIN` 字标、来自已确认创意的定位文案、品牌装饰线及 Logo 衍生的非白色主题背景。`PRYRIN` 不替换用户提供的项目名称，Logo 不烘焙文字。原生页不显示交互、进度、步骤、百分比、呼吸/光晕动画或错误操作；系统画面只在冷启动期间出现，其后必须由同款原生承接层持续到 Welcome 实际就绪后 250 毫秒再淡出；只有承接层做退出透明度过渡，系统 Launch Screen 本身保持静态。清除数据成功返回 Initialization 时不重新展示原生启动页。

在 `.codex-work/brand-assets.md` 记录原生启动页与 Welcome/Initialization 的素材、页面 ID、Logo 色板映射及实际引用。在当前构建上分别保留原生冷启动、Welcome 页面及其受控慢准备/错误状态、Initialization 页面和清除成功返回路径的运行截图或录屏，不能仅凭热重载、设计稿或页面代码声称已改善。准备时间不能为截图加入生产延时；慢准备/失败仅用测试入口或受控测试数据触发，不能进入正式行为。小屏/大屏 iPhone、大字号、Light/Dark、减少动态及运行中切换均需检查，不能出现留白、重叠、裁切、进度不实或不可操作错误；缺少运行条件时如实记录 `Not verified`，详见第 11.1、11.3 节。

### 7.2 初始化页（Initialization，`/entry`）

定义：初始化页是 Flutter 的单独页面，只在用户从 Settings 确认 `Clear Data` 且数据真实清理成功后展示；它有 `Entry` 主按钮。它不是每次启动出现的 Welcome 页、不是 iOS 原生启动页，也不是启动准备页。不得在正常冷启动或首次安装时把它当作 Welcome 展示。下次启动仍进入 Welcome。

UI：按第 6.13 节独立设计清理成功后的项目专属骨架，与本项目 Welcome 及其他页面至少三个结构维度不同，并比对可取得的历史 Initialization。使用 Logo 派生的多色渐变、独立主题插画/图解、精致装饰、清晰的完成状态层级和有信息价值的复合区域；可围绕保留的随包内容、真实清除结果与重新开始的任务组织画面，不固定为居中完成图标加一句文字和底部按钮，不伪造统计或增加额外步骤。显示准确的英文说明与 `Entry` 按钮，避免 Welcome 的 3–5 张引导卡片在此重复。初始化页底部安全区内居中显示 `By continuing, you agree to our` 换行 `Terms of Use and Privacy Policy` 这两行通用协议文本，在 `our` 后显式换行、无句末句号；第二行仅 `Terms of Use` 和 `Privacy Policy` 可点击，`and` 为普通文本：

```text
By continuing, you agree to our
Terms of Use and Privacy Policy
```

此页是唯一显示这段协议文案的位置。Welcome 和独立 `aduit/welcome.html` 交付页均不得显示或复制该协议页脚。协议链接仅在 AppListing 整理为 `aduit/` 后、生成 Review Remarks 前接入，直接使用 `aduit/intro.md` `All URL` 中对应原始值，不检查、规范化或修复目标；开发预览阶段可展示同样文案并经文档 ID 导航。协议提示不等于用户同意记录，不替代媒体权限。

行为：`Entry` 直接设 `AppFlowState` 为 `active` 并进入选定的主任务目的地，防止重复点击堆叠路由；不弹额外确认、不发起认证、不要求填资料或重新勾选协议。初始化页保留默认主题和随包示例；实际存在的用户私有数据/媒体列表为空，未选媒体功能不建立此类列表。清除成功后直接替换导航栈为该页；后台/重启恢复仍遵守“每次 App 启动进入 Welcome”，不从持久化标记将初始化页误当成普通启动首页。

### 7.3 按主题生成的主要任务页面

每个选定主要目的地必须说明，不论其入口是目录、工作台、工具栏、菜单、分段切换还是实际选用的 Tab：

1. 顶部层级和上下文操作。
2. 首屏和主要 CTA。
3. 内容模块和卡片结构。
4. 在主题确实需要时使用搜索、筛选、排序、视图或播放控件。
5. 空、加载、部分失败、离线和成功状态。
6. 消费的数据模型和资源 ID。
7. 详情路由和返回行为。
8. 本地持久化内容。
9. 无障碍标签、焦点顺序和减少动态行为。
10. 按第 6.10 节列出本页及适用状态的非纯文字表达、实际信息模块、资源/组件引用和逐页视觉验收依据；不能只写“丰富内容”或复用首页描述。

页面必须消费真实种子数据或审核通过的本地资源。静态占位卡片不算完成。

### 7.4 Detail

UI：返回操作、稳定媒体比例、标题、副标题、分类、时长或有用户价值的元数据、结构化内容区段、主要操作与相关内容。图片/视频的图库来源、作者和许可不作为默认展示字段；仅按第 10.1.1 节处理确有义务的必要署名，不展示内部资源清单。

图文深度：按第 6.10 节将正文组织为至少三个有不同信息价值的模块，并实际加入有助理解的主题图片、图解、步骤或实例；视觉与当前 `contentId` 的内容一致，不能只在顶部放一张通用封面、下部仍是连续无层次段落。

行为：按 `contentId` 加载，处理不存在的 ID，返回时保留来源状态，支持展开长文本，并对复制或重试操作提供可见反馈。

### 7.5 Player（主题需要媒体时）

UI：媒体区域、标题、播放/暂停、进度、剩余时间、静音/音量；仅在实际支持时显示全屏控制和下一条内容。图片/视频来源和许可按第 10.1.1 节处理，不默认展示图库名、下载链接或来源声明。

生命周期：退出路由、进入后台、中断或替换时释放控制器；取消过期加载。运行时播放审核后的随包本地资源或用户私有媒体，不调用第三方素材供应商 API；文件缺失、损坏或解码失败时显示真实错误并允许重试/返回，有相关且有效的本地替代内容时才提供替代，不反复切换同一损坏文件。

### 7.6 Settings 与工具路由

Settings 包含外观、主题相关偏好、页面最底部的版本页脚和三个统一的 WebView 入口按钮；不默认创建图片/视频来源列表、素材归因页或 Credits 入口。素材的必要声明按第 10.1.1 节处理，软件依法须保留的许可通知不受影响：

- `Privacy Policy`：打开隐私政策 WebView。
- `Terms of Use`：打开用户协议 WebView。
- `Support`：打开 Support 页面 WebView。

**版本页脚（硬门槛）**：完整项目生成后，Settings 所有设置项、协议入口与清除区域之后，页面最底部仅保留一份 `项目名称 · 版本号`，例如 `ProjectName · 1.2.3`；中点两侧各一个空格，不显示示例方括号或其他说明。

- 项目名称使用用户提供的实际 App 显示名；版本字段只使用当前安装构建的真实数字版本及必要的小数点，格式为 `[0-9]+(?:\.[0-9]+)*`。不加 `Version`、`v`、`feat`、`release`、`debug`、`beta`、渠道/分支名、构建模式、Git hash、括号或其他后缀；不显示构建号或 `+` 后的元数据。此限制只作用于版本字段，不按关键词删改用户提供的项目名。
- 从当前 App 版本元数据读取，iOS 对照最终 `CFBundleShortVersionString`，并核对 Flutter 的版本配置/实际 `FLUTTER_BUILD_NAME`；例如 `pubspec.yaml` 的 `version: 1.2.3+45` 只显示 `1.2.3`，不显示 `45`。不从 Git 分支、文件夹或 release/feat 字符串推断版本，不写死过期值或伪造 `0.0.0`。源版本若混入非数字标签，修正实际版本配置并重建核对，不能仅隐藏错误而留下不一致元数据；内部 `CFBundleVersion`/构建号继续按工具要求保留，但不绑定为此页脚。
- 同步修改实际 Settings 组件、消费字符串与无障碍文案；字号、换行和底部安全区要可读，不遮挡、截断或重复添加其他版本说明。改动后在当前 iPhone 构建滚动到页底核对准确全文与真实版本，验收按第 11.3 节执行。

三个按钮必须集成在同一个 Settings 页面，通过同一 `policy_webview_page` 展示。`aduit/site/index.html` 原位保留生成器输出的内容与结构，不替换为 About Home 或欢迎页；`lib/welcome.dart` 才是运行欢迎页，`aduit/welcome.html` 仅交付，不进入 App 或 Settings。Settings 独立数据区提供 `Clear Data`、删除范围和二次确认，真实成功后进入 Initialization；清除由 Dart 原流程执行，不通过网页或服务。无 Exit/登出、账号/身份输入或个人资料入口，支持联系方式按第 0.3 节。

站点 `aduit/site/` 固定四页：`index.html`、`PrivacyPolicy.html`、`Terms&Conditions.html`、`Support.html`，只配 `img/logo.png`；免责/版权合并原法律页。`aduit/welcome.html` 为独立欢迎 UI 交付，不算第五个站点页、不接入或打包；Remarks 也不加载到 App。实际 Welcome 是 `lib/welcome.dart`。四个 `All URL` 原样登记，Settings 仅三个协议入口，Initialization 清除成功后才有 Terms/Privacy 文本链接，共用原协议 WebView。Welcome/独立 HTML 无协议页脚；协议失败给返回/有限重试，不影响 Continue，不等域名部署。

WebView 实现边界：

URL 原文保护按第 12.1 节执行：四个 `All URL` 完整字符串严格区分大小写；即使暂不可访问，也须原封不动保存并传递。不得把 URL 或路径转成全小写/全大写，不得根据页面标题重拼 `PrivacyPolicy.html`、`Terms&Conditions.html`、`Support.html`；只允许必要的源码转义，运行时值必须与生成器原文精确相等。协议地址错误态和重试均复用同一原始值，不能在失败回退中偷偷重写网址。


- 固定 URL 注册表按名称保存 `All URL` 中的四个原始值；Settings 只暴露 Privacy Policy、Terms of Use、Support 三个入口，只有 Clear Data 成功后出现的 Initialization 才暴露 Terms/Privacy 两个文本链接；Welcome 与独立 HTML 交付页不显示协议通用文案或协议链接。About Home 不出现在 Settings。实际入口只接受固定文档 ID。Disclaimer 与 Content & Copyright Notice 映射到现有法律页的章节锚点，不新增物理文件。注册值必须与第 12.1 节 `All URL` 中四个值逐字对应。
- 开发期正文通过开发浏览器本地预览，App 协议容器以无网络 stub 验证，不注册本地协议资源，不启动远程首屏请求。完成最终回接后，仅在用户主动点击某协议入口时，将对应的原始 URL 字符串交给 WebView；注册值按普通字符串原样保存和传递，不执行 URI 预解析/有效性检查作为导航前置条件。若 WebView 平台不能解析或加载失败，取消当前请求并使其操作 ID 失效，显示可读错误和返回操作。不得清理、修复、重写或跳过该值；重试仅由用户明确点击触发，不循环请求。
- 不开放任意 URL 输入或任意本机文件读取。四原始 `All URL` 为显式注册协议目标，其他导航遵守原 WebView 安全边界，不运行未知脚本或加宽 ATS。Welcome 以 Dart callback 进入，不注册网页桥、AppBridge、`go://continue` 或导航拦截。独立 HTML 可以保留原 Continue 函数，但 App 不加载它；回归用 Dart 导航测试与协议无网络 stub 分别验证，不请求真实目标。
- 三个 Settings 协议页面与 Initialization 两条文本链接提供实际导航；Welcome 仅用 `lib/welcome.dart`，独立 `aduit/welcome.html` 和四站点页不作为运行欢迎源或 Settings 入口。Welcome 与独立 HTML 无协议页脚。法律章节合并原四页；公开页不加追踪/第三方字体/嵌入请求。最终 URL 回接后按真实协议数据流复核隐私声明。
- 原生系统选择器和权限弹窗保留系统交互；WebView 不承担摄像机或麦克风采集，也不请求这些权限。正文文字缩放、长文滚动、最终 URL 的用户点击路径、返回目标、开发期离线预览及最终地址失败状态均实际检查；URL 回归用 stub，不发起真实请求。

#### AppListing 完成后的协议链接回接

本小节是最终链接回接步骤，优先于上文仅适用于开发期本地 WebView 的说明。在 About/AppListing 本地生成并改名/整理为 `aduit/`、`lib/welcome.dart` 完成实现与接入、独立 `aduit/welcome.html` 已保留后、生成 Review Remarks 前，必须实际回接 Initialization 底部协议文案并更新 Initialization 与 Settings 链接目标。只有 Clear Data 成功后出现的 Initialization 页面使用以下固定两行；每次启动进入的 Welcome 及其 HTML 引导页均不显示协议通用文案或协议页脚。文案在 `our` 后显式换行，不依赖自动折行，不增加句号：

```text
By continuing, you agree to our
Terms of Use and Privacy Policy
```

第二行的 `Terms of Use` 与 `Privacy Policy` 是独立可点击的文字链接，分别使用 `aduit/intro.md` 的 `All URL` 中对应原始值，`and` 为普通文本；仅在 Initialization 页面底部安全区内居中显示，不遮挡该页 `Entry`。Dart Welcome 页只包含产品介绍卡片和 `Continue`，不显示协议通用文案或协议页脚。协议提示不添加复选框或额外确认，不保存个人协议同意记录；该协议提示不替代摄像机、相册、麦克风授权。Settings 只显示三个入口：`Privacy Policy`、`Terms of Use`、`Support`，分别使用 All URL 中对应值；不显示或链接首页引导页。将四个 `All URL` 值全部逐字复制到应用固定 URL 注册表，即使对应首页的 About Home URL 没有用户可见入口也保留原始值。所有值按原始字符串保存和传递，不以 URI 预解析或有效性检查作为复制、保存或导航前置条件；不得验证、规范化、补全、替换或因无法访问/格式异常而删除。注册值保存在 App 的固定配置中，不新增 `aduit/` 白名单以外文件。

三个 Settings 入口及 Initialization 的两个协议入口统一通过现有 `policy_webview_page` 加载各自注册 URL。失效或不可访问的 URL 只影响当前 WebView，显示易懂的错误态并提供返回与有限重试；不得阻断 App 启动、Welcome 引导页 `Continue`、Settings 其他功能或清除数据。回归时用不发起网络请求的 WebView stub/fake 核验实际入口传入 URL、首页引导页不出现在 Settings、Welcome 无协议文案、失败与返回状态，不访问或探测真实地址。完成后针对 Welcome 引导页、Initialization、Settings 三个入口和主流程进行定向回归。

### 7.7 清除本地数据（二次确认后进入初始化页）

1. **首次点击只显示确认框**：Settings 的 `Clear Data` 打开标题为 `Clear Data?` 的对话框，提供 `Cancel` 与破坏性 `Clear Data`。二次确认指点击入口后，再在这一个对话框内明确确认，不连续弹出两个确认框；点击入口时不能提前删除、停止当前任务或改变路由。
2. **准确说明后果**：确认正文须只列本 App 实际保存的数据类别；若有照片副本、导入媒体或录音才纳入，否则不出现相关删除声明。说明实际记录和设置将被删除，无法通过 App 撤销，随后进入 Initialization；系统相册原件和已导出文件不受影响。可采用 `This will permanently remove photos, videos, recordings, records, and settings saved in this app, then show the Entry page. Originals in Photos and exported files are not affected. This cannot be undone.`，按实际媒体类型与数据范围调整，不出现 `local`、`device` 或内部存储术语，不宣称能擦除设备备份或远端副本。
3. **取消不产生副作用**：点击 `Cancel`，或在确认前使用允许的返回/关闭动作，只关闭确认框并保留 Settings、滚动位置、主题、媒体和偏好；无确认回复、超时和系统权限结果都不能代替 `Clear Data`。连续点击入口只显示一个确认框。
4. **确认后安全清理**：将 `AppFlowState` 设为 `clearing`，立即防重复并阻止新保存、导入与编辑；最小恢复标记成功落盘后才开始破坏性清理，使旧操作结果失效。仅停止/释放实际存在且正在使用的摄像机、录音、播放或音频会话，取消/隔离实际导入、文档加载与旧异步任务；未选功能不创建空服务以供清理，关闭旧预览及相关 Sheet，按第 8.4、8.5 节收尾在途事务并删除 App 自有可变数据；清理完成前不允许旧回调重新写入记录、文件、缓存或偏好。
5. **清理中可观察且防重复**：显示 `Clearing data…` 和真实阶段状态，禁用重复提交及进入主流程的动作；完成量来自实际步骤，不虚报百分比。确认后删除可能已部分执行，不提供会把残余内容当作完整数据的普通取消/返回；系统后台或关闭 App 不等于取消，重启按恢复标记继续。重试复用同一清除操作，不新增确认框或叠加删除任务。
6. **只有真实成功才返回**：全部目标数据与缓存清理、设备释放、默认状态重建和残留核验通过后，按第 8.5 节移除恢复标记，清空整个导航栈与旧页面状态，设为 `entry` 并替换到 `/entry`；默认主题为 `System`，介绍展示记录、筛选和播放位置均恢复初始值。返回手势和旧深链不能打开已清除内容；再次点击 Initialization 的 `Entry` 后进入选定主任务入口，随包示例仍可用，实际实现的创建/保存操作仍能正常完成，不为未选功能添加入口。
7. **失败可恢复且不谎报成功**：恢复标记写入报错时先核对真实提交状态；确定未提交且未开始删除时，清理本次不完整暂存标记、解除写入隔离并恢复 `active`，留在原 Settings 显示可重试错误，不能声称已清除。若标记实际已提交则按已确认操作继续；无法判断时保留隔离并显示可恢复错误，不盲目重启操作。删除已开始后的部分失败保留标记、剩余阶段与写入隔离，展示 `We couldn't clear all your data. Try again.` 及可操作的重试，不得显示成功、提前进入 Initialization 或自动恢复主页面。记录脱敏错误与实际未完成项，不在 UI 暴露文件路径或内部事务信息；iOS 不调用进程终止接口或强制关闭 App。

媒体停止/释放单次默认最多等待 5 秒；超时按失败处理并继续跟踪原任务，不把超时视为释放完成、不丢弃任务引用、不并发重启同一任务。其他清理按阶段/有界批次推进，连续 15 秒没有可观察进展时转为可操作的异常恢复状态，说明仍未完成；底层任务尚未结束时先核对状态，不允许重试与旧任务同时删除。实际仍在进展的批次可以继续，不以 5 秒或 15 秒强制宣称全量清理完成。清除是设备端操作，不等待网络、域名或开发期外部服务。

### 7.8 摄像机拍摄（仅选用时适用）

- 必须提供与主题任务相连的拍摄入口、真实摄像机预览、拍摄、结果预览、重拍、取消与确认保存；支持设备实际具备的前后摄像头和闪光灯状态，无对应能力时隐藏或禁用控件。
- 处理初始化失败、授权拒绝/受限、设备缺失、方向变化、后台切换、连续点击和空间不足；不使用静态图冒充实时预览，不以权限弹窗出现视为功能完成。
- 保存后结果必须出现在对应主题记录或本地素材列表，可再次打开、查看并删除；照片方向、缩略图和实际文件一致。录像可按主题增加，拍照本身不得连带采集音频。

### 7.9 相册导入（仅选用时适用）

- 使用系统相册选择器选择图片，按主题需要支持多选或视频；导入后提供缩略图、加载进度、预览、取消与保存到主题记录的动作，不先申请不必要的整库访问权限。
- 处理取消、空选择、有限访问（使用 PhotoKit 时）、HEIC/JPEG/PNG 等声明支持的格式、超大图、方向、损坏文件和 iCloud 项目下载失败；异步导入可以取消，失败不遗留半条记录或临时文件。
- 必须将用户选择的可用文件安全复制到 App 私有目录并验证后再标记成功，不长期依赖选择器的临时 URL；对不支持的格式清楚提示。只有实际实现系统相册导出时才增加相应权限与状态。

### 7.10 麦克风录音与本地媒体管理（按实际选用范围适用）

录音相关要求仅在实际选用录音时适用；仅有拍照或导入时只实现所需媒体管理，不连带添加录音、音频会话或麦克风权限；全部未选时整节不适用。

- 必须实现真实录音、明确的录制状态、计时、停止、试听、重录、取消、保存与删除；波形/音量反馈如显示必须来自实际采样。暂停/继续只在底层可靠支持时提供，不做无效按钮。
- 保存格式与编码必须兼容 iOS；录音结果能在主题记录或本地素材列表中重新打开并播放，显示准确时长。处理权限拒绝、音频会话中断、蓝牙/耳机切换、后台、空间不足、保存失败与重复点击。
- 仅为实际存在的拍摄、导入或录音结果提供所需的本地媒体管理：按实际来源显示类型与缩略图/波形、预览、主题关联和删除，不为凑三种来源补建未选功能。删除同步清理记录、文件、派生缩略图及临时缓存。权限撤销不删除已保存文件，不建立个人账号或社区内容流；三项均未选用时不创建私有媒体仓库。
- 第一次使用时提供清晰空状态、示例用途和可达入口；拒绝某一权限仍能使用已有内容与其他已获授权能力。不得自动录制、后台偷录或自动上传。
