## 路径与章节引用

- “第 0.4 节”“第 10.6 节”等引用仍使用原章节编号；按上表找到所属正文，不重新编号。
- `Workflow resource root` 是本文件所在 `工作流文档/` 的父目录，不是文档集目录，也不是 App 输出目录。资料包直接使用时为包根；安装副本使用时为技能的 `references/`。
- `.work/` 是可删除的开发记录目录。主项目、依赖、资源、测试、构建和最终交付物均不得直接或间接依赖它；执行第 9.2.1 节的路径隔离契约，并在第 19 步按第 11.12 节验证移出该目录后工程仍可独立使用。
- AppListing 来源顺序为安装器同步的远程 `feature/1.2.1-A1` → `/Users/admin/Desktop/config/ios-app-listing` → 本规范第 12 节完整输出契约。记录实际来源、版本、缺失的可选工具和替代校验。任一来源、生成器或校验失败都不能中断后续 AppListing 文件、About、`aduit/`、引导页和 Review Remarks；逐项修复，不能通过的检查单独记为 `Failed`/`Blocked`/`Not verified`，不伪报通过。目标工程路径仍按原第 0.4 节解析。

所有实现、AppListing/About、协议回接、Review Remarks 和交付目录清理均完成后，先按第 10.7 节执行最后的图片加载检查，再按第 11.6 节执行最终 iOS 权限双向校验（必需完整、未用移除）；两者及修复复验完成后，最后按第 12.5 节实际截取五张有意义的最终 App 画面到 `aduit/imgs/`，每张原始竖屏 1206×2622 PNG；逐张核对内容、尺寸、解码和恰好五张的目录白名单；全部验收及修复复验通过后，再按第 13.1 节执行第 22 步，关联用户 Git 仓库并创建/切换 `feat/1.0.0`，不暂存、提交或推送代码，等待用户自行提交，之后才提交最终报告。验收未完整通过则延后 Git 操作、如实报告缺口。占位图或加载错误必须从第 16 节列出的第三方来源补齐真实主题图片并复验；没有 iPhone 运行证据时不得声称图片检查通过。
同一次最终检查还要扫描当前工程的本地依赖与构建产物，移除其中所有 `aduit/` 副本并确认依赖树/Bundle 中不得残留；项目根目录的 `aduit/` 是审核交付物，必须保留。App 运行期品牌图片使用 `assets/logo.png`，Entry/Settings 协议链接使用三个固定 HTTP 模板，在 App 内 WebView 显示，不跳转外部 App；通过无网络 stub 核对映射，不访问或探测真实 URL，也不将本地协议 HTML 打包为应用依赖。具体扫描范围与例外见第 10.7 节。
- 安装器会在已安装技能中生成 `references/workflow.md` 作为兼容入口，内容取自本总入口；若资料包仍保留旧版顶层长文档，安装器只将它作为旧路径副本，不把它当作独立规范。唯一规范内容维护源是本总入口和下面十份正文。
- `manifest.txt` 是安装器按相同顺序核对完整性的清单，先列本入口再列十份正文。复制到其他机器时必须连同整个 `工作流文档/` 复制，不能只复制总入口或某个章节。

## 使用与维护

执行前按 [01-执行约定.md 第 0.12 节](01-执行约定.md#012-最新用户硬性覆盖与历史要求对照)的历史要求对照逐项建立验收映射；同主题以用户最新指令为准。表格是规则索引，各正文是实施与取证依据，不重复维护另一套阈值。随机范围仅限获授权的主题与已确认范围内的页面/功能组合，全部适用的 UI、资源、工程、材料和验证要求均为硬门槛。

原生启动衔接执行第 10.4.3 节硬门槛：以系统启动画面同款原生承接层连续覆盖，Welcome 实际首屏就绪后保持 0.25 秒再淡出；时间记录与连续冷启动画面共同验收，不能用启动时固定延迟或Flutter 首帧回调代替。

Codex 入口为已安装的 `$flutter-engine-runner`；额外 Codex 插件按可用能力选用，不作为统一前置条件。实际执行仍需核验 Flutter、Xcode/iPhone SDK、适用的 CocoaPods，以及满足质量要求的生图工具/服务和浏览/下载能力；工具或服务缺失按第 0.5、0.8 节记录并继续可执行工作，不能将插件可选解释为工具链已具备。

三个协议 HTML 页面禁止草稿、开发分发和发布资料待配置等提示；生成、改名、独立欢迎页制作及最终交付时，按第 12.1 节运行随技能安装的 `scripts/validate_about_copy.py` 并逐页渲染复核，移除完整提示区块，缺失事实只记录在内部。不要依赖远程包是否提供可选的页面文案校验器。

逐页规划文件执行第 3.6 节：思维导图与执行文档分目录保存，每个逻辑页面分别生成 `.work/map/page/<page_id>.md`、`.work/exec/page/<page_id>.md`，两个全局索引和页面清单双向关联同版文件。确认前写齐、校验并连续分批展示全部页面图及执行摘要，最后只确认一次；实施每页前完整读取本页两份文件，按任务执行并回填，最终反查每页详细规格与真实结果。总图、通用模板或文档数量不能替代具体页面覆盖，开发文档不进入 aduit 或 App bundle。

每个新项目默认制作复杂且内容丰富的完整成品；产品规模与深度按第 4.3 节硬性下限制定并验收。领域对象/关系与覆盖矩阵先于内容生成，功能页面、核心模块、层级、分类/场景、有效条目/案例、详情、任务与信息形式的具体分配随既有导图整体确认；工具型定位、阶段划分、工期或后续版本都不能成为减量理由。实施、当前 iPhone 运行与最终报告对照计划目标、实际实现、实际验证和缺口，详见第 3.2.1、11.1、11.9、14 节，不新增确认。

全项目每个独立页面按第 6.13 节拥有不同骨架，任意两页六维结构至少三项实质不同，并比对可取得历史记录；Welcome/Initialization 不再套固定构图。主内容按第 4.4 节充足展开并可连续翻页，首中末批与全程内容不能重复。第 0.2.2、1.4 节要求完整列出极低、低、中、高、极高五档让用户直接选择，不用手写性能/功能标准；默认推荐中端 iPhone，性能“不在乎/无限制”等意思映射极高档；不自设量化指标，用户明确指标才按对应条件验收，功能、视觉、启动时序及文件契约继续核验。

动画与动态按第 6.14 节执行：每个 App 屏幕默认状态至少两个不同的主题动态元素，纯色块拼凑、几何块移动和简单渐变加缓动不能充数；为每页写明形态/材质/层次、轨迹、因果状态及数值参数，并通过当前 iPhone 录屏/逐帧复核。复杂背景可直接制作程序/组件动画或使用生成的动画成品，同时按第 6.11 节保留真实半透明主题图片点缀；不强制为动画另行生图，但图片层不能省略；动画工具、服务与第三方组件合成不限，例举工具不是白名单，具体方式与记录按第 6.11 节。原生 Launch Screen 静态例外；包按任务评估、核验兼容与授权，不默认全装。

主导航与整体 UI 按第 5.1 节贴合主题和核心任务自主设计，底部导航不是默认，也不要求存在 Tab。规划时比较结构上不同的可行方案，随既有一次思维导图确认展示选定依据；实现与验收须同步核对主任务入口、返回/状态恢复和 iPhone 可用性，不把换底栏外形当成消除同质化。

游戏是可选主题分支，不是所有项目的默认类型。项目类型必须先判定为非游戏、游戏或混合：只有用户选择游戏主题，或创意明确包含真实游戏模块时，才按第 9.6 节选用专用游戏引擎，确认前只读核查兼容环境，Logo/主题及工程创建后实际搭建并在同一 iPhone App 中跑通玩法；非游戏项目不创建游戏引擎、游戏场景、游戏入口或游戏验收任务，按自身主题执行第 6.10.2 节等适用路线。非游戏模块按第 6.10.2 节在多个主要场景使用贴题、本地可播放的动态图。每个项目按第 9.5 节独立设计产品架构、导航、页面与视觉语言，禁止套用整套通用壳；规划、实施与第 11.11 节验收共同落实，不新增用户输入或审批。

Logo 按第 2.5 节生成 12 张独立候选，模拟现实、手绘、油画、艺术表现四种画风各 3 张，逐张比较后从全部候选中选生成痕迹最少且合格的一张；旧的只生一张/只选一种画风规则不再适用。按第 2.5 节按主题自主设计候选构图与画风，色彩统一明亮；Logo、App 与交付 HTML 统一采用明亮色调，不设色系分布或渐变数量配额；渐变按创意选用，取消颜色及明暗调节功能；不要把所有题材默认套成同一种橙黄夕阳图。主题与三个协议 HTML 页面按项目选定视觉明亮配色，About Logo 按第 12.1 节生成小体积派生图并验证不阻塞内容/按钮。所有图片在制作阶段下载或生成至当前工程，实际背景图片直接放项目 `assets/backgrounds/`，无图片的程序/动画场景按第 6.11 节登记真实实现与所用资源，Google 图片搜索可用于发现和合法取得原图；不同独立内容展示位不复用同图，运行时不联网拉取图片。文本执行第 6.6 节的事实核对、去重与去套话编辑；排版必须落实标题斜体/斜切、按创意选用并保证对比度的渐变或纯色标题、至少三种有意且可复用的字体风格、sentence case 正文和重点词强调；全页面 UI 精修执行第 6.6.1、6.7 节，以上均纳入第 11.1、11.3 节最终验收。

最终 `aduit/intro.md` 的项目描述须按第 12.1 节详尽覆盖当前实际用途、主模块、完整任务、实际媒体能力（如有）、成果回访和数据边界，不能只交付短摘要。遵守生成器选定的文案结构及 Description 的 4,000 字符上限；生成后精修该正文，删除重复 URL 栏目及多余网址，最终保留三个固定 HTTP 模板且文件名大小写不变，两份 Intro/Remarks 中原教育类展示标签统一为英文 `Popular Science`（科普），其他类别与事实不变，并按第 11.1 节验收后再用于引导页与审核备注。
