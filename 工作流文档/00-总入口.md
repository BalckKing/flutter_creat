## 路径与章节引用

- “第 0.4 节”“第 10.6 节”等引用仍使用原章节编号；按上表找到所属正文，不重新编号。
- `Workflow resource root` 是本文件所在 `工作流文档/` 的父目录，不是文档集目录，也不是 App 输出目录。资料包直接使用时为包根；安装副本使用时为技能的 `references/`。
- AppListing 来源顺序为安装器同步的远程 `feature/1.2.1-A1` → `/Applications/config/ios-app-listing` → 本规范第 12 节完整输出契约。记录实际来源、版本、缺失的可选工具和替代校验。任一来源、生成器或校验失败都不能中断后续 AppListing 文件、About、`aduit/`、引导页和 Review Remarks；逐项修复，不能通过的检查单独记为 `Failed`/`Blocked`/`Not verified`，不伪报通过。目标工程路径仍按原第 0.4 节解析。

所有实现、AppListing/About、协议回接、Review Remarks 和交付目录清理均完成后，先按第 10.7 节执行最后的图片加载检查，再按第 11.6 节执行最终 iOS 权限双向校验（必需完整、未用移除）；两者完成后才能提交最终报告。占位图或加载错误必须从第 16 节列出的第三方来源补齐真实主题图片并复验；没有 iPhone 运行证据时不得声称图片检查通过。
同一次最终检查还要扫描当前工程的本地依赖与构建产物，移除其中所有 `aduit/` 副本并确认依赖树/Bundle 中不得残留；项目根目录的 `aduit/` 是审核交付物，必须保留。App 运行期品牌图片使用 `assets/logo.png`，Entry/Settings 协议链接直接使用 `aduit/intro.md` 的 `All URL` 原始地址，通过无网络 stub 核对映射，不访问或探测真实 URL，也不将本地协议 HTML 打包为应用依赖。具体扫描范围与例外见第 10.7 节。
- 安装器会在已安装技能中生成 `references/workflow.md` 作为兼容入口，内容取自本总入口；若资料包仍保留旧版顶层长文档，安装器只将它作为旧路径副本，不把它当作独立规范。唯一规范内容维护源是本总入口和下面十份正文。
- `manifest.txt` 是安装器按相同顺序核对完整性的清单，先列本入口再列十份正文。复制到其他机器时必须连同整个 `工作流文档/` 复制，不能只复制总入口或某个章节。

## 使用与维护

执行前按 [01-执行约定.md 第 0.12 节](01-执行约定.md#012-最新用户硬性覆盖与历史要求对照)的历史要求对照逐项建立验收映射；同主题以用户最新指令为准。表格是规则索引，各正文是实施与取证依据，不重复维护另一套阈值。随机范围仅限获授权的主题与已确认范围内的页面/功能组合，全部适用的 UI、资源、工程、材料和验证要求均为硬门槛。

原生启动衔接执行第 10.4.3 节硬门槛：以系统启动画面同款原生承接层连续覆盖，Welcome 实际首屏就绪后保持 0.25 秒再淡出；时间记录与连续冷启动画面共同验收，不能用启动时固定延迟或Flutter 首帧回调代替。

Codex 入口为已安装的 `$flutter-engine-runner`；额外 Codex 插件按可用能力选用，不作为统一前置条件。实际执行仍需核验 Flutter、Xcode/iPhone SDK、适用的 CocoaPods，以及 Stargate 和浏览/下载能力；工具或服务缺失按第 0.5、0.8 节记录并继续可执行工作，不能将插件可选解释为工具链已具备。

四个最终 HTML 页面禁止草稿、开发分发和发布资料待配置等提示；生成、改名、引导页替换及最终交付时，按第 12.1 节运行随技能安装的 `scripts/validate_about_copy.py` 并逐页渲染复核，移除完整提示区块，缺失事实只记录在内部。不要依赖远程包是否提供可选的页面文案校验器。

产品规模与深度按第 4.3 节制定并验收：领域对象/关系与覆盖矩阵先于内容生成，具体模块、内容、详情、任务与信息形式的目标随既有导图整体确认；参考范围按主题调整，不用重复内容凑量。实施、当前 iPhone 运行与最终报告对照计划目标、实际实现、实际验证和缺口，详见第 3.2.1、11.1、11.9、14 节，不新增确认。

主导航与整体 UI 按第 5.1 节贴合主题和核心任务自主设计，底部导航不是默认，也不要求存在 Tab。规划时比较结构上不同的可行方案，随既有一次思维导图确认展示选定依据；实现与验收须同步核对主任务入口、返回/状态恢复和 iPhone 可用性，不把换底栏外形当成消除同质化。

Logo 按第 2.5 节生成 12 张独立候选，模拟现实、手绘、油画、艺术表现四种画风各 3 张，逐张比较后从全部候选中选生成痕迹最少且合格的一张；旧的只生一张/只选一种画风规则不再适用。生成提示词和实际参数提交阶段就必须使用温暖、鲜明、受控的多色渐变，并排除冷蓝、冰青、钢灰、灰紫、冷白及冷峻单色主导，成图后再做同样的视觉复核。主题与四个最终 HTML 页面按该成品实际色板落实渐变，About Logo 按第 12.1 节生成小体积派生图并验证不阻塞内容/按钮。所有图片在制作阶段下载或生成至当前工程，背景直接放项目 `assets/backgrounds/`，Google 图片搜索可用于发现和合法取得原图；不同独立内容展示位不复用同图，运行时不联网拉取图片。文本执行第 6.6 节的事实核对、去重与去套话编辑；排版必须落实标题斜体/斜切、对比度允许时的 Logo 派生渐变标题、至少三种有意且可复用的字体风格、sentence case 正文和重点词强调；全页面 UI 精修执行第 6.6.1、6.7 节，以上均纳入第 11.1、11.3 节最终验收。

最终 `aduit/intro.md` 的项目描述须按第 12.1 节详尽覆盖当前实际用途、主模块、完整任务、实际媒体能力（如有）、成果回访和数据边界，不能只交付短摘要。遵守生成器选定的文案结构及 Description 的 4,000 字符上限；生成后精修该正文，删除重复 URL 栏目及多余网址，最终仅在 `All URL` 保留四个完整地址且四值原文不变，两份 Intro/Remarks 中原教育类展示标签统一为英文 `Popular Science`（科普），其他类别与事实不变，并按第 11.1 节验收后再用于引导页与审核备注。

原运行方式不变：安装/更新运行 `start.command`，AppListing 来源依远程指定分支 → `/Applications/config/ios-app-listing` → 随包契约；Codex 使用 `$flutter-engine-runner`。先收集缺失主题与用户项目名，展示完整导图并等待整体确认；方案包含主题差异化 brief、标志性动作和可回访成果，不增加审批。确认后自主实施，工程直接写入选定根目录，不套建项目名子目录。质量复核后生成 AppListing/About、校对配色并改名/整理为 `aduit/`，立即建立空 `imgs/`；保留生成的 `aduit/site/index.html` 和其余三站点页。随后将同等欢迎 UI 实现于 `lib/welcome.dart` 并接入 `/welcome`，原自包含 HTML 保留为 `aduit/welcome.html`，只作独立交付、不被 App 使用或打包。按第 12.1 节分别验收 Dart 本地图片/卡片/轮播/分页点/直接 Continue 导航/启动承接与 HTML 内嵌图片、大小和四种视口。完成检查并记录结果后，才回接 `aduit/intro.md` 四个原始 `All URL`：通用协议文案仅在清除成功后的 Initialization 底部显示，Settings 仅有 Privacy Policy/Terms of Use/Support 三个 WebView 入口，Welcome 无协议页脚。然后生成 `aduit/review/remarks.md`，再完成最终图片、依赖与权限检查。任何外部失败只记录对应门槛，不取消后续材料、不伪报通过；不询问域名、不公开部署。依赖树和 bundle 中 `aduit/` 不得残留，根目录交付 `aduit/` 保留。

全局品牌色彩入口固定为 `lib/common_module/theme/app_theme.dart`：从最终 `assets/logo.png` 的真实像素提取 raw HEX，写入 AppPalette/AppTheme，再由实际页面、组件和 About 消费并以 iPhone 截图闭环验证。冷色主导的 Logo 必须重新生成或重选，主题颜色须温暖、鲜明、含协调渐变且不过度鲜艳。

新建及复用工程的最低 iOS 部署版本为 15.6；实际依赖要求更高时保留更高值。Podfile、各 target 的解析后构建设置与可用构建产物都按正文规则核验。
